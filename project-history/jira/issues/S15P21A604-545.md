## 설명

## 배경

S15P21A604-158 에서 GAME_PORTAL 을 Layout canonical whitelist 에 추가할 때 LayoutObjectType 이 타입별 local AABB 를 요구했다. 그 값의 출처는 규약상 Unity 프리팹 실측값(rotationY=0, 원점은 바닥 min.y = 0, 단위 미터 — GitLab #19 3항, 2026-08-21 확정)인데 GAME_PORTAL 몫이 문서에 없었다.

일정 때문에 프리팹 collider 에서 유도한 값을 임시로 적용했다. 작업자 승인된 임시값이며 최종값이 아니다.

| 항목 | 값 |
|---|---|
| 임시 적용값 | (-0.37, 0, -0.34) ~ (0.37, 1.97, 0.58) |
| 유도 원본 | festa-unity/Assets/_Project/Prefabs/World/ArcadeCabinet_GamePortal.prefab 루트 BoxCollider (m_Size 0.73 x 1.97 x 0.92, m_Center (0, 0.985, 0.12)) |
| 교차 검증 | 자식 ArcadeCabinet_01 (localScale 100) 의 벤더 BoxCollider 4개를 100배 한 포락과 소수 둘째 자리까지 일치 |
| 반올림 | GitLab #19 합의(서버가 보수적인 쪽) 대로 바깥으로 |

## 문제

collider 는 renderer 경계가 아니다. enum 의 다른 10종은 전부 Renderer 실측값이고, collider 가 renderer 보다 작게 잡혀 있으면 통행 판정(LayoutPassageChecker)과 실물 영역 판정(AREA_OUT_OF_BOUNDS)이 실제보다 후하게 나온다. AREA_OUT_OF_BOUNDS 는 Draft 저장에도 걸리므로 편집기에서 통과한 배치가 월드에서 벽을 뚫을 수 있다.

또 GAME_PORTAL 타입에 속하는 프리팹이 ArcadeCabinet_GamePortal 하나로 맞는지 확인되지 않았다. ArcadeCabinet_Plaza 는 광장 게임기(GitLab #135, WORLD_ARCADE_INTERACT)로 보고 포락에서 제외했다.

## 작업 내용

1. Unity 에서 ArcadeCabinet_GamePortal 프리팹의 전체 Renderer 를 기준으로 local AABB 를 실측한다 (rotationY=0, 바닥 원점, 미터).
2. Collider 기반 임시값과 비교하고 차이를 이 이슈에 남긴다.
3. GAME_PORTAL 타입에 속하는 프리팹이 하나인지 확정한다. 둘 이상이면 GitLab #19 합의대로 가장 큰 프리팹 기준 포락으로 잡는다.
4. 아래 세 사본을 하나의 MR 에서 함께 갱신한다.
5. React 편집기 → Backend 저장 → Unity 월드 배치 왕복을 실제 빌드에서 확인한다.

## 갱신할 세 사본

| 위치 | 내용 |
|---|---|
| backend/src/main/java/com/example/ssafesta/booth/LayoutObjectType.java | GAME_PORTAL 의 LocalBounds |
| festa-frontend/src/entities/layout/objectTypes.ts | OBJECT_LOCAL_BOUNDS 의 GAME_PORTAL |
| specs/005-booth-studio-layout/contracts/layout-api.md | 10-1 AABB 표 |

OBJECT_LOCAL_BOUNDS 는 같은 숫자의 세 번째 사본이다. 하나만 고치면 서버 판정과 편집기 사전 경고가 갈린다.

## 테스트 방법

1. Unity 에디터에서 프리팹의 Renderer bounds 를 읽어 값을 기록한다.
2. 값을 세 사본에 반영한 뒤 백엔드 회귀를 돌린다. AREA_OUT_OF_BOUNDS 경계 테스트가 새 값으로 통과해야 한다.
3. 편집기에서 부스 경계에 붙여 배치하고 서버 판정과 편집기 사전 경고가 같은 결론을 내는지 확인한다.
4. WebGL 빌드에서 월드에 들어가 게임기가 벽을 뚫지 않는지 본다.
