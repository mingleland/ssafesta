## 설명

## 배경

게임 파트가 남성 팔레트에서 여성복 3종을 뺐다 (S15P21A604-355). 빼는 방식이 AvatarCatalog.asset 의 items 배열에서 참조만 제거한 것이라 .asset 파일은 디스크에 남아 있고, 서버 시드 catalog_items 의 97행도 그대로다.

그래서 지금 살 수는 있고 입을 수는 없는 상품 3종이 있다.

- GET /api/v1/catalog/items?type=AVATAR_PART 가 onSale true 로 내려준다.
- POST /catalog/items/{itemId}/purchases 가 201 로 성공하고 코인 100 이 빠진다 (coin_ledger_entries 에 PURCHASE 기록).
- Unity 커스터마이징 화면이 이 3종을 그리지 않으므로 착용할 경로가 없다.

계약 테스트 AvatarCatalogSeedContractTest 는 이 어긋남을 잡지 못한다. 디스크의 .asset 파일 105개를 세면서 AvatarCatalog.asset 은 filter 로 제외하기 때문에, items 배열에서 빠지는 방향에는 걸리지 않는다.

GitLab #120 에서 (가)안으로 확정했다. is_on_sale 을 FALSE 로 내리면 계약 §2-1 표 4행(미보유·판매 중지 → 잠금, 구매 버튼 없음)에 그대로 들어가고 계약 변경이 없다.

## 변경 범위

- Flyway V20 마이그레이션 하나. asset_key 1814256283 (M_Bot.03), 356384796 (M_Top.07-A), 415781343 (M_Outfit.03) 세 행의 is_on_sale 을 FALSE 로 내린다. V19 는 GitLab #119 의 AI 문서 스키마가 잡고 있어 V20 을 쓴다.
- AvatarItemOwnershipApiIntegrationTest 에 시드 상태를 고정하는 테스트 하나. 세 asset_key 가 마이그레이션 후 판매 중지 상태인지 본다.

애플리케이션 코드는 바뀌지 않는다. 구매 거절은 InventoryService.purchase 가 이미 is_on_sale 로 판정해 ITEM_NOT_ON_SALE (409) 를 돌려주고, 그 동작은 기존 테스트가 덮고 있다.

## 범위 밖

- 계약 테스트 기준을 items 배열로 옮기는 것 (GitLab #120 의 (나)안). 이번 구멍은 (가)로 닫히고, 기준을 옮기면 Unity 배열을 건드릴 때마다 BE 테스트가 깨진다. 같은 어긋남이 재발하면 그때 옮긴다.
- 이미 구매한 계정 처리. is_on_sale FALSE 는 기보유를 되돌리지 않는다. dev·demo 구매 이력 확인을 GitLab #120 에서 게임 파트에 요청했고, 이력이 있으면 별도로 정한다.
