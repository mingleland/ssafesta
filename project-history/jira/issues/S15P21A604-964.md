## 설명

## 발생 환경  - Branch: develop - Runtime: EC2 / infra/observability/compose.yaml - Services: Alloy, Loki  ## 재현 방법  1. infra/observability/.env에 필수 retention/resource/Grafana 값을 설정한다. 2. docker compose --env-file .env -f compose.yaml up -d alloy loki prometheus grafana 를 실행한다. 3. Alloy/Loki health 상태와 로그를 확인한다.  ## 기대 결과  - 새 EC2 또는 새 Docker volume에서 별도 수동 chmod 없이 stack이 기동한다. - Alloy, Loki, Prometheus, Grafana가 healthy가 된다. - Loki는 normal runtime에서 non-root로 유지된다. - CI가 Alloy syntax와 fresh Loki volume 기동을 재현·검증한다.  ## 실제 결과  - Alloy: config.alloy의 rule 블록 세미콜론 문법 때문에 River parser 초기 로드가 실패한다. - Loki: 새 named volume이 root 소유로 생성되어 non-root Loki가 /var/lib/loki/chunks를 생성하지 못한다. - Prometheus는 healthy이나 Alloy/Loki는 unhealthy 또는 restart 상태가 된다.  ## 완료 조건  - [ ] Alloy River rule syntax 수정 및 runtime parser 검증 추가 - [ ] fresh Loki named volume ownership bootstrap 구현 - [ ] Loki normal runtime non-root 확인 - [ ] fresh project/volume 기동 regression test 추가 - [ ] 기존 Demo/Production/Jenkins 컨테이너가 관측 stack 기동으로 재시작되지 않음
