## 설명

## 발견 경위

2026-08-31 로컬 풀스택 기동 테스트(게임 파트) 중, 새로 세팅하는 입장에서 `.env.example` 만 보고 환경을 구성해 봤다.

## 문제

코드가 실제로 읽는 `VITE_*` 는 4개인데 `.env.example` 에는 2개만 있다.

```
코드 사용:     VITE_API_BASE_URL, VITE_GAME_STUDIO_API_ENABLED, VITE_USE_MOCK, VITE_UNITY_BUILD_BASE
.env.example: VITE_API_BASE_URL, VITE_GAME_STUDIO_API_ENABLED
```

(확인 명령: `grep -rhoE 'import\.meta\.env\.[A-Z_]+' src | sort -u`)

- `VITE_USE_MOCK` — 미설정이면 `=== 'true'` 비교로 실 API 모드가 되긴 하지만, **mock 으로 개발하려는 사람은 이 키의 존재를 알 방법이 없다**
- `VITE_UNITY_BUILD_BASE` — Unity WebGL 임베드 원점. 미설정 시 월드 화면이 어떻게 되는지 example 만 봐서는 알 수 없다

backend 쪽 `.gitignore` 주석("… .env.example 은 필요한 키 목록을 팀원에게 전달하는 유일한 경로다")이 이 저장소의 원칙인데, FE example 이 그 원칙에서 벗어나 있다.

## 제안

`.env.example` 에 두 키를 주석과 함께 추가. 게임 파트 로컬 기동 기준으로는 `VITE_UNITY_BUILD_BASE=http://localhost:8000` (serve.mjs), `VITE_USE_MOCK=false` (실 BE 연동 시)가 동작하는 조합이었다.

FE 파일이라 게임 파트에서 직접 MR 하지 않고 이슈로 남긴다.
