## 설명

BE 가 문서 수정본 교체 API 를 열었다(PUT /api/v1/documents/{documentId}/replacement, S15P21A604-386 develop 도달). FE 에는 그 호출부가 없다.

지금은 같은 파일을 다시 올리면 duplicate 로 막히고, 내용을 고쳐 올리면 해시가 달라 문서가 하나 더 쌓인다 — 사용자에게 교체 수단이 없다.

범위
- entities/aiAgent/api.ts 에 교체 호출 추가. 요청·응답은 기존 업로드(POST /agents/{agentId}/documents/upload-url)와 같고 이후 단계도 presigned PUT → POST /documents/{newDocumentId}/complete 그대로다.
- mock 포트 동기화.
- AI 직원 관리 탭 문서 행에 교체 진입.

완료조건
- 단위 2건: 교체 성공, 중복 해시 거부.
- 로컬 왕복 1회. demo BE 에는 이 경로가 없어 로컬에서 검증한다.

팀 공유·논의 정본: GitLab #179

### 이정헌 · 2026-09-13 23:28 KST

구현과 로컬 실 왕복을 마쳤다. MR !802 (pipeline 191900 success).

replaceAiDocument(documentId, file) 을 더했다. 3단계 중 1단계만 신규 등록과 다르고 presigned PUT 과 complete 는 같아서, 갈라지는 1단계를 인자로 받는 공통 몸통으로 묶었다. 완료는 1단계가 돌려준 새 문서 id 로 부른다 — 원본 id 로 부르면 409 다. 관리 탭에서는 준비 완료(READY) 문서 행에만 교체 진입을 연다. 서버도 그 상태만 받는다.

로컬 실 스택 왕복(FE 5175 · Spring 8080 · Postgres 5432 · Redis 6379 · MinIO 9000, SSAFY OAuth 회원 세션):

1. AI 직원 등록 후 guide.md 업로드 — QUEUED, MinIO 에 booths/1/agents/1/documents/1/guide.md 96B 생성
2. 로컬에 AI 처리 서버가 없어 READY 로 가지 않으므로 DB 에서 상태만 올려 교체 진입을 열었다
3. guide-v2.md 로 교체 — ai_documents 에 id=2, replaces_document_id=1, QUEUED 생성. 원본 1 은 READY 유지. MinIO 에 두 번째 객체 109B 생성
4. 같은 파일로 다시 교체 — "같은 내용이라 교체하지 않았습니다.", 문서 수 2 유지

단위 3건 추가, tsc 0, 전체 216 files / 1388 tests 통과.

부수 발견: 로컬에서 OAuth 가 시작되지 않았다. dev 게이트웨이가 /api 만 넘기는데 Spring 은 /api/v1/auth/oauth/{provider} 에서 /oauth2/authorization/{provider} 로 302 를 보내고, 그 경로가 게이트웨이에 없어 FE 오리진에 떨어졌다. authBaseUrl 이 원래 이 경우를 위한 값이라 로컬만 Spring 직행으로 두어 해결했다(.env.local, 커밋 대상 아님). 게이트웨이에 /oauth2 를 넣어 같은 오리진으로 통일하는 정리는 devGateway 를 이미 손대고 있는 -649 후속으로 분리한다.

MR 에 Closes 는 넣지 않았고 develop 병합 후 완료로 옮긴다.
