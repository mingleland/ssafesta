## 설명

배경

infra-002 tasks.md의 US2(T029~T039)는 demo 환경을 infra/environments/compose/demo/, config/manifests/demo.json, nginx/nginx.conf에 새로 만들도록 적혀 있다. 그런데 실제 demo는 이미 다른 경로에서 운영 중이다.

실측

- 운영 중인 demo: infra/deploy/compose/integration/compose.yaml (festa-integration), infra/unity-server/compose.yaml (festa-demo-world)
- 라우팅: infra/environments/nginx/sites/{demo,api,world-dev}.conf.template
- CD 경로: infra/jenkins/pipelines/demo-promotion.groovy -> infra/deploy/scripts/{deploy,verify,rollback,promote}-release.sh
- infra/environments/config/manifests/demo.json 과 compose/demo/ 는 존재하지 않는다

원인

infra-001이 먼저 완성되면서 실제 배포 경로가 infra/deploy에 자리잡았고, infra-002 tasks는 그 이전에 작성됐다. 명세를 문자 그대로 따르면 현재 자동 배포·롤백이 물려 있는 CD 파이프라인을 통째로 교체해야 한다.

같은 판단의 독립 근거로, spec 007 T076도 storage-failover.sh의 위치를 infra/deploy/scripts/로 지정하고 있다. 런타임 스크립트 소유권을 deploy 트리로 보는 것이 이미 다른 명세와도 일치한다.

작업 내용

1. tasks.md US2(T029~T039)의 대상 경로를 현재 운영 실체로 재정의한다. 검증·매니페스트·자원 경합 게이트의 요구사항은 유지하고 위치만 실제 경로로 바꾼다.
2. 이미 구현됐으나 미체크로 남은 항목을 정정한다. T059·T060은 backend/src/main/resources/application-infra.yml, common/RedisKeyspaceProperties.java, MemberSessionService, OAuthHandoffService, DailyCoinGrantService에 반영 완료 상태다.
3. T007의 부분 구현 범위를 명시한다. Usage Guard 검증은 있고 Storage Failover 상태 일치 검증이 빠져 있다.
4. plan.md, quickstart.md에 같은 경로 기준을 반영한다.

완료 조건

- tasks.md US2 항목이 실제 검증 가능한 경로를 가리킨다
- T059·T060 완료 표기가 실제 구현과 일치한다
- T007 잔여 범위가 문서에 드러난다
- 코드·CD 파이프라인 변경은 없다

범위 밖

- demo 배포 경로 이전
- US4 보안 경계 구현 (별도 진행)
