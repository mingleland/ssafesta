## 설명

## 작업 목적

S15P21A604-409에서 `PlayGamePage.tsx`의 모듈 최상단 env 상수(`browserPublicationEnabled` 등)가 "모듈 import 시점에 한 번만 읽힘" 구조라 테스트가 로컬 `.env.local` 값에 좌우되는 버그가 있었다. 같은 패턴이 `EditGamePage.tsx`에도 있음을 정헌님이 리뷰 중 발견했다(GitLab Issue #125 코멘트). 두 파일의 env 읽기를 실행 시점 accessor 함수로 분리해 정리한다.

## 작업 내용

- game-studio 안 모듈 최상단 `import.meta.env` 읽기 패턴 전수 확인(`grep "^const .*import.meta.env"` 기준 `PlayGamePage.tsx`, `EditGamePage.tsx` 2곳)
- `EditGamePage.tsx`에 -409와 같은 클래스의 버그가 실제로 있는지 검증할 테스트 추가(`.env.local` 유무에 따라 red/green이 갈리는지 먼저 재현 — 수정의 근거가 되는 실패 테스트를 남긴다)
- 두 파일의 env 읽기를 `getUseMock()` / `resolveRuntimeMode()` 같은 실행 시점 accessor 함수로 추출(공용 유틸 모듈 위치는 구현 중 결정)
- `PlayGamePage.tsx`의 기존 `useMemo(() => ..., [])` 방식도 이 accessor로 통일할지 판단 후 반영
- `publishedAssetResolver`처럼 "참조 고정"이 의도적으로 필요한 모듈 상수는 이번 리팩터 대상에서 제외(그 의도·동작 그대로 유지)

## 완료 조건

- [ ] `EditGamePage.tsx`에 env-격리 테스트 추가, 수정 전 상태로 실패(빨간) 재현 확인
- [ ] `PlayGamePage.tsx`/`EditGamePage.tsx`의 env 읽기가 실행 시점 accessor로 통일됨
- [ ] 위 테스트가 `.env.local` 유무와 무관하게 통과
- [ ] `npx tsc --noEmit`, `npx vitest run src/game-studio` 전체 통과
- [ ] `publishedAssetResolver` 등 의도적 참조 고정 상수의 동작은 변경 없음(회귀 없음)
