## 종료 API 만 넣으면 D11 이 깨집니다

`stream_service` 는 `authorize()` 가 넘긴 Conversation 객체를 메모리에 들고 스트리밍하고, 확정 지점의 `save()` 는 조건 없는 `SET` 이었습니다. FE 를 읽어 확인한 사실입니다.

- AI 경로에 `AbortController` 가 0건이고 `reader.cancel()` 도 없습니다
- 오버레이 닫기는 `onClose` 하나뿐이고 진행 중 스트림을 정리하는 코드가 없습니다. `ask()` 가 분리된 async 함수라 컴포넌트가 사라진 뒤에도 SSE 를 끝까지 계속 읽습니다

따라서 취소 신호가 서버에 도달하지 않고 서버는 확정 지점까지 진행합니다. FE 가 close 를 붙이면 **닫기 → DELETE → 서버가 답변을 끝내고 save** 순서가 되어 질문·답변 원문이 30분 수명으로 부활합니다. 창은 전체 응답 한도인 **최대 60초 전체**입니다. 유휴 TTL 만료가 긴 응답 도중 지나가는 경우도 같은 구멍이고 이쪽은 SC-012 후단을 직접 깹니다.

확정 쓰기를 `SET ... EX ... XX` 로 바꿔 대화가 살아 있을 때만 저장하게 했습니다. 진행 중 스트림은 끊지 않고 확정만 막습니다 — C-08 의 "임대 만료 시 진행 중 1건은 60초 안에 완료"와 같은 방향입니다. S15P21A604-141 이 확정 지점을 둘로 늘려놓았어서(자료 미준비 경로 + 정상 답변 경로) 두 곳을 하나로 모았습니다.
