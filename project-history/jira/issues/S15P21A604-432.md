## 설명

배경 (docs/25 T-115·T-120, GitLab #52·#128): 브라우저 탭을 뒤로 보내면 Chrome 이 requestAnimationFrame 을 멈춰 Unity 하트비트가 끊기고 30초 안에 접속이 떨어진다. 포그라운드로 돌아와도 재접속도 안내도 없다. 사용자가 다른 탭을 잠시 보는 것은 정상 행동이라 09-08 사용자 테스트에서 밟힐 가능성이 높다.

이 이슈는 Lobby→Main 50~84초 문제와 섞지 않는다 — 원인도 해법도 다르다.

역할 분할
- FE: visibilitychange 로 복귀 감지, '재접속 중' 안내, 복구 불가 시 명확한 재진입 동선. FE 단독으로 할 수 있는 부분이다.
- Unity/게임: connection health 판정, reconnect/rejoin, world state 복원. 어느 시점에 끊긴 것으로 볼 것인지, 재접속을 클라이언트가 시도하는지가 이쪽 결정이다.
- 서버: resume 정책과 세션 만료 — 끊긴 세션을 얼마나 살려두는가.

FE 가 먼저 필요로 하는 것: ① 재접속 가능 여부를 FE 가 알 수 있는 신호(브리지 이벤트 또는 상태 조회) ② 재접속을 FE 가 트리거해야 하는지, Unity 가 자동으로 하는지.

주의: verify-public-wss.sh 의 '10분 무입력' 항목은 탭을 앞에 둔 채 재야 한다 — 뒤로 보내면 이 현상 때문에 실패로 잘못 읽힌다(#52).

완료 조건: 백그라운드 30초+ 후 포그라운드 복귀 시 자동 reconnect/rejoin 이 되거나, 안 되면 사용자가 무엇을 해야 하는지 화면으로 명확하다 / 끊김을 조용히 두지 않는다.
