## 설명

## 발생 환경

- Branch: develop
- Component: infra/observability
- Images: grafana/alloy:v1.18.0, grafana/loki:3.7.4

## 재현 방법

1. observability compose를 기동한다.
2. Alloy와 Loki의 상태 및 로그를 확인한다.

## 기대 결과

- Alloy가 redaction 모듈을 로드하고 로그를 Loki로 전달한다.
- Loki healthcheck가 이미지에 존재하는 실행 경로로 정상 판정한다.

## 실제 결과

- redaction.alloy의 River 세미콜론 문법 때문에 sanitize custom component 등록이 실패하고 Alloy가 재시작한다.
- distroless Loki 이미지에 /bin/sh와 wget이 없어 CMD-SHELL healthcheck가 항상 실패한다.
- 기존 redaction 테스트는 Python re.sub 동작만 검증해 Alloy stage.replace 캡처 의미 차이를 잡지 못한다.

## 완료 조건

- [ ] redaction.alloy가 Alloy v1.18 validate를 통과한다.
- [ ] credential·webhook·email·phone 값이 실제 stage.replace 캡처 규칙에 맞게 치환된다.
- [ ] Alloy healthcheck가 fmt가 아닌 validate를 사용한다.
- [ ] Loki healthcheck가 /bin/sh 또는 wget 없이 실행된다.
- [ ] 기존 observability isolation·redaction 테스트가 통과한다.
