## 설명

### 작업 목적

Spring이 업로드를 끝낸 문서를 AI 처리 대기열에 등록하는 API 생성

### 작업 내용

- `POST /ai/v1/documents/process` 구현
- Service Token과 요청 형식 검증
- AI DB에서 동일 `documentId`의 활성 Job 조회
- 기존 Job의 `boothId`, `agentId`, `sourceHash`와 요청 snapshot 비교
   
   - 일치: 새 Job을 만들지 않고 `existing: true`로 기존 Job 반환
   - 불일치: `409 Conflict` 반환
- 활성 Job이 없으면 `QUEUED` Job 생성 후 `existing: false`로 반환
- 동시 요청은 활성 Job 부분 유니크 인덱스로 중복 생성 방지
- 신규·기존 Job 모두 HTTP `202 Accepted` 반환

### 완료 조건

- [ ] `document-processing-api.yaml` 계약과 요청·응답이 일치한다.
- [ ] 정상 요청 시 `QUEUED` Job이 생성되고 `202`, `existing: false`가 반환된다.
- [ ] 동일 요청을 반복해도 Job은 한 개만 존재하고 `existing: true`가 반환된다.
- [ ] 활성 Job과 요청 snapshot이 다르면 `409`가 반환된다.
- [ ] 인증 실패는 `401`, 요청 형식 오류는 `422`가 반환된다.
- [ ] 동시 중복 요청에서도 활성 Job이 하나만 생성된다.

### 선행 작업 / Dependency

- https://ssafy.atlassian.net/browse/S15P21A604-95#icft=S15P21A604-95 (document_jobs)

### 참고

- specs/007 plan §2

### 테스트 방법

1. 동일 요청을 두 번 전송한다.
2. AI DB의 활성 Job이 한 건인지 확인한다.
3. 첫 응답이 `existing: false`, 두 번째 응답이 `existing: true`인지 확인한다.
4. 같은 `documentId`에 다른 `sourceHash`를 보내 `409`를 확인한다.
5. Service Token 누락·오류 요청이 `401`인지 확인한다.
