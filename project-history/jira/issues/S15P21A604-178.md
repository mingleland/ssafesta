## 설명

작업 목적

저장·게시되는 GameProject가 공통 schema와 의미 규칙을 지키는지 서버가 검증한다.

작업 내용

- JSON schema 검증
- 참조 무결성·Scene 시작점·상한·Event/Component 의미 검증
- FE·BE·AI 공유 fixture와 rule 이름 동치 유지

완료 조건

[x] 불량 문서는 S15P21A604-217에서 승인한 HTTP/code/rule 계약으로 거부된다.

[x] FE 통과 문서를 BE가 임의로 거부하거나 반대 결과를 내지 않는다.

[x] 오류에 sceneId/objectId/path 등 사용자가 고칠 위치 정보가 포함된다.

[x] v1.0과 승인된 v1.1 문서를 모두 회귀 검증한다.

선행 작업 / Dependency

BLOCKED BY: S15P21A604-111·217, S15P21A604-246 상한 계약

테스트 방법

공유 정상·오류 fixture를 양측 validator에서 실행해 결과를 대조한다.

---

검증 근거 (2026-08-26, MR !33 + !38 develop 머지)

- 거부 계약: 409 GAME_VALIDATION_FAILED + errors[].rule. 계약 fixture 8/8 통과, rule 이름 전수 대조가 계약표·서버·검증기에서 일치한다
- 위치 정보: 모든 메시지가 JSON Pointer 를 담는다 (/scenes/0/objects/12/id 형태). 좌표·id·참조 전부 고칠 칸을 가리킨다
- v1.1 회귀: GameNamedRuleTest 가 rules 블록을 7 곳에서 다룬다 — DUPLICATE_OBJECTIVE_TYPE · OBJECTIVE_TARGET_INVALID · PLAYER_DEFEAT_INVALID · objectives 상한이 MALFORMED_PROJECT 로 떨어지는 것. v1.0 은 fixture 8 건이 담당한다
- 미승인 코드 안 씀: 테스트가 쓰는 status 는 200·201·204·304·403·404·409 뿐이고 422 사용은 0 건이다

FE 대조 — !38 에서 불일치 2 건을 없앴다

- SHOW_DIALOGUE 대상이 DIALOGUE 인데 FULL_SCREEN: 서버가 DIALOGUE_TARGET_INVALID 를 내고 있었는데 FE(gameProject.ts:693)·계약 검증기(validate-fixtures.mjs:111)는 DIALOGUE_PRESENTATION_INVALID 다. 서버를 맞췄다
- presentation 이 enum 밖: 서버가 MALFORMED_PROJECT 로 흘리고 있었는데 검증기(:200)는 이름을 낸다. GameSchemaRuleMap 에 매핑했다

문서화된 예외 1 건 (임의 거부가 아니다)

- validate-fixtures.mjs:50 의 정규식이 /^(builtin|asset):/// 라서 asset://local 을 통과시키지만 서버는 authority 까지 보고 거부한다. 계약 §Asset 정책이 "fixture 는 하한이고 서버가 상한" 으로 명시한 의도적 비대칭이다 — 이 차이를 문서에 적지 않으면 fixture 통과 문서가 서버에서 거부되는 것을 계약 위반으로 오해한다
