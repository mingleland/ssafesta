## 설명

S15P21A604-127(AI Conversation 명시적 종료 API)이 MR !432 로 develop 에 도달했다(2026-09-07 17:06). 그에 대응하는 FE 결선을 붙인다. GitLab #147 요청.

[왜 지금인가]
abort 가 없으면 버려질 답변에 LLM 토큰과 커넥션을 최대 60초 더 태운다(전체 응답 timeout, 헌법 19조). close 가 없으면 사용자가 닫은 대화 원문이 최대 30분 Redis 유휴 TTL 까지 남는다. 영구 저장이 아니라 D-11 위반은 아니지만 '닫으면 즉시 삭제' 약속이 안 지켜진다. 09-08 오후 사용자 테스트에서 실제 방문자가 AI 채팅에 입력한다(#137).

[실측한 현재 상태]
- features/ai/ui/AiChatOverlay.tsx 는 onClose 가 closeOverlay 뿐이고 useEffect 는 스크롤용이며 cleanup 이 없다
- ask() 가 분리된 async 함수라 consumeSseStream 이 언마운트 뒤에도 계속 돈다
- entities/conversation/api.ts 의 streamMessage 는 finally 에서 releaseLock 만 하고 cancel·abort 가 없다
- entities/conversation 과 features/ai 에 AbortController 0건

[범위]
1. entities/conversation/api.ts 에 closeConversation 추가(DELETE, 204 멱등, 403 소유권). aiFetch 는 init 을 그대로 펼치므로 signal 이 이미 통과한다 — 새 래퍼를 만들지 않는다
2. streamMessage 에 signal 인자 추가, finally 를 releaseLock 에서 cancel 로 교체
3. AiChatOverlay 언마운트 하나로 모든 닫기 경로를 덮는다. OverlayHost 가 request 없으면 null 을 반환하고 타입별로 컴포넌트를 갈아끼우므로 Esc·dim 클릭·X 버튼·외부 closeOverlay·다른 오버레이 전환이 전부 언마운트로 수렴한다
4. AbortError 는 오류 말풍선을 그리지 않는다. GameOverlay.tsx 의 기존 관용구를 재사용한다
5. close 실패는 삼킨다. ai 라우팅이 아직 인프라 대기라 호출이 안 나갈 수 있고 그때도 조용해야 한다

[함께 고치는 것 — GitLab #145]
같은 파일의 red 2건은 원인이 둘 다 테스트다. 실행으로 증명했다.
- 두 번째 질문 테스트: mockReturnValue(mockStreamSuccess()) 가 같은 제너레이터 인스턴스를 두 번 준다. 실측 1회차 ab, 2회차 빈 문자열. factory 형태는 두 번 다 ab
- 403 테스트: mockRejectedValueOnce 가 Promise 를 주는데 streamMessage 는 async generator 라 for await 가 TypeError 를 낸다. 실측 rejected is not async iterable. 던지는 async generator 로 바꾸면 status 403 이 그대로 전달돼 isAiHttpError 를 통과한다

[Jira 키를 새로 발급한 이유]
S15P21A604-189 작업일지가 '범위 밖: Conversation 명시적 종료 미호출 — 127 아직 To Do' 로 명시적으로 밀어 둔 항목이다. 밀어 둔 것을 원 티켓에 되붙이면 완료 판정이 흐려진다.

[검증]
기준선 실측(develop 2704a2a9): vitest 1 failed 134 passed(135) · 2 failed 817 passed(819) · build 통과. 작업 후 실패가 0 이 되어야 하고 나머지 수치는 기준선과 같아야 한다.
