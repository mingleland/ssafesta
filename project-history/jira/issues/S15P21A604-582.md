## 설명

## 작업 목적

- 변수/아이템/자산 카드의 삭제(×) 버튼을 누르면 뜨는 "…삭제할까요?" 확인 UI가 클릭한 카드  
   옆이 아니라 각 섹션 맨 끝 고정 위치에 렌더되고, 스타일이 전혀 없어(관련 CSS 없음)  
   다이얼로그로 안 보인다. 목록이 길고 스크롤한 상태면 확인창이 화면 밖에 뜬다. 화면 중앙에  
   뜨는 메시지 박스(삭제/취소)로 바꾼다.

## 작업 내용

- ProjectDataPanel의 세 삭제 확인 블록(`gss-asset-delete-confirm` — 변수·아이템·자산)을  
   `GameStudioShell.tsx`의 `showResetConfirm`과 동일한 중앙 모달 패턴으로 교체:
   
   - `.gss-guide-backdrop`(화면 덮는 반투명 오버레이) + `role="dialog"` `aria-modal="true"`  
      `section` + 취소/삭제 액션 영역
   - 바깥 클릭 → 취소, 안쪽 클릭 → `stopPropagation`, 취소가 기본 포커스
- 기존 문구·사용 위치(⌖ location) 표시 로직은 그대로 재사용, 감싸는 컨테이너만 교체
- `role="alertdialog"` → `role="dialog"`로 변경(실제 모달 backdrop이 생기므로)
- 삭제 버튼은 위험 동작이라 빨간 톤으로 구분(기존 `.gss-danger-button`/`.gss-guide-start`  
   참고). 반복되는 3곳을 작은 로컬 컴포넌트로 묶을지는 구현 중 판단
- 삭제 테스트 3개(`projectDataPanelVariableDelete`/`ItemDelete`/`AssetDelete`)의  
   `getByRole('alertdialog')` → `getByRole('dialog')`로 갱신

## 완료 조건

- [ ] 세 삭제 확인 UI가 스크롤 위치와 무관하게 화면 중앙 모달로 뜬다
- [ ] 모달에 배경·테두리·그림자가 있어 다이얼로그로 인식된다(기존 `showResetConfirm` 톤)
- [ ] "삭제" → 실제 삭제 + 모달 닫힘, "취소"/바깥 클릭 → 삭제 안 되고 모달만 닫힘
- [ ] 사용 중인 항목 삭제 시도 시 사용 위치(⌖) 목록이 모달 안에 그대로 표시된다
- [ ] `role="dialog"` + `aria-modal="true"`로 접근성이 실제 동작과 일치한다
- [ ] `npx vitest run`, `npm run build`, `npx tsc --noEmit`, `npm run lint` 통과

## 선행 작업 / Dependency

- 없음

## 테스트 방법

1. 변수/아이템/자산 각각의 삭제(×) 버튼 클릭 → 화면 중앙에 모달이 뜨는지 확인(스크롤 위치와  
   무관하게 항상 같은 자리)
2. 모달 "삭제" → 실제 삭제 + 모달 닫힘 / "취소"·바깥 클릭 → 삭제 안 되고 모달만 닫힘
3. 사용 중인 항목 삭제 시도 → 사용 위치(⌖) 목록이 모달 안에 그대로 표시되는지 확인
4. 삭제 테스트 3개의 `getByRole` 셀렉터 갱신 후 통과 확인
5. `npx vitest run`, `npm run build`, `npx tsc --noEmit`, `npm run lint` 통과
