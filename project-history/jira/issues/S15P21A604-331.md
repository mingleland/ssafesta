## 설명

### 증상

로컬 개발 접속(`DevConnectionHud` → "정식 접속 흐름 검증" → world-sessions Mock → `StartClient`)이 **항상 입장 거부된다.**

### 원인 (실측 확인)

`MockUserApiClient.CreateWorldSessionAsync()` 가 고정 문자열을 준다:

```csharp
connectionToken = "mock-connection-token",
```

S15P21A604-85 로 서버가 HS256 서명을 검증하게 된 뒤로 이 값은 통과할 수 없다. 에디터에서 직접 검증해 확인했다:

```
Mock 토큰 검증 통과=False | 거부 사유="JWT 형식이 아니다"
```

`ApiConfig.asset` 이 `useMockApi: 1` 이고 `ApiServices.EnsureInitialized()` 도 Mock 으로 초기화하므로, **로컬 개발 루프 전체가 이 경로**다.

### 왜 놓쳤나

`-85` 때 `LoadTestBot` 은 같이 고쳤다 — 그 파일 주석에 이렇게 적혀 있다:

> 입장 검증이 켜진 뒤로(S15P21A604-85) 고정 문자열 토큰은 거부된다. (…) 봇이 서버와 같은 키로 진짜 grant 를 서명한다

**같은 성격의 고정 토큰이 Mock 에도 있었는데 그 스윕에서 빠졌다.**

### 작업 내용

- `MockUserApiClient` 가 `WorldEntryTokenSigner.TryIssue` 로 진짜 grant 를 서명하도록 변경 (`LoadTestBot` 과 같은 방식). `jti` 는 매번 달라야 한다 — 재사용 원장이 거부한다
- 서명할 수 없으면(시크릿 없음 — 예: WebGL) **조용히 고정 문자열로 되돌아가지 말 것.** 원인을 명시한 에러로 드러낸다 (T-24 원칙)

### 완료 조건

- [ ] 시크릿이 있는 환경에서 Mock 경로로 실제 접속·스폰 성공
- [ ] 시크릿이 없으면 거부 사유가 "Mock 이 grant 를 서명하지 못했다"로 로그에 드러남
- [ ] 서버에 "Mock 은 봐준다" 예외를 만들지 않을 것 — 그 예외가 곧 우회로가 된다
