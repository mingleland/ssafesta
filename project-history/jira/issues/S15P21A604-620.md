## 설명

h3. 작업 목적

월드에서 부스 스튜디오·관리 상세로 나갔다 돌아오면 *Unity 가 처음부터 다시 뜬다.* 부팅 + 로비 + main 씬 로드로 50~84초다(#128 실측). 사용자가 직접 플레이하며 보고한 항목(2026-09-10 감사 11)의 뿌리다.

원인은 렌더 자리 하나다.

{code}
/app/world 진입   WorldPage mount → WorldSurface → UnityHost
                  → acquireUnitySession → instance

/app/studio/42    WorldPage unmount → UnityHost unmount
                  → releaseUnitySession → instance.Quit()   ← 여기서 파괴된다

돌아오기          전부 다시
{code}

h3. 왜 작은 변경으로 끝나는가

인스턴스 소유는 *이미 라우트 독립적이다.* {{sessionManager}} 가 모듈 스코프 싱글톤이고 {{getReadyUnityInstance()}} 로 트리 밖에서도 인스턴스를 얻는다 — 그 파일 주석이 "누가 Unity 를 부를 수 있는가가 화면 트리 모양에 묶이면 안 된다"고 이미 적고 있다.

라우트에 묶여 있는 것은 두 가지뿐이다.

# {{UnityHost}} 가 그리는 *canvas DOM 노드*
# 그 컴포넌트의 *unmount 가 곧 release* 라는 배선

이 둘만 라우트 밖으로 올린다.

h3. 후보 비교

|| 안 || 라우터 변경 || Unity 재생성 || 위험 ||
| A. {{/app}} 전체를 레이아웃 라우트로 묶고 그 안에 GameShell | 9개 라우트를 children 으로 재배치 | 월드 첫 진입 1회 | 라우터 구조 변경이 커서 되돌리기 비쌈 |
| B. world·game 라우트 그룹에만 | 위와 비슷 | 동상 | {{/app/games/*}} 는 Unity 를 쓰지 않아 그룹에 넣을 근거가 없다 — 사실상 A 와 같아진다 |
| *C. {{WorldSurface.select}} seam 을 상주 호스트로 승격* | *없음* | 월드 첫 진입 1회 | 라우트 밖 DOM 소유가 생긴다 — 다만 {{sessionManager}} 가 이미 같은 성질이다 |

*C 를 택한다.* {{WorldSurface.select.ts}} 주석이 이미 "Persistent GameShell 단계에서 이 seam 이 그대로 상주 Unity 로 승격된다"고 승격 지점을 지목해 두었고, 라우터를 건드리지 않아 되돌리기가 싸다.

h3. 작업 내용

# {{unity/host/worldMount.ts}} — 신규. {{mounted}}(한 번 서면 명시 해제 전까지 유지) · {{visible}}(월드 라우트에 있는 동안만) 두 값을 갖는 module store. {{hostPhase}}·{{worldUiState}} 와 같은 관례다.
# {{unity/host/PersistentWorld.tsx}} — 신규. {{RouterProvider}} 와 형제로 서서 {{WorldSurface}} 를 상주시킨다. WorldPage 를 복제하지 않는다 — seam 그대로 옮긴다.
# {{WorldPage}} — {{WorldSurface}} 를 직접 그리지 않고 mount·show 를 요청한다. 나갈 때는 감추기만 하고 파괴하지 않는다.
# 명시적 teardown 두 곳 — 로그아웃, 가드가 {{/login}} 으로 돌려보낼 때. 그 밖에는 유지한다.

h3. 이 작업에서 하지 않는 것 (감사 11 의 나머지)

감사가 이미 "Story 승격 + 4 Task 분해"로 판정한 건이다. 이번은 그중 *인스턴스 생존*만 다룬다.

* 관리 상세 3종·Booth Studio 를 라우트에서 오버레이로 전환
* {{?panel=management}} 복원 땜빵 제거
* 게임 내부 화면 전환이 history entry 를 만들지 않게 하기
* deep link normalization({{/app/studio/:id}} 직접 진입 → GameShell replace + 내부 오버레이)
* Booth Studio 배경을 {{landing-background.png}} 에서 실제 월드로

h3. 하지 않는 것 (계약)

* *새 Unity message 계약을 만들지 않는다.* {{SetInputLocked}}·{{RequestExitWorldUi}}·{{AudioBridge}} 그대로다.
* 새 input-lock 체계·새 Overlay lifecycle 을 만들지 않는다. {{worldScreen}} 이 소유권 판정의 유일한 지점인 것도 그대로다.
* Unity 내부 씬 전환을 FE 가 추정하지 않는다.

h3. 섞지 않는 상태

{code}
Unity instance 생존   sessionManager
HostStatus            월드 준비 단계 (booting~ready)
현재 route            react-router
worldScreen           React 화면 소유권
insideBooth           월드 컨텍스트 — 계약 없음 (GitLab #174)
focus / minigame      Unity 모달 관측값
{code}

서로 대체하지 않는다. 특히 {{HostStatus.ready}} 와 {{worldScreen}} 과 {{visible}} 은 다른 층이다.
