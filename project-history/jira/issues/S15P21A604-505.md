## 설명

## 증상

인프라(정승욱)가 GitLab #142 에서 보고했다. 릴리스 WebGL(41107ee2)로 wss://world-dev.ssafesta.world:443 접속 시 네트워크 요청이 만들어지기도 전에 종료된다.

Invalid network endpoint: world-dev.ssafesta.world:443.
Target server network address (world-dev.ssafesta.world) is Invalid!
[Netcode] Client is shutting down due to network transport start failure of UnityTransport!

DNS, Cloudflare, Nginx, 게임 서버, Unity 라이선스 문제가 아니다. Backend 의 world-session 발급은 정상이고 외부 WSS Upgrade 도 HTTP 101 로 확인됐다.

## 원인

NGO 2.4.3 의 UnityTransport 에 FQDN 지원 코드가 이미 들어 있으나, asmdef 의 versionDefine 으로 잠겨 있다.

Runtime/Unity.Netcode.Runtime.asmdef
  name: Unity, expression: 6000.1.0a1, define: HOSTNAME_RESOLUTION_AVAILABLE

프로젝트는 Unity 6000.0.78f1 이라 이 디파인이 켜지지 않고, UnityTransport.cs 의 FQDN 분기가 통째로 컴파일에서 빠진다. 그래서 ServerEndPoint 가 Invalid 를 반환하는 즉시 에러를 내고 종료한다.

## 이 디파인을 켜도 되는 근거

버전 게이트는 Unity 6000.1 을 요구하지만, 그 코드가 실제로 쓰는 API 는 설치된 패키지에 이미 전부 있다.

1. UnityTransport.ClientBindAndConnect 의 FQDN 경로는 m_Driver.Connect(address, port) 를 호출한다.
2. 그 오버로드 NetworkDriver.Connect(FixedString512Bytes, ushort) 는 com.unity.transport 2.5.1 에 존재하며, UNITY_WEBGL 전용 분기가 host:port 문자열로 NetworkEndpoint 를 만들어 그대로 WebSocket URL 로 쓴다.
3. 그 NetworkEndpoint(FixedString512Bytes) 생성자도 WebGL 블록 안에 존재하고 Family 를 NetworkFamily.Custom 으로 둔다.
4. 같이 필요한 UTP_TRANSPORT_2_4_ABOVE 는 transport 2.4.0 이상 조건이라 이미 켜져 있다.
5. 추가로 필요한 참조는 System.Text.RegularExpressions 뿐이다.

## 조치

Player Settings 의 Scripting Define Symbols 에 HOSTNAME_RESOLUTION_AVAILABLE 를 추가한다. WebGL 과 Standalone 둘 다에 넣는다 — 부하테스트 봇 클라이언트도 같은 FQDN 으로 붙어야 해서 같은 벽에 막힌다.

클라이언트 코드는 고칠 것이 없다. ConnectionManager 는 SetConnectionData 앞에서 이미 UseWebSockets 를 켜고 있다.

## 검증

WebGL 재빌드 후 wss://world-dev.ssafesta.world:443 으로 StartClient 가 true 를 반환하고 접속이 성립하는지 인프라와 함께 실측한다.

### 강형순 · 2026-09-08 13:05 KST

2026-09-08 진단 기록 — GitLab #142 후속 포트 0 차단점

Infra 13:01 댓글은 StartClient wss://world.ssafesta.world:443 → True 이후 실제 브라우저 URL이 wss://world.ssafesta.world:0/로 생성된다고 보고했다. 전달 소스 e4ea8c26의 manifest와 현재 manifest/lock은 Unity Transport 2.5.1이다.

Unity 공식 2.5.3 변경 이력에 hostname 인자의 NetworkDriver.Connect로 WSS 접속 시 포트 0을 사용하는 버그 수정이 명시돼 있다. 증상·버전·접속 조건이 일치하므로 게임 클라이언트 Transport 의존성 문제로 판단한다. WORLD_HOST 주입 누락은 Infra의 별도 설정 문제다.

https://docs.unity3d.com/Packages/com.unity.transport@2.6/changelog/CHANGELOG.html#253---2025-08-06

최소 수정 후보: Transport 2.5.3 갱신 및 WebGL 재빌드 후 실제 목적 포트 443, WebSocket 101, NGO 승인·스폰, 재접속 실측. 이번 요청은 원인 조사로 패키지 변경·빌드·배포는 실행하지 않았다. 기존 define 수정의 StartClient=True 및 문자열 검증만으로 종단 접속 성공을 판정할 수 없다. 로컬 docs/25_트러블슈팅.md T-136과 작업일지에 기록했다.
