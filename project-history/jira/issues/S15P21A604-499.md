## 설명

작업 목적

채널 정원 20을 강제하려면 Spring 이 채널별 현재 인원을 알아야 한다. 그런데 Unity Dedicated Server 는 Spring 으로 아무것도 보내지 않고, 사용자가 브라우저를 닫거나 로그아웃해도 퇴장 신호가 오지 않는다. 이탈 신호가 없으면 정확한 인원은 원리적으로 알 수 없다. 따라서 어떤 오차를 감수할지 먼저 정하고 그 방식으로 구현한다.

후보 3안

(A) 월드 호스트 페이지 heartbeat — Unity WebGL 을 감싼 React 호스트가 30초마다 POST /world-sessions/{sessionId}/heartbeat 를 보내고 Spring 은 TTL 이 걸린 키로 채널별 인원을 센다. festa-frontend/src/unity/host/authBridge.ts 가 이미 world-sessions 를 호출하고 있어 Unity C# 수정이 필요 없고, 상한을 실제로 강제하는 유일한 안이다. 주의: 백그라운드 탭에서 setInterval 이 초당 1회로 조절되거나 멈춘다(S15P21A604-363 에서 이미 겪은 문제). TTL 여유가 없으면 접속 중인 사용자가 축출된다.

(B) 기존 요청에 편승 — 인증된 /api/v1/** 요청이 올 때마다 그 사용자의 채널 lease TTL 을 갱신한다. DailyCoinGrantInterceptor 가 이미 같은 자리에 걸려 있어 새 endpoint 가 필요 없다. 대신 월드 안에서 API 를 부르지 않는 구간이 길면 접속 중인 사용자의 자리가 비워진다.

(C) 세지 않는다 — sessionId 해시로 채널을 결정적으로 분산하고 상한은 soft 로 둔다. 저장 상태가 0 이고 구현이 가장 작지만 한 채널이 20명을 넘을 수 있다.

작업 내용

- 방식 1개를 확정한다. 추천은 (A) 다.
- 확정한 방식으로 채널별 인원 집계를 구현하고 배정 이슈(S15P21A604-498)에서 쓸 수 있게 노출한다.

완료 조건

- 브라우저를 강제 종료한 뒤 정해진 시간 안에 그 자리가 회수된다.
- 백그라운드 탭에 오래 머문 사용자가 축출되지 않는다.
- 채널별 인원 수치가 배정 로직에서 읽힌다.

선행 작업 / Dependency

- 없음. 다만 이 이슈의 결론이 S15P21A604-498 의 선행이다.

참고

- backend/src/main/java/com/example/ssafesta/world/WorldSessionService.java (현재 저장 상태 0건)
- backend/src/main/java/com/example/ssafesta/wallet/DailyCoinGrantInterceptor.java ((B) 안이 쓸 seam)
- festa-frontend/src/unity/host/authBridge.ts ((A) 안이 쓸 자리)
- S15P21A604-363 (백그라운드 탭 타이머 조절 문제)

비고

헌법 30조에 따라 방식을 임의로 확정하지 않는다. 확정되면 docs/26_팀_결정_필요사항.md 에 기록한다. (A) 는 FE 쪽 타이머 작업이 함께 필요하므로 확정 시 FE 이슈를 별도로 만든다.
