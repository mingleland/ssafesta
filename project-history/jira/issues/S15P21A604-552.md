## 설명

2.5D 설계 복잡도를 줄이는 결정에 따른 두 갈래 작업.

[1] 내부 Booth — 매핑 정합
정본 문서 §8 의 canonical (type, assetCode) 표를 Unity 전달용 최종 계약표로 확정한다. 새 매핑 시스템·중간 변환 계층을 만들지 않는다. 표에 type / assetCode / 사용자 화면에 보여야 하는 실제 물건 / typeDefault 여부를 반드시 담고, Unity 레거시 값(FURNITURE_DEFAULT · DECORATION_DEFAULT)이 canonical 값으로 어떻게 교체되는지 명시한다. 목표는 FE 배치 자산과 Unity World 표시 자산의 1:1 일치.

[2] 외부 Facade — 경량화 실측
Facade 는 정밀 편집 대상이 아니라 선택 UI 다. 현재 CarnivalKit 완성형 18종은 최대 897k tri / GLB 20.4 MB 로 웹에 그대로 실을 수 없다. 표본 5~7종을 골라 원본, 50%, 25%, 10%, 5% 단계별로 triangles / GLB bytes / compile time / AABB 변화 / 실루엣 유지를 실측하고, 최종 tri 상한을 먼저 정하지 않고 실측 결과로 budget 을 정한다. texture 감축(resize, webp, map 제거)도 같은 방식으로 실측한다.

판정 기준은 내부 자산과 다르다: 실루엣 구별, 색·재질 인상 유지, 어떤 외부 부스인지 즉시 식별, 대표 장식·간판 유지. 작은 디테일 손실은 허용한다.

검토 대상 구조: assetCode 는 동일하게 두고 representation 만 이원화한다(Unity World = 원본, React preview = 강하게 simplify 한 GLB + thumbnail). 목록은 thumbnail 만 로드하고 preview GLB 는 선택 시 로드한다.

하지 않을 것: 내부 assetCode 체계 재설계, Facade 자유 편집기, Facade 부품 조합 preset, 대규모 generic asset platform, 라이선스 재조사, Spring Catalog SSOT 재논의.

산출물: 기존 canonical 2.5D 설계 문서 갱신 + 실험 근거 섹션 추가.
