## 설명

GitLab #216. FE 몫(!1039)과 게임 몫(!1078)은 이미 develop 에 있고 BE 판단만 남아 있다.

문제

MemberSessionService.issue 는 새 로그인과 refresh 가 같은 함수이고 그 안에서 매번 sessionId(Access Token 의 sid 클레임)를 새로 쓴다. SessionRevocationFilter 가 매 요청마다 현행 sid 와 대조하므로, refresh 가 성공하는 순간 직전 Access Token 은 만료를 기다리지 않고 즉시 폐기된다. 그 토큰을 React 와 Unity 가 나눠 쓰기 때문에 월드에서 12슬롯 게시본·world-sessions·catalog 가 한꺼번에 401 이 된다. 다중 탭도 같은 축이다.

방향 (GitLab #216 의 선택지 1)

옛 sid 에 짧은 유예를 둔다. Unity 전용 토큰 신설(선택지 2)은 #60 의 "Unity REST 는 AT 원본을 쓴다" 확정을 뒤집는 계약 변경이라 채택하지 않는다.

작업 범위

- 유예 판정은 MemberSessionService.check 한 곳에만 둔다. SessionRevocationFilter 는 손대지 않는다.
- refresh 경로에서만 이전 sessionId 를 auth:session:prev:{userId} 에 유예 TTL 로 남긴다. 새 로그인은 남기지 않는다.
- prev 는 새 로그인·로그아웃·계보 폐기(revokeReusedFamily)에서 반드시 삭제한다. 그러지 않으면 "다른 기기 로그인은 즉시 밀어낸다" 는 규칙이 유예 동안 깨진다.
- 유예 값은 app.auth.session-rotation-grace 로 새로 둔다. refresh 토큰 재사용 판정 유예(refresh-reuse-grace)와 보안 의미가 달라 재사용하지 않는다.

완료 조건

- refresh 직후 옛 sid 가 유예 안에서는 통과하고 유예 밖에서는 SID_MISMATCH 다.
- 새 로그인 직후에는 옛 sid 가 즉시 SID_MISMATCH 다(유예 키가 남아 있어도).
- 로그아웃 뒤에는 prev 도 통하지 않는다.
- 재사용 감지(계보 폐기) 동작은 바뀌지 않는다.
