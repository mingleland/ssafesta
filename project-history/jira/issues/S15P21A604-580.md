## 설명

## 작업 목적

- variables/items/assets 세 목록의 삭제 버튼이 전부 스타일 안 입혀진 네이티브 버튼 "삭제"  
   텍스트라 이 화면의 다른 버튼들과 확 튀어 보이고, assets 목록은 삭제 버튼 위치까지 어긋나  
   있다(variables/items는 오른쪽 정렬인데 assets만 좌측 하단으로 밀림). 빨간 × 아이콘으로  
   통일하고 위치도 맞춘다.

## 작업 내용

- 공통 삭제 아이콘 버튼 스타일 클래스 추가(가칭 `gss-delete-icon-button`) — 빨간 × 아이콘,  
   기존 `--gss-red`/`.gss-danger-button` 톤 재사용
- variables·items·assets 세 삭제 트리거 버튼의 텍스트 "삭제"를 "×"로 교체하고 새 클래스 적용  
   (`aria-label`은 `{id} 삭제`로 그대로 유지 — 시각적 텍스트만 바뀜)
- assets 목록(`.gss-asset-list > div`, grid 레이아웃)의 삭제 버튼에 명시적 위치(오른쪽) 지정 —  
   또는 variables/items와 같은 flex 헤더 구조로 통일. 구현 단계에서 방향 확정(아래 조율 필요  
   항목 참고)
- GAME GOALS 목표 삭제 버튼(이미 "×" 사용 중)도 새 클래스로 같이 정리해 일관성 확보

## 완료 조건

- [ ] variables/items/assets 세 목록의 삭제 트리거 버튼이 빨간 × 아이콘으로 통일된다
- [ ] assets 목록의 삭제 버튼이 각 행 오른쪽에 정렬된다
- [ ] 기존 삭제 확인 흐름(사용 위치 표시 → 취소/삭제)에 회귀가 없다
- [ ] 버튼의 `aria-label`이 유지되어 접근성이 깨지지 않는다
- [ ] `npx vitest run`, `npm run build`, `npx tsc --noEmit`, `npm run lint` 통과

## 선행 작업 / Dependency

- 없음

## 테스트 방법

1. 데이터 탭에서 variables/items/assets 각 항목의 삭제 버튼이 빨간 × 아이콘으로 통일돼  
   보이는지 확인
2. assets 목록의 삭제 버튼이 각 행 오른쪽에 정렬되는지 확인(variables/items와 시각적으로  
   일관되는지)
3. 삭제 버튼 클릭 → 기존 확인 카드(사용 위치 표시 → 취소/삭제) 흐름이 그대로 동작하는지 확인
4. 스크린 리더/접근성 — 버튼의 `aria-label`이 여전히 `{id} 삭제`로 남아있는지 확인
5. `npx vitest run`, `npm run build`, `npx tsc --noEmit`, `npm run lint` 통과
