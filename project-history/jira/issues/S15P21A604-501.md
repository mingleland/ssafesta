## 설명

작업 목적

docs/08 §15 에 이름만 있고 구현이 없는 부스 운영 요약 조회다. spec 015 에 contracts 디렉터리가 없어 응답 스키마부터 확정이 필요하다.

작업 내용

- spec 015 에 contracts 를 신설해 응답 스키마를 먼저 확정한다. 집계 항목(방문·체류·상담·설문·Coin) 범위를 spec 015 기준으로 정한다.
- from·to 쿼리 범위 검증을 넣는다.
- Owner 및 권한 있는 Staff 만 조회할 수 있게 게이트를 건다.

완료 조건

- 권한 없는 호출이 거부된다.
- from/to 범위가 검증되고 잘못된 범위는 거부된다.
- 응답이 spec 015 contracts 와 필드 단위로 일치한다.

선행 작업 / Dependency

- S15P21A604-240 (Booth 방문·체류·Coin 계측 이벤트 로깅). 집계할 원천 데이터가 먼저 있어야 한다.

참고

- docs/08_Backend_API_명세서.md §15
- specs/015-dashboard/spec.md

비고

에픽 배정은 임시다. 대시보드 전용 에픽이 없어 Booth Studio 아래에 두었다.

### 황덕 · 2026-09-13 17:21 KST

구현 완료. MR !778 (!777 위에 쌓아 둔 상태 — !777 이 develop 에 들어가면 자동 재지정되고 그때 파이프라인이 돕니다).

`GET /api/v1/booths/{boothId}/dashboard/summary?from=&to=`

응답 스키마는 `specs/015-dashboard/contracts/dashboard-summary-api.md` 를 신설해 고정했고, 비어 있던 spec 015 의 BE 리뷰란(C-01~C-05 답변 포함)도 함께 채웠습니다.

**다섯 칸 중 셋만 원천이 있었습니다.**

| spec 015 | 원천 |
|---|---|
| FR-001 방문·체류 | booth_visit_events (S15P21A604-240 으로 방금 생김) |
| FR-004 사람 상담 | consultations (S15P21A604-137) |
| FR-003 설문 응답 | survey_responses ⋈ surveys.booth_id |
| FR-002 AI 이용 | 없음 — AI 대화를 남기는 표가 저장소에 없습니다 |
| FR-005 수익 | 없음 — 아래 |

**부스는 코인을 벌지 않습니다.** 원장 사유를 전수로 확인한 결과 부스와 닿는 것은 둘뿐이고 둘 다 수익이 아닙니다 — 임대료(BOOTH_LEASE)는 소유자의 지출이고, 설문 보상(SURVEY_REWARD)은 차감되는 지갑 없이 발행됩니다. PURCHASE 는 카탈로그라 플랫폼이 파는 것입니다.

revenueCoin 도 booth_daily_metrics.revenue_coin 컬럼도 있지도 않은 유입을 가정한 자리입니다. 무엇을 수익으로 볼지는 기획 결정이라 임의로 정하지 않고 docs/26 에 결정 요청으로 올렸습니다(헌법 30조). AI 이용 건수도 같이 올렸습니다.

그래서 **null 과 0 을 가르는 규약**을 세웠습니다. null = 셀 원천이 아직 없다, 0 = 세어 보니 0건이다. 이 구분이 없으면 FE 는 "AI 이용 0건 · 수익 0" 카드를 영원히 띄웁니다. 원천이 서면 null 을 숫자로 바꾸는 것이 전부라 FE 계약은 지금 확정할 수 있습니다.

완료 조건 대응:

- 권한 없는 호출 거부 — BoothAccessGuard.requireEditor. CONSULTANT 는 거부됩니다
- from/to 범위 검증 — from >= to 면 400 (errors[0].field = "from")
- 응답이 contracts 와 필드 단위 일치 — 일치합니다. 다만 그 contracts 가 한 칸(revenueCoin)을 미정으로 두고 있어 MR 에 Closes 를 넣지 않았습니다

검증: 전용 10건, clean test 1290건 통과. null→0, 상담을 endedAt 기준으로, 설문의 부스 필터 제거 — 세 변이를 각각 테스트가 잡는 것까지 확인했습니다.
