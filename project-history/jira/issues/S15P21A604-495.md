## 설명

S15P21A604-357(BE SSAFY provider 추가)이 develop 에 도달했는데 FE 가 아직 'not_configured' 슬롯을 들고 있어 로그인 화면에 SSAFY 버튼이 '준비 중' 으로 뜬다. -366 이 만들어 둔 해제 경로를 실행하고, 그 김에 OAuth 3종 전체를 재점검한다.

[배경 — 왜 지금까지 안 보였나]
docs/LJH/backlog.md:33 이 'BE 가 09-01 결과 미게시(#114)' 로 막힌 상태를 기록하고 있었다. BE 가 코멘트가 아니라 커밋으로 답했기 때문에 코멘트 기준 인박스 판정으로는 잡히지 않았다. festa-inbox 의 종결 잔존 대조로 드러났다.

[실측 — BE 는 준비 완료]
- OAuthProvider enum 에 SSAFY 존재
- application.yml 에 ssafy registration(client-id/secret/redirect-uri, scope 없음) + provider(authorization-uri, token-uri, user-info-uri, user-name-attribute=userId) 전부
- OAuthAuthorizationController 가 allowableValues={google,kakao,ssafy}
- OAuthLoginSuccessHandler 는 principal.getName() 으로 provider 별 subject 를 읽어 분기 없이 동작
- backend/.env 에 SSAFY_CLIENT_ID/SECRET/REDIRECT_URI 설정됨

[FE 변경 — -366 주석이 규정한 최소 경로]
- entities/auth/providers.ts: ssafy availability 'not_configured' -> 'available'
- 같은 파일 isConfiguredOAuth 의 타입 서술에 'ssafy' 추가
- entities/auth/api.mock.ts: mockStartOAuth 시그니처에 'ssafy' 추가
- 낡은 주석 3곳 교체 (providers.ts 머리말, shared/contracts/auth.ts, LoginPage.tsx startOAuth)
- providers.test.ts 의 not_configured 단언 갱신
- LoginPage UI 는 이미 준비돼 있다 — OAUTH_DISPLAY_ORDER 에 ssafy 가 첫째, providerIcon·login-btn-ssafy CSS 존재. 추가 작업 없음

[재점검에서 함께 발견한 것]
1. 공유 BE_ENV/.env 의 KAKAO_REDIRECT_URI 줄이 개행 없이 다른 키와 붙어 있다. 값이 '.../code/kakaoCONNECTION_TOKEN_SECRET=local-only-mock-secret-...' 이 되어 로컬 Kakao OAuth 는 redirect_uri 불일치로 동작하지 않는다. 개행 하나가 빠진 것이고 원본 공유 파일과 기존 백업본 양쪽에 있다.
2. FRONTEND_BASE_URL 이 로컬에서 5174 로 설정돼 있다. OAuthLoginSuccessHandler 가 이 값으로 /auth/callback 리다이렉트를 만들고 GuestAuthController.requireTrustedOrigin 이 정확 일치를 요구하므로, Vite 포트와 어긋나면 소셜 로그인이 콜백에서 끊긴다.

[완료 조건]
- 로그인 화면에서 SSAFY 버튼의 '준비 중' 배지가 사라지고 클릭이 /api/v1/auth/oauth/ssafy 로 나간다
- vitest(entities/auth, pages/login) 통과, npm run build 통과
- 위 env 발견 2건을 게임/BE 파트에 통보
