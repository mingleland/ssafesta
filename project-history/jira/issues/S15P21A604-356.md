## 설명

## 작업 목적

- demo 배포에서 Spring·FastAPI에 필요한 Secret과 환경변수가 Jenkins Credentials에서 Compose 컨테이너까지 안전하게 전달되도록 연결한다.
- 필수값 누락이 로컬 기본값으로 조용히 대체되지 않고 배포 전에 실패하도록 한다.

## 작업 내용

- Jenkins `withCredentials` → `infra/jenkins/scripts/with-credentials.sh` → Compose `environment` 주입 경로 연결
- `INTERNAL_AI_TO_SPRING_TOKENS`를 한 곳에서 관리하고 Spring·FastAPI 양쪽에 동일하게 주입
- 기존 계약인 `FESTA_ENVIRONMENT=dev|demo`를 Redis 키 환경 네임스페이스 입력으로 전달
- `POSTGRES_PASSWORD`, `FRONTEND_BASE_URL`, `AUTH_COOKIE_SECURE`, Redis ACL 자격증명 등 배포 필수값 누락 검증
- Secret 원문은 저장소·로그·MR·검증 증적에 기록하지 않음

## 완료 조건

- [ ] Jenkins Credential에서 받은 필수값이 `with-credentials.sh`를 거쳐 Backend·AI Compose 환경에 전달된다.
- [ ] Spring과 FastAPI가 동일한 `INTERNAL_AI_TO_SPRING_TOKENS`를 사용한다.
- [ ] dev와 demo에 각각 `FESTA_ENVIRONMENT=dev|demo`가 전달된다.
- [ ] 필수값 누락 시 컨테이너 기동 또는 배포 preflight가 명시적으로 실패한다.
- [ ] Redis ACL 활성 환경에서 `REDIS_USERNAME`·`REDIS_PASSWORD`가 전달된다.
- [ ] Secret scan과 관련 정적·계약 테스트가 통과한다.

## 선행 작업 / Dependency

- Backend 설정 정리 `S15P21A604-347` 완료
- Redis 키 환경 네임스페이스 구현 `S15P21A604-349`와 입력 계약 공유
- 실제 demo 도메인: `ssafesta.world`
- Secret 실값은 Jenkins Credentials 또는 승인된 비공개 경로로만 전달

## 테스트 방법

1. 필수 환경변수 하나씩 제거해 배포 preflight 또는 컨테이너 기동 실패를 확인한다.
2. demo Compose에서 Backend·AI 환경변수 이름이 전달되는지 Secret 원문 없이 검사한다.
3. Spring → FastAPI 및 FastAPI → Spring 내부 호출의 인증 성공·불일치를 확인한다.
4. `./mvnw clean` 후 관련 Backend 테스트와 Infra Secret scan을 실행한다.
