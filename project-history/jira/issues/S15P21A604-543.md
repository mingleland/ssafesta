## 설명

S15P21A604-538 FE 전체 회귀 실측에서 나온 FAIL 1건.
근거 문서: docs/LJH/verify/fe-full-regression-0908.md §2 F-5

증상
/app/profile 거래내역이 다른 행은 "일일 지급"·"가입 지급" 인데 설문 보상만
"SURVEY_REWARD" 로 보인다. 실 화면 실측(회원 설문 제출 → 7코인 지급 후).

원인
entities/wallet/types.ts:36 REASON_LABELS =
  { INITIAL_GRANT, DAILY_GRANT, ADMIN_ADJUSTMENT, LEASE_PAYMENT }
BE 가 내는 값(실측)
  CoinReason: INITIAL_GRANT, DAILY_GRANT, ADMIN_ADJUSTMENT, PURCHASE, SURVEY_REWARD
  + LEASE_PAYMENT (BoothLeaseService.LEASE_REASON)
누락 2건: SURVEY_REWARD · PURCHASE

fallback(?? reasonType)이 항목을 숨기지 않는 것은 의도된 설계다(SC-005) —
데이터 유실은 없고 라벨만 없다.

왜 지금 드러났나
S15P21A604-528 이 Survey 실 어댑터를 붙이면서 보상 지급 경로가 처음 도달 가능해졌다.
PURCHASE 는 카탈로그 구매(catalog/items/{id}/purchases) 경로라 아직 닿지 않았을 뿐 같은 누락이다.

수정
REASON_LABELS 에 SURVEY_REWARD·PURCHASE 를 더한다. 문구는 기획 용어와 맞추어 정한다
(예: "설문 보상" · "구매"). 동시에 BE enum 과 FE 라벨맵이 어긋나는 것을
테스트로 잠그는 것을 검토한다 — 이번처럼 새 reason 이 늘 때마다 같은 누락이 생긴다.
