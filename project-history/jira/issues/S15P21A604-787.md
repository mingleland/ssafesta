## 설명

### 작업 목적

지금까지 부스 이름은 첫 임대 때 `"내 부스"` 로 만들어진 뒤 **바꿀 방법이 없어 모든 부스가 같은 이름**이었다. `BoothLeaseService.ownBooth()` 가 `new Booth(userId, "내 부스")` 로 박고 엔티티에 이름 변경 메서드가 없었으며, 외관 수정 폼도 `themeCode`·`primaryColor`·`signText`·`logoUrl` 네 칸뿐이었다.

BE 가 `S15P21A604-756`(MR `!890`, develop 병합 `ff0e03fa`)으로 `PUT /api/v1/booths/{boothId}/facade` 요청에 `name`(1~100자)을 더했다. 남은 것은 그 값을 입력할 칸 하나다.

월드 간판이 `signText` → `boothName` 순으로 고르기 때문에 간판 문구를 채운 부스에서는 가려져 있었을 뿐, **간판 문구를 비운 부스와 슬롯 목록·스태프 초대 응답은 전부 같은 이름을 내보내고 있었다.**

### 작업 내용

스튜디오 외관 모드(`FacadePanel`)에 입력칸 하나. **저장 호출은 그대로다** — 같은 `PUT .../facade` 에 필드가 하나 늘 뿐이고 새 endpoint 도, 새 어댑터도 없다.

**⚠️ **`name` 만 "안 보내면 유지" 다. 이 endpoint 의 기본 규칙은 "보내지 않은 필드는 비운다" 인데 `booths.name` 이 `NOT NULL` 이라 비우면 500 이고, 반대로 필수 키로 만들면 이름 칸이 없던 **기존 외관 저장이 전부 400** 이 된다(BE 가 실측했다 — `validatedName` 의 null 분기를 죽이자 `BoothFacadeApiIntegrationTest` 18개 중 12개가 깨졌고, 그 12개가 지금 FE 가 보내는 모양이다).

따라서 **칸을 비운 채 저장해도 기존 이름이 유지된다.** 지우는 UI 는 만들지 않는다.

- 저장된 이름은 `GET /api/v1/booths/{boothId}` 의 `name` 에서 읽는다.
- **응답에는 **`name` 이 없다. `FacadeView` 는 4필드 그대로다 — 부스 상세와 슬롯 목록의 `facade` 가 같은 표현을 쓰기 때문이다. 저장 직후 화면을 갱신하려면 부스 상세를 다시 읽는다.

### 완료 조건

- [ ] 외관 모드에서 부스 이름을 바꿔 저장하면 `GET /booths/{boothId}` 의 `name` 이 바뀐다
- [ ] 이름 칸을 비운 채 저장하면 **기존 이름이 유지된다** (400 도, 빈 이름도 아니다)
- [ ] 1자 미만·100자 초과는 서버가 `400 VALIDATION_FAILED` 로 거부하고, 그 `field`·문장을 그대로 화면에 붙인다
- [ ] 기존 외관 4필드 저장 동작에 회귀가 없다
