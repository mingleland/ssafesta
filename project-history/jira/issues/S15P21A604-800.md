## 설명

## 증상
개발 서버(VITE_USE_MOCK=true, 백엔드 미기동)에서 내 부스 관리 → AI 직원 관리 진입 시 "AI 직원 설정을 불러오지 못했습니다" 오류. 콘솔에 `localhost:8080/api/v1/booths/1/agents` CORS 실패 로그.

## 원인
`entities/aiAgent/api.ts`만 booth·wallet·profile 등과 달리 `api.select.ts`/`api.mock.ts` mock 분기가 없다. 소비자 3곳(`AiAgentManagementTab.tsx`·`BoothManagementOverlay.tsx`·`StudioPage.tsx`)이 이 모듈을 직접 import해 VITE_USE_MOCK 값과 무관하게 항상 실 API를 탄다.

## 작업 내용
- `entities/aiAgent/api.mock.ts` 신설 — boothId=agentId 1:1 가정(부스당 1명 제약과 일치)의 메모리 mock. getAiAgent·createAiAgent·updateAiAgent·listAiDocuments·uploadAiDocument·replaceAiDocument·deleteAiDocument 구현.
- `entities/aiAgent/api.select.ts` 신설 — leaseApi.select 와 같은 VITE_USE_MOCK 스위치, 기존 named export 모양 그대로 재수출해 소비자 호출부는 안 바낀다.
- 소비자 3곳의 import 경로만 `entities/aiAgent/api` → `entities/aiAgent/api.select` 로 교체.
- 기존 테스트(`aiAgentRegisterUpload`·`aiAgentSectionGate`·`studioAiAgentAutoLink` 등)는 여전히 `entities/aiAgent/api`를 직접 mock하므로(vi.mock) 수정 불필요 — select가 test 환경(USE_MOCK 미설정)에서는 real api.ts 분기로 그대로 타기 때문.

## 완료 조건
- VITE_USE_MOCK=true 로 떠 dev 서버에서 AI 직원 관리 진입·등록·수정·문서 업로드·삭제가 백엔드 없이 동작한다
- 기존 테스트 회귀 없음
- unit test, tsc 0, vitest green, oxlint 신규 경고 0
