## 설명

## 작업 목적

클라이언트 잘못으로 생긴 요청이 4xx 가 아니라 500 으로 응답되는 것을 바로잡는다. 정상 동작이 서버 오류 로그로 쌓이면 진짜 장애가 그 안에 묻힌다.

## 원인

`GlobalExceptionHandler` 가 프레임워크 거부를 `ResponseStatusException` 으로 매칭한다. Spring 7 에서 프레임워크 자체 예외는 `ErrorResponse` 인터페이스를 구현하고 `ServletException` 을 상속하며, `ResponseStatusException` 을 상속하지 않는다. 따라서 전부 `handleUnexpected(Exception)` 으로 떨어져 `INTERNAL_ERROR` 500 이 된다.

spring-web 7.0.8 기준 상속 관계:

| 예외 | 상속 | ErrorResponse |
|---|---|---|
| ResponseStatusException | ErrorResponseException | 구현 (유일하게 잡힘) |
| NoResourceFoundException | ServletException | 구현 (놓침) |
| MissingRequestCookieException | ServletException | 구현 (놓침) |
| HttpRequestMethodNotSupportedException | ServletException | 구현 (놓침) |

## 영향 범위

| 예외 | 현재 | 정상 | 출처 |
|---|---|---|---|
| NoResourceFoundException | 500 | 404 NOT_FOUND | GitLab 113 |
| MissingRequestCookieException | 500 | 401 | GitLab 113 |
| HttpRequestMethodNotSupportedException | 500 | 405 METHOD_NOT_ALLOWED | 조사 중 발견 |
| InvalidRefreshTokenException | 500 | 401 | 조사 중 발견 |

- `POST /api/v1/auth/refresh` 를 쿠키 없이 호출하면 500 이다. FE `bootstrapAuth` 가 페이지 로드마다 한 번 시도하므로 비로그인 방문자 전원이 매 방문마다 500 을 하나씩 남긴다.
- 미매핑 `/api/v1/**` 경로를 인증된 요청으로 부르면 404 가 아니라 500 이다. 미구현 endpoint 전부가 클라이언트에게 서버 장애로 보인다. INTERNAL_ERROR 를 재시도 가능 코드로 정렬해 둔 것과 어긋나 FE 가 미구현 경로를 재시도한다.
- `codeFor` 의 METHOD_NOT_ALLOWED 분기는 도달 불가능한 죽은 코드였다. 클래스 javadoc 의 unsupported method 405 서술도 사실과 다르다.
- `InvalidRefreshTokenException` 이 순수 RuntimeException 이라 핸들러가 없다. 쿠키가 있어도 만료 또는 재사용이면 똑같이 500 이다.

## 기존 테스트가 잡지 못한 이유

`ErrorEnvelopeIntegrationTest.anUnknownPathIsStillAnEnvelope` 와 `frameworkRejectionsAreStillKorean` 이 이미 미매핑 경로를 호출한다. 그러나 무인증 요청이라 Security filter 가 401 로 먼저 답하고, 4xx 단언과 한글 단언이 모두 통과한다. advice 에 도달한 적이 없다.

## 수정 범위

- `GlobalExceptionHandler` — 매칭 기준을 ErrorResponse 로 바꾼다. 4xx 만 조용히 처리하고 5xx 는 계속 크게 로그한다 (T-24 규칙 유지).
- `InvalidRefreshTokenException` — ApiException 을 상속해 INVALID_MEMBER_TOKEN 을 싣는다.
- `GuestAuthController.refresh` — 쿠키를 required false 로 받고 없으면 같은 예외를 던진다. 쿠키 없음과 만료가 한 코드가 된다.
- 위 4건을 관통하는 테스트를 `ErrorEnvelopeIntegrationTest` 에 추가한다. 인증을 실어 advice 경로에 실제로 도달시킨다.

### 황덕 · 2026-08-27 15:10 KST

**스코프 확장** — 처음 4건에서 7건이 됐다. MR !56 하나로 간다.

#113 을 고친 뒤 같은 계열(`extends RuntimeException` 이라 ErrorCode 를 못 싣고 `handleUnexpected` 로 떨어지는 것)을 전수 훑어 3건을 더 찾았다.

| 추가 발견 | 현재 | 수정 후 |
|---|---|---|
| 회원가입 닉네임 중복 (`DuplicateNicknameException`) | 500 | 409 NICKNAME_DUPLICATED |
| 가입 경합 (`RegistrationConflictException`) | 500 | 409 REGISTRATION_CONFLICT 신설 |
| 정지 계정 소셜 로그인 | 필터체인 유출 (BE 오리진에서 원문 오류) | /auth/callback?error=ACCOUNT_SUSPENDED redirect |

**닉네임 중복이 가장 크다.** 사용자가 실제로 밟는 길인데 "이미 사용 중인 닉네임입니다" 대신 "서버 오류가 발생했습니다"가 나가고 있었다. `ErrorCode.NICKNAME_DUPLICATED(409)` 는 이미 있었고 닉네임 *변경* 경로에는 연결돼 있었다 — 가입 경로만 빠져 있었다.

두 409 는 합치지 않았다. 중복은 "다른 닉네임을 고르라", 경합은 "같은 요청을 다시 보내라"로 요구하는 행동이 다르다.

**정지 계정은 redirect 만으로 부족해서** 잔존 handoff 쿠키 삭제(Max-Age=0, 동일 Path)를 함께 넣었다. handoff 는 5분 살아 있고 FE 는 /auth/callback 도착마다 complete 를 무조건 부르므로, 쿠키를 남겨두면 거부된 방문자가 그것을 타고 세션을 얻는다.

---

**완료 조건에 관한 정정 — AS-5 는 이 티켓으로 충족되지 않는다.**

정지 계정 redirect 는 전달 계약까지다. FE CallbackPage 가 URL query 를 읽지 않아 정지 회원은 지금도 "로그인 정보가 만료되었습니다"라는 사실과 다른 안내를 본다. spec 001 AS-5 는 FE 가 이 값을 소비할 때 충족된다. **이 티켓을 AS-5 해결로 기록하지 않는다** — FE 결정 항목을 docs/26 에 등록했다.

곁가지로 AS-4(제공자 실패·사용자 취소 안내)도 `oauth2Login` 에 failureHandler 가 없어 미구현임을 확인했다. 이 티켓 범위 밖이고 docs/26 에 함께 적었다 — 별도 티켓이 필요하면 알려달라.

**작업 완료 — MR !56 develop 병합 대기.**

GitLab #113 신고 2건에서 출발해 같은 원인으로 **총 7건**을 수습했다.

| 상황 | 전 | 후 |
|---|---|---|
| 미매핑 경로 (인증됨) | 500 | 404 NOT_FOUND |
| refresh 무쿠키 | 500 | 401 INVALID_MEMBER_TOKEN |
| 지원하지 않는 method | 500 | 405 METHOD_NOT_ALLOWED |
| 지원하지 않는 Content-Type | 500 | 415 UNSUPPORTED_MEDIA_TYPE |
| 만료·재사용 refresh token | 500 | 401 INVALID_MEMBER_TOKEN |
| 회원가입 닉네임 중복 | 500 | 409 NICKNAME_DUPLICATED |
| 가입 경합 | 500 | 409 REGISTRATION_CONFLICT (신설) |

원인은 하나였다. GlobalExceptionHandler 가 프레임워크 거부를 ResponseStatusException 으로 매칭했는데, Spring 7 의 프레임워크 예외는 그 클래스가 아니라 ErrorResponse 인터페이스로 상태를 싣는다.

**곁가지로 고친 것**

- 닉네임이 거부되면 handoff 가 소진돼 재제출이 410 이던 것 (FR-021c 위반). peek → 등록 성공 → discard 순서로 바꿨다.
- 정지 계정 소셜 로그인이 Security 필터체인 밖으로 예외를 흘려 브라우저가 BE 오리진에 멈추던 것. redirect + 잔존 handoff 쿠키 삭제로 바꿨다.
- 참조 0건인 죽은 예외 클래스 3개 삭제.

**검증**

리뷰가 7라운드 19건 나왔고, 지적 대응을 멈추고 네 렌즈(테스트 공허·문서 거짓·소비자 누락·좁힘 구멍)로 전수 감사를 돌렸다.

- **표적 mutation 12건 전부 RED-EXPECTED** — 임시 worktree 에서 행위별로 되돌려 "컴파일되고 대상 테스트가 예상한 이유로 실패"를 판정 기준으로 확인했다. guard 가 아닌 테스트 5건은 성격을 라벨로 명시했다.
- 계약이 약속한 code 10개 중 3개가 테스트로 고정돼 있지 않아 2개는 테스트를 붙였고, 406 NOT_ACCEPTABLE 은 실측 결과 거짓이라 걷어냈다 — Accept 가 JSON 을 안 받으면 서버가 봉투를 만들어 놓고도 기록하지 못한다.
- 테스트 370건 전량 통과.

**완료 조건 대비**

- 4건 모두 4xx 응답 → 7건으로 확대 충족
- 5xx 는 종전대로 error 로그 유지 → 충족 (handleUnexpected 분기가 is4xxClientError 일 때만 탄다)
- 인증을 실은 회귀 테스트 추가·통과 → 충족
- backend test 전량 통과 → 충족

**후속으로 남긴 것 (이 티켓 아님)**

- spec 001 AS-5 (정지 계정 안내)는 BE 가 `?error=ACCOUNT_SUSPENDED` 를 전달하는 데까지다. FE 가 이 값을 읽어야 충족되며 docs/26 에 결정 항목으로 올렸다. **이 티켓을 AS-5 해결로 기록하지 않는다.**
- 같은 자리에서 AS-4 (제공자 실패·사용자 취소 안내)도 oauth2Login 에 failureHandler 가 없어 미구현임을 확인했다. docs/26 에 함께 적었다.
