## 설명

develop 반입 MR !1161 의 back-test 가 OpenApiSchemaNameTest.noTwoApiTypesShareASchemaName 으로 실패했다.

증상

StartRequest 라는 스키마 이름에 두 타입이 등록된다 — game.GameAssetController$StartRequest 와 project.ProjectLogoController$StartRequest. 나중 것이 앞의 것을 덮으므로 한쪽 endpoint 의 요청 본문이 남의 필드로 문서화된다. 이것은 S15P21A604-502 에서 이미 한 번 밟은 증상이고(GitLab #172, 설문 SubmitCommand 가 미니게임 요청으로 표시됨) 그때 이 테스트가 생겼다.

왜 놓쳤나

S15P21A604-895 를 구현할 때 Project*·GameAsset*·ImageBytes*·AccountWithdrawal*·AiDocument* 를 돌렸고 OpenApi* 는 돌리지 않았다. OpenApi* 는 이벤트 상점 DTO 변경(S15P21A604-885)에서만 돌렸는데, 그때는 로고 컨트롤러가 없었다. 새 컨트롤러·새 요청 DTO 를 더하면 OpenApi* 가 항상 영향 범위다.

작업 범위

- ProjectLogoController.StartRequest 에 @Schema(name = ...) 로 고유 이름을 준다. JSON 필드 이름은 바뀌지 않는다 — 문서 스키마 이름만 갈라진다.
- 같은 방식으로 충돌하는 다른 타입이 없는지 OpenApiSchemaNameTest 로 확인한다.

완료 조건

- OpenApi* 통과. back 과 develop 반입 브랜치 양쪽에 반영된다.
