로컬 브라우저 접근을 FE dev 게이트웨이 하나로 모으면서, BE 에는 인증 보안 경계인 Origin 신뢰와 OAuth 복귀 판단만 최소로 남기는 seam 이다.

## 문제

`app.auth.frontend-base-url` 한 값이 세 가지를 겸한다 — CORS 허용 오리진(`SecurityConfiguration`), refresh/logout 의 Origin 신뢰 정본(`GuestAuthController`), OAuth 복귀 URL(`OAuthLoginSuccessHandler`). 그래서 Vite dev 서버 포트가 5173 에서 밀리면(5174·5175·5199) 그 순간 `POST /auth/refresh` 가 403 UNTRUSTED_ORIGIN 이 되고 로그인이 5173 으로 돌아간다.

FE 프록시는 `changeOrigin` 없이 돌기 때문에 BE 가 보는 Host 와 Origin 이 둘 다 FE 포트다. 즉 프록시를 타면 CORS 는 문제가 아니고, 남는 것은 `GuestAuthController.requireTrustedOrigin` 의 equals 와 `OAuthLoginSuccessHandler` 의 절대 URL 두 곳이다.

## 신뢰 규칙 (한 곳, RequestOrigins)

- `frontendBaseUrl` 정확 일치는 항상 허용 (배포는 이것뿐)
- 그 밖에는 요청이 localhost·127.0.0.1 로 들어왔을 때에 한해 요청 자신의 origin(`scheme://serverName[:port]`, 기본 포트 생략) 만 허용
- 비교는 전부 문자열 정확 일치. `contains`·`startsWith`·wildcard 금지 — 쓰면 `http://localhost.evil.example` 이 통과한다

## 범위 (BE 4파일, 설정 0)

| 파일 | 변경 |
|---|---|
| auth/RequestOrigins.java (신규) | ownOrigin · isTrusted |
| auth/GuestAuthController.java | refresh/logout 의 Origin 검사를 규칙으로 교체 |
| auth/OAuthAuthorizationController.java | optional `?return`, 시작 요청에서만 검증, 통과값만 HttpSession 저장 |
| auth/OAuthLoginSuccessHandler.java | 저장값 one-shot consume, 없으면 frontendBaseUrl |

OAuth 는 시작 단계에서만 검증하고 콜백에서는 재검증하지 않는다. provider 콜백은 등록된 redirect URI 때문에 `localhost:8080/login/oauth2/code/*` 로 들어오므로, 콜백 시점의 Host(8080)와 저장값(5175)을 다시 비교하면 항상 실패하기 때문이다. 세션은 Spring 이 authorization request 때문에 어차피 만드는 HttpSession 이라 새 저장소도 새 쿠키도 늘지 않는다.

변경하지 않은 것: SecurityConfiguration · AuthProperties · application*.yml · provider redirect URI · Spring OAuth state 검증 · handoff/refresh 쿠키 계약 · Infra/nginx/compose.

## 알려진 천장 (의도된 것, 코드 주석·테스트에 명시)

`request.getServerName()` 은 서버 속성이 아니라 요청이 보낸 Host 헤더이고, nginx 가 세 환경 모두 `proxy_set_header Host $host` 로 원본을 그대로 넘긴다. 따라서 "배포에서는 로컬 가지가 열리지 않는다"를 보증하는 것은 이 코드가 아니라 앞단 인프라(Cloudflare·server_name·allowlist)다. 브라우저는 Host 를 주소창에서 만들어 임의 값을 못 보내므로 실사용 공격 경로는 아니다.

코드로 닫으려면 조건에 `frontendBaseUrl` 의 host 가 localhost 인지(= 로컬 배포인지)를 함께 걸면 된다. #177 리뷰에서 제안했고 FE 제안 원안대로 가기로 해 넣지 않았다. `RequestOriginsTest.aDeployedProfileStillOpensTheLocalBranchForALocalHostHeader` 가 이 천장을 드러내 놓고 있으며, 닫는 순간 그 테스트가 assertFalse 로 뒤집힌다.

## 범위 밖

- FE 몫 — `tools/devGateway.mjs` 의 `/oauth2` 프록시 추가, `LoginPage.tsx` 의 `?return`, `.env.example` 정리
- 콜백 provenance 의 통합 레벨 검증 (가짜 provider 를 세운 필터 체인 테스트). 현재는 mock 단위 테스트이며, Spring Security 6 기본 session fixation 전략 changeSessionId 는 세션 객체를 그대로 두므로 속성은 살아남는다
- dev 토폴로지 — `dev.conf` 에는 `/oauth2/`·`/login/oauth2/` route 가 없어 dev 의 OAuth 시작은 `api.<domain>` vhost 를 탄다. 로컬 게이트웨이는 한 오리진으로 접는 구조라 위상이 다르다
