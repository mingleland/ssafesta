## 설명

## 발견 경위

2026-08-31 로컬 풀스택 기동 테스트(게임 파트). `pom.xml` 은 Java 21 을 요구하는데 테스트 머신에는 JDK 11·17 만 있어 컴파일부터 실패했다.

```
[ERROR] Fatal error compiling: error: release version 21 not supported
```

## 문제

- `festa-ai`·`festa-frontend` 에는 Dockerfile 이 있는데 **backend 에는 없다**
- `infra/environments/compose/common.yaml` 은 `services: {}` 빈 골격
- 즉 JDK 21 이 없는 머신에서 백엔드를 올릴 공식 경로가 없다

## 임시 우회 (오늘 실제로 동작 확인)

```bash
docker run --rm -v "$(pwd)":/app -w /app -v ssafesta-m2:/root/.m2 \
  --env-file <정규화된 env> -p 8080:8080 \
  maven:3.9-eclipse-temurin-21 mvn -B spring-boot:run
```

- `POSTGRES_HOST=host.docker.internal`, `REDIS_HOST=host.docker.internal`, `SPRING_PROFILES_ACTIVE=local` 추가 필요
- 이 방식으로 기동 → Flyway 15개 적용 → actuator UP → 게스트 로그인·world-sessions 발급까지 확인됨

## 함께 발견한 함정 2건

1. `backend/.env` 는 **compose(postgres/redis 치환)만** 읽는다 — pom 에 dotenv 의존성이 없어 Spring 은 그 파일을 안 읽는다. compose.yaml 옆에 있어서 읽는 줄 알기 쉽다. README 한 줄이면 막을 함정.
2. `env.example` 의 `INTERNAL_AI_TO_SPRING_TOKENS` 가 **빈 값**인데 `application-local.yml` 은 이 키를 기본값 없이 요구한다 — example 을 그대로 복사하면 기동 실패. 로컬용 생성 방법(예: `openssl rand -base64 32`) 주석이 필요하다.

## 제안

backend Dockerfile 또는 위 maven 컨테이너 방식을 README 에 공식화. BE 파일이라 게임 파트에서 직접 MR 하지 않고 이슈로 남긴다.
