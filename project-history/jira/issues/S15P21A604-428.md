## 설명

배경: OverlayFrame 이 열릴 때 자기 루트(tabIndex=-1)에 focus 를 가져오지만, 닫힐 때 그 focus 를 돌려주지 않는다. 그러면 focus 가 body 에 남고, Unity 6 WebGL 은 키보드 이벤트를 canvas 타깃으로 받으므로 오버레이를 닫은 뒤 WASD·F 가 월드로 안 가는 경로가 생한다. 09-08 사용자 테스트의 주 동선(오브젝트 상호작용 → 닫기 → 이동)이라 먼저 닫는다.

수정: OverlayFrame 이 언마운트될 때, 열리기 직전에 focus 를 갖고 있던 요소로 돌려주고, 그것이 없거나 사라졌으면 #unity-canvas 로 돌린다. canvas 가 없는 화면(Game Studio 등)에서는 아무것도 하지 않는다.

범위: FE 단독. G-8-2(Unity captureAllKeyboardInput·input lock API·pointer ownership)는 건드리지 않는다 — 그것은 Unity 합의 사항이고 이 수정은 그 API 없이도 유효하다. 근거 문서: docs/LJH/ui-design/07_handoff/fe-contract-boundary.md G-8-1.

완료 조건: 오버레이 닫기 후 focus 가 canvas 또는 이전 요소로 돌아간다 / canvas 가 없는 화면에서 예외가 나지 않는다 / 단위 테스트로 고정한다.
