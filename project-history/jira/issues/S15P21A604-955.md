## 설명

## 신고

AI 직원과 대화해도 일일 미션 카운트가 올라가지 않는다.

## 원인 (코드 결함 아님 — 계약 누락)

- `AI_CONSULT` 진행도는 `consultations` 표(= 사람 상담 요청) 행 수로 판정된다. `DailyMissionService.progressOf` 의 `AI_CONSULT` 분기, `countByVisitorUserIdAndRequestedAt...`. spec 022 `data-model.md` 도 `consultations.requested_at` 으로 적혀 있다.
- `consultations` 행은 방문자가 "사람 상담 신청" 을 눌러야만 생긴다 (`Consultation` javadoc, spec 011 US1).
- AI 대화는 nginx `/ai/v1/*` 로 FastAPI 에 직행한다 (`demo.conf.template:83`, `prod.conf.template:25`). 대화 생성·메시지·종료 전 구간에서 Spring 호출 0건 — 백엔드에 대화 사실이 남지 않는다.
- FE 라벨은 "AI 직원과 이야기 나누기" (`festa-frontend/src/features/mission/model/labels.ts:7`). 라벨의 의미와 판정 근거가 어긋나 있다.

## 결정 (2026-09-22)

미션의 의도는 "AI 직원과 대화" 가 맞다. 대화 사실을 미션 근거로 삼는다.

AI → Spring 내부 경로는 이미 존재한다 (`/internal/ai/**`, 서비스 토큰 전용 필터 체인, 공개 리스너 차단). FastAPI 는 대화 생성 직전 이미 `GET /internal/ai/booth-access` 를 호출하고 있다. 따라서 새 인증 인프라 없이 통보 엔드포인트 하나만 추가한다.

클라이언트 신고 값은 쓰지 않는다 (`DailyMissionController` 문서의 기존 원칙). 사용자 토큰으로는 `/internal/**` 이 열리지 않으므로 위조가 불가능하다.

마커 기록 실패는 대화를 막지 않는다. 월드 입장(`WORLD_ENTER`)은 마커 실패 시 입장을 거절하지만, AI 대화는 미션보다 대화가 본체이므로 반대로 간다 — 실패는 로그로 남기고 해당 사용자는 그날 이 미션을 놓친다. 다시 대화를 시작하면 재시도된다.

## 작업 범위

1. Spring: `POST /internal/ai/mission/ai-consult` 신설. Redis 마커 `mission:ai-consult:{userId}:{KST 일자}` 를 `setIfAbsent` 로 기록하고 TTL 은 다음 자정까지. `WorldMissionProgressService` 를 미션 인자를 받는 형태로 일반화해 재사용한다 (새 서비스 클래스를 만들지 않는다).
2. Spring: `DailyMissionService.progressOf` 의 `AI_CONSULT` 분기를 `consultations` 카운트에서 마커 조회로 교체. 더 이상 쓰이지 않게 되는 `ConsultationRepository` 카운트 메서드 정리 여부도 함께 판단한다.
3. FastAPI: 대화 생성 성공 직후 위 엔드포인트를 호출한다. 기존 서비스 토큰 클라이언트(`internal_ai_to_spring_tokens`, `spring_internal_base_url`)를 재사용하고, 호출 지점은 `booth-access` 호출부 인접이다. 실패는 로그만 남기고 대화 생성은 성공으로 반환한다.
4. spec 022 `data-model.md` 의 `AI_CONSULT` 행을 갱신한다 (근거: `consultations.requested_at` → Redis 마커). `WORLD_ENTER` 행과 같은 형태가 된다.

## 테스트

- 마커 있음 → `GET /api/v1/missions/daily` 의 `AI_CONSULT` 가 1/1 CLAIMABLE, 수령 성공
- 마커 없음 → 0/1 LOCKED, 수령 시 400 NOT_COMPLETED
- 사용자 access token 으로 `/internal/ai/mission/ai-consult` 호출 → 401 (내부 경로가 사용자 토큰으로 열리지 않음)
- 같은 날 두 번 호출해도 마커는 하나 (멱등), 진행도 1/1 유지
- FastAPI: Spring 통보가 실패해도 대화 생성은 성공한다

## 참고

- 유사 신고 S15P21A604-948 (BOOTH_VISIT_3/6) 과는 원인이 다르다. 그쪽은 사실 기록 경로가 존재하고 백엔드 재현이 안 됐다. 이 건은 사실 기록 경로 자체가 없다.
