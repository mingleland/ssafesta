## 설명

### 작업 목적

이미 머지된 상담 STOMP 채널(S15P21A604-137)의 결함 두 가지를 고친다. 월드 채팅(후속 티켓)의 선행이지만, 채팅과 무관하게 지금 존재하는 문제다.

### 문제 1 — 클라이언트가 브로커 destination 으로 직접 SEND 할 수 있다

Spring 의 SimpleBrokerMessageHandler 는 클라이언트가 보낸 SEND 중 destination 이 broker prefix(`/topic`, `/queue`)와 맞으면 컨트롤러를 거치지 않고 브로커로 넘긴다. 현재 `StompAuthChannelInterceptor` 는 CONNECT 만 검증하고 나머지 프레임은 전부 통과시킨다(`otherFramesPassThrough` 테스트가 그 동작을 고정하고 있다).

따라서 유효한 WS Token 을 가진 회원이 다음처럼 보내면 서버 검증을 전부 우회해 남의 부스 대기열에 위조 이벤트를 넣을 수 있다.

```
SEND /topic/booths/7/consultation
{ "type": "REQUESTED", ... }
```

"상담에 @MessageMapping 이 없으니 SEND 할 곳이 없다" 는 방어가 아니다. 컨트롤러를 거치지 않는 경로이기 때문이다.

### 문제 2 — WS Token 키에 환경 namespace 가 없다

`WsTokenService.KEY_PREFIX` 가 `consultation:ws:` 상수다. `RedisKeyspaceProperties` 의 javadoc 이 명시하듯 dev 와 demo 가 하나의 Redis 인스턴스를 공유하므로, 환경 접두가 없는 키는 두 환경이 서로의 토큰을 해석한다.

### 작업 내용

**인바운드 SEND 정책** — `StompAuthChannelInterceptor` 확장

| 프레임 | 정책 |
|---|---|
| CONNECT | 기존 WS Token 검증 유지 |
| SEND (전부) | 거부. 이 티켓 시점에는 허용 destination 이 하나도 없다 |
| SUBSCRIBE `/queue/**` (raw) | 거부 |
| SUBSCRIBE `/user/queue/**`, `/topic/**` | 통과 |
| UNSUBSCRIBE, DISCONNECT | 통과 |

raw `/queue/**` 구독 거부가 계약을 깨지 않는 것은 확인했다. 계약(`staff-consultation-api.md:102`)이 정하는 구독은 `/user/queue/consultation` 과 `/topic/booths/{boothId}/consultation` 둘뿐이고, 서버는 `convertAndSendToUser` 로 발행한다.

**WS Token 환경 격리** — `WsTokenService` 가 `RedisKeyspaceProperties.prefix()` 를 붙인다.

**기존 테스트 교체** — `otherFramesPassThrough()` 는 "모든 프레임 통과" 를 고정하고 있으므로 허용·거부 목록 테스트로 바꾼다.

### 범위 밖 (문서에 명시할 것)

이 티켓은 **broker 직접 SEND 위조와 raw **`/queue` 구독만 차단한다. SUBSCRIBE destination 별 인가 — 예를 들어 `/topic/booths/{id}/consultation` 을 그 부스 직원만 구독할 수 있게 하는 것 — 은 기존 동작을 유지하며 **별도 보안 검토 대상**으로 남긴다. 직원 자격 검증까지 넣으면 이 티켓이 커진다.

### 완료 조건

- [ ] 클라이언트의 `SEND /topic/**` 이 거부된다
- [ ] 클라이언트의 `SEND /topic/booths/{id}/consultation` 위조가 거부된다
- [ ] 미등록 destination 으로의 SEND 가 기본 거부된다
- [ ] raw `SEND`·`SUBSCRIBE /queue/**` 가 거부되고 `/user/queue/**` 구독은 통과한다
- [ ] SUBSCRIBE·UNSUBSCRIBE·DISCONNECT 가 통과해 연결이 유지된다
- [ ] dev 에서 발급한 WS Token 을 demo 가 해석하지 못한다
- [ ] 실제 Redis 키가 `dev:consultation:ws:*` 형태다

### 배포 영향

키 접두가 바뀌므로 배포 시점에 발급돼 있던 기존 토큰은 **최대 5분 안에** 무효가 된다. 배포로 연결도 함께 끊기므로 클라이언트가 토큰을 새로 발급받아 재연결하면 복구된다. 별도 마이그레이션은 필요 없다.

인터셉터를 직접 호출해 허용·거부를 판정한다(브로커 기동이 필요 없어 결과가 안정적이다). 환경 격리는 두 namespace 로 토큰을 발급·해석해 교차 실패를 확인한다.
