## 설명

## 작업 목적 관리자가 회원의 코인을 안전하게 조정하고 잔액 및 거래 내역을 조회할 수 있도록 블록 2 기능 9~12를 HTTP로 노출한다.  ## 작업 내용 - 관리자 코인 지급·회수 API를 추가한다. - 대상 회원의 잔액과 최신순 거래 내역을 페이지 단위로 조회한다. - 코인 원장, 잔액, admin_actions 감사 기록을 하나의 트랜잭션으로 처리한다. - 재요청은 원장뿐 아니라 감사 기록도 중복 생성하지 않는다. - Idempotency-Key는 UUID operationId로 받고, 재시도에는 같은 값을 사용한다. 서버 키는 대상 회원별로 만든다. 같은 대상·operationId에서 금액 또는 행위자가 다르면 409 IDEMPOTENCY_CONFLICT를 반환한다. note는 멱등 동일성에 포함하지 않고 첫 기록을 유지한다. - 0원, 잘못된 UUID, Integer.MIN_VALUE 등 표현할 수 없는 요청은 400으로 거부한다. 잔액 부족과 멱등 payload 충돌은 409로 구분한다. 제품상 조정 한도는 팀 결정 없이 추가하지 않는다.  ## 완료 조건 - [ ] 관리자 외 호출은 403이며 마스터 계정에 대한 조정은 403 MASTER_PROTECTED다. - [ ] 지급·회수 시 잔액, 원장, admin_actions가 원자적으로 일치한다. - [ ] 같은 operationId와 같은 요청의 재시도는 원장·감사 행을 추가하지 않는다. - [ ] 같은 대상·operationId의 다른 금액 또는 행위자는 409 IDEMPOTENCY_CONFLICT다. - [ ] 잔액·거래 내역은 최신순 페이지네이션으로 조회된다. - [ ] 잘못된 입력, 금액 경계, 잔액 부족, 동시 재시도 통합 테스트가 통과한다. - [ ] docs/08 API 계약을 갱신하고 전체 backend 테스트에서 기존 지갑 호출자 회귀가 없다.  ## 선행 작업 / 관련 이슈 - S15P21A604-742 관리자 권한 모델 상위 추적 - S15P21A604-743 관리자 권한·감사 기반 (완료)  ## 참고 - 이번 범위는 S15P21A604-742 블록 2의 기능 9~12다. 회원 상세·검색·정합성 점검은 포함하지 않는다. - 허용 금액 경계와 페이지네이션 계약은 구현 전에 docs/08에서 확정한다. 정책상 상한이 필요하면 docs/26 팀 결정으로 처리한다.
