## 설명

월드 위에 뜨는 화면이 6종이고 전부 OverlayFrame 하나를 쓴다. 이번 2종을 별도 모달·페이지로 만들면 shell·backdrop·close·focus 가 일곱 번째·여덟 번째로 복제된다. 목적은 화면 2개를 얹는 것이 아니라 그 체계를 두 자리만 넓혀 이후 수정 비용을 낮추는 것이다.

이벤트 상점은 처음부터 이벤트 코인을 쓰는 한정수량 경품 상점이다. 준비 중 모달을 따로 만들어 나중에 버리면 같은 화면을 두 번 만든다. 최종 shell 을 먼저 세우고 지금 상태를 PREPARING 으로 표현한다.

[범위]
1. 공용 기반 2개 추가 — OverlayCardGrid(게임형 카드 그리드)·OverlayNotice(준비 중·점검·로그인 필요 패널). CSS 는 overlayFrame.css 에 더하고 새 파일을 만들지 않는다
2. WorldGuideOverlay — 무엇을 할 수 있는가 축. WorldHud 의 WASD·F 조작표를 복제하지 않는다. 최초 진입 1회 자동 + 재열람 버튼, 판정은 FE 가 전부 갖고 Unity 신규 요청 0
3. EventRewardShopOverlay — 최종 상점 shell + PREPARING 상태. items 만 주입하면 READY 로 간다
4. Overlay Bus 에 WORLD_GUIDE·EVENT_SHOP 2종 추가. 그 길로 열면 배타·ESC·입력잠금·focus 가 전부 따라온다

[재사용 정본]
OverlayFrame · OverlayLoading/Empty/Error · .ov-btn(-primary) · .ov-chip · .ov-note · .ov-alert · --ov-* 토큰 · WalletBadge

[실측으로 확정한 설계 근거]
- FE 가 Overlay Bus 를 직접 여는 선례가 이미 있다(AiChatOverlay:197 · ConsultationQuickAccess:55) — 가이드도 그 길로 열고 gameClientUi 슬롯을 만들지 않는다
- index.css 의 --festa-* 와 overlayFrame.css 의 --ov-* 는 다른 층이다. .festa-overlay 스코프 안에서는 --ov-* 만 쓴다
- 이벤트 코인은 wallet Coin 이다. 단일 balance 이고 reason 에 PURCHASE 가 이미 있어 별도 화폐 근거가 없다. EventCoin API 를 만들지 않는다

[완료조건]
1. 공용 Overlay theme 를 그대로 재사용한다 — 새 shell·backdrop·close 디자인 0
2. 가이드가 FE 자체 진입(최초 1회 + 재열람)으로 동작한다
3. 상점이 최종 shell 과 PREPARING 상태로 서고, 향후 items 주입만으로 READY 가 된다(shell 재작성 없음)
4. ESC·input lock·focus 신규 계약 0 — 기존 lifecycle 을 그대로 태운다
5. tsc · vitest 전체 · build · oxlint green
6. dev 월드에서 두 오버레이를 실제로 열어 육안 확인 — 웹 페이지처럼 보이면 완료로 보지 않는다

[범위 밖]
- worldScreen·UnityHost·WorldPage 수정
- 새 .jslib · 새 Unity callback · 새 input-lock API
- 경품 상품 서버 계약 구현 — 계약이 오면 rewardShop 모듈 하나만 고친다

[HOLD 1건]
설문 CTA 의 대상 식별자. SurveyOverlay 는 payload 가 boothId 필수이고 서버가 boothId 로 설문을 resolve 한다. 이벤트 NPC 는 부스가 없어 가짜 boothId 를 만들지 않는다. resolveEventSurveyTarget() 한 지점으로 좁혀 두고, 미확정이면 CTA 를 비활성 + 안내로 처리한다. 이 HOLD 때문에 나머지 구현을 멈추지 않는다.

### 이정헌 · 2026-09-10 18:35 KST

MR !613 develop 병합(c76b9f49). 완료조건 6개 판정과 근거를 남긴다.

h3. 완료조건 판정

1. 공용 Overlay theme 재사용 — PASS. 새 shell·backdrop·close 디자인 0. CSS 는 overlayFrame.css 에 더했고 새 파일도 새 토큰 층도 만들지 않았다.
2. 가이드 FE 자체 진입 — PASS. 최초 1회 자동 + 우하단 버튼 재열람. 판정은 localStorage 하나고 Unity 신규 요청 0 이다.
3. 상점 최종 shell + PREPARING — PASS. items 만 주입하면 READY 로 가는 것을 테스트로 고정했다(같은 격자에 상품이 차고 안내만 사라진다).
4. ESC·input lock·focus 신규 계약 0 — PASS. worldScreen·UnityHost·WorldPage 미수정. 실측으로 ESC 후 document.activeElement 가 CANVAS 로 복귀했다.
5. tsc · vitest 185파일 1203테스트 · build · oxlint(신규 파일 경고 0) — PASS.
6. 실 월드 육안 확인 — PASS. Chrome 으로 dev 서버를 열어 가이드 자동 노출·재열람, 이벤트 상점 PREPARING(빈 격자 + 준비 중 안내 + 비활성 CTA + 코인 150 배지), 가이드가 떠 있는 상태에서 상점을 열면 가이드가 걷히는 배타 동작까지 봤다.

h3. 설계에서 가장 중요했던 판단 세 개

별도 모달을 만들지 않았다. 월드 위 화면이 이미 6종이고 전부 OverlayFrame 하나를 쓴다 — 여기서 갈라지면 shell 이 일곱 번째가 된다. Overlay Bus 로 열면 배타·ESC·입력잠금·focus 반환이 전부 따라온다.

상점을 임시 화면으로 만들지 않았다. 준비 중 모달을 따로 만들면 상품이 들어올 때 같은 화면을 두 번 만든다. 빈 격자를 유지한 채 그 위에 OverlayNotice 를 얹는 구조라 상품이 오면 안내만 사라진다.

이벤트 코인을 새로 만들지 않았다. entities/wallet 은 단일 balance 이고 거래 사유에 PURCHASE 가 이미 있다 — 별도 화폐라는 근거가 저장소 어디에도 없어 WalletBadge 를 그대로 썼다.

h3. 남은 외부 의존 2건 — FE 구현은 이것 때문에 멈추지 않았다

1. 설문 CTA 대상 식별자. SurveyOverlay 가 boothId 를 강제하는데 이벤트 NPC 는 부스가 없다. 가짜 값을 만들면 없는 부스의 설문을 찾다가 404 로 떨어지고 사용자에게는 설문이 고장난 것으로 보인다. features/event/model/surveyEntry.ts 의 resolveEventSurveyTarget() 한 지점으로 좁혔고, 대상이 정해지면 상수 하나만 바꾸면 된다. 지금은 CTA 가 비활성 + 사유 안내다.
2. WORLD_EVENT_INTERACT Unity 송신부. FE 수신부가 먼저 서 있는 상태다(BOOTH_PROJECT_INTERACT 가 -343 에서 그러했던 것과 같다). 게임 파트에 송신을 요청해야 제품 진입 경로가 생긴다 — 그전까지는 dev 트리거로만 열린다.

둘 다 이 티켓의 범위 밖이고, 오면 각각 한 줄·한 케이스로 붙는다.
