## 설명

### 작업 목적

develop 백엔드 전 패키지 코드리뷰에서 확정한 버그 3건을 고친다. 세 건 모두 실행 경로가 살아 있고 테스트가 없다.

### 작업 내용

1. 게임 휴지통 밀어내기가 game_assets 를 남긴다 — GameLifecycleService.hardDelete
   game_assets.game_id FK 에 ON DELETE CASCADE 가 없고(V18) JPA cascade 도 없다. 에셋을 가진 게임이 삭제본 상한(5) 밀어내기 대상이 되면 games DELETE 가 FK 위반으로 실패하고 softDelete 요청 전체가 500 이 된다. 탈퇴 경로(AccountDeletionService)는 삭제 큐 INSERT 뒤 행을 지우는데 이 경로만 빠져 있다.
   고침: hardDelete 안에서 탈퇴와 같은 순서로 에셋 좌표를 game_asset_delete_queue 로 옮기고 행을 지운다.
2. refresh 토큰 get 과 delete 가 원자적이지 않다 — MemberSessionService.refresh
   같은 refresh 토큰으로 두 요청이 동시에 오면 둘 다 세션을 읽고 isActive 를 통과해 각각 새 세션을 발급한다. 재사용 감지(reusedKey 기록 후 계정 강제 로그아웃)가 통째로 우회된다. 같은 패키지 OAuthHandoffService 는 이미 getAndDelete 로 이 문제를 피하고 있다.
   고침: get 을 getAndDelete 로 바꾸고 뒤따르던 delete 를 지운다. 키를 먼저 집은 쪽만 발급한다.
3. 탈퇴가 AI 문서 객체를 저장소에 남긴다 — AccountDeletionService
   ai_documents 행만 지워서 storage_provider·storage_bucket·s3_key 좌표가 사라진다. 팀 결정은 탈퇴 즉시 관련 데이터 전체 하드삭제(docs/26 2026-08-19)이고, 게임 에셋은 이미 삭제 큐로 넘긴다.
   고침: 행 삭제 앞에 좌표를 game_asset_delete_queue 로 옮기는 SELECT INSERT 한 줄을 넣는다. 큐 스키마가 provider·bucket·key 범용이라 새 테이블이 필요 없다.

### 완료 조건

- [ ] 에셋 있는 게임이 밀어내기 대상이 되는 경로가 500 없이 끝나고 에셋 좌표가 큐에 남는다
- [ ] 같은 refresh 토큰 동시 2회 요청에서 한 쪽만 성공하고 다른 쪽이 세션을 무효화한다
- [ ] 문서 있는 계정 탈퇴 뒤 객체 좌표가 삭제 큐에 남는다
- [ ] 세 건 각각 회귀 테스트 1개

### 영향 범위

- GameLifecycleService, MemberSessionService, AccountDeletionService
- 마이그레이션 없음. 스키마 변경 없음
- 3번은 S15P21A604-150(탈퇴 외부 자원 정리) 의 R2 문서 몫을 앞당겨 처리한다. 벡터·OAuth unlink 어댑터는 여전히 -150 에 남는다

### 테스트 방법

1. 삭제본 상한까지 채운 뒤 에셋 있는 게임을 삭제해 밀어내기를 유발한다
2. 같은 refresh 토큰으로 동시 요청 2건을 보낸다
3. 문서를 올린 계정을 탈퇴시키고 game_asset_delete_queue 를 조회한다
