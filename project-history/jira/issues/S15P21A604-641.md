## 설명

증상
게임기·부스 NPC 에 F 를 누르면 Unity 초점 카메라 줌인과 FE 오버레이가 함께 뜨는데, ESC·오버레이 밖 클릭·X 버튼 어느 것으로 닫아도 FE 오버레이만 사라지고 줌은 남는다. 그 상태에서 월드 조작이 통째로 잠긴다.

원인
Unity Interact() 한 메서드가 줌과 이벤트 송신을 같은 동기 경로에서 한다(여는 것은 의도대로다). 닫는 경로만 갈려 있다.
- WorldPage.tsx:106 closeTopScreen() 이 true 를 반환하고 즉시 return 해 :107 의 requestExitWorldUi 에 도달하지 않는다.
- .festa-overlay-dim 밖 클릭과 X 버튼은 closeOverlay() 만 부른다.

왜 조작 불가까지 가는가
InputBridge.cs:79-93 가 owner-set 이다. holders 가 {InteractionFocusCamera, host} 인 상태에서 host 만 빠지면 IsLocked 가 그대로 true 라 if (IsLocked == before) return 으로 끝나 LockedChanged 가 발화하지 않는다. FE 가 오버레이를 닫은 것에 Unity 가 반응하는 경로는 InteractionFocusCamera.cs:112-113 의 LockedChanged 구독 하나뿐이다.
결과: 초점 유지 + IsLocked 유지 → F 무효(BoothInteractionInput.cs:254) · WASD 무효(PlayerMovement.cs:557,571,582) · 재진입 무효(if (IsFocused) return). 탈출구인 Unity 자체 ESC 와 IMGUI 나가기 알약은 오버레이가 focus 를 가져가고(OverlayFrame.tsx:35) dim 이 전면을 덮어 둘 다 막힌다.

조치 (FE 만, Unity C# 변경 0)
- unity/host/worldUiBridge.ts — ExitWorldUiReason 에 'overlay-closed' 추가.
- unity/host/UnityHost.tsx — syncInputLock 효과 바로 아래에 효과 1개. worldScreen 이 짝이 되는 레이어(visitor·management)를 떠났고 hasUnityModal() 이 아직 true 면 requestExitWorldUi(instance, 'overlay-closed').
합류점을 closeOverlay() 가 아니라 worldScreen 전이로 잡는다 — 관리 화면(WORLD_MANAGEMENT_INTERACT)은 줌을 하면서 gameClientUi store 를 쓰므로 closeOverlay 로는 안 걸린다.
InputBridge 무접촉(2026-09-08 슬롯머신 사고). WorldPage ESC 3단계는 그대로 — 초점만 있는 경우의 2단계와 조건이 배타라 이중 송신이 없다.

역방향(Unity → FE)은 범위 밖이다
worldUiState.ts:12-14 가 "focus 가 false 가 됐다고 FE 가 제 오버레이를 닫지 않는다" 를 명시하고, 트리거도 사실상 도달 불가다. 필요해지면 Unity 가 보내는 명령 이벤트로 설계한다.

검증
단위 신규 1파일(unityHostWorldUiExit.test.tsx) + 로컬 Chrome 실측(게임기·부스 NPC 각각 F → ESC·밖 클릭·X → 줌 해제와 WASD·F 재진입 확인).
