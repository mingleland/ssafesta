## 설명

## 작업 목적

- 빌트인 타일셋은 8×8 = 64칸("64 Tiles"라고 라벨에도 표기)인데, 타일맵 팔레트는 인덱스  
   0~15의 16칸(4×4)만 버튼으로 노출해 나머지 48칸을 선택할 수 없다. 데이터·BE 검증·렌더링은  
   이미 전체 인덱스를 지원하므로, 팔레트 UI가 타일셋 실제 칸 수만큼 렌더하도록 고친다.

## 재현 방법

1. Game Studio → 캔버스 왼쪽 팔레트에서 "타일맵" 탭 선택
2. 타일 레이어 추가 후 타일셋("판타지 도서관 · 64 Tiles" 또는 "플랫폼 액션 · 64 Tiles") 선택
3. 팔레트에 타일 버튼이 0~15번 16개(4×4)만 표시됨 — 16~63번은 선택 불가

## 작업 내용

- `GameStudioShell.tsx` 타일 팔레트: `Array.from({ length: 16 }, ...)` → 선택된 타일셋의  
   `columns * rows`(= 64)만큼 버튼 렌더
- `.gss-tile-palette` CSS: 4열 유지 시 16행이라 세로로 길어짐 → `max-height` + `overflow-y: auto`(또는 열 수 조정)로 왼쪽 사이드바 레이아웃 유지
- 계약(`gameProject.ts` `TileLayer`), BE 스키마, `tileBackgroundStyle` 렌더러는 미변경  
   — `tileBackgroundStyle`은 이미 임의 `tileIndex`를 크롭하고, FE/BE 검증 모두 인덱스 값  
   상한이 없다

## 완료 조건

- [ ] 타일 팔레트가 선택된 타일셋의 전체 칸(8×8 = 64)을 노출한다
- [ ] 16번 이후 타일을 선택·배치·저장·재로드할 수 있다
- [ ] 팔레트가 길어져도 왼쪽 사이드바 레이아웃(장면 목록/오브젝트 섹션)이 깨지지 않는다
- [ ] 계약·BE 스키마·타일 렌더링 로직에 변경이 없다
- [ ] `npx vitest run`, `npm run build`, `npx tsc --noEmit`, `npm run lint` 통과

## 선행 작업 / Dependency

- 없음

## 테스트 방법

1. 타일맵 탭에서 "판타지 도서관 · 64 Tiles" / "플랫폼 액션 · 64 Tiles" 선택 → 팔레트에  
   64칸이 모두 보이는지 확인
2. 16번 이후 타일(예: 40번) 선택 → 캔버스에 배치 → 시트의 해당 칸이 정확히 그려지고,  
   저장·재로드 후에도 유지되는지 확인
3. 팔레트가 길어졌을 때 왼쪽 사이드바 스크롤/레이아웃 확인
4. `npx vitest run`, `npm run build`, `npx tsc --noEmit`, `npm run lint` 통과
