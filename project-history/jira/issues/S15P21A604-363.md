## 설명

# 작업 목적

- 방향키 입력 처리 구조를 개선해 연속 입력 시 이동이 매끄럽지 않은 문제(stutter)와 대각선 이동이 안 되는 문제를 해결한다. 방향키 입력 처리 구조를 개선해 ① 방향키를 꾹 누르면 초반 지연 후 급발진하는 문제, ② 피해 있는 함정을 꾹 누른 채 통과하면 스킵되는 것처럼 보이는 문제, ③ 두 방향키 동시 입력(대각선) 안 되는 문제를 해결한다.



# 작업 내용

- ReferenceGamePlayer.tsx:147-166의 onKeyDown 이펙트를 raw keydown 즉시 처리 방식에서 누른 키 Set을 추적하는 구조로 변경(keydown/keyup으로 pressed-key Set 유지 + 매 프레임마다 이동 적용)
- moveReferencePlayer(referenceRuntime.ts:408-439)가 한 번 처리할 때마다 1타일만 이동하는 현재 구조에서 대각선 이동을 지원하도록 검토(동시 keydown 조합 처리)
- ReferenceGamePlayer.tsx:151의 raw keydown 즉시 이동 처리가 OS/브라우저 키 auto-repeat 타이밍(초반 지연 → 빠른 반복)을 그대로 따라가 "멈췄다가 급발진"하는 것이 원인 — pressed-key Set 기반 틱 처리로 바꾸면 이 증상도 함께 해결됨
- 함정 스킵 증상은 별도 버그가 아니라 위 증상의 결과로 추정: damagePlayer(referenceRuntime.ts:152)가 체력 0 시 즉시 체크포인트로 순간이동시키는데, 키 반복이 너무 빠르면 사망→리스폰이 다음 이동에 묻혀 "스킵"처럼 보임 — 입력 구조 수정 후 함정 판정이 실제로 스킵 없이 정확히 이뤄지는지 별도 검증 필요



# 완료 조건

- [ ] 방향키를 꾹 누르면 초반 지연·급발진 없이 일정한 속도로 이동한다
- [ ] 피해가 있는 함정을 방향키를 꾹 누른 채 통과할 때 스킵 없이 정확히 판정(즉시 사망/리스폰)된다
- [ ] 두 방향키를 동시에 누르면 대각선 이동이 된다
- [ ] enterPosition/applyContactComponents 기반 충돌 체크가 회귀 없이 유지된다
- [ ] damagePlayer의 invulnerableUntilTick 무적 시간, 체크포인트 복귀 로직에 회귀가 없다
- [ ] 기존 단일 방향키 이동, 상호작용(E/Enter/Space), 발사(F) 키에 회귀가 없다



# 테스트 방법

- 방향키를 꾹 눌러 이동이 끊김 없이 일정한 속도로 나가는지 확인한다(초반 지연·급발진 없는지)
- 피해 10짜리 함정 위를 방향키를 꾹 누른 채로 통과 시도 → 반드시 즉시 사망/리스폰되는지 확인한다(스킵되지 않는지)
- 위+오른쪽 등 두 방향키를 동시에 눌러 대각선 이동이 되는지 확인한다
- PLATFORMER Scene에서도 좌우 이동이 동일하게 정상 동작하는지 확인한다(점프는 기존 로직 유지 여부 확인)
- 기존 단일 방향키 이동, 상호작용(E/Enter/Space), 발사(F) 키가 회귀 없이 그대로 되는지 확인한다
