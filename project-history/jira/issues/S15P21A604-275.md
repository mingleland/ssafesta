## 설명

### 증상

`normalizeGameAuthoringError` 의 재시도 판정이 **한 번도 타지 않는다.**

```ts
// festa-frontend/src/game-studio/studio/ports/gameAuthoringApi.ts
const retryable = error.code === 'UNKNOWN' || error.code === 'INTERNAL_SERVER_ERROR';
```

**서버 공통 오류 코드는 **`INTERNAL_ERROR` 다 — GitLab #104 에서 BE 가 확정했다(*"재시도 코드는 서버 *`INTERNAL_ERROR` 유지, FE 판정만 정렬"). `entities/conversation/stream.types.ts` 도 그 이름을 쓴다.

화면에 드러나지 않는 종류다 — 게임 저장이 서버 오류로 실패했을 때 재시도 가능으로 분류되지 않고 그냥 실패로 끝난다.

함께: `authoringCommands` 의 상한 guard 를 계약 정본 쪽으로 이관한다.

### 이 이슈를 새로 만든 이유 — 키 오사용 정정

이 작업은 2026-08-25 부터 `S15P21A604-179` 키를 달고 진행됐는데, 그 키는 황덕 님의 BE 티켓(`[TEST] Game Draft 조회·오류 계약 테스트 작성`)이다. 브랜치·커밋·MR 3곳에 잘못된 키가 붙어 남의 티켓 상태를 움직였다.

- 잘못 붙은 브랜치: `fix/S15P21A604-179-draft-contract-align`(MR !13, `front` 로 소진) · `fix/S15P21A604-179-develop-intake`(MR !61)
- `-179` 에 `Closes` 를 넣은 커밋은 develop 에 도달하지 않았다 — MR !61 은 아직 열려 있고, 이 이슈 키로 다시 만든다.
