## 설명

## 작업 목적

- 데이터 탭에서 추가한 변수를 개별적으로 삭제할 수 있게 한다. 현재는 "+ Boolean 변수"만 있고 삭제 경로가 없어서, 잘못 만들거나 더 이상 안 쓰는 변수를 지울 방법이 없다. (-561 자산 삭제와 같은 배경에서 나온 후속 작업 — 세 갈래 중 두 번째)

## 작업 내용

- `publishValidation.ts`에 `findVariableUsageLocations(project, variableId)` 신설 — `findAssetUsageLocations`와 같은 모양으로, 다음을 순회하며 사용 위치를 모은다:
   
   - WORLD Scene의 `event.conditions`(`VARIABLE_EQUALS`) / `event.actions`(`SET_VARIABLE`)
   - DIALOGUE Scene 각 노드의 `choice.conditions`(`VARIABLE_EQUALS`) / `choice.actions`(`SET_VARIABLE`)
   - (자산과 달리 사용 위치 조회 함수 자체가 아직 없어서 이번에 새로 만들어야 함 — -561은 기존 함수를 재사용했지만 이번엔 신설)
- `authoringCommands.ts`에 `removeVariableDefinition(project, variableId)` 신설 — `project.variables`에서 필터링 제거, `validated()`로 검증. 참조 중인 변수를 지우면 `VARIABLE_REFERENCE_NOT_FOUND`로 스키마 검증이 이미 막아준다(자산 때와 동일한 안전망 — 별도 로직 불필요, 확인만 하면 됨)
- `ProjectDataPanel.tsx`의 변수 목록 각 항목에 삭제 버튼 추가. 클릭 시 `findVariableUsageLocations`로 사용 위치를 보여주는 확인 카드 → 확인 후에만 삭제(-561의 자산 삭제 확인 카드와 동일한 UX 패턴 재사용)
- `GameStudioShell.tsx`에 `deleteVariable(variableId)` 핸들러 추가, `ProjectDataPanel`에 `onDeleteVariable` prop으로 연결

## 완료 조건

- [ ] 변수 목록에서 개별 변수를 삭제할 수 있다
- [ ] 조건(`VARIABLE_EQUALS`)이나 액션(`SET_VARIABLE`)에서 사용 중인 변수를 삭제하려 하면 사용 위치(Scene/이벤트/대화 노드 단위)를 보여준다
- [ ] 확인 후에만 실제로 삭제된다
- [ ] 삭제 후 저장 → 새로고침해도 삭제 상태가 유지된다
- [ ] 사용 중인 변수를 억지로 지우려는 경로가 있어도 스키마 검증이 최종적으로 막는다(회귀 없음)

## 선행 작업 / Dependency

- 없음 — 프론트 단독으로 완결 가능(변수는 `GameProject` 스키마·검증 로직에만 걸려있고, -561의 자산과 달리 서버 API 연동이 필요 없음)

- 관련 Issue: (아이템 삭제 — 세 번째, 별도 티켓 예정)

## 테스트 방법

1. 변수를 하나 추가한 뒤 삭제 버튼으로 제거되는지, 목록에서 즉시 사라지는지 확인한다.
2. 어떤 이벤트 조건이나 액션에서 참조 중인 변수를 삭제 시도했을 때 사용 위치 안내가 뜨는지 확인한다.
3. 확인 후 삭제하면 해당 조건/액션이 어떻게 처리되는지(스키마 검증이 막는지) 확인한다.
4. 취소를 누르면 아무 변화 없이 확인 카드만 닫히는지 확인한다.
5. 삭제 후 저장 → 새로고침해도 삭제 상태가 유지되는지 확인한다.
