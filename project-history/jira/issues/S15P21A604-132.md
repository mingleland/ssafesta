### 황덕 · 2026-09-07 20:12 KST

MR !443 머지 완료 (develop `b5ac19dc`). Survey BE 3개 MR 중 마지막이며 계약 endpoint 6개가 전부 열렸다.

**이 MR (-132 · -193 · -191)**

- `GET /api/v1/surveys/{surveyId}/results` — 편집자, 임대 무관(축제 종료 후 조회가 주 용도)
- `GET /api/v1/surveys/{surveyId}/text-answers?questionId&page&size` — 편집자, `page` 0부터 / `size` 1~100

**설계에서 정한 것**

1. 집계는 문항 목록을 기준으로 조립한다. 응답 0건에도 모든 문항이 `answeredCount: 0`, 선택지까지 `count: 0`, `average: null`로 실린다.
2. 별점 평균은 함께 나가는 분포에서 유도한다 — `avg()`를 따로 쏘면 평균과 히스토그램이 어긋날 수 있다.
3. 비율은 싣지 않는다. `count / answeredCount`는 화면이 계산한다(복수선택은 합이 100%를 넘는다).
4. 주관식 정렬은 답변 id 오름차순 고정 — 페이지 순회 중 제출이 들어와도 경계에서 중복·누락이 없다.
5. 응답 본문에 응답자 식별 필드가 없다. `responseId`는 같은 사람의 답을 묶는 열쇠다.

**정정 통보 재확인** — 본문의 "커서 페이지네이션"은 전역 페이지 규약과 FE Port에 맞춰 `page`/`size` 오프셋으로 구현했다. 완료조건의 "경계 중복·누락 0건"은 정렬을 id ASC로 고정해 충족하고, 테스트가 실제로 페이지 순회 중 제출을 끼워 넣어 확인한다.

**검증** — 922건 통과, 실패 0 (직전 907 + 15). 변이 12종 중 11종이 특정 테스트를 깬다. 20응답 픽스처를 API로 제출해 집계값을 손으로 센 값과 대조했다(선택지 11/9, 복수선택 10/15/5 합 30 > 응답 15, 별점 평균 4.2·분포 0/1/2/9/8).

안 잡힌 변이 1종은 내 주석이 틀렸음을 알려줬다 — native projection alias를 snake_case로 맞추며 "camelCase는 바인딩되지 않는다"고 썼는데 그 변이가 통과했다. 주석의 거짓 주장을 지웠다. 근거는 `specs/010-survey/BE/quickstart.md` §5-1에 표로 남겼다.

**손 왕복은 부분 실행이다** — V22를 살아 있는 로컬 V21 DB에 Flyway로 적용하고 `ddl-auto: validate`를 통과시켰으며, 롤백 스크립트 14문장과 무인증 401 / 게스트 403을 실제 HTTP로 확인했다. 회원 curl 왕복은 회원 토큰이 소셜 로그인 경로밖에 없어 못 돌렸고, 그 경로는 통합 테스트 75건이 실 Postgres에서 덮는다. quickstart §4-3에 돌린 것과 못 돌린 것을 나눠 적었다.

**FE에 남은 것** — 결과 화면 어댑터가 옮길 것은 계약 §9 표에 있다. `items = content.map(c => c.text)`, `hasNext = page + 1 < totalPages`, `kind`는 응답의 `type`으로 결정. 비율은 서버가 주지 않는다.

**미결 그대로** — `docs/26` row 20(게스트 응답)·21(보상 상한)은 기획 결정 대기이며 구현 기본값만 기록돼 있다. C-03(지원서 제출자별 상세 조회)은 범위 밖이라 텍스트 답변이 `responseId`를 실어 열쇠만 남겨 뒀다.
