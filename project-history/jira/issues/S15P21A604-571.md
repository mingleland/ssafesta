## 설명

### 작업 목적

S15P21A604-503, -173, -556, -152 를 develop 에 넣은 뒤 전수 점검에서 마감이 덜 된 것 세 가지가 나왔다. 기능은 정상이지만 셋 다 나중에 조용히 문제를 만드는 자리라 한 번에 닫는다.

### 1. 버전 목록 응답의 계약 필드 두 개를 아무 테스트도 단정하지 않는다

계약(specs/019-game-studio/contracts/game-api.md 버전 목록 절)은 versions 항목이 versionNo, schemaVersion, publishedAt 세 필드를 갖는다고 정한다. GameVersionsApiIntegrationTest 는 versionNo 순서, project 본문 부재, 50건 상한, 권한만 확인하고 schemaVersion 과 publishedAt 이 실제로 응답에 들어가는지는 보지 않는다.

이 응답은 GamePublishedVersionRepository.VersionRow 라는 Spring Data 프로젝션 인터페이스를 그대로 직렬화한다. 프록시를 거치는 자리라 필드가 빠지거나 예상 밖의 키가 섞여도 현재 테스트는 전부 통과한다. FE 가 붙는 시점에야 드러난다.

### 2. spec 007 tasks.md 의 T063 이 실제 코드와 어긋난 채 남았다

T063 은 ObjectDeletionWorker.java 에 구현하라고 적혀 있고 체크되지 않은 상태다. 실제로는 S15P21A604-556 이 그 요구사항을 AiDocumentOriginalDeleteSweeper 로 구현해 develop 에 넣었다. 문서만 보면 아직 안 된 일로 읽힌다.

같은 상황에서 S15P21A604-173 은 tasks.md 에 판단 근거를 남겼다. 556 은 남기지 않아 기록 방식도 어긋나 있다.

### 3. stress 태그가 실제로는 제외되지 않는다

backend/pom.xml 에 surefire 설정이 없어 excludedGroups 가 지정되어 있지 않다. 그래서 BoothLeaseStressIntegrationTest 의 Tag stress 는 기본 빌드에서 그대로 실행된다. 그 클래스 주석의 excluded from the fast build 라는 설명은 현재 사실이 아니다.

원래 이 항목은 S15P21A604-521 의 완료 조건에 들어 있었다. 여기서 처리하므로 521 에서는 성능 프로파일 분리만 남는다.

### 작업 내용

- GameVersionsApiIntegrationTest 에 schemaVersion 과 publishedAt 단정 추가
- spec 007 tasks.md T063 을 실제 구현 위치와 클래스명으로 정정하고 완료 표시, 판단 근거 기록
- backend/pom.xml 에 surefire excludedGroups 설정 추가, BoothLeaseStressIntegrationTest 주석이 사실이 되도록 확인

### 완료 조건

- 버전 목록 응답에서 schemaVersion 과 publishedAt 이 사라지면 테스트가 실패한다
- tasks.md 를 읽고 T063 의 구현 위치를 찾을 수 있다
- mvnw test 실행에 stress 태그 테스트가 포함되지 않는다

### 참고

- S15P21A604-503, -173, -556, -152
- S15P21A604-521 (성능 프로파일 분리)
