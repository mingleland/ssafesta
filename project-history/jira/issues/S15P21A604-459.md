## 설명

### 배경

월요일 릴리스 빌드를 준비하다 발견했다(2026-09-06). 릴리스 WebGL 산출물은 ApiConfig 의 활성 환경에서 Spring URL 을 빌드 타임에 박아 넣는다 — 빌드 로그가 env=Prod spring=https://api.ssafesta.world 를 찍는다.

### 무엇이 문제인가

1. 그 호스트가 아직 없어서 릴리스 산출물을 로컬 스택에서 검증할 수가 없다. 실배포에서 처음 돌려보는 셈이 된다.
2. 최종 API 호스트가 박아 넣은 값과 다르면 40분짜리 재빌드가 유일한 수정 수단이다.
3. 로컬 검증은 별도 Local 환경 빌드로 해야 해서, 검증한 것과 배포하는 것이 같은 산출물이 아니다.

### 프런트는 이미 같은 문제를 풀었다

컨테이너 entrypoint 가 /runtime-config.js 를 다시 써서 window.**FESTA_CONFIG** 를 채우고, festa-frontend/src/shared/config/runtime.ts 가 거기서 apiBaseUrl 을 읽으며 없으면 빌드 타임 값으로 물러난다. Unity 도 같은 키를 읽으면 하나의 산출물이 로컬·dev·demo 에서 돌아간다.

### 조치

- jslib FestaHostApiBaseUrl(buffer, len) 이 window.**FESTA_CONFIG**.apiBaseUrl 을 호출자가 준 버퍼에 쓴다(malloc/free 계약 없음).
- Integration/HostRuntimeConfig 가 값을 캐시한다.
- ApiServices.Init(ApiConfig) 가 mock 이 아닐 때 이 값을 빌드 타임 값보다 우선하고, 덮어썼다는 사실을 로그로 남긴다.
- 주입이 없으면(dev 서버·probe.html·단독 실행) 기존 동작 그대로다.

### 프런트에 필요한 것

로컬 개발은 아무것도 필요 없다(빈 객체로 충분). 배포 이미지에서는 entrypoint 가 apiBaseUrl 을 쓰도록 PUBLIC_API_BASE_URL 을 설정하면 되는데, 이미 FE 자신을 위해 그렇게 하고 있다.
