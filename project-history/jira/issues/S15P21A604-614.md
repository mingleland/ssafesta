## 설명

### 작업 목적

Swagger 문서가 endpoint 2개의 본문을 다른 기능의 것으로 알려주고 있다. FE 가 검증 중에 발견해 GitLab 이슈 #172 로 보고했다.

springdoc 은 스키마를 단순 이름으로 등록한다. 서로 다른 패키지의 중첩 레코드가 같은 이름이면 나중 것이 앞의 것을 덮고, 그 결과는 조용하다. 문서만 봐서는 스키마 둘이 합쳐졌다는 사실을 알 수 없다.

develop 백엔드를 띄워 실제 /v3/api-docs 를 덤프해 확인한 잘못된 문서는 다음 2건이다.

- POST /api/v1/minigames/timer-stop/sessions/{sessionId}/result — 요청이 설문의 answers 로, 응답이 설문의 responseId/rewardedCoin 으로 문서화된다. 실제는 stoppedSeconds 를 받고 accepted/errorSeconds/tier 등을 돌려준다
- GET /api/v1/games/{gameId}/published — 부스 배치 공개 응답으로 문서화된다. 게시본 페이로드인 project 필드가 문서에서 통째로 사라져 있다

런타임 바인딩은 정상이므로 동작 결함은 없다. 문서만 어긋난다.

소스 전체에 단순 이름이 겹치는 레코드가 7쌍 있고, 그중 지금 문서에 닿는 것이 3쌍이다. 나머지 4쌍(PublishedView, DraftView, PublishOutcome, IssuedGrant)은 한쪽만 노출되어 현재는 정상이지만 반대쪽을 컨트롤러에서 직접 반환하는 순간 같은 방식으로 깨진다.

### 작업 내용

1. OpenApiDocumentationTest 에 검사 하나 추가 — 한 스키마 이름을 서로 다른 타입 둘이 주장하면 실패한다. 테스트를 먼저 넣고 red 를 확인한다.
2. 충돌하는 3쌍에 @Schema(name = ...) 로 문서상 이름만 도메인 접두사로 가른다. Java 레코드 이름과 호출부는 바꾸지 않는다.

| 지금 이름 | 바뀔 문서상 이름 |
|---|---|
| SubmitCommand / SubmitResult (TimerStopService) | TimerStopSubmitCommand / TimerStopSubmitResult |
| SubmitCommand / SubmitResult (SurveyResponseService) | SurveySubmitCommand / SurveySubmitResult |
| PublishedResponse (BoothLayoutController) | BoothLayoutPublishedResponse |
| PublishedResponse (GameController) | GamePublishedResponse |

1. 이긴 쪽에도 함께 접두사를 붙인다. 진 쪽만 고치면 세 번째 도메인이 같은 이름을 추가할 때 반복된다.

채택하지 않은 대안 두 가지를 기록해 둔다.

- springdoc.use-fqn=true — 한 줄로 전부 해결되지만 문서의 모든 스키마 이름이 FQN 으로 바뀐다. 3건을 고치자고 손으로 타입을 적는 FE 의 읽기 경험 전체를 망가뜨리는 거래다
- 레코드 이름 자체를 변경 — 문서만 어긋난 문제에 호출부 변경을 끌고 올 이유가 없다

### 완료 조건

- 충돌 검증 테스트가 존재하고, 정정 전 red 였다가 정정 후 green 이 된다
- /v3/api-docs 에서 위 2개 endpoint 가 자기 본문을 문서화한다
- 응답 필드 이름과 런타임 동작은 바꾸지 않는다. 문서 생성에만 닿는다 (헌법 24조)
- GitLab 이슈 #172 에 develop 병합 후 결과를 통보한다
