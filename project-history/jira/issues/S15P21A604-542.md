## 설명

## 작업 목적

- 대화형(DIALOGUE) 씬은 플레이 화면을 크게 채우는데, 맵형(TOP_DOWN/PLATFORMER) 씬은 고정 `1120px` 상한 때문에 화면보다 훨씬 작게 떠서 씬 전환이 불연속적으로 느껴진다. 맵형 씬도 대화형 씬과 비슷한 체감 크기로 화면을 채우게 한다.

## 작업 내용

- `.grp-map`(플레이 화면 게임 캔버스) 크기 계산에서 화면 크기와 무관한 고정 `1120px` 가로 상한을 없애고, 가로·세로 상한을 실제 가용 화면의 92%로 바꾼다.
- 씬의 종횡비(격자 비율)는 그대로 유지한다 — 긴 쪽만 화면 경계에 닿고, 반대쪽엔 여백이 남는 것은 그대로 둔다(비율을 억지로 늘리거나 찌그러뜨리지 않는다).
- CSS의 `max-width: 1120px; max-height: calc(100vh - 130px);`는 실제 크기를 계산하는 인라인 스타일의 안전망 역할만 하도록 `100%` 기준으로 정리한다.

## 완료 조건

- [ ] 맵형 씬이 기존 `1120px` 고정 상한 없이, 화면(가용 영역)의 최대 92%까지 커진다
- [ ] 종횡비는 그대로 유지되고, 긴 쪽만 화면 경계에 닿으며 반대쪽엔 자연스러운 여백이 남는다(늘어나거나 찌그러지지 않는다)
- [ ] 타일/오브젝트 크기·비율은 화면이 커져도 격자 칸 비율대로 일관되게 유지된다(S15P21A604-537 회귀 없음)
- [ ] 기존 종횡비 계산 테스트(`referenceGamePlayerMapAspectRatio.test.tsx`)가 새 계산식 기준으로 통과한다

## 선행 작업 / Dependency

- 없음

## 테스트 방법

1. 정사각형/가로로 긴/세로로 긴 씬 각각에서 화면 대비 눈에 띄게 커졌는지, 종횡비가 유지되는지 확인한다.
2. 브라우저 창 크기를 바꿔가며 맵 크기가 그에 비례해 반응하는지 확인한다.
3. 오브젝트/타일이 화면 크기 변화와 무관하게 여전히 격자 칸 비율대로 렌더링되는지 확인한다(회귀 없음).
4. 대화형 씬 전환 시에도 기존 동작에 영향이 없는지 확인한다.
