## 설명

h3. 증상 (5173 · OAuth 회원 · 실 Unity 9a977c0d 실측, 2026-09-11)

{code}
13:35  월드 진입 — Unity PublishedLayoutLoader 12슬롯 조회, 6번은 404(미임대)
13:41  6번 슬롯 임대 (월드 안 → 내 부스 관리 → /app/booths → 임대 → 월드 복귀)
       BE: slot 6 OCCUPIED · mine:true · entryAvailable:true · layouts/published 200
       Unity: 6번 여전히 빈 프레임 — 부스 접근 불가
{code}

h3. 원인

Unity 는 진입 시 1회만 게시본을 조회하고 다시 보지 않는다. 게임 파트가 이를 위해 *{{BoothLayoutBridge.ReloadBoothSlot(slotId)}}* 수신부를 만들어 뒀는데(QA 2026-09-08 #11, -508), *FE 호출이 0건*이다 — {{docs/LJH/24_작업일지.md:69}} 에 이미 적혀 있던 사실이다.

-620 이전에는 {{/app/booths}} 로 나갔다 오면 Unity 가 재부팅돼 재조회됐다. Persistent World 가 Unity 를 살려두니 이 미구현이 드러났다.

h3. 연결할 mutation — 전수 판정

Unity {{RequestReload(slotId)}} 는 {{GetPublishedLayoutBySlotAsync}} 로 *게시본 version 이 바뀌었으면* 다시 짓는다. 그 기준으로 가른다.

|| FE mutation || Unity 가 읽는가 || 연결 ||
| 슬롯 임대 {{useLeaseSlot}} | 임대 시 BE 가 게시본을 만든다 — 6번 임대 직후 {{layouts/published}} 200 실측 | *연결* |
| 게시 {{usePublish}} | 게시본 version 변경 — 이 seam 의 원래 용도 | *연결* |
| 저장(draft) {{useSaveDraft}} | Unity 는 draft 를 읽지 않는다 | 제외 |
| facade 저장 {{FacadePanel}} | reload 는 게시본 version 비교로 재구축 여부를 정하는데 facade 는 version 을 바꾸지 않는다. 보내도 효과 없음 | 제외 — Unity 계약 별건 |

h3. 수정

* {{unity/host/boothLayoutBridge.ts}} 신규 — {{audioBridge.ts}} 와 같은 꼴. {{notifyBoothSlotChanged(slotId)}} 는 {{getReadyUnityInstance()}} 가 null 이면 no-op. mock 월드·boot 전·월드 미진입은 전부 여기서 걸러진다. *큐를 두지 않는다* — 다음 월드 진입이 최신을 읽는다.
* {{useLeaseSlot}} onSuccess — slotId 는 mutation 변수라 바로 있다
* {{usePublish}} onSuccess — {{['my-booth']}} 캐시의 {{lease.slotId}}. {{useOwnerGate}} 가 같은 키를 채우고 StudioPage 는 그 게이트 뒤에서만 렌더된다

새 Unity 계약·C# 수정 없음.

h3. 완료 조건

# 임대 성공 + instance ready → 해당 slotId 로 {{SendMessage('BoothLayoutBridge','ReloadBoothSlot','N')}} 1회
# 게시 성공 + ready → 1회 · API 실패 → 0 · instance 미준비 → throw 없이 0 · draft 저장 → 0
