## 설명

## 작업 목적

GitLab Work Item #119의 게시된 합의에 따라, 기존 “Spring Business DB / FastAPI AI DB 분리” 문서를 “Spring Business DB 단일 영속화 + FastAPI DB 무접속” 경계로 정합화한다.

미게시 댓글 입력창 초안의 변경안은 범위에 포함하지 않는다. 기존 게시 합의와 다른 변경은 #119에서 별도 재합의 후 반영한다.

## 작업 내용

- specs/007-ai-agent-document/spec.md 정합화
  - C-11을 Spring의 Document·Job·Chunk·Staging 단일 DB 소유로 교체
  - C-14의 ai_document_chunks 제외 근거 교정
  - FR-017, FR-034, FR-036, FR-037~FR-042와 관련 Edge Cases·State Model·Key Entities·Success Criteria 수정
  - FastAPI의 DB credential·직접 SQL·Alembic 소유 전제를 제거
  - 처리 접수, batch, heartbeat, finalize, failed, cancel, attempt fencing, Spring vector search 경계를 반영
- specs/007-ai-agent-document/contracts 정합화
  - 처리 접수·취소 계약
  - batch·heartbeat·finalize·failed 결과 수신 계약
  - POST /internal/ai/chunk-search 및 Agent 설정 조회 계약
  - storage reconciliation 계약의 소유권 표현 점검
- plan.md, research.md, data-model.md, quickstart.md, tasks.md를 새 경계로 갱신

  - spec, plan, research, data-model, quickstart, tasks 정합화

- docs/26_팀_결정_필요사항.md와 S15P21A604-262의 폐기·대체 근거 정합화

## 반영할 게시 합의

- Spring Flyway가 AI 문서 Job·Chunk·Staging과 pgvector를 관리
- FastAPI는 DB credential 없이 파싱·청킹·임베딩·질의 임베딩 계산만 수행
- Spring이 Job을 먼저 만든 뒤 FastAPI가 202 Accepted로 비동기 접수
- jobId + attemptNo fencing, stale attempt 409, 취소·삭제·비활성 늦은 결과 410
- heartbeat 30초, lease 90초, 최대 3회 재시도와 1·5·15분 backoff
- finalize에서 Chunk 교체 + Job SUCCEEDED + Document READY를 Spring 로컬 트랜잭션으로 확정
- 검색은 Spring이 boothId + agentId + READY 조건을 강제
- 현재 게시 합의 기준 distance(코사인 거리), 최소 임계값 없음
- V21의 확정 스키마 설명과 충돌하지 않게 작성
