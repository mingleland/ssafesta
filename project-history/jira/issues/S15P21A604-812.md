## 설명

BE 가 S15P21A604-764 / !974 로 refresh 재사용 감지에 30초 유예를 넣었다. 유예 안이고 계보가 현행이면 세션을 끊지 않고 401 만 응답하며, 전용 코드 REFRESH_TOKEN_ROTATED 가 온다. 진짜 계보 폐기와 코드가 달라 한 번 재시도와 재로그인을 가를 수 있다.

변경
- features/auth/model/unauthorizedHandler.ts 의 attemptRefresh 만 고친다. refresh 가 던진 오류가 ApiError 이고 code 가 REFRESH_TOKEN_ROTATED 면 refresh 를 한 번 더 부른다. 그것도 실패하면 기존대로 false 를 돌려 세션 클리어 경로를 탄다.
- 근거: 다른 탭이 방금 회전시킨 상태라 쿠키에 이미 새 RT 가 들어 있다. 재시도 한 번이면 성공한다.

재시도는 1회 고정이다. 지수 백오프나 큐를 만들지 않는다 — 유예가 30초이고 원인이 경합이다. refreshInFlight single-flight 와 client.ts 의 skipAuthRetry 상한은 그대로 둔다. handleUnauthorized·client.ts·세션 상태기계는 건드리지 않는다.

완료 조건
- rotated 뒤 두 번째 refresh 성공이면 true 반환 + 세션 유지
- 두 번 다 rotated 면 false + session-expired
- 다른 코드는 재시도 없이 기존대로 1회
- vitest / tsc / build green
