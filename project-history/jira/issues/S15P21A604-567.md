## 설명

## 배경

S15P21A604-564 로 Local FE Host Gateway 를 세우면서 runtime-config 의 공백이 드러났다. docker/40-runtime-config.sh 는 RuntimeAssetConfig 5키 중 apiBaseUrl·unityBuildBase 둘만 쓴다. 스크립트 주석은 "키 목록은 RuntimeAssetConfig 와 1:1 이다" 라 적어 두었는데 실제로는 어긋나 있다.

결과로 authBaseUrl·aiApiBaseUrl·boothAssetBase 는 배포 환경에서 주입할 방법이 없다. 특히 AI Chat 은 배포본에서 빌드타임 VITE_AI_API_BASE_URL 에만 의존한다 — 같은 이미지를 환경마다 다시 빌드해야 한다는 뜻이고, -254·-427 이 없애려던 바로 그 구조다.

이 파일은 festa-frontend/ 안의 FE 파일이다. 값을 정하는 것은 Infra 몫이지만 키를 받을 수 있게 만드는 것은 FE 몫이라 자체 처리한다.

## 범위

1. docker/40-runtime-config.sh 가 5키 전부를 쓴다 — PUBLIC_AUTH_BASE_URL·PUBLIC_AI_API_BASE_URL·PUBLIC_BOOTH_ASSET_BASE 추가. 값이 비면 그 키를 넣지 않는다(빈 문자열은 accessor 의 미설정 판정을 흐린다). 각 키의 지정/미지정을 기동 로그로 남긴다.
2. 키 일치 회귀 테스트 — entrypoint 스크립트에서 키를 뽑아 RuntimeAssetConfig 키 집합과 대조한다. 한쪽만 늘면 red.
3. aiApiBaseUrl() 판정을 apiBaseUrl() 과 같은 규칙(resolveHostApiBaseUrl)으로 통일한다. 지금은 미설정이 '' 라 "설정 없음" 과 "same-origin 의도" 가 구분되지 않는다.
4. AI 미연결 진단 — /ai/v1 프록시가 없는 상태에서 POST /ai/v1/conversations 는 404 에 content-type 이 없다(실측). 현재는 UNKNOWN 404 로만 끝나 "AI 서버가 붙어 있지 않다" 를 말하지 않는다. 응답이 JSON 이 아니면 그 사실을 코드로 구분한다.
5. SSE 회귀 테스트 — streamMessage 가 base 변경에 영향받지 않음을 잠근다.
6. .env.example 문서화, runtime.ts 의 낡은 서술 교체.

## 완료조건

1. RuntimeAssetConfig 5키가 전부 배포 주입 경로를 갖는다 (값은 Infra 몫)
2. entrypoint 와 타입의 키 불일치가 테스트로 잠긴다
3. aiApiBaseUrl 판정이 apiBaseUrl 과 같은 규칙을 쓴다
4. AI 미연결이 진단 가능한 실패로 드러난다
5. auth 5곳이 단일 authBaseUrl 계약을 쓰는 것이 테스트로 확인된다
6. /unity 계약 회귀 없음
7. tsc · vitest 전체 · build green
8. 파일 무수정 상태에서 수동 주입 없이 월드 진입 성공

## 범위 밖

- Dev/Demo/Prod 의 실제 upstream 주소와 route 값 결정 (Infra)
- infra nginx / ingress 파일 수정
- OAuth provider redirect URI · BE cookie Domain/Path · Spring OAuth session 정책
- Unity C# · PlayerSettings · Game server contract · 월드 WebSocket 구조
