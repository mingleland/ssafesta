## 설명

QA 발견 — dev 배포본에서 AI 직원 문서 업로드 시 R2 presigned PUT 직전 OPTIONS preflight가 400으로 거부됨(응답 Content-Type: application/xml, Cloudflare 서버 헤더).

요청 출처: https://demo.ssafesta.world (Referer 확인됨)

대상: <account>.r2.cloudflarestorage.com/festa_documents/booths/2/agents/1/documents/1/...

저장소 선언(infra/environments/storage/r2/documents-cors.json)은 이미 이 origin·PUT·Content-Type+x-amz-checksum-sha256 허용으로 맞게 적혀 있고, FE가 보내는 헤더도 그 둘뿐이라 설정 자체는 문제가 없다. 다만 이 JSON을 실제 Cloudflare R2 버켓에 적용하는 자동화가 repo에 없고(r2-storage.sh는 JSON 모양만 검증함), 실제 버켓 CORS가 이 선언과 드리프트된 것으로 보인다.

요청: dev/demo 환경의 실제 documents 버켓에 documents-cors.json 귀칙이 적용되어 있는지 확인하고, 아니면 Cloudflare 대시보드/wrangler로 적용해 달라. 재발 방지를 위해 적용 자동화(wrangler 명령 또는 Jenkins 스텝) 추가도 검토 부탁드린다.
