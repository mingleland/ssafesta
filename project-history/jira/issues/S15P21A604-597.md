## 설명

목적 S15P21A604-396의 rule-based 단축 응답이 사용할 프로젝트 정형 정보를 Spring이 저장·제공한다. 대상 사용자와 사용 기술은 문서 임베딩 완료 후 AI가 자동 추출하여 전달한다.  작업 내용 - projects에 targetAudience, techStack 저장 필드 추가(기존 description은 프로젝트 소개로 사용) - AI 추출 결과를 수신하는 내부 API 및 DTO 추가 - documentId/jobId/sourceRevision 기준으로 오래된 작업 결과가 최신 값을 덮지 않도록 멱등성 보장 - AI Agent 설정 내부 응답에 projectFacts(introduction, targetAudience, techStack) 추가 - 기존 데이터와 구버전 AI 호환을 위해 신규 필드는 nullable로 제공 - spec 008·009 계약 및 DB 마이그레이션·단위/통합 테스트 갱신  완료 조건 - AI 추출 결과가 올바른 boothId의 프로젝트에만 반영된다. - 값이 없으면 null을 반환하며 기존 RAG 흐름을 깨지 않는다. - 오래되거나 취소된 문서 처리 결과가 최신 값을 덮어쓰지 않는다. - 기존 프로젝트 생성·수정·조회 API 호환성이 유지된다.  관련 Jira - S15P21A604-396

### 황덕 · 2026-09-13 17:20 KST

구현 완료. MR !779 (CI 초록, 머지 대기).

**경로를 새로 만들지 않았습니다.** `POST /internal/ai/document-jobs/{jobId}/project-facts` 로 기존 결과 수신 컨트롤러의 다섯 번째 경로로 붙였습니다. attempt 소유 검증·Job 잠금·sourceHash 대조가 이미 그 자리에 있고, 추출 결과는 그 Job 이 처리한 문서에서 나오기 때문입니다.

완료 조건 대응:

| 완료 조건 | 어떻게 |
|---|---|
| 올바른 boothId 의 프로젝트에만 반영 | Job 이 booth 를 들고 있어 그 값으로 프로젝트를 찾습니다. 요청의 documentId 는 선택이고, 보내면 Job 의 문서와 대조해 다르면 400 입니다 |
| 값이 없으면 null, RAG 흐름 유지 | agent-config 응답의 projectFacts 는 없는 값을 빈 문자열로 채우지 않고 키 자체를 뺍니다. 프로젝트가 없는 부스는 projectFacts 자체가 없습니다 |
| 오래되거나 취소된 결과가 덮지 않음 | 최신성은 jobId 로만 판정합니다(단조 증가라 그 자체가 순서). 취소·사망 Job 은 410 |
| 기존 프로젝트 API 호환 | 공개 계약을 건드리지 않았습니다. 두 값은 등록·수정으로 바뀌지 않고 공개 응답에도 실리지 않습니다 |

**AI 파트 확인이 필요한 것 하나**: 티켓의 `sourceRevision` 을 `sourceHash` 로 맞췄습니다. 같은 컨트롤러의 다른 네 경로가 전부 그 이름입니다. `sourceRevision` 을 원하면 한 줄 수정이고, 계약 yaml 에도 적어 두었습니다.

이 경로만 `SUCCEEDED` Job 을 받습니다 — 추출은 임베딩이 끝난 뒤에 오므로, 다른 경로처럼 성공한 Job 을 막으면 이 기능은 한 번도 동작하지 않습니다.

검증: 전용 12건, clean test 1281건 통과(v35). 최신성 가드 제거와 SUCCEEDED 를 끝난 Job 으로 취급하는 변이를 각각 테스트가 잡는 것까지 확인했습니다.

계약 반영: specs/007 document-result-api.yaml, specs/008 spring-agent-config-api.yaml, specs/009 data-model.md 및 project-api.md.
