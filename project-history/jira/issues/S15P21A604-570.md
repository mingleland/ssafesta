## 설명

## 작업 목적

- 배경/인물 이미지 select 3곳(장면 배경, 대화 배경, 대화 인물 이미지)에서 빌트인 자산과 내가 올린  
   커스텀 이미지가 구분 없이 섞여 나오고, 커스텀 이미지는 `내 자산 · image7`처럼 내용을 전혀  
   알 수 없는 라벨로 표시되어 엉뚱한 이미지를 고르기 쉬운 문제를 해결한다.

## 작업 내용

- `AssetReference`에 선택적 `label`(원본 파일명) 필드 추가
- `uploadAsset`(GameStudioShell.tsx)에서 `assetRepository.save()`가 반환하는 `originalName`을  
   버리지 않고 `addAssetReference` 호출 시 자산에 함께 저장
- `assetDisplayLabel()`이 커스텀 자산일 때 `label`이 있으면 `내 자산 · {label}`을 우선 사용하도록  
   수정(label 없는 기존 자산은 현행 `내 자산 · {assetId}` 폴백 유지)
- InspectorPanel의 BACKGROUND select, DialogueEditor의 BACKGROUND·PORTRAIT select 3곳에  
   `<optgroup label="제공 자료">`(역할 일치 빌트인) / `<optgroup label="내 자산">`(커스텀 전체)  
   구분 적용 — AssetPickerModal의 기존 ALL/MY 그룹 전례와 일관
- 범위 밖: 커스텀 자산에 역할을 강제 지정하는 것은 하지 않는다(현재도 하나의 업로드 이미지를  
   여러 컴포넌트에서 재사용 중이라 강제 시 재사용성이 깨짐) — select에는 계속 모든 역할에 노출됨

## 완료 조건

- [ ] 이미지 업로드 시 원본 파일명이 프로젝트에 저장되고, 데이터 탭/피커/3개 select 어디서든  
       `내 자산 · {원본 파일명}`으로 표시된다
- [ ] BACKGROUND/PORTRAIT select 3곳에서 "제공 자료"/"내 자산"이 optgroup으로 시각적으로 구분된다
- [ ] 커스텀 자산은 기존대로 모든 역할 select에 계속 나타난다(강제 필터링 없음)
- [ ] label이 없는 기존 프로젝트를 열어도 오류 없이 폴백 라벨(`내 자산 · {assetId}`)이 표시된다
- [ ] `npx vitest run`, `npm run build`, `npx tsc --noEmit`, `npm run lint` 통과

## 선행 작업 / Dependency

- 없음

## 테스트 방법

1. 이미지 업로드 → 데이터 탭/피커/select 어디서든 `내 자산 · {원본 파일명}`으로 표시되는지 확인
2. 장면 배경(InspectorPanel), 대화 배경·인물 이미지(DialogueEditor) select를 열어 "제공 자료"/  
   "내 자산" optgroup이 나뉘어 보이는지 확인
3. label 없는(기존) 자산이 섞인 프로젝트를 열어 폴백 라벨과 select 동작이 깨지지 않는지 확인
4. `npx vitest run` — assetDisplayLabel/uploadAsset 관련 단위 테스트 통과
5. `npm run build`, `npx tsc --noEmit`, `npm run lint` 통과
