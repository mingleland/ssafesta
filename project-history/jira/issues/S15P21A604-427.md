## 설명

배경 (GitLab #127, #128 §4, 2026-09-05): Unity WebGL 산출물 서빙 URL 이 아직 미정이고, FE 는 VITE_UNITY_BUILD_BASE 를 빌드 타임에 박는다. 09-08 배포에서 URL 이 바뀌면 FE 이미지를 재빌드해야 한다. 또 manifest.json 의 URL 4종은 상대경로(Build/<hash>.loader.js)인데 resolver.ts/loader.ts 가 값을 그대로 script.src 에 넘겨 FE 오리진 기준으로 해석된다 — base 가 다른 오리진·하위 경로면 404.

수정:
1. shared/config/runtime.ts 의 window.__FESTA_CONFIG__ 에 unityBuildBase 를 추가하고, docker/40-runtime-config.sh 가 PUBLIC_UNITY_BUILD_BASE 로 주입한다. 런타임 값이 없으면 VITE_UNITY_BUILD_BASE 로 내려간다(로컬/dev fallback·기존 호환 seam). production 정본은 런타임 값이다 — 같은 FE 이미지로 local/dev/demo 에서 base 만 바꾼다.
2. resolver.ts 가 base 를 모듈 로드 시점이 아니라 호출 시점에 읽고, manifest 의 URL 4종을 new URL(relative, base) 로 base 기준 해석한다. 절대 URL 은 그대로 통과. 상대 base(/unity/)는 현재 오리진 기준으로 절대화한다.
3. 해석 함수는 Unity 전용이 아니라 shared 의 Runtime Asset Delivery seam(base + manifest 상대경로 → resolveAssetUrl)으로 두어 향후 boothAssetBase 를 같은 자리에 추가할 수 있게 한다. 이번에 R3F·GLB·에셋 마이그레이션은 하지 않는다. Unity 빌드와 Booth 에셋을 하나의 base 로 결합하지 않는다.

검증: local base / 상대 manifest URL / 절대 URL / 잘못된 base / config 누락 / fallback 각 케이스 단위 테스트, tsc·build·oxlint·vitest 전체.

관련: S15P21A604-82(인프라 서빙), -417(manifest 생성), -254(runtime-config 설계), docs/26 미결 WebGL 정적 서빙 URL.

### 이정헌 · 2026-09-05 17:58 KST

MR !268 develop 병합 완료 (2026-09-05).

Unity 빌드 base URL 을 런타임 주입으로 정본화했다. window.__FESTA_CONFIG__.unityBuildBase(PUBLIC_UNITY_BUILD_BASE) → VITE_UNITY_BUILD_BASE fallback 순이고, 같은 FE 이미지로 local/dev/demo 에서 base 만 바뀐다. manifest.json 의 상대경로 4종은 new URL(relative, base) 로 base 기준 해석한다 — 이전에는 FE 오리진 기준으로 풀려 base 가 다른 오리진·하위 경로면 404 였다(GitLab #128 §4).

해석 함수는 shared/assets/resolveAssetUrl.ts 의 공통 seam 으로 두었다. 향후 Booth 2.5D 에셋 manifest 가 같은 해석을 쓰고, RuntimeAssetConfig 에 boothAssetBase 키를 늘리는 것으로 확장된다. 이번에 R3F·GLB loader·에셋 마이그레이션은 하지 않았고, Unity 빌드와 Booth 에셋은 base 를 공유하지 않는다.

검증: resolveAssetUrl 6건 + resolver 7건(런타임 우선·fallback·상대/절대 URL·오리진 상대 base·잘못된 base·config 누락·manifest 404/키 누락), develop head 기준 tsc 0 · vitest 487/487 · vite build · sh -n 통과. 추가로 FE 컨테이너 이미지를 직접 빌드·기동해 runtime-config.js 주입과 경고 로그를 실측했다(상세는 다음 코멘트).

완료 전환하지 않는 이유: 인프라가 compose 에 PUBLIC_UNITY_BUILD_BASE 를 주입해야 하고(GitLab #127 에 정승욱님 Assignee 로 요청함), 실 Unity WebGL 산출물로의 asset resolve 왕복이 남아 있다. Closes 미사용.
