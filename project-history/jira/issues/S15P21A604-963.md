## 설명

### 작업 목적

Unity 오락실의 오락기에서 기록한 점수를 서버에 저장하고, 오락기별 전 사용자 최고점 TOP 5를 제공한다. (GitLab 이슈 #264)

### 요구사항

- 오락기 식별자는 `machineId`를 사용한다. 게임 파트 초안은 `arcade-01` ~ `arcade-20`.
- 게임 종료 시 로그인 사용자 기준 점수를 등록한다.
- `machineId`별 최고점 상위 5명을 조회한다.
- 동일 사용자는 해당 오락기에서 개인 최고점 1건만 랭킹에 반영한다.
- 더 낮은 점수 재등록 시 기존 최고점을 유지하고, 더 높은 점수만 갱신한다.
- 동점이면 먼저 달성한 기록을 우선한다.
- 응답에는 순위, 사용자 표시명, 최고점, 달성 시각을 포함한다.
- 서버에서 유효한 `machineId`와 점수 범위를 검증한다.
- 클라이언트가 전달한 사용자 ID는 신뢰하지 않고 인증 주체를 사용한다.
- 랭킹 조회 실패가 Unity 게임 진행을 막지 않도록 한다(클라이언트 폴백은 게임/FE 파트 범위).

### API 초안 (GitLab #264 본문)

- `POST /api/arcade/rankings/{machineId}/scores` — body `{ score: number }`, 본인 최고점 등록/갱신
- `GET /api/arcade/rankings/{machineId}?limit=5` — 해당 오락기 전 사용자 TOP 5
- `GET /api/arcade/rankings/{machineId}/me` — 본인 최고점과 현재 순위

### 착수 전 확인 필요

- machineId 체계: 기존 BE 구현(S15P21A604-602, `arcade_machine_bindings`)과 Unity 씬은 `plaza-arcade-01` 형태를 쓴다. #264 본문의 `arcade-01` 과 어느 쪽이 canonical 인지 게임 파트와 확정해야 한다. 유효성 검증 방식(고정 패턴 vs `arcade_machine_bindings` 조회)이 여기서 갈린다.
- 점수 범위 상한: 게임별로 다르면 서버가 무엇을 기준으로 검증할지 정해야 한다.
- 표시명 노출 정책: 비공개/탈퇴 사용자의 랭킹 표기 방식.
- URL prefix: 기존 API 는 `/api/v1/...` 를 쓴다. `/api/arcade/...` 를 그대로 둘지 확인.

### 완료 조건

- [ ] 서로 다른 `machineId` 가 독립된 TOP 5 를 유지한다
- [ ] 6위 이하 기록이 등록돼도 조회 결과는 최대 5명이다
- [ ] 개인 최고점 갱신(더 높은 점수만 반영)이 테스트로 검증된다
- [ ] 동점 시 먼저 달성한 기록이 상위로 정렬된다
- [ ] 비정상 `machineId`·점수 범위 위반이 4xx 로 거절된다
- [ ] 클라이언트가 보낸 userId 가 무시되고 인증 주체가 사용된다
- [ ] 요청/응답 계약이 문서화되어 Unity 연동이 가능하다

### 영향 범위

- Backend API / DB (마이그레이션 1건 — 랭킹 표)
- Unity 오락기 랭킹 UI 연동
- 인증 사용자 식별 및 표시명 노출 정책
