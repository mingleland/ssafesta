## 설명

GitLab #150 대응. festa-ai가 로컬에서 뜨려면 13개 필수 env(JWT_SECRET·REDIS_URL·SPRING_INTERNAL_BASE_URL·INTERNAL_*_TOKENS·R2_*·MINIO_*)가 전부 채워져야 하는데(app/core/config.py 전체 fail-fast), 로컬 실행 레시피가 문서화돼 있지 않아 FE가 AI Chat SSE를 로컬에서 검증할 수 없었다.

확인 결과 이 값들은 실배포 infra secret이 아니라 로컬 self-serve로 채울 수 있다:
- DATABASE_URL/REDIS_URL: 로컬 docker
- R2_*/MINIO_*: 로컬 MinIO 하나로 양쪽 다 충족 (S15P21A604-120 통합테스트 패턴 재사용, S3CompatibleObjectStorage가 endpoint 문자열 구분 안 함)
- JWT_SECRET: backend와 동일 값 공유가 스펙 확정 사항 (app/core/auth.py 문서화 — Spring이 HS512로 서명한 AT를 festa-ai가 같은 키로 검증)
- INTERNAL_AI_TO_SPRING_TOKENS: AI→Spring 방향 실제 사용 중(conversations.py), 로컬 dev 값으로 생성해 backend .env와 동기화 필요
- INTERNAL_SPRING_TO_AI_TOKENS: 역방향(S15P21A604-175) 아직 backend 미구현이라 festa-ai Settings 검증만 통과하면 되는 placeholder

작업 범위: festa-ai/README.md에 로컬 실행 레시피 섹션 추가, 로컬에서 실제 기동·SSE 라운드트립 검증.
