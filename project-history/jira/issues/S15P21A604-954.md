## 설명

World 밖 React 화면의 최종 오류 수용선을 만든다. 지금은 없는 주소·라우트 렌더 오류·lazy chunk 2차 로드 실패가 모두 React Router 기본 영어 화면("Unexpected Application Error! / 404 Not Found / Hey developer")으로 떨어지고, RouterProvider 밖에서 던진 오류는 흰 화면으로 끝난다.

nginx 가 SPA fallback 으로 모든 주소에 index.html 을 200 으로 주므로 없는 주소 판정은 원래부터 FE 라우터만 할 수 있었고, 그 자리가 비어 있었다. preloadRecovery.ts 는 chunk 2차 실패를 "route errorElement 에 맡긴다"고 적어 두었지만 그 errorElement 가 실제로는 없었다 - 계약과 구현이 어긋나 있었다.

변경 범위 (3계층)
1. 없는 주소 -> 제품 404 화면. 기존 14개 라우트를 pathless layout route 의 children 으로 옮기고 끝에 splat 을 둔다. 부모에 path 를 주지 않으므로 기존 URL 문자열은 그대로 산다.
2. 라우트 렌더/로딩 오류 -> pathless 부모의 errorElement 가 받는다. 원인 문자열은 화면에 싣지 않고 console 로만 보낸다.
3. RouterProvider 밖 오류 -> 최외곽 class 경계가 받는다. router·provider·toast·Unity·CSS 파일에 의존하지 않고 inline style 로 그리며, 조작은 브라우저 기본 동작만 쓴다.

화면은 Unity 부팅 게이트(uh-boot-panel)를 재사용한다 - 로고 패널이 떴다가 사라진 자리에 다른 디자인이 나오면 그게 더 고장 나 보인다. 진행 바는 두지 않는다: 게이지는 진행 중의 표시라 오류 화면에서는 거짓말이 된다.

기존 GameRuntimeErrorBoundary 는 그대로 둔다. 오류 경계는 Fatal > Router error > Game runtime 순으로 큰 영역에서 작은 영역으로 중첩된다.

완료 조건
- 없는 주소에서 React Router 기본 영어 화면이 사용자에게 보이지 않는다
- 기존 14개 route path 변경 0건, nginx 변경 0건, Unity/PersistentWorld 구조 변경 0건
- 404 화면 뒤에서 Unity 가 보이거나 입력을 가로채지 않는다
- 3계층 각각의 테스트가 있고 기존 route/auth/game 테스트가 회귀하지 않는다
