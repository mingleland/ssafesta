## 설명

### 작업 목적

게임 파트가 GitLab #134 로 미니게임 API 2종(슬롯머신 스핀, 타이밍 스톱 결과 보고)을 요청했다. 그중 슬롯머신은 받을 수 없다.

- 헌법 28조: 미니게임은 1종만 만든다
- spec 014 FR-009: 미니게임은 1종만 구현한다 (헌법 19조 범위 통제)
- docs/26 결정 기록(2026-08-12): 미니게임 종류는 타이머 정지 게임

슬롯머신에 서버 판정과 코인 지급을 붙이는 것은 미니게임을 2종으로 만드는 범위 확대라서 구현자가 정할 수 없다. 2026-09-07 #134 회신에서 그 사유를 설명하고 docs/26 에 결정 요청으로 올리겠다고 적었으나, 실제로 등록하지 않았다. 리드가 보는 자리에 올라가 있지 않으면 결정이 나지 않는다.

### 작업 내용

docs/26_팀_결정_필요사항.md 상단에 결정 요청 절을 신설한다. 기존 결정 요청 절(월드 채널 다중화, FAILED 문서 원본 삭제 정책)과 같은 형태로 쓴다.

담을 것

- 무엇이 막혀 있는지: 슬롯머신 서버 판정·코인 지급 API
- 왜 구현자가 정할 수 없는지: 헌법 28조, spec 014 FR-009
- 선택지 두 갈래: 2종으로 승인해 FR-009 를 개정할 것인가, 승인하지 않고 체험판 유지로 둘 것인가
- 승인하는 경우 함께 필요한 것: 확률표와 RTP, 일일 한도. Unity Mock 값(낙첨 64 퍼센트, 배수 2가 25 퍼센트, 배수 3이 8 퍼센트, 배수 5가 3 퍼센트, RTP 약 89 퍼센트)은 참고값이며 기획 확정이 필요하다
- 승인하지 않는 경우의 현재 상태: 게임 파트가 서버 우선 클라이언트에 404 폴백을 넣어 두어 체험판 표시로 계속 동작한다

### 완료 조건

- docs/26 에 슬롯머신 결정 요청 절이 있고 선택지와 근거가 적혀 있다
- 결정값 칸이 비어 있어 미결임이 드러난다
- GitLab #134 와 S15P21A604-502 에서 이 절을 찾아갈 수 있다
