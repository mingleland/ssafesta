## 설명

### 작업 목적

Infra의 `infra/deploy/compose/integration/compose.yaml` 이 `FRONT_IMAGE_REF` 로 완성된 FE 이미지를 참조하는데, **그 이미지를 만들 Dockerfile이 없다.** `festa-frontend/` 에 Docker 관련 파일이 하나도 없어 조립 구조가 FE 이미지를 기다리는 상태다.

`docs/17_Git_개발_Convention.md` §2-1 규칙 6이 그 자리를 FE 소관으로 확정했다 — "festa-frontend/Dockerfile.dev 등 파트 디렉터리 내부의 Docker 파일은 그 파트 소관이다."

### 작업 내용

- `festa-frontend/Dockerfile` — 멀티스테이지(base → dev / build → prod)
- `festa-frontend/.dockerignore` — 빌드 컨텍스트가 `festa-frontend/` 라 저장소 루트의 것이 적용되지 않는다
- runtime config 주입 — `PUBLIC_API_BASE_URL` → entrypoint가 `/runtime-config.js` 생성 → `window.__FESTA_CONFIG__` → `shared/` 단일 accessor → 없으면 `VITE_API_BASE_URL` 로 fallback
- nginx SPA fallback(`try_files $uri /index.html`), 80 포트 서빙
- dev 타깃 HMR — `/app/node_modules` 를 container-owned volume 으로 분리해 bind mount 에 가려지지 않게

빌드 산출물 `index.html` 을 직접 치환하지 않는 이유: 치환 실패가 조용히 남고(페이지는 뜨고 API 단계에서야 실패) 재실행마다 원본이 오염된다. 별도 파일 생성은 없으면 `window.__FESTA_CONFIG__` 가 undefined 가 되어 fallback 이 명시적으로 동작한다.

### 완료 조건

- [ ] `docker build --target prod` 성공, nginx `/` 200
- [ ] SPA deep link(`/app/booths`) fallback 200
- [ ] `PUBLIC_API_BASE_URL` 이 `/runtime-config.js` 에 반영된다
- [ ] 동일 이미지를 다른 API URL로 재실행하면 값이 바뀐다 — runtime 주입의 결정적 증거
- [ ] 호스트 `npm run dev` + mock 경로가 그대로 동작한다 (fallback 회귀 없음)
- [ ] dev 타깃에서 소스 수정 시 rebuild 없이 HMR 동작

### 선행 작업 / Dependency

선행 없음. 이 이슈 자체가 S15P21A604-154(Jenkins BE·FE 검증·이미지 빌드 파이프라인)의 선행이다 — `-154` 는 "front 변경 경로별 검증·빌드·이미지 publish" 로 Dockerfile을 호출하는 소비자이고, Dockerfile 작성은 `-154` 범위에 없다.

### 경계

root/integration compose 는 Infra 소유다(GitLab 이슈 #107, docs/17 §2-1 규칙 6). 이 이슈는 `festa-frontend/` 내부만 건드리며 `infra/deploy/compose/**`·root compose·`backend/compose.yaml` 을 수정하지 않는다. 변경이 필요하면 develop행 MR + Infra 리뷰로 제안한다.

### 참고

- 설계 정본: `docs/LJH/27_FE_Docker_설계.md` (front 브랜치, 2026-08-26 확정)
- 소유 경계: `docs/17_Git_개발_Convention.md` §2-1 규칙 6

### 테스트 방법

```
cd festa-frontend
docker build --target prod -t festa-front:local .
docker run --rm -e PUBLIC_API_BASE_URL=http://localhost:8080 -p 3001:80 festa-front:local
curl -s http://localhost:3001/runtime-config.js
curl -s -o /dev/null -w '%{http_code}' http://localhost:3001/app/booths
```

그다음 같은 이미지를 `-e PUBLIC_API_BASE_URL=http://example.test` 로 재실행해 값이 바뀌는지 확인한다.
