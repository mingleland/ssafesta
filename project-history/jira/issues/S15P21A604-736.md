## 설명

### 작업 목적

운영자가 남의 활성 임대를 강제로 회수해 슬롯을 비울 수 있게 한다. 부적절한 부스 콘텐츠 대응·시연 자리 확보·데이터 복구가 쓰임새다.

임차인 본인의 조기 반납은 S15P21A604-735 로 따로 있다. 이 티켓은 **제3자가 남의 임대를 끝내는 경로**라서 권한 판정이 본질이며, 거기서 막혀 있다.

### 착수 불가 사유 — 먼저 결정돼야 한다

develop 에 **전역 관리자 개념이 없다.** `ROLE_ADMIN`·`isAdmin`·`AdminGuard` 검색 결과 0건이고, 권한 판정은 부스 단위 `BoothAccessGuard` 뿐이다. `docs/26_팀_결정_필요사항.md` 의 "admin 권한 모델" 항목(#19, 2026-09-13 등록, S15P21A604-165·-680)이 미확정이라, 누가 admin 인지(사용자 플래그 / 역할 테이블 / 설정 화이트리스트)와 감사 이력 범위가 정해지기 전에는 이 API 를 만들 수 없다. 헌법 30조에 따라 임의로 확정하지 않는다.

**우회안 하나는 있다** — 결정 없이도 열 수 있는 경로로 `/internal/*` 패턴(내부 서비스 토큰, 2026-08-25 GitLab #102 확정)을 쓰는 방법이 있다. 사용자 계정이 아니라 토큰으로 인증하므로 admin 사용자 모델이 필요 없다. 다만 이는 운영 백도어지 관리자 기능이 아니며, 감사 이력에 행위자가 남지 않는다. **채택 여부 자체가 팀 결정 대상이다.**

### 작업 내용 (권한 모델 확정 후)

- admin 판정 지점 하나 (확정된 모델에 따름)
- `BoothLeaseService` 에 강제 회수 진입점 — S15P21A604-735 가 만드는 `release(lease, LeaseStatus)` 를 그대로 재사용한다. 상태 값만 회수용으로 가를지(`REVOKED`) 취소와 합칠지는 구현 시 결정
- 감사 이력 — 누가·언제·어느 임대를·왜 회수했는지
- 코인 처리: 강제 회수는 사용자 변심이 아니므로 D06 의 "변심 환불 없음" 에 걸리지 않는다. `REFUND` 원장 경로가 이미 있으나(`LedgerEntryType.REFUND`), **환불할지 말지는 정책 결정이며 이 티켓에서 임의로 정하지 않는다**
