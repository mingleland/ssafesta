## 설명

## 배경

타이밍 스톱 미니게임 화면이 GitLab #166 / S15P21A604-601 로 FE 오버레이에 이관됐다. Unity 의 `MinigameInteractable` 은 `WORLD_MINIGAME_INTERACT` 송신만 하고, 세션 발급·결과 제출은 FE(`festa-frontend/src/entities/minigame/api.ts`)가 한다. Unity 의 옛 구현은 S15P21A604-624 로 제거됐다.

그 결과 BE 가 소유한 계약 문서와 Javadoc 이 근거로 삼은 "배포된 Unity 클라이언트" 전제가 전부 사실과 다르다. 동작은 바뀌지 않지만, 문서가 없는 소비자를 근거로 규칙을 설명하고 있어 다음 사람이 잘못 읽는다. 특히 MinigameController 의 문장은 `@Operation` description 이라 Swagger 문서로 그대로 노출된다.

## 범위

1. `specs/014-minigame/contracts/minigame-api.yaml` — "배포된 Unity 클라이언트가 보내서 무시한다"(세션 발급·SubmitCommand), "Unity 의 429 분기", "Unity WebGL 의 IMGUI" 근거 문장
2. `backend/src/main/java/com/example/ssafesta/minigame/MinigameController.java` (62, 80행) — 같은 문장이 `@Operation` description 에 들어가 Swagger 에 노출됨
3. `backend/src/main/java/com/example/ssafesta/minigame/TimerStopService.java` (199, 282-285행) — `message` 가 ASCII 인 근거 주석
4. `specs/014-minigame/spec.md` (6행) — 주 담당 `Unity + Backend` → `FE + Backend`
5. `specs/014-minigame/tasks.md` (31행) — T013 "WebGL IMGUI 한글 미표시 또는 React 오버레이 검토" 는 #166 / -601 로 확정됐으므로 닫는다
6. `docs/26_팀_결정_필요사항.md` 슬롯머신 행 — 현재 Mock 실측값 정정(본문의 RTP 89% 는 옛 값, develop 실제는 낙첨 78 / x2 15 / x3 5 / x5 2, RTP 0.55), 제안 확률(x10 @0.8%, RTP 50.4%)의 미정 구간, 계약 응답의 `tier` 대 `outcome` 충돌 경고

## 동작을 바꾸지 않는 것 (의도)

- 결과 제출 요청의 추가 필드 관용(`targetSeconds`·`errorSeconds`·`timedOut`·`gameId` 를 받아만 두고 무시)은 유지한다. 지금은 아무도 보내지 않지만 거부로 바꾸면 호환만 깨지고 얻는 것이 없다.
- `message` 의 ASCII 유지도 그대로다. IMGUI 근거는 사라졌지만 FE 는 `resultCopy.ts` 로 자체 문구를 만들고 서버 `message` 를 쓰지 않는다. 주석의 근거만 "현재 소비자 없음, 로그·디버깅용" 으로 고친다.

## 완료 조건

- 위 6개 파일에서 Unity 소비자 전제가 사라지고 FE 소비자 기준으로 읽힌다
- `/v3/api-docs` 의 미니게임 endpoint 설명에 Unity 관련 문장이 없다
- 기존 미니게임 통합테스트가 그대로 green (동작 변경 없음)
