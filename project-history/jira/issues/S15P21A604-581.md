## 설명

## 작업 목적  Unity 담당자가 QA를 마친 최종 WebGL 전달본을 GitLab Generic Package Registry에 업로드하면, Jenkins가 해당 불변 릴리스를 검증하여 EC2 Nginx 정적 경로에 자동 배포한다. 수동 curl·압축 해제·심볼릭 링크 교체 과정에서 생길 수 있는 누락과 오배포를 제거한다.  ## 작업 내용  - WebGL zip 업로드 성공을 배포 승인 신호로 사용하고 release ID와 SHA-256을 Jenkins에 전달한다. - Jenkins deploy-agent가 read_package_registry 전용 Credential로 지정 릴리스를 다운로드한다. - SHA-256, zip 무결성, 경로 안전성, index.html·manifest.json·Build/·TemplateData/ 구조를 검증한다. - /srv/festa/webgl/releases/<release-id>/에 설치하고 current 심볼릭 링크를 원자적으로 전환한다. - manifest 및 Brotli·MIME·Cache-Control 외부 응답을 확인하고 실패하면 직전 known-good 릴리스를 보존·복구한다. - Secret 원문은 로그·artifact·저장소에 남기지 않는다.  ## 완료 조건  - [ ] 검증된 Package Registry 릴리스만 배포된다. - [ ] 중복 이벤트는 같은 릴리스를 재배포하지 않는다. - [ ] 다운로드·구조·HTTP 검증 실패 시 current가 손상되지 않는다. - [ ] 성공 시 current가 새 릴리스로 원자적으로 전환된다. - [ ] 실패 시 직전 known-good 릴리스로 복구 가능하다. - [ ] Jenkins Credential에는 최소 read_package_registry 권한만 사용한다. - [ ] 자동 배포·수동 롤백 절차와 실환경 검증 결과를 문서화한다.  ## 선행 작업 / Dependency  - GitLab project 1443023의 festa-webgl Generic Package Registry - EC2 Jenkins deploy-agent 및 /srv/festa/webgl/releases 경로 - demo.ssafesta.world/unity/ Nginx 정적 서빙 설정  ## 참고  - specs/infra-001-ci-cd-pipelines/tasks.md T022A~T022F - Jira S15P21A604-574 조사 결과를 구현 경계로 반영  ## 테스트 방법  1. 정상 릴리스를 업로드해 다운로드·검증·current 전환과 외부 응답을 확인한다. 2. 잘못된 해시·구조·manifest 릴리스가 current를 변경하지 않는지 확인한다. 3. post-switch 검증 실패를 강제해 직전 known-good 복구를 확인한다.
