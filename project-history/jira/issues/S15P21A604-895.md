## 설명

GitLab #241 (FE 요청, blocker). 프로젝트 전시 대표 이미지를 URL 직접 입력에서 정식 파일 업로드로 전환한다. FE 는 파일 picker·로컬 preview·uploadProjectLogo(file) 어댑터 경계까지 만들고(S15P21A604-860) 실제 호출은 막아 둔 상태다.

spec 009 C-03 은 "업로드 미지원, URL 참조" 확정이고 "업로드가 필요해지면 #69 규모의 별도 이슈" 라고 적어 두었다 — 그 문을 여는 건이라 계약 개정이 함께 간다.

설계 (게임 Asset 업로드 spec 019 를 본뜬다)

- 저장소는 기존 ObjectStorage(presignPut/headSize/getObject/deleteObject)를 그대로 쓴다. 새 클라이언트를 만들지 않는다.
- 이미지 실검증(magic number + ImageIO 디코드 + 크기·픽셀 상한)은 GameAssetImageValidator 를 공용 위치로 옮겨 game·project 가 함께 의존한다. game 전용 상수는 game 에 남긴다.
- grant 기준은 boothId — 프로젝트 생성 전 업로드 요구가 있고 BoothAccessGuard 가 이미 단일 관문이다.
- 흐름: start(grant 발급) → presigned PUT → complete(바이트 검증, 실패는 200 + status FAILED + errors[].rule) → GET /content 바이트 프록시.
- 키는 업로더가 고른 문자열을 담지 않는다: booths/{boothId}/projects/logos/{logoId}.

업로드 lifecycle 테이블 (project_logo_uploads)

id, booth_id, logo_id(서버 발급, 추측 불가), status(PENDING/READY/FAILED), content_type/byte_size/width/height/sha256(검증 확정값), declared_byte_size, provider/storage_bucket/object_key, failure_rule, created_at/completed_at, expires_at(발급 시점 계산값 — presign-ttl 변경이 이미 발급된 grant 에 소급되지 않게).

읽기 권한 3갈래

- 게시된 프로젝트가 이 로고를 참조 + 유효 임대 → 누구나(permitAll 프록시)
- 그 밖의 READY 로고 → project_logo_uploads.booth_id 의 편집 권한 보유자만 (complete 와 PATCH 사이, PATCH 실패 후 재확인 경로를 덮는다)
- 그 밖 → 404

미참조 객체 정리

- thumbnailUrl 교체·프로젝트 삭제 시 옛 managed logo 를 지연 삭제 후보로 즉시 등록한다(주 경로).
- complete 후 24시간 미참조는 보조 경로: start 시점에 같은 부스의 orphan 까지 sweep + 공용 주기 드레인.
- 주기 드레인은 GameAssetDeleteQueue 에 project 로직을 넣지 않는다. 스케줄 트리거를 공용 영역으로 빼고 도메인별 cleanup 을 호출하거나 큐 자체를 공용으로 승격한다. 새 스케줄 실행 지점은 늘리지 않는다.
- 실제 삭제 직전에 참조를 재확인한다 — A → B → 다시 A 로 되돌린 경우 예약된 A 삭제가 살아 있는 이미지를 지운다.
- 부스당 미참조 READY 로고 개수 상한을 start 에서 검사한다.
- 참조 판정은 canonical parser 한 곳에서 logoId 를 뽑아 쓴다(contains() 산재 금지).

문서

spec 009 C-03 개정, project-api 계약, docs/08.

완료 조건

- start → presigned PUT → complete → /content 왕복이 로컬에서 성립한다.
- 위장 MIME·초과 크기·초과 픽셀이 complete 에서 FAILED 로 거절된다.
- 미게시 프로젝트의 로고를 편집자는 읽고 방문자는 404 를 받는다.
- thumbnailUrl 을 바꾸면 옛 로고가 삭제 후보가 되고, 다시 되돌리면 삭제되지 않는다.
