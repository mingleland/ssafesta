## 설명

### 작업 목적

인원수 제곱으로 늘어나는 동기화 트래픽을 줄인다. 현재 PositionThreshold 0.001(=1mm)은 과민해 정지 상태에서도 갱신이 나갈 수 있다.

### 작업 내용

- PositionThreshold 0.001 → 2~5cm(0.2~0.5 unit) 구간 실측 튜닝 — 월드 스케일 1m=10unit 기준
- RotAngleThreshold 동반 조정
- HalfFloat·쿼터니언 압축 적용 검토
- 외형 FixedString4096 동기화 시점 점검 (변경 시에만 전송되는지)

### 강형순 · 2026-08-29 01:11 KST

MR !102 — https://lab.ssafy.com/s15-metaverse-game-sub1/S15P21A604/-/merge_requests/102

**실측으로 약 25% 절감** (11명 동일 조건, 4,529 → 3,290~3,505 KB/s)

찾은 낭비 두 가지

- 회전 X/Z 동기화가 순수 낭비 — `PlayerMovement` 는 `Quaternion.Euler(0f, next, 0f)` 로 Y축만 돌린다
- 임계값이 사실상 0 — `PositionThreshold: 0.001` 은 1 m = 10 유닛 월드에서 **0.1 mm** 다

```
SyncRotAngleX      1     → 0
SyncRotAngleZ      1     → 0
PositionThreshold  0.001 → 0.05
RotAngleThreshold  0.01  → 1
```

**빗나간 가설도 남긴다** — `UseHalfFloatPrecision` 을 켜면 절반이 될 거라 봤는데 오히려 **16% 늘었다** (3,290 → 3,816 KB/s). NGO 반정밀도는 기준 위치 델타를 보내고 주기적으로 재기준화하는데, 좌표가 수천 유닛까지 가는 이 월드에선 재기준화가 잦아지는 것으로 추정한다. 껐다.

**Closes 는 넣지 않았다** — 1인당 아직 약 300 KB/s 다. 다음 후보인 틱 레이트(30 Hz)·AOI 컬링은 전역 영향이라 팀 판단이 필요해 `docs/26` 영역이다. 이 측정은 한 머신에서 봇을 돌린 값이라 절대치가 아니라 비율만 신뢰한다.

`docs/KHS/28_최적화_기법_정리.md` §8 정리.
