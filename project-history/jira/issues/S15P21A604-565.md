## 설명

## 작업 목적

- 데이터 탭에서 추가한 아이템을 개별적으로 삭제할 수 있게 한다. "+ 아이템"만 있고 삭제 경로가 없어서, 잘못 만들거나 안 쓰는 아이템을 지울 방법이 없었다. (-561 자산 삭제, -562 변수 삭제와 같은 배경에서 나온 후속 작업 — 세 갈래 중 세 번째이자 마지막)

## 작업 내용

- `findItemUsageLocations(project, itemId)` 신설(`publishValidation.ts`) — 자산/변수 때와 달리 **오브젝트 컴포넌트까지 추가로 훑어야 한다**:
   
   - WORLD Scene 오브젝트의 `PICKUP` 컴포넌트(`component.itemId`)
   - WORLD Scene `event.conditions`(`HAS_ITEM`) / `event.actions`(`GIVE_ITEM`, `REMOVE_ITEM`)
   - DIALOGUE Scene 각 노드 선택지의 `choice.conditions`(`HAS_ITEM`) / `choice.actions`(`GIVE_ITEM`, `REMOVE_ITEM`)
   - (참고: `findAssetUsageLocations`가 이미 `project.items`를 순회하지만 그건 "자산 → 그 자산 쓰는 아이템" 방향이라 반대 방향이다. 이번엔 "아이템 → 그 아이템 쓰는 곳" 방향을 새로 만든다)
- `removeItemDefinition(project, itemId)` 신설(`authoringCommands.ts`) — 참조 중인 아이템을 지우면 `validated()`가 던지는지 확인(-561/-562와 동일한 안전망 구조 — 조건/액션 참조는 `ITEM_REFERENCE_NOT_FOUND`로 이미 검증되지만, **오브젝트의 PICKUP 컴포넌트 참조는 스키마 검증이 잡아주는지 별도 확인 필요** — `gameProject.ts`의 `PICKUP_ITEM_NOT_FOUND` 검증 로직 확인)
- `ProjectDataPanel.tsx`의 아이템 목록 각 항목에 삭제 버튼 추가. 클릭 시 `findItemUsageLocations`로 사용 위치를 보여주는 확인 카드를 거친 뒤에만 삭제(-561/-562와 동일한 UX 패턴 재사용)
- `GameStudioShell.tsx`에 `deleteItem(itemId)` 핸들러 추가, `ProjectDataPanel`에 `onDeleteItem` prop으로 연결

## 완료 조건

- [ ] 아이템 목록에서 개별 아이템을 삭제할 수 있다
- [ ] 오브젝트의 PICKUP 컴포넌트, 이벤트/선택지의 조건(`HAS_ITEM`)·액션(`GIVE_ITEM`/`REMOVE_ITEM`) 중 하나라도 참조 중이면 사용 위치를 보여준다
- [ ] 확인 후에만 실제로 삭제된다
- [ ] 삭제 후 저장 → 새로고침해도 삭제 상태가 유지된다
- [ ] 참조 중인 아이템을 억지로 지우려는 경로가 있어도 스키마 검증이 최종적으로 막는다(PICKUP 컴포넌트 참조 포함)

## 선행 작업 / Dependency

- 없음 — 프론트 단독으로 완결 가능(아이템은 `GameProject` 스키마·검증 로직에만 걸려있고, 서버 API 연동 불필요)

## 참고

- 관련 Issue: S15P21A604-561(자산 삭제), S15P21A604-562(변수 삭제) — 세 갈래 중 마지막, 확인 카드 UX 패턴 그대로 재사용
- 참고 구현: `festa-frontend/src/game-studio/studio/ports/publishValidation.ts`의 `findAssetUsageLocations`/`findVariableUsageLocations`(사용 위치 조회 패턴), `festa-frontend/src/game-studio/studio/ui/ProjectDataPanel.tsx`의 삭제 확인 카드(-561/-562에서 구현한 UI 패턴)
- 변수 삭제 때 미정이었던 "참조 중인 걸 지우면 어떻게 되는가"는 -562에서 **차단**(경고 후 확인 없이는 삭제 불가) 방식으로 이미 확정됨 — 아이템도 동일 방침

## 테스트 방법

1. 아이템을 하나 추가한 뒤 삭제 버튼으로 제거되는지, 목록에서 즉시 사라지는지 확인한다.
2. 어떤 오브젝트의 PICKUP 컴포넌트에서 참조 중인 아이템을 삭제 시도했을 때 사용 위치 안내가 뜨는지 확인한다.
3. 어떤 이벤트/대화 선택지의 조건(HAS_ITEM)이나 액션(GIVE_ITEM/REMOVE_ITEM)에서 참조 중인 아이템도 동일하게 확인한다.
4. 취소를 누르면 아무 변화 없이 확인 카드만 닫히는지 확인한다.
5. 삭제 후 저장 → 새로고침해도 삭제 상태가 유지되는지 확인한다.
