## 설명

GitLab #173 (FE 요청, S15P21A604-608 · MR !622 대응) 의 BE 몫. 이벤트 경품 상점의 [설문 참여하기] 가 여는 설문은 부스 설문이 아니라 SSAFESTA 공용 이벤트 설문이다. FE 는 !622 로 develop 에 붙어 있고 서버 조각만 없다.

## 확정된 결정 (GitLab #173, 2026-09-10)

- ④ 운영 조회(/internal/event-surveys/**)는 이번 범위 밖. 후속 순서: 관리자 인증 → 운영 API → UI → 추첨 대상 조회
- 탈퇴 시 응답 hard delete 는 현행 유지, 예외 없음 (docs/26 결정 요청 등재, !629)
- ends_at 은 NULL(무기한). 종료 시각이 확정되면 UPDATE 1건
- surveyKey = SSAFESTA_2026. 용어는 surveyKey 하나
- 문항 텍스트는 아직 받지 못했다 → 설문 행만 시드하고 문항은 기획 텍스트 도착 후 별도 마이그레이션

## 범위 ① 스키마 (Flyway, 번호는 머지 순서로 확정)

- surveys.booth_id DROP NOT NULL, created_by_user_id DROP NOT NULL, survey_key VARCHAR(50) 추가
- CHECK ck_surveys_scope: ((booth_id IS NULL) <> (survey_key IS NULL)) AND (booth_id IS NULL OR created_by_user_id IS NOT NULL) — 부스 설문의 creator 불변조건은 그대로 유지
- CREATE UNIQUE INDEX ux_surveys_key ON surveys(survey_key) WHERE survey_key IS NOT NULL. ux_surveys_booth 는 재생성하지 않는다 (NULL 은 unique 에 걸리지 않음)
- 시드: survey_key 'SSAFESTA_2026', title, status 'OPEN', reward_coin 0, ends_at NULL, booth_id NULL, created_by_user_id NULL
- 엔티티 Survey: boothId·createdByUserId nullable 로, surveyKey 추가, isEvent()

## 범위 ② run 조회

GET /api/v1/event-surveys/{surveyKey}/run — 회원 인증 (게스트 403 MEMBER_ONLY, 무토큰 401)

응답: { surveyKey, surveyId, closed, rewardCoin, memberOnly: true, responded: { responseId, submittedAt } | null, questions } — questions 는 기존 RunView 와 같은 모양. 없는 key 는 404 SURVEY_NOT_FOUND.

## 범위 ③ 제출 — 기존 POST /api/v1/surveys/{surveyId}/responses 재사용

- findBoothIdById 가 NULL 칼럼을 Optional.empty 로 돌려주므로 existsById 로 "설문 없음"과 갈라 404 오판을 막는다
- boothId == null 이면 requireVisitorVisible 과 부스 공유 락을 생략한다 (편집 엔드포인트가 없어 동시 편집이 없다 — 편집기가 생기면 락을 surveys 행으로 옮겨야 한다는 주석을 남긴다)
- 이벤트 설문은 reward_coin 과 무관하게 게스트 403 MEMBER_ONLY
- 중복 참여는 기존 ux_survey_responses_member + 409 SURVEY_ALREADY_RESPONDED 그대로
- 반대 가드: SurveyResultService.requireEditableSurvey 에서 boothId == null 이면 404 SURVEY_NOT_FOUND (지금은 findById(null) 로 500)
