## 설명

BE 가 S15P21A604-756 / !890 으로 PUT /api/v1/booths/{boothId}/facade 요청에 name(1~100자)을 더했다. 지금까지 부스 이름은 첫 임대 때 만들어진 기본값에서 바꿀 방법이 없어 모든 부스가 같은 이름이었다.

두 축을 한 MR 로 묶는다 — 둘 다 FacadePanel 의 같은 mutation onSuccess 를 고친다.

1. 이름 편집
- 응답은 facade 4필드 그대로라 name 을 form(BoothFacade) 과 별도 state 로 둔다. setForm(result) 가 name 을 undefined 로 날리는 사고가 구조적으로 불가능해진다.
- 입력 정규화는 FE 가 담당한다 — 앞뒤 공백 제거, trim 후 비었거나 최초값과 같으면 name 키를 보내지 않는다(계약상 생략 = 현재 이름 유지). 공백만 있는 이름이 BE 1자 검증을 통과할 수 있는 것이 이 정책의 근거다. #171 에 명시 통보하고, BE 가 서버 정규화를 택하면 FE 쪽을 걷는다.

2. facade 저장 후 월드 즉시 반영
- 지금 signText·대표색도 저장 후 월드에 반영되지 않는다. 이름만 특별 처리하지 않고 facade mutation 성공 전체가 한 번 갱신한다.
- 정본 경로 재사용: notifyBoothSlotChanged → Unity BoothLayoutBridge → WorldBoothPublishedBootstrap.RequestReload → BoothSlotDirectory.Invalidate + BoothSignPresenter/BoothFacadePresenter.Refresh.
- boothLayoutBridge.ts 상단의 facade 저장은 보내도 아무 일이 없다는 주석은 S15P21A604-659 이후 틀렸다 — 같은 MR 에서 정정한다.
- usePublish 가 이미 쓰는 slotId 조회 한 줄을 공용 helper 로 추출해 두 곳이 같이 쓴다.

Unity 변경 0 — BoothLayoutBridge 가 BoothLiveSyncNetwork.Announce 로 월드 전체에 중계한다(S15P21A604-730).

완료 조건
- 단위 테스트: 4필드 응답이 name 을 지우지 않음 / 공백만·변경없음이면 name 키 미전송 / errors[].field=name 이 입력칸 아래 표시 / 저장 성공이 슬롯 알림을 한 번 호출 / my-booth 캐시에 slotId 가 없어도 저장 성공
- demo acceptance (다른 접속자 화면의 간판 즉시 갱신)는 별도 — MR 병합만으로 닫지 않는다
