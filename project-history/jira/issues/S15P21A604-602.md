## 설명

### 작업 목적

게임 전용 부스에 놓인 오락기가 어떤 Published 게임을 실행하는지 서버가 매 요청 판정해 FE 에 내려준다. Unity 는 씬이 정한 canonical `machineId` 만 알고 `gameId` 를 모른다 (spec 019 FR-017).

### 배경 — 2026-09-10 배치 확정

- 관리자 제작 미니게임(타이밍 스톱·슬롯머신·하이 스트라이커)은 Unity 씬에 조형물로 고정 배치한다.
- 사용자가 Game Studio 에서 만든 게임은 게임 전용 부스에서 플레이한다. 이 부스는 월드 고정물이며 임대 부스가 아니다.
- 오락기 1대 = 게임 1개 고정 바인딩. GitLab #56 ⓒ(큐레이션 방식)가 이 결정으로 닫힌다.
- 부스 내부 GAME_PORTAL 경로(configId)는 보류를 유지한다. S15P21A604-158 과 -204 는 닫지 않는다.

### 작업 내용

- machineId → gameId 고정 바인딩 저장. 마이그레이션 1건이고 v1 은 운영자 시드 데이터로 채운다(관리자 UI 는 범위 밖).
- GET /api/v1/arcade-machines/{machineId} 구현. Cache-Control: no-store 이고 공개 상태는 매 요청 서버가 판정한다.
- 응답 필드: machineId, gameId, publishedVersion, playable, unavailableReason.
- unavailableReason 어휘는 게임 공개 상태만 다룬다 — GAME_NOT_PUBLISHED, GAME_NOT_PUBLIC, GAME_DELETED. 임대 관련 코드(BOOTH_LEASE_EXPIRED)는 쓰지 않고 응답에 boothId 도 넣지 않는다. 월드 고정물이라 임대·소유권 판정이 없다.
- 없는 machineId 는 404 MACHINE_NOT_FOUND.
- 게스트도 호출할 수 있다 (FR-023 — Published 게임 플레이는 게스트 몫이기도 하다).

### 완료 조건

- [ ] 바인딩된 machineId 조회가 gameId 와 publishedVersion 을 돌려준다
- [ ] 미공개·비공개·삭제된 게임은 playable=false 와 해당 unavailableReason 을 돌려준다
- [ ] 없는 machineId 는 404 MACHINE_NOT_FOUND
- [ ] 응답에 Cache-Control: no-store 헤더가 있다
- [ ] 게스트 토큰으로 200 을 받는다

### 선행 작업 / Dependency

- 선행 없음. GitLab #56 안 1 로 3파트 합의가 끝났고 큐레이션 방식은 2026-09-10 배치 결정으로 닫혔다.
- 관련(보류 유지): S15P21A604-158, S15P21A604-204 (부스 내부 GAME_PORTAL 경로), S15P21A604-108 (Published 게임 유료 입장)
- 대기 중인 소비자: FE dispatcher 의 WORLD_ARCADE_INTERACT 수신부는 이 API 확정을 선행 조건으로 보류 중이다(GitLab #135). Unity 는 이미 이벤트를 송신하고 있다.
- machineId 실값과 대수는 게임 파트가 오락기를 게임 전용 부스에 배치한 뒤 통보한다. 현재 씬 값은 plaza-arcade-01 과 plaza-arcade-02 다. 바인딩 행은 값이 확정된 뒤 채우고, API 구현은 그것을 기다리지 않는다.

### 테스트 방법

1. 서로 다른 게임이 바인딩된 machineId 2대를 조회해 gameId 가 다르게 나오는지 확인한다.
2. 바인딩된 게임을 비공개로 바꾼 뒤 재조회해 playable=false 와 GAME_NOT_PUBLIC 을 확인한다.
3. 없는 machineId 로 호출해 404 MACHINE_NOT_FOUND 를 확인한다.
4. 게스트 토큰으로 호출해 200 을 확인한다.
