## 배경

infra-002 T015 가 Redis 의 default 사용자를 비활성화하고 ACL 로 dev_back / dev_ai / demo_back / demo_ai 를 분리한다. 그래서 Backend 는 REDIS_USERNAME 과 REDIS_PASSWORD 로 반드시 인증해야 한다 (GitLab #123, #117).

주입 자리는 S15P21A604-347 에서 이미 만들어 두었다 (application.yml 의 spring.data.redis.username / password). 문제는 그 두 값의 기본값이 빈 문자열이라는 점이다. 로컬 무인증 Redis 를 위해 의도한 기본값이지만, 배포에서 주입을 빠뜨리면 다음 순서로 실패한다.

1. Lettuce 는 지연 연결이라 애플리케이션 기동은 성공한다.
2. 첫 Redis 사용(로그인, Refresh, 일일 코인 지급) 시점에 NOAUTH / WRONGPASS 로 실패한다.
3. Actuator 의 Redis health 가 DOWN 이 되어 컨테이너는 unhealthy 로 표시되지만, management 설정이 없어 기본값이 show-details=never 다. health 본문은 상태 한 줄뿐이고 원인은 로그에 묻힌다.

즉 "떠 있는데 로그인만 안 되는" 상태로 배포가 통과한다. AUTH_COOKIE_SECURE 와 FESTA_ENVIRONMENT 에 이미 적용한 fail-fast 원칙을 같은 이유로 여기에도 적용한다.

## 변경 범위

- application-infra.yml 에 spring.data.redis.username / password 를 기본값 없이 선언한다. infra 프로파일에서만 필수가 되고, 로컬은 application.yml 의 빈 기본값을 그대로 쓴다.
- SharedConfigProfileTest 의 DEPLOY_ENV 배열에 REDIS_USERNAME / REDIS_PASSWORD 를 추가한다. 이 배열이 배포 주입 목록의 실행 가능한 정본이다.
- 누락 테스트를 하나 추가한다. missingCookieSecureDoesNotFallBackToTheLocalDefault 와 같은 모양으로, REDIS_PASSWORD 를 뺀 환경이 조용히 빈 값으로 해석되지 않는 것을 고정한다.

## 검증

- SharedConfigProfileTest 통과 (infra 프로파일이 모든 설정을 해석하고, REDIS_PASSWORD 누락은 시끄럽게 실패한다)
- 로컬 무인증 Redis 로 기존 기동 경로에 회귀가 없는지 확인

## 주의

자격증명 값 자체는 저장소, Jira, GitLab 이슈, 문서 어디에도 남기지 않는다 (헌법 15조). 값은 Jenkins Secret File 경로로만 주입되며 이 티켓은 키 이름만 다룬다.
