### 황덕 · 2026-09-13 19:49 KST

**이 티켓은 성립하지 않습니다. 닫아 주세요.**

작업 내용이 "provider unlink 호출·실패 재시도 멱등" 인데, **호출할 수단이 없습니다.**

`oauth_identities` 가 담는 것은 `provider` 와 `provider_subject` 둘뿐입니다. provider access·refresh 토큰을 저장하지 않습니다.

- **Google** `oauth2/revoke` 는 그 사용자의 토큰을 요구합니다 → 서버 단독 불가
- **Kakao** `user/unlink` 는 사용자 토큰 또는 admin key + `target_id` → 서버 단독 가능

두 provider 가 비대칭입니다.

**결정 (2026-09-13, 백엔드 파트 자체 확정, docs/26)**: **해제하지 않고 안내합니다.**

남겨지는 것이 무엇인지 따져보면 분명합니다. 연결이 남는다는 건 "이 앱이 내 프로필을 볼 권한" 이 살아 있다는 뜻인데, 탈퇴 시점에 그 사람 데이터는 **이미 전부 지웠습니다.** 실질 영향은 "재가입 시 동의 화면 없이 로그인된다" 정도입니다.

반대 선택지의 대가가 더 큽니다.

| 선택 | 대가 |
|---|---|
| 로그인 때 provider 토큰 저장 | 작은 문제를 풀려고 **전 회원의 제3자 토큰을 상주**시킵니다. 유출 시 피해가 우리 밖(남의 Google 계정)으로 나갑니다 |
| 탈퇴 때 재인증 | **탈퇴가 막힐 수 있습니다** — provider 세션이 끊긴 사람은 탈퇴를 못 합니다 |
| Kakao 만 해제 | 두 provider 동작이 갈려 설명·유지보수 비용만 늡니다 |

**남는 일은 BE 가 아닙니다.**

- 개인정보 처리방침에 "소셜 계정 연동 해제는 각 서비스의 계정 설정에서 직접 해제해 주세요" 한 줄
- 탈퇴 완료 화면의 해제 링크 (FE)

선행 티켓 S15P21A604-150 은 MR !781 로 머지됐습니다. 나머지 세 자원(Redis 세션·객체 저장소 바이트·벡터)은 이미 정리되고 있었고 거기서 테스트로 고정했습니다.
