## 설명

S15P21A604-470 (D-05 R3F Spike) 은 PASS_CANDIDATE 로 끝났다 — 정식 채택 확정이 아니다. 그 Spike 가 증명한 것은 "R3F 가 돌아간다" 까지고, 이번에 증명할 것은 "Unity 가 실제로 쓰는 모델이 React/R3F 화면에 제대로 들어온다" 다.

[범위 — 대표 2종만]
BoothObjectRegistry.asset 이 타입 10종 + GamePortal 을 prefab 11개로 이미 매핑하고 있다. 그 중 2종만 먼저 반입한다. 전 타입 일괄 변환 금지.

[착수 전 실측 — 대표 선정 근거]
three 의 FBXLoader 로 Node 에서 직접 파싱해 치수를 재 봤다.
- DisplayBox01.FBX  bbox +-11.811 x +-11.811 x 63.327 (Z-up)
- Chair01.FBX       bbox +-7.428 x +-7.428 x 17.717
- Counter01.FBX     bbox +-11.525 x -5.53~5.471 x 35.433

단위는 inch 다. 0.0254 를 곱하면 DisplayBox01 은 +-0.3 x +-0.3 x 1.608 이 되고, 이것은 계약의 OBJECT_LOCAL_BOUNDS.DECORATION (+-0.3, max.y 1.61) 과 정확히 일치한다. Z-up → Y-up 변환이 필요하다는 것도 같은 측정에서 나왔다(프리팩도 x -90도로 누워 쓴다).

그래서 대표 2종을 이렇게 잡는다:
1. DECORATION <- DisplayBox01.FBX — 계약 AABB 와 치수가 정확히 맞아 스케일/축/피벗 정규화가 맞는지를 숫자로 판정할 수 있는 유일한 후보
2. FURNITURE <- Chair01.FBX — 의자

SURVEY_KIOSK 는 이번에 넣지 않는다. 프리팩을 열어 보니 단일 메시가 아니라 Counter01.prefab + Tablet.prefab 의 조립체고, Counter01 은 다시 4개 FBX 를 참조하는 중첩 prefab 이다. 즉 "prefab 정적 조합" 은 별도 단계(스파이크 문서의 P3)다. 단일 메시 경로를 먼저 닫고 조립체는 그 다음에 본다.

[파이프라인]
Unity 원본 FBX -> 빌드 시 GLB 변환 -> FE manifest -> R3F 로드.

변환기는 외부 도구 없이 돌린다 — Blender·FBX2glTF·assimp 는 이 장비에 설치돼 있지 않고, three 가 FBXLoader 와 GLTFExporter 를 이미 갖고 있다. 실제로 DisplayBox01.FBX(52KB) -> GLB 25.7KB 변환이 Node 에서 성공하는 것까지 확인했다(FileReader shim 1개 필요).

지오메트리만 가져온다. 텍스처는 범위 밖이고, 사용 재질의 원본 합이 ~24MB 라 그대로는 웹에 올릴 수 도 없다.

[라이선스 — 이번에 넘지 않는 선]
3D 에셋이 전부 벤더팩이다(ExpoKit·ithappy·Synty·Rukha93, 라이선스 파일 0건). 벤더 에셋 웹 재배포 확인 전에는 전체 반입도 정적 배포도 하지 않는다. 따라서 이번 라운드는 GLB 바이너리를 저장소에 커밋하지 않는다 — 변환 스크립트·manifest·로더 코드만 올리고 산출물은 로컬 생성물로 둔다.

[검증 항목]
1. 스케일 — GLB bbox 가 OBJECT_LOCAL_BOUNDS 와 일치하는가 (오차 숫자로)
2. 축 — Z-up 원본이 Y-up 으로 바로 서는가
3. 피벗 — 바닥(min.y=0) 중앙에 오는가
4. 회전 — rotationY 가 계약대로 먹는가 (0 = +Z 정면)
5. 선택 — 박스를 실모델로 바꿔도 픽킹이 동작하는가
6. bounds — 이탈 판정이 예전과 같은가 (판정은 계약 AABB 기준이지 메시 기준이 아니다)
7. 성능 — 청크 크기·로드 시간·heap·프레임
8. 시각 — BoxGeometry 대비 무엇이 달라졌는가
9. 실패 처리 — manifest 에 없거나 로드가 실패하면 조용히 기본값으로 되돌아가지 않고 로그+상태로 드러낸다(T-24 교훈)

[범위 밖]
전 타입 변환 / 텍스처 반입 / prefab 조립체(P3) / AiAgent 스킨드 메시 / 정적 배포 / Unity 신규 작업 / Shell·Inspector 재설계

[품질 게이트]
npm run build / vitest / tsc / oxlint 전부 green. npm run build 를 배포 게이트로 반드시 포함한다(S15P21A604-469 교훈).
