## 설명

## 작업 목적

- 아바타 파츠의 보유 개념을 도입하고 품목별 보유 여부를 제공한다.
- 미보유 파츠를 포함한 아바타 저장 요청을 서버에서 차단한다.

## 작업 내용

- `catalog_items`에 Unity 실측 기준 아바타 판매 단위 97종을 seed한다.
- 카탈로그+보유 여부 조회 및 구매 REST API를 구현한다.
- 구매 시 코인 차감과 인벤토리 지급을 단일 트랜잭션으로 처리한다.
- `avatar_code`의 `i=` 8슬롯을 서버에서 파싱해 미보유 착용을 검증한다.
- spec 012·013 및 팀 결정 문서에 C-06 변경을 반영한다.

## 완료 조건

- [ ] 카탈로그 97종과 무료 12종의 보유 판정이 검증된다.
- [ ] 구매 성공·잔액 부족·중복 구매·판매 중지·게스트 거부가 검증된다.
- [ ] 미보유 파츠 저장은 거부되고 보유 파츠 및 preset 저장은 통과한다.
- [ ] 기존 아바타 저장 API 회귀 테스트를 통과한다.
- [ ] 관련 문서와 작업일지가 갱신된다.

## Unity · FE 연동 통보

`origin/develop` 기준 작업 브랜치 `feat/S15P21A604-378-avatar-item-ownership`에서 spec 012·013 연동 구현과 계약 문서 정합화를 완료했습니다.

- 조회: `GET /api/v1/catalog/items?type=AVATAR_PART`
   
   - 97개 판매 단위를 한 번에 반환하며 각 항목에 `owned`가 포함됩니다.
   - Unity 기본 12종(`price=0`)은 회원·게스트 모두 자동 보유입니다.
   - Unity 판매 키는 비모자 `itemId` 94개, 모자는 `familyId` 3개(`1001`·`1002`·`1003`)입니다.
- 구매: `POST /api/v1/catalog/items/{itemId}/purchases`
   
   - 회원 전용이며 코인 차감과 인벤토리 지급이 한 트랜잭션입니다.
   - 무료/기보유는 `ITEM_ALREADY_OWNED`, 판매 중지는 `ITEM_NOT_ON_SALE`, 잔액 부족은 기존 `INSUFFICIENT_COIN`입니다.
- 착용 저장: 기존 `PUT /api/v1/users/me/avatar` payload는 변경하지 않았습니다.
   
   - Spring이 `fa|` 형식의 `i=` 8슬롯만 읽어 미보유 파츠를 `AVATAR_ITEM_NOT_OWNED`(409)로 거부합니다.
   - 누락된 키는 `errors[].objectId`에 담깁니다.
   - preset·legacy·형식 불일치는 호환을 위해 계속 통과합니다.
- 결정 변경: spec 013 C-06의 “MVP 전체 개방”을 폐기하고 구매·보유 및 미보유 착용 차단을 도입했습니다. `docs/26_팀_결정_필요사항.md`, spec 012·013, `docs/08`에 반영했습니다.

Unity `CharacterLobby`는 조회 결과의 `owned`로 팔레트 잠금/구매 진입을 연결하면 됩니다. FE도 동일 REST를 사용할 수 있습니다. 최종 검증은 58개 스위트 / 562개 테스트 / 실패·오류·스킵 0입니다. 유료 85종의 100코인은 기획 확정 전 placeholder입니다.
