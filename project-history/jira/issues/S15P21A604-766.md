## 설명

### 작업 목적

`!824`에서 back-test 가 green 에서 red 로 바뀌었는데 **실패한 테스트 이름을 CI 안에서 볼 수 없다.** FE가 GitLab #190에서 추적하다 거기서 멈췄다.

```
job 로그      Job's log exceeded limit of 4194304 bytes → 수집 중단
기록된 범위   backend 테스트 클래스 120개 중 53개까지
성공 런도 동일  527282 도 같은 지점에서 잘렸다 (실패 런만의 문제가 아니다)
artifact     back-test 는 job.log 하나뿐
test_report  pipelines/192300/test_report → test_suites: [] (빈 결과)
```

`ci/test` 의 ai 분기는 `--junitxml="${CI_ARTIFACT_DIR}/tests.xml"` 로 리포트를 남기는데 back 분기는 `./mvnw test` 만 돌고 아무것도 내보내지 않는다. surefire 가 만든 `target/surefire-reports/` 가 잡이 끝나면 사라진다.

**원인 규명이 아니라 관측 수단이 없는 상태다.** back-test 가 실패할 때마다 같은 벽에 부딪힌다.

### 작업 내용

**1. 리포트 artifact 화**

- `ci/test` 의 back 분기에서 surefire 결과를 `${CI_ARTIFACT_DIR}` 로 복사
- `.gitlab-ci.yml` 의 back-test 잡에 `artifacts:reports:junit` 추가

로그가 4MB 에서 잘려도 실패 테스트 이름이 MR 화면에 그대로 뜬다. ai 분기에 이미 같은 형태가 있다.

**2. **`!824` 재현 확인

back-test 를 재실행해 재현되는지 본다. 재현되지 않으면 간헐 실패로 확정되고 `!824` 는 그대로 병합 가능하다. FE 가 자기 MR 이 아니라 재실행하지 않았다.

**3. 별도 MR 로 분리한다**

이 변경은 `!824` 와 같은 파일(`ci/test`)을 건드리지만 `!824` 에 얹지 않는다. `!824` 의 front-test 는 이미 success 라 그 성과를 다시 위험에 두지 않는 편이 낫다.

### 참고 관측 (FE, GitLab #190)

```

러너 둘 다 festa-ec2-docker-runner / failure_reason=script_failure (타임아웃 아님)
```

두 sha 사이의 유일한 차이는 `eb1b473d`(S15P21A604-695)인데, develop HEAD 를 로컬에서 돌리면 `Tests run: 1368, Failures: 0, Errors: 0` 로 전수 통과한다. 결정론적 BE 회귀는 재현되지 않았고 CI 환경·간헐 실패 쪽이 더 유력하다(#167·#168 과 같은 축). 실행 시간이 로컬 183초 / CI green 330초 / CI red 571초로 벌어진 것도 자원 경합을 가리킨다. **단정하지 않는다.**

곁가지: `ci/test` 가 `TESTCONTAINERS_RYUK_DISABLED=true` 로 도는데 공유 EC2 러너에서는 잡이 중단될 때 컨테이너가 남을 수 있다. 자원 경합 가설과 이어지는 지점이라 적어 둔다 (실측 없음).
