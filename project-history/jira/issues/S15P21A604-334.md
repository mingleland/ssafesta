## 설명

### 증상

캐릭터 로비에서 **옷을 갈아입으면 이전 조립본이 지워지지 않고 겹친다.** 겹친 메시가 z-파이팅하며 옷 위에 **검은 반점**이 생기고, 갈아입을수록 렌더러 수가 계속 늘어난다.

배포(릴리즈) WebGL 빌드에서 **실사용자 경로 그대로** 관측했다 — 상의를 "없음" 으로 바꿨다가 "링거 티셔츠" 로 되돌리자 가슴에 검은 반점 두 개와 어깨·넥라인에 검은 자국이 나타났다.

### 실측 — 정식 `CharacterLobbyController.Apply()` 한 번에 중복이 생긴다

에디터, 깨끗한 플레이 세션:

|  | 조작 전 | 상의 1회 변경 후 |
|---|---|---|
| 전체 SkinnedMeshRenderer | 20 | **26** |
| 머리(long/bangs) | 1 | **2** |
| 얼굴(F_head) | 1 | **2** |

**한 번 갈아입었을 뿐인데 머리·얼굴이 두 벌이 된다.** 반복하면 계속 쌓인다 — Apply 5회 후에는 머리 5벌·얼굴 5개였고, 병합 바디 정점 수가 **1784 → 4357 → 7925** 로 증가했다(누적된 중복을 계속 흡수한다).

### 스킨메시 병합과는 무관하다

같은 순서를 **병합 ON / OFF 로 각각** 태웠고 **둘 다 동일하게 검은 반점이 나온다.**
→ S15P21A604-258(병합 게이트 해제)의 결함이 아니다. 병합은 이 결함을 **드러내 보이게** 할 뿐이다.

### 원인 지목 (미확정)

`AvatarAssembler.Apply()` 는 성별이 바뀔 때만 `BuildBody()` 를 부르고, `BuildBody()` 만이 자식을 파괴한다:

```csharp
bool rebuild = !_animator || _config.gender != config.gender;
if (rebuild) BuildBody();      // 여기서만 foreach (Transform child in transform) Destroy(...)
foreach (...) Equip(c);
```

같은 성별에서 옷만 바꾸면 `BuildBody()` 가 돌지 않으므로 `Equip()` 이 이전 파츠를 치우는 책임을 진다. 거기서 정리가 누락된 것으로 보이나 **확정하지 않았다** — 플레이 모드의 `Destroy` 지연(T-228)이 얽혀 있을 수 있다.

### 영향

- **시각** — spec 013 **FR-018**("옷 착용 시 가려지는 신체 부위가 노출되지 않아야 한다") 위반. 시연에서 바로 보인다
- **성능** — 아바타당 렌더러가 옷 변경 횟수만큼 늘어난다. S15P21A604-236 에서 확정한 "아바타당 7 렌더러" 가 **로비를 거친 사용자에게는 성립하지 않는다**
- **월드 전파** — 로비에서 만든 외형이 월드로 넘어가므로 원격 아바타 비용에도 영향 가능 (미확인)

MR !142 로 develop 반영. **다만 이 이슈를 열 때 내가 적은 판정 두 개가 틀렸다. 먼저 정정한다.**

**❌ "옷을 갈아입을 때마다 렌더러가 누적된다 (20 → 26)" — 아니다.** 그 값은 **에디터가 포커스를 잃어 플레이 프레임이 멈춘 상태**에서 잰 것이다. `Time.frameCount` 가 Apply 전후 모두 **38** 이었다 — 프레임이 안 넘어가니 `Destroy` 가 처리되지 않았고, **파괴 대기 중인 오브젝트를 실재로 센 것**이다. `Application.runInBackground = true` 로 프레임을 돌리자(38 → 3416) **중복은 사라졌다. 누적은 없다.**

**❌ "스킨메시 병합과는 무관하다 (ON/OFF 둘 다 발생)" — 아니다.** `CombineSameMaterialParts` 가 **꺼져 있으면 정리보다 먼저 **`return` 해서, F10 으로 끈 상태에도 **옛 병합체가 그대로 살아 있었다.** 내가 "병합 OFF" 라고 부른 상태는 OFF 가 아니었다. 성별을 왕복시켜 `BuildBody()` 로 전체 재구축한 **진짜 OFF** 에서 다시 재니 **얼룩이 없다. 병합이 원인이 맞다.**

---

**✅ 실제 원인.** 플레이 모드의 `Destroy` 는 프레임 끝까지 미뤄진다. `CombineSameMaterialParts` 가 후보를 고를 때 **직전에 파괴를 건 옛 병합체가 아직 살아 있고 **`enabled` 인데 `_merged` 목록은 그 직전에 비워져 걸러지지도 않는다 → **새 병합이 옛 병합체를 통째로 삼킨다.** 거기 구워져 있던 속옷 형상이 새 메시에 영구히 남아 셔츠를 뚫고 나왔다.
