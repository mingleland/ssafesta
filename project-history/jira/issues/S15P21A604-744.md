## 설명

# 작업 목적

FE(`gameProject.ts` TS 손코딩 검증)와 BE(`game-project-v1.schema.json` + `GameProjectValidator.java`)가 독립적으로 유지하는 GameProject 계약이 실제로 정확히 일치하는지 전수 검증한다.

# 배경

숫자 상한(scene·object·event·asset 개수 등)은 이번에 전수 대조한 결과 지금은 FE·BE가 정확히 일치한다. 하지만 `additionalProperties: false`로 막아둔 객체 형태는 FE `recordAt(...)` 호출이 34곳인데, 이 중 실제로 BE와 맞대본 적이 있는 건 `assetReference` 하나뿐이었고 그마저 의도적 검증이 아니라 S15P21A604-708에서 실제 업로드를 저장하다 `label` 필드 누락으로 우연히 걸린 것이었다. 나머지 33곳은 한 번도 실제 요청으로 대조되지 않았다.

추가로 JSON 크기 상한(2,000,000바이트)은 FE(`estimateGameProjectJsonBytes`, 브라우저 `JSON.stringify`)와 BE(`GameProjectJson.write`, Jackson 재직렬화)가 서로 다른 직렬화기로 잰다. 같은 "2,000,000"이라는 숫자를 쓰지만, 두 직렬화기가 정확히 경계값에서 같은 바이트 수를 낸다는 보장은 없다.

# 작업 내용

1. FE `recordAt` 호출 34곳의 허용 필드 목록과 BE 스키마 `$defs`의 `properties` 키 목록을 객체 타입별로 전수 diff
2. 숫자 상한 9종(scene 50 · scene당 object 500 · scene당 event 300 · scene당 tileLayer 10 · tileLayer 데이터 10,000칸 · asset 300 · variable 100 · item 100 · dialogue node 300) 각각 "정확히 상한" / "상한+1" 경계에서 FE·BE 판정 대조
3. JSON 크기 상한을 FE·BE 두 직렬화기 기준으로 실측해 실제 교차점이 같은지 확인
4. 발견된 불일치를 기록하고 즉시 수정 대상과 팀 판단 필요 대상을 구분

# 완료 조건

- [ ] FE `recordAt` 34곳과 BE 스키마 `properties`가 객체 타입별로 전부 diff되어 불일치 여부가 기록됨
- [ ] 숫자 상한 9종 전부 "상한/상한+1" 경계에서 FE·BE 판정 일치 확인
- [ ] JSON 크기 상한의 FE·BE 직렬화기 차이가 실제 accept/reject를 뒤집는지 확인
- [ ] 발견된 불일치 각각에 대해 즉시 수정 여부/후속 티켓 필요 여부 판단

# 선행 작업 / Dependency

- 없음. 검증 자체가 목적이라 FE 단독으로 진행 가능하다. 드리프트가 새로 발견되면(label 케이스처럼) 어느 쪽을 정본으로 맞출지는 그때 결정한다.

# 참고

- `festa-frontend/src/game-studio/contracts/gameProject.ts` (FE 검증기, `GAME_PROJECT_LIMITS`, `recordAt` 호출부)
- `backend/src/main/resources/game/game-project-v1.schema.json`, `GameProjectValidator.java`, `GameProjectJson.java`(`MAX_PROJECT_BYTES`, `utf8Size`)
- S15P21A604-708 (동일 클래스의 실제 드리프트 사례 — `assetReference.label` 필드 누락)

# 테스트 방법

1. `recordAt(...)` 34곳을 추출해 표로 정리하고 BE 스키마 `properties`와 나란히 대조
2. 브라우저 콘솔에서 `createStarterProject` 기반 프로젝트를 조작해 상한 9종을 "정확히 상한"/"상한+1"로 맞춰 `PUT /draft`에 직접 요청, FE 로컬 검증과 BE 응답을 나란히 기록
3. 2,000,000바이트 근처 프로젝트를 만들어 FE 추정치·BE 실측치·실제 accept/reject 여부를 대조 (필요시 1바이트 단위로 좁혀 교차점 확인)
4. 발견된 불일치 전부 기록, 즉시 수정 여부 판단
