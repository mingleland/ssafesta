## 설명

## 증상

월드 → 로비 → 월드 왕복 후 접속이 실패하고 콘솔에 아래가 뜬다.

```
InvalidOperationException: Only one ConnectionApprovalCallback can be registered at a time.
  NetworkManager.cs:703
```

접속이 실패하면 플레이어가 스폰되지 않고, `PlayerCameraFollow` 가 따라갈 대상이 없어 **씬에 저장된 **`Main Camera`(-92, 18, 0) 가 그대로 보인다. 그 자리는 축제 통로 안이라 나무 벽·자갈 바닥 화면이 뜬다 — 사용자가 본 화면이 이것이다. 렌더로 픽셀 단위 일치 확인함.

## 원인

`@Network`(NetworkManager + ConnectionManager + NetworkBootstrap + DevConnectionHud)가 `main.unity` 에 들어 있는데, `NetworkManager` 는 `DontDestroyOnLoad` 로 살아남는다. 그래서 `main` 을 다시 로드할 때마다 씬이 **새 **`@Network` 를 또 만들고, 그것이 중복 제거되지 않고 누적된다.

실측 (main 을 3회 로드):

```
ConnectionManager 개수 = 3
  - @Network 씬=DontDestroyOnLoad id=485148
  - @Network 씬=DontDestroyOnLoad id=530566
  - @Network 씬=DontDestroyOnLoad id=545536
DevConnectionHud 개수 = 3
NetworkBootstrap 개수 = 3
NM IsClient=False IsConnected=False
활성 카메라 = Main Camera pos=(-92.00, 18.00, 0.00)   ← 축제 통로
```

중복 인스턴스의 `ConnectionManager.Start()` 가 살아 있는 싱글턴에 `ConnectionApprovalCallback += ApprovalCheck` 를 시도해 예외가 나고, 그 지점에서 `Start()` 가 중단된다. 중복된 `DevConnectionHud.Start()` 는 `ConsumeWorldConnectionRequest()` 로 자동 접속 요청을 **먼저 소비해버린다** — 곧 죽거나 반쯤 초기화된 인스턴스가 접속을 가져가는 셈이다.

## 재현

1. `main` 에서 Play
2. `SceneManager.LoadScene("CharacterLobby")`
3. `SceneManager.LoadScene("main")`
4. → 예외 발생, `@Network` 2개

## 주의 — 동결 기준선

`ConnectionManager.cs` 는 헌법 27조 동결 대상이다. **재구현·리팩터링하지 말 것.** 고칠 지점은 그 파일 내부가 아니라 중복 `@Network` 자체를 막는 쪽이 맞다. 후보:

- `@Network` 를 `main` 에서 빼고 부트스트랩 전용 지점에서 1회 생성
- 또는 `@Network` 에 중복 자기 파괴 가드를 **별도 컴포넌트로** 추가 (동결 파일 미변경)

어느 쪽이든 팀 결정이 필요하면 `docs/26_팀_결정_필요사항.md` 로 올린다.
