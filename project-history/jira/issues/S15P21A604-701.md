## 설명

# 작업 목적

Game Studio에서 게임을 게시(Publish)해도 공개설정을 켜는 UI가 없어 직접 URL 플레이조차 완성되지 않는다. 공개설정(PRIVATE↔PUBLIC) 토글을 구현하고, 이를 사용해 Publish→Published 백엔드 연동 계약을 실제 흐름으로 검증한다.

# 배경

- 게임 기본 공개설정은 `PRIVATE`(`Game.java:37,63`)이고, `PUBLIC` 전환 API(`PATCH /{gameId}`, `GameController.java:107-129`)는 이미 있지만 FE에서 호출하는 코드가 없다.
- `/app/games/:gameId/play`는 이미 guest 접근 가능하게 가드돼 있고(`app/router/index.tsx:142`), `PublishedGameSurface.tsx`도 완성돼 있어 토글만 연결하면 바로 동작한다.
- **MVP 범위 확인**: `spec.md` User Story 3(웹에서 Published 게임 플레이, P1)이 이 흐름을 MVP 핵심으로 명시한다. "공개 게임 목록/자동 탐색"은 GitLab #56 3파트 합의로 MVP는 큐레이션(오락기, `S15P21A604-602`)으로 닫혔고, 부스 진입(User Story 4)은 P2·최후순위다 — 따라서 이 티켓은 목록 페이지를 만들지 않는다.

# 작업 내용

1. `PATCH /{gameId}` `{"visibility": "PUBLIC"|"PRIVATE"}` 호출하는 토글 UI를 Game Studio 편집 화면에 추가 (기존 `GET /mine` 응답의 `visibility` 필드로 초기 상태 표시)
2. 위 기능을 사용해 Publish→Published 연동 계약을 실제 UI 흐름으로 검증 (아래 완료 조건)

# 완료 조건

- [ ] 공개설정 토글 UI가 구현되어 정상 동작함
- [ ] 토글 ON 상태에서 `/app/games/{id}/play` 직접 URL로 guest 플레이가 실제로 동작함
- [ ] `POST /publish` 성공 시 `publishedVersion`이 증가함(최초 1, 재게시 시 +1)을 확인
- [ ] guest 토큰 없이 `GET /published` 200 조회, `ETag`/`If-None-Match` → `304` 캐시 동작 확인
- [ ] `GAME_NOT_PUBLIC`·`GAME_NOT_PUBLISHED`·`GAME_DELETED` 에러 우선순위가 `GamePublishedQueryService.java:53-79` 문서대로 재현됨을 확인
- [ ] `publishedGameRepository.ts:105-113`의 FE 에러 매핑 7개와 실제 BE 응답 코드 일치 여부 확인·기록

# 선행 작업 / Dependency

- 없음. 사용할 API가 전부 이미 구현돼 있어 신규 BE 작업이나 팀 협의가 필요하지 않다.
- 관련(범위 제외, 참고): 공개 게임 목록/자동 탐색은 GitLab #56 ⓒ 결정으로 MVP 제외, 큐레이션(`S15P21A604-602`)으로 대체됨.

- `backend/.../game/GameController.java:107-129`(공개설정 API), `GamePublishedQueryService.java:53-79`(상태 우선순위)
- `festa-frontend/src/game-studio/runtime/ports/publishedGameRepository.ts:105-113`(FE 에러 매핑)
- `specs/019-game-studio/spec.md` User Story 3(P1)·4(P2), GitLab #56

# 테스트 방법

1. 토글 UI로 테스트 게임을 `PUBLIC` 전환 → 응답·UI 상태 반영 확인
2. Draft 저장 → 게시 → `publishedVersion` 확인, 재게시로 +1 확인
3. guest 세션에서 `/app/games/{id}/play` 직접 URL 접속 → 정상 플레이 확인
4. 토글로 `PRIVATE` 전환 → `GET /published` 호출 시 `403 GAME_NOT_PUBLIC`로 바뀌는지 확인
5. `PUBLIC`이지만 미게시인 게임 → `404 GAME_NOT_PUBLISHED` 확인
6. (가능하면) 삭제된 게임 → `404 GAME_DELETED` 최우선 확인
7. 5·6에서 받은 `ETag`로 `If-None-Match` 재요청 → `304` 확인
8. 각 단계 FE 반환 `code`/`retryable`을 매핑표와 대조해 기록
