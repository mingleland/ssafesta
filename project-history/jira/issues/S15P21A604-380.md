## 설명

## 작업 목적

고정 토큰 청킹 기준선과 구조 인식·의미 기반·Parent-Child 청킹을 동일한 Gold Label로 비교하여, 표와 줄글이 혼재한 NPC 문서에 적용할 최종 청킹·검색 전략을 선정한다.

## 배경 및 기준선

- S15P21A604-370에서 고정 토큰 기준선 확정
- 기준선: `text-embedding-3-large`, Chunk 900 tokens, Overlap 20%, Retrieval Top-K 10
- 기준선 성능: 전체 가중 Recall 1.0000, MRR 0.6900
- 370번 결과는 폐기하지 않고 비교 Baseline으로 유지한다.

## 비교 범위

### 1. 고정 토큰 청킹

- S15P21A604-370 결과 재사용
- 900 tokens / 20% overlap / Top-K 10

### 2. 구조 인식 청킹

- 제목·섹션·문단·목록 경계 보존
- 표는 표 제목·열 이름·행 이름을 포함한 검색 가능한 텍스트로 직렬화
- 표가 최대 크기를 넘는 경우 헤더를 반복하여 행 묶음으로 분할
- 페이지·섹션·블록 유형 메타데이터 보존

### 3. 의미 기반 청킹

- 줄글을 문장 단위로 분리하고 주제 전환 지점에서 청크 분리
- 최소·목표·최대 토큰 범위를 두어 지나치게 짧거나 긴 청크 방지
- 동일 입력에서 재현 가능한 분할 우선
- LLM 기반 분할을 사용할 경우 처리시간·Credit을 별도 기록

### 4. Parent-Child Retrieval

- 작은 Child 청크(후보: 250 / 400 tokens)를 임베딩·검색
- 큰 Parent 청크(후보: 800 / 1,200 tokens)를 LLM Context로 전달
- 여러 Child가 같은 Parent를 가리키면 Parent 중복 제거
- Child 검색 Top-K와 최종 Parent Top-N 및 Context token budget을 분리

### 5. 혼합 전략

- 제목·문단·표 구조를 먼저 보존
- 긴 줄글에만 의미 기반 분할 적용
- Child로 검색하고 해당 Parent로 생성 Context 구성

## 평가 데이터

- 승인된 PinLog·SSAFESTA·수달 Gold Label 35문항
- 표 관련 질문과 줄글 관련 질문을 구분해 유형별 결과도 기록
- `NO_ANSWER` 질문은 Recall/MRR에서 제외하고 임계값·거절 정책 평가 대상으로 별도 표시

## 평가 항목

- Child Recall@K, MRR, NDCG
- 최종 Parent Context에 정답 근거가 포함되는 비율
- 문서별·표/줄글 유형별 성능 편차
- 평균·P95 LLM Context tokens
- 문서 처리시간, 검색 P50/P95, Embedding/LLM Credit
- 청크 수·저장 용량·중복 Parent 비율
- 실패 질문과 구조 추출 실패 사례
- 동일 문서 재처리 시 청크 ID와 경계의 재현성
