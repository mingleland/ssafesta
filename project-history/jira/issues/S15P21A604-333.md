## 설명

### 문제

S15P21A604-85 로 게임 서버가 입장 토큰의 HS256 서명을 검증하게 된 뒤, **브라우저(WebGL)에서 로컬 접속이 불가능하다.**

S15P21A604-331 로 Mock 이 진짜 grant 를 서명하도록 고쳤지만 그것은 **에디터·데스크톱만** 살렸다. WebGL 에는 환경변수가 없어 `WorldEntryTokenSecret` 이 비어 있고, 서명할 수 없다.

시크릿을 WebGL 빌드에 박는 것은 **답이 아니다** — 그러면 누구나 grant 를 만들 수 있어 입장 토큰 체계 전체가 무의미해진다. 실제 배포에서도 서명은 BE 가 한다.

### 왜 정적 파일로는 안 되나

`festa-unity/Tools/mock-api` 는 정적 JSON 파일뿐이다. world-session 응답은 **매번 새로 서명된 토큰**이어야 한다 — `jti` 가 같으면 `GrantReplayLedger` 가 두 번째 접속부터 거부한다. 정적 파일로는 원리적으로 불가능하다.

### 작업 내용

- `Tools/mock-api/serve.mjs` — 의존성 없는 Node 서버(`node:http`·`node:crypto`)
   
   - 정적 파일 서빙(기존 용도 유지, WebGL 산출물과 같은 오리진 → CORS 회피)
   - `POST /api/v1/world-sessions` → HS256 서명 grant 발급. 클레임은 `WorldEntryTokenSigner` 와 동일
   - 시크릿이 없으면 **뜨지 않는다**(exit 78) — 조용히 가짜 토큰을 주면 게임 서버 로그에 "JWT 형식이 아니다" 만 남아 진짜 원인이 가려진다 (T-24, S15P21A604-331 에서 겪음)
- 시크릿은 **서버 프로세스에만** 있고 브라우저로 나가지 않는다

### 완료 조건

- [ ] 목 서버가 발급한 토큰이 Unity `WorldEntryTokenVerifier` 검증을 통과 — 실측
- [ ] WebGL 빌드가 이 서버를 통해 실제 접속·스폰 — 실측
- [ ] 연속 2회 이상 접속 성공 (jti 재사용 원장에 걸리지 않음)
