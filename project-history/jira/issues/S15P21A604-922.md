## 설명

## 배경

이벤트 상점(S15P21A604-836)은 즉시 구매만 지원한다. 추첨 개념이 없어, 응모권 화면(S15P21A604-842)은 FE mock으로만 동작한다 — 응모해도 코인이 빠지지 않고 서버에 기록도 남지 않는다.

치킨 경품을 실제로 운영하려면 응모형 경품이 필요하다. 새 테이블·새 컨트롤러를 만들지 않고, 기존 `event_prizes`/`event_purchases`에 컬럼을 추가해 일반 상품과 응모형 경품을 한 모델로 다룬다. `winner_count > 0`이면 응모형, `0`이면 지금과 똑같은 즉시 구매다.

## 확정된 운영 값

| 항목 | 값 |
|---|---|
| 응모권 이름 | 치킨 응모권 |
| 가격 | 50 코인 |
| 응모권 한도 | 100장 (소진 시 `EVENT_PRIZE_OUT_OF_STOCK`) |
| 인당 응모 | 1회 |
| 당첨자 | 정확히 1명 |
| 마감 | 2026-09-23 15:00 KST (모든 경품 공통) |
| 추첨 시점 | 마감 후 일괄 |
| 낙첨자 코인 | 소멸(환불 없음) |

## 작업 범위

### 1. 마이그레이션 V44

- `event_prizes`에 `closes_at TIMESTAMPTZ`, `winner_count INT NOT NULL DEFAULT 0`, `drawn_at TIMESTAMPTZ` 추가
- 기존 전 경품에 `closes_at = 2026-09-23 15:00+09` 일괄 세팅
- `event_purchases`에 `won BOOLEAN` 추가 (NULL = 추첨 전이거나 일반 상품, TRUE = 당첨, FALSE = 낙첨)
- `(prize_id, won)` 인덱스

당락을 `fulfillment`로 표현하지 않는다. `CANCELLED`는 취소(환불 뉘앙스)라 낙첨을 담으면 오독된다. 당첨자만 이후 `PENDING → FULFILLED`로 지급 절차를 탄다.

### 2. 응모 게이트 (EventShopService.purchase)

마감의 실제 경계는 스케줄러가 아니라 구매 경로다. 스케줄러가 늦게 돌아도 마감 시각 이후 응모는 거절되어야 한다.

- `closes_at`이 지났으면 `EVENT_PRIZE_CLOSED`
- 응모형이면 `quantity`는 1만 허용
- 응모형이면 같은 회원의 기존 응모가 있을 때 `EVENT_PRIZE_ALREADY_ENTERED`

인당 1회 판정에 추가 락은 필요 없다. `wallets.lockOwner(userId)`가 같은 회원의 동시 요청을 이미 직렬화하므로, 그 아래에서의 check-then-act가 안전하다.

`ErrorCode`에 `EVENT_PRIZE_CLOSED`, `EVENT_PRIZE_ALREADY_ENTERED` 추가(둘 다 409).

### 3. 마감·추첨 스케줄러

`BoothLeaseExpirySweeper`와 같은 형태(얇은 스케줄러 + 서비스). 한 번 돌 때 순서대로:

1. `closes_at <= now AND active` → `active = false`
2. `NOT active AND winner_count > 0 AND drawn_at IS NULL` → 경품 행을 잠그고 응모자 중 `winner_count`명을 무작위로 뽑아 `won = true`, 나머지 `won = false`, `drawn_at` 기록

`drawn_at`은 중복 추첨을 막고, 관리자가 마감 시각 전에 수동으로 `active=false`로 내린 경우에도 추첨이 돌게 한다. 없으면 그 경우 당첨자가 나오지 않는다.

### 4. 관리자 API

- `AdminPurchaseView`에 `won` 추가. `campus`·`teamName`·`recipientName`은 이미 내려주고 있어 추가 작업 없음
- `PrizeRequest`에 `closesAt`·`winnerCount` 추가 — 콘솔에서 응모권 등록과 마감 시각 수정이 가능해진다
- 구매 내역 조회에 `won` 필터 추가(당첨자 조회용)
- 응모 강제 종료는 기존 `PUT /prizes/{id}`의 `active:false`로 이미 가능

### 5. 사용자 API

엔드포인트 변경 없음. `PrizeView`에 `closesAt`·`winnerCount`만 추가해 화면이 마감 시각과 잔여 응모권 수를 서버 값으로 표시할 수 있게 한다.

## 완료 조건

- 같은 회원이 두 번 응모하면 409
- 마감 시각 이후 응모하면 409
- 101번째 응모는 `EVENT_PRIZE_OUT_OF_STOCK`
- 스케줄러 1회 실행 후 `won = true`가 정확히 1건
- 스케줄러를 두 번 실행해도 여전히 1건
- 응모가 100장 미만이어도 당첨자 1명이 나온다
- 응모가 0건이면 당첨자 없이 `drawn_at`만 기록된다

## 범위 밖

- FE 작업 전부. `festa-frontend/src/entities/raffle/`의 mock 제거와 실 API 배선, 관리자 콘솔의 캠퍼스 컬럼 추가는 FE 파트에서 별도로 처리한다. 이 이슈는 BE만 다룬다
- 추첨 결과 알림, 당첨자 발표 페이지, 낙첨 환불, 응모 여러 회차, 인당 N회 응모
