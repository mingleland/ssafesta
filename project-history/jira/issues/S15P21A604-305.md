## 검증 완료 (2026-08-31)

레이캐스트 → 사거리 판정 → `Interact()` → 브리지까지 **실제 경로를 그대로 태워** 두 payload 를 잡았다. 부스 7, 앵커 lossy 10, Mock 레이아웃.

```
AiAgent 'ai-1'     — 레이 적중 True, 거리  5.8/30 unit → 사거리 안 → AiNpcInteractable.Interact()
Laptop  'laptop-1' — 레이 적중 True, 거리 10.9/30 unit → 사거리 안 → LaptopInteractable.Interact()

[BoothInteractBridge] onBoothInteract → {"type":"AI_AGENT_INTERACT","boothId":7,"objectId":"ai-1","configId":78}
[BoothInteractBridge] onBoothInteract → {"type":"BOOTH_LAPTOP_INTERACT","boothId":7,"objectId":"laptop-1"}
```

- `AI_AGENT_INTERACT` **3필드 전부 존재** — `boothId` · `objectId` · `configId`. 계약(Issue #2) 일치.
- `BOOTH_LAPTOP_INTERACT` 는 `configId` 를 **넣지 않는다** — 회귀 없음. (선택 필드는 키 자체를 넣지 않는 규칙이 지켜진다.)

## 원문과 달라진 점

1. **"클릭" 이 아니라 F 키다** (S15P21A604-323). 이슈 본문이 낡았다.
2. **브라우저 콘솔이 아니라 에디터에서 잡았다.** 백그라운드 창에서 프레임이 1,050 ~ 28,700 ms 로 늘어 키 입력이 프레임에 걸리지 않는다 — 그 상태로는 "안 되는 것" 과 "느린 것" 을 구분할 수 없다.

그래서 검증 대상을 나눴다.

| 검증 대상 | 어디서 | 근거 |
|---|---|---|
| JSON 문자열 자체 | Editor 단위 테스트 | `BoothInteractBridgeTests` 가 정확한 문자열을 단언 |
| 레이아웃 → 오브젝트 필드 배선 | 에디터 플레이 모드 | 플랫폼 무관한 C# 경로 |
| jslib → `window.FestaUnity` 전달 | **WebGL 빌드** | LAPTOP 실측으로 확인 (아래) |

WebGL 빌드에서 실제로 잡힌 로그 — 브리지가 브라우저 경계까지 도달함을 보인다.

```
[FestaUnityBridge] window.FestaUnity.onBoothInteract is not ready
{"type":"BOOTH_LAPTOP_INTERACT","boothId":7,"objectId":"laptop-1"}
```

## 검증 중 발견한 결함 — S15P21A604-339

**이 이슈가 오래 안 닫힌 진짜 이유다.** 상호작용 사거리가 `3f` 로 되어 있는데 이 프로젝트는 1 m = 10 unit 이라 실제로는 **0.3 m** 였다. 대상 표면에 몸이 닿아도 판정 기준점까지 NPC 4.3 / 노트북 6.8 unit 이라 **F 가 기하학적으로 발동할 수 없었다** — 걸어가서 확인하려 해도 확인이 불가능한 상태였다.

`30f / 22f` (3 m / 2.2 m)로 고쳤다. 상세는 S15P21A604-339, T-232.

기록: `docs/KHS/measurements/booth-interaction-payload.md`
