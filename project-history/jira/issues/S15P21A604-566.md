## 설명

## 작업 목적

- 데이터 탭에서 INTEGER·STRING 타입 변수를 생성할 수 있게 한다. 스키마·조건(`VARIABLE_EQUALS`)·액션(`SET_VARIABLE`)·값 편집(`VariableValueInput`)은 세 타입(BOOLEAN/INTEGER/STRING) 전부 지원하는데, 생성 버튼은 "+ Boolean 변수" 하나뿐이라 정수·문자열 변수는 UI로 만들 방법이 없다. 미연시 QA 중 만든 호감도 시스템(INTEGER)도 JSON 가져오기로 우회해야 했다 — 정상 제작 경로가 아니다.

## 작업 내용

- `authoringCommands.ts`에 `addIntegerVariable`, `addStringVariable` 신설 — `addBooleanVariable`과 대칭 구조. `nextStableId(project, 'variable')`를 그대로 재사용(기존과 동일한 id 프리픽스). 초기값 기본은 INTEGER `0`, STRING 빈 문자열(`''`)
- `ProjectDataPanel.tsx`에 "+ Integer 변수", "+ String 변수" 버튼 추가 — 같은 파일의 GAME GOALS 섹션(점수 달성/적 처치/시간 생존 — 독립 버튼 3개) 패턴을 그대로 따름
- `VariableValueInput`(값 편집 UI)은 이미 세 타입을 전부 지원하므로 **수정 불필요** — 이번 작업 범위는 생성 진입점 2개 추가로 한정됨

## 완료 조건

- [ ] "+ Integer 변수" 버튼으로 INTEGER 타입 변수를 생성할 수 있다
- [ ] "+ String 변수" 버튼으로 STRING 타입 변수를 생성할 수 있다
- [ ] 새로 만든 변수의 초기값을 각 타입에 맞게 편집할 수 있다(기존 `VariableValueInput` 그대로 동작, 회귀 없음)
- [ ] 새로 만든 변수를 조건(VARIABLE_EQUALS)·액션(SET_VARIABLE)에서 정상적으로 선택·사용할 수 있다
- [ ] 변수 100개 상한 도달 시 새 버튼들도 기존 Boolean 버튼과 동일하게 비활성화된다
- [ ] 저장 → 새로고침해도 생성한 변수가 유지된다

## 선행 작업 / Dependency

- 없음 — 프론트 단독으로 완결 가능(`GameProject` 스키마·검증 로직에만 걸려있고 서버 API 연동 불필요)

## 참고

- 참고 구현: `festa-frontend/src/game-studio/studio/model/authoringCommands.ts`의 `addBooleanVariable`(대칭 함수), `festa-frontend/src/game-studio/studio/ui/ProjectDataPanel.tsx`의 GAME GOALS 3버튼 섹션(UI 패턴 선례)

## 테스트 방법

1. "+ Integer 변수" 클릭 시 INTEGER 타입, 초기값 0인 변수가 생성되는지 확인한다.
2. "+ String 변수" 클릭 시 STRING 타입, 초기값 빈 문자열인 변수가 생성되는지 확인한다.
3. 새로 만든 INTEGER/STRING 변수의 값을 편집할 수 있는지 확인한다.
4. 새로 만든 변수를 이벤트/대화 선택지의 조건·액션에서 정상적으로 선택·사용할 수 있는지 확인한다.
5. 생성 후 저장 → 새로고침해도 유지되는지 확인한다.
6. 변수 100개 상한에서 새 버튼들도 비활성화되는지 확인한다.
