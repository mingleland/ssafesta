## 설명

### 작업 목적

방문자가 부스의 `PROJECT_PANEL` 을 상호작용하면 React 오버레이가 열리도록 Unity 송신부를 만든다.
FE 는 이 트리거만 오면 dispatcher·오버레이 층을 붙일 수 있다 (spec 009 FR-007 — 표시 UI 는 React, Unity 는 트리거만).

### 계약 (2026-08-31 확정, GitLab #110 note 2754197)

```
BOOTH_PROJECT_INTERACT { type, boothId, objectId }
```

- `configId` 는 보내지 않는다. C-01 로 부스당 프로젝트 1개가 확정돼 `boothId` 만으로 조회가 끝나고, `AI_AGENT_INTERACT` 와 달리 매핑할 대상이 없다.
- 근거 선례 — S15P21A604-297 에서 `BOOTH_LAPTOP_INTERACT` 의 `url?` 을 같은 이유로 제거했다 ("채울 출처가 없는데 남겨 두면 Unity 가 보낼 수도 있다고 읽힌다").
- payload 모양은 `BOOTH_LAPTOP_INTERACT` 와 동형.

### 작업 내용

현재 `PROJECT_PANEL` 은 Unity 에서 상호작용 컴포넌트가 **아무것도 붙지 않는다** (팩토리가 큐브만 놓는다).

1. `ProjectPanelInteractable` 신설 — `LaptopInteractable` 패턴 그대로
2. `BoothObjectFactory.AttachCommonInteraction` 에서 `PROJECT_PANEL` 에 부착
3. `BoothInteractBridge` 에 상수 + `SendProjectInteract(boothId, objectId)` 추가
4. 브리지 테스트 추가 (`BoothInteractBridgeTests` 패턴)

### 완료 조건

- [ ] 부스 안에서 프로젝트 패널에 다가가 F 프롬프트가 뜬다
- [ ] 상호작용 시 `{"type":"BOOTH_PROJECT_INTERACT","boothId":N,"objectId":"..."}` 가 FE 로 전달된다
- [ ] `configId` 가 payload 에 포함되지 않는다
- [ ] WebGL 빌드에서 실제 경로 확인

### 선행 작업 / Dependency

- 부스 실내 수정 3건(S15P21A604-336·338·339) 빌드 검증 후 착수 — 상호작용 사거리 수정이 선행되어야 F 가 발동한다
