## 설명

### 작업 목적

게임 파트 로컬 통합 실측(GitLab #181, 2026-09-11)에서 나온 별건이다.

`SURVEY_KIOSK` 를 `configId=1` 로 게시했는데 월드에서 `GET /api/v1/booths/1/survey/run` 이 `404 SURVEY_NOT_FOUND` 였다. 방문자에게는 "설문을 찾을 수 없습니다" 로 보인다. 게시는 통과했는데 그 자리에 띄울 것이 없는 상태다.

### 원인 (develop 확인함)

`booth/LayoutConfigResolver.java:30-42` 의 `belongsToBooth` 가 `AI_AGENT` 하나만 실제로 센다. 나머지는 전부 `default -> true` 다.

```java
return switch (type) {
    case AI_AGENT -> countAgents(configId, boothId) > 0;
    default -> true;
};
```

그래서 `SURVEY_KIOSK` 는 `LayoutValidator.java:244` 의 소유 검사를 그냥 지나가고 `CONFIG_UNVERIFIED` 경고만 남는다. 경고는 게시를 막지 않는다.

주석이 그 이유를 "다른 종류의 콘텐츠는 아직 spec 이 없다" 로 적고 있는데, **spec 010 설문은 이제 존재하고 구현도 develop 에 있다**(`S15P21A604-608`·`-621`). 주석이 스테일이다.

참고로 `configId` 자체는 조회 키가 아니다. `SurveyController.java:30` 이 명시하듯 Unity 는 `{boothId, objectId}` 만 보내고 `GET /booths/{boothId}/survey/run` 은 부스 단위로 찾는다. 즉 봐야 할 것은 "이 configId 가 이 부스 것인가" 가 아니라 **"이 부스에 방문자에게 보일 설문이 있는가"** 다.

### 등급 — 경고로 확정 (2026-09-14)

오류가 아니라 **경고**다. GitLab #181 회신으로 게시했다.

키오스크를 먼저 놓고 설문을 나중에 만드는 순서가 정상 사용이고, `LAPTOP` 의 홈페이지 미등록 경고(`CONFIG_NOT_LINKED`)와 같은 취급이다. 게시를 막지 않는다.

대신 지금처럼 `CONFIG_UNVERIFIED`("서버가 확인할 수 없다")로 뭉뚱그리지 않고 **설문이 없다는 것을 가리키는 판정**으로 내려간다.

BE 범위 밖 후속 2건도 같은 회신에 적었다.

- FE — 게시 화면에서 이 경고를 사용자에게 보여 준다. 응답에 실려도 화면에 안 나오면 지금과 똑같이 빈 키오스크가 월드에 선다
- 게임 — 경고를 무시하고 게시하면 여전히 빈 키오스크가 설 수 있다. 그때 토스트 문구가 서버 메시지를 그대로 쓰는 구조인지 회신 요청함

### 작업 내용

1. `LayoutConfigResolver` 에 설문 판정을 더한다. `boothHomepageRegistered`(`:59`, `LAPTOP` 용)가 같은 모양의 선례다 — 행을 세고, 없으면 예외 대신 `false`.
2. `LayoutValidator` 의 경고 체인에 연결한다. 설문이 없는 `SURVEY_KIOSK` 가 전용 경고로 잡히게 한다.
3. 스테일 주석(`LayoutConfigResolver:36-38`) 정정.

### 완료 조건

- [ ] 설문이 없는 부스에 `SURVEY_KIOSK` 를 게시하면 **설문 부재를 가리키는 경고**가 나온다 (`CONFIG_UNVERIFIED` 뭉뚱그림이 아니다)
- [ ] 그 경고가 **게시를 막지 않는다** — 게시는 성공한다
- [ ] 설문이 있는 부스는 경고 없이 통과한다
- [ ] `LayoutConfigResolver` 의 "spec 이 없다" 주석이 현재 사실로 정정돼 있다

### 선행 작업 / Dependency

**없다. 등급이 경고로 확정돼 게이트가 열렸다** (2026-09-14, GitLab #181).

### 범위 밖

`VIDEO_SCREEN`·`PROJECT_PANEL`·`RECRUITMENT_BOARD`·`CONSULTATION_DESK`·`LIKE_VOTE` 도 같은 `default -> true` 를 지난다. 이 티켓은 실제로 재현된 `SURVEY_KIOSK` 만 닫는다. 나머지는 각자의 콘텐츠 소유 spec 이 확정된 뒤 같은 자리에 한 줄씩 더하면 된다.

### 테스트 방법

`cd backend && ./mvnw test -Dtest=BoothLayoutValidationTest`

1. 설문 없는 부스 + `SURVEY_KIOSK` 게시 → 설문 부재 경고가 나오고 **게시는 성공한다**
2. 설문 있는 부스 + `SURVEY_KIOSK` 게시 → 경고 없음
3. `AI_AGENT` 기존 판정 회귀 없음
