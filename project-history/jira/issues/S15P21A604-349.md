## 설명

## 배경

infra-002 는 dev·demo 두 환경이 **단일 EC2 의 공용 data Compose project 에서 Redis 한 인스턴스를 공유**하도록 설계돼 있다(`specs/infra-002-environments/plan.md:59`, `research.md:9` R-01). 그런데 현재 Spring 의 Redis 키에는 환경 구분이 없어 두 환경이 같은 키를 덮어쓴다.

`specs/infra-002-environments/tasks.md` 의 T059·T060 이 이 문제를 다루는데 둘 다 `[ ]` 이고 담당이 정해지지 않았다. GitLab 이슈 #117 논의에서 **코드는 BE, 환경 값 공급은 Infra** 로 경계를 잡았고 이 티켓이 코드 몫 전부를 담는다.

T059·T060 을 한 티켓으로 묶는 이유는 T059 가 만드는 `RedisKeyspaceProperties` 가 **T060 의 입력**이기 때문이다. 나누면 T060 이 T059 에 blocked 되어 순서만 늘어난다.

## 실측 — 현재 키에 환경 구분이 없다

```java
// auth/MemberSessionService.java:77-80
"auth:active:" + userId
"auth:refresh:" + hash
"auth:refresh:used:" + hash
"auth:session:" + userId

// auth/OAuthHandoffService.java:18
"auth:oauth-handoff:"

// wallet/DailyCoinGrantService.java:103
"wallet:daily:" + userId + ":" + date
```

dev 와 demo 가 같은 Redis 를 보면 `auth:refresh:{hash}` 가 환경을 넘어 충돌한다. 세션 무효화와 일일 지급 중복 방지가 환경 간에 섞인다.

## 완료 조건

- [ ] `RedisKeyspaceProperties` 를 신설해 환경 네임스페이스 문자열을 주입받는다. 값이 없으면 기동을 실패시킨다 — 조용히 빈 prefix 로 떨어지면 환경 격리가 사라진 것을 아무도 모른다 (T-24 원칙)
- [ ] `MemberSessionService` 의 네 키에 네임스페이스 prefix 를 붙인다. **TTL 과 재사용 감지 동작은 그대로 유지한다**
- [ ] `OAuthHandoffService` 의 `PREFIX` 에 네임스페이스를 붙인다. handoff TTL 5분 유지
- [ ] `DailyCoinGrantService` 의 일일 지급 키에 네임스페이스를 붙인다. 지급 중복 방지 동작 유지
- [ ] 네임스페이스가 다르면 같은 사용자·같은 날짜의 키가 서로 간섭하지 않는 것을 테스트로 고정한다
- [ ] `docs/08_Backend_API_명세서.md` §20 환경변수 표에 네임스페이스 변수를 추가한다
