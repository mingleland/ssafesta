## 이 MR 이 담은 것 — endpoint 3개

| endpoint | 권한 |
|---|---|
| `GET /api/v1/booths/{boothId}/survey` | 편집자. **임대 만료여도 조회됩니다** (FR-011 보존) |
| `PUT /api/v1/booths/{boothId}/survey` | 편집자 + 유효 임대. upsert, 항상 200 |
| `GET /api/v1/booths/{boothId}/survey/run` | 방문자(회원·게스트). 응답의 `surveyId` 가 이후 경로의 키 |

`V22` 는 신규 테이블 0, 컬럼 3, 인덱스 4입니다. 두 자리가 스키마와 어긋나 있었습니다 — 별점 척도를 담을 칸이 없어 1~5 와 1~10 이 똑같이 저장됐고, **게스트 응답은 **`respondent_user_id NOT NULL` 때문에 구조적으로 불가능했습니다(게스트는 `users` 행이 없습니다). nullable 화 + 게스트 키 + xor CHECK + 부분 유니크 두 개로 풀었습니다.

설계 결정 넷은 MR 설명에 근거와 함께 적었습니다 — 중첩 `@OneToMany` cascade 를 쓰지 않은 이유, PUT 누락 필드를 `PresenceField` 로 받아야 하는 이유(FE 저장이 보상을 지웁니다, T-97), 문항 구조만 잠그는 이유, 방문자 게이트를 가드로 올린 이유.
