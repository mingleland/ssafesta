## 설명

## 작업 목적

- 데이터 탭에서 업로드한 이미지 자산을 개별적으로 삭제할 수 있게 한다. 현재는 "이미지 추가"만 있고 삭제 경로가 전혀 없어서, 잘못 올렸거나 더 이상 안 쓰는 자산이 계속 쌓이기만 하고 정리할 방법이 없다.

## 작업 내용

- `authoringCommands.ts`에 `removeAssetReference(project, assetId)` 신설 — `project.assets`에서 해당 항목 제거
- `ProjectDataPanel.tsx`의 "내 자산으로 교체" 목록 각 항목에 삭제(×) 버튼 추가
- 삭제 시도 시 그 자산이 현재 씬 배경 / 대화 인물 초상화 / 오브젝트 스프라이트 중 어디서 쓰이고 있는지 확인한다 — `publishValidation.ts`의 `findAssetUsageLocations`를 그대로 재사용 가능
- 사용 중인 자산이면 확인 다이얼로그로 사용 위치를 보여주고, 사용자가 확인해야 삭제되게 한다(그냥 차단하지 않는다 — 참고로 서버 계약 `game-asset-upload.md` §7의 `GAME_ASSET_IN_USE` + `force` 재시도 패턴과 같은 방향)
- 서버 연동 모드(`asset://game/...`)일 때는 실제 DELETE API 호출까지 필요 — 백엔드 구현 여부 확인 후 연동(아래 Dependency 참고). 로컬(Mock, `asset://local/...`) 모드는 IndexedDB에서 프론트 단독으로 제거 가능
- 삭제 후 프로젝트 저장(로컬 draft / 서버 draft) 시 정상 반영되는지 확인

## 완료 조건

- [ ] 자산 목록에서 개별 이미지를 삭제할 수 있다
- [ ] 사용 중인 자산을 삭제하려 하면 사용 위치(Scene 배경 / 대화 인물 / 오브젝트 스프라이트 등)를 보여준다
- [ ] 확인 후에만 실제로 삭제된다(오조작 방지)
- [ ] 로컬(Mock) 모드에서 삭제한 자산이 저장 → 새로고침 후에도 사라진 상태로 유지된다
- [ ] 서버 연동 모드에서 삭제 시 실제 서버 자산도 제거된다(백엔드 DELETE 엔드포인트 준비된 경우)
- [ ] 삭제된 자산을 참조하던 항목(배경/인물/스프라이트)이 깨진 참조 없이 안전하게 처리된다(빈 값으로 대체되거나 명확한 안내가 뜬다)

## 선행 작업 / Dependency

- 서버 연동 모드까지 지원하려면 백엔드가 `game-asset-upload.md` §7의 `DELETE /api/v1/games/{gameId}/assets/{assetId}` 를 실제로 구현했는지 확인 필요 — 미구현이면 이번 티켓은 로컬(Mock) 모드까지만 범위로 좁히고 서버 연동은 후속 티켓으로 분리

## 참고

- 관련 Issue: (변수 삭제 · 아이템 삭제 — 같은 배경에서 파생, 별도 티켓 예정)
- 자산 사용 위치 조회: `festa-frontend/src/game-studio/studio/ports/publishValidation.ts`의 `findAssetUsageLocations`
- 자산 삭제 서버 계약: `specs/019-game-studio/contracts/game-asset-upload.md` §7

## 테스트 방법

1. 이미지 자산을 하나 추가한 뒤 삭제 버튼으로 제거되는지, 목록과 배경/인물/스프라이트 선택 드롭다운에서 즉시 사라지는지 확인한다.
2. 어떤 씬의 배경으로 지정돼 있는 자산을 삭제 시도했을 때 사용 위치 안내가 뜨는지 확인한다.
3. 확인 후 삭제하면 해당 씬의 배경 참조가 어떻게 처리되는지(빈 값/경고) 확인한다.
4. 로컬(Mock) 모드에서 삭제 후 저장 → 새로고침해도 삭제 상태가 유지되는지 확인한다.
5. (백엔드 준비된 경우) 서버 연동 모드에서 삭제 후 실제 서버 자산 목록에서도 사라졌는지 확인한다.
