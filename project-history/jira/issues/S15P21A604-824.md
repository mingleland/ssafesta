## 설명

## 작업 목적

- Game Studio 제작 화면으로 들어가는 진입 UI가 없다. `/app/games/:gameId/edit` URL을 직접 알아야만 편집기에 들어갈 수 있고, 게임을 새로 만들거나 만든 게임 목록을 보는 화면 자체가 존재하지 않는다.
- BE 계약(생성·목록·삭제·복원·공개설정)은 이미 전부 구현·고정되어 있어, 이 작업은 FE 화면만 만들면 완결된다.

## 작업 내용

- `/app/games` 라우트 신설 (member-only 가드, 기존 `/app/games/:gameId/edit`·`/play`와 같은 계열)
- 생성 영역: title 입력(1~100자) + 버튼 → `POST /api/v1/games`, 성공 시 편집 화면으로 이동
- 살아있는 게임 목록: title, `#gameId`, 공개설정(visibility) 칩, 게시 여부, 마지막 수정 시각, [공개/비공개 전환]·[편집하기]·[삭제] 액션
- 삭제한 게임 섹션(0건이면 숨김): title, 삭제 시각, [복원] 액션
- 상단에 살아있는 게임 수 / 상한 카운터, 생성 상한 도달(409) 시 안내
- **범위 제외**: 이 화면으로 들어오는 진입점(어디에 링크를 둘지)은 이 작업에 포함하지 않는다 — ESC 메뉴는 UI 설계 문서(`user-flow-decisions.md` §12)에서 이미 제외 대상으로 명시돼 있어 별도 팀 논의로 결정한다.

## 완료 조건

- [ ] `/app/games` 라우트가 member-only로 보호된다.
- [ ] title을 입력해 새 게임을 생성할 수 있고, 생성 즉시 목록에 반영된다.
- [ ] 상한 초과 시 `GAME_LIMIT_EXCEEDED` 메시지가 그대로 노출된다.
- [ ] 살아있는 게임 목록에 visibility·게시 여부·수정 시각·gameId가 표시된다.
- [ ] 삭제한 게임이 별도 섹션에 나타나고, 복원하면 다시 살아있는 목록으로 돌아온다.
- [ ] 목록에서 공개설정을 바꾸면 편집 화면(GameStudioShell) 상단바의 공개설정 표시와 상태가 어긋나지 않는다.
- [ ] 진입점이 아직 없어도 URL 직접 접근으로 전체 기능이 동작함을 확인할 수 있다.

## 선행 작업 / Dependency

- 없음 (BE 계약 전체가 이미 구현·고정되어 있다)

## 참고

- API: `GameController.java` — `POST /api/v1/games`, `GET /api/v1/games/mine`, `PATCH /api/v1/games/{gameId}`, `DELETE /api/v1/games/{gameId}`, `POST /api/v1/games/{gameId}/restore`
- 관련 Issue: S15P21A604-701 (편집 화면 공개설정 토글 — `front` 브랜치에 구현됨, 이 작업의 목록 화면 토글과 상태 동기화 필요)

## 테스트 방법

1. 신규 게임 생성 → 목록에 즉시 반영되는지 확인
2. 상한 도달 시 에러 메시지 노출 확인
3. 삭제 → 삭제 섹션 이동 → 복원 → 살아있는 목록 복귀 확인
4. 목록·편집 화면 양쪽에서 공개설정 토글 후 서로 상태가 일치하는지 확인
5. 게스트 계정으로 `/app/games` 접근 시 가드 동작 확인
