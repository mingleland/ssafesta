## 설명

### 작업 목적

`OpenApiSchemaNameTest` 는 서로 다른 DTO 가 같은 이름으로 springdoc 에 등록되는 것을 막으려고 만든 테스트다(T-148 — endpoint 세 쌍이 남의 응답 본문으로 문서화된 사고). 그런데 타입 수집이 **record 에서만** 재귀한다.

```java
private void collect(Class<?> type, Map<String, Set<Class<?>>> byWireName, Set<Class<?>> seen) {
    ...
    if (!type.isRecord()) {
        return;              // ← 일반 class 는 여기서 끊긴다
    }
    for (RecordComponent component : type.getRecordComponents()) { ... }
}
```

실제 API 입력 중에 일반 class 가 있다 — `SurveyService.SurveyCommand` 는 record 가 아니고 그 안에 `QuestionCommand`·`OptionCommand` 가 중첩되어 있다. 지금은 그 이름들이 충돌하지 않아 초록이지만, **앞으로 같은 이름의 DTO 가 다른 도메인에 생겨도 이 테스트는 통과한다.** 막으려던 사고가 그대로 재현된다.

### 수정 방향

record component 만이 아니라 Jackson 에 실제로 노출되는 것을 따라간다 — 필드·getter·제네릭 인자. 또는 방향을 바꿔 **생성된 OpenAPI 문서의 **`components` 와 경로 참조를 직접 대조한다. 후자가 "문서에 실제로 무엇이 실렸는가" 를 보므로 수집 규칙을 따라다니지 않아도 된다.

### 완료 조건

- [ ] 일반 class DTO 의 중첩 타입이 수집된다
- [ ] 고치기 전 상태에서 실패하는 회귀 케이스를 넣는다 — 같은 wire 이름을 갖는 class 중첩 DTO 두 개를 심어 테스트가 잡는지 확인한다
- [ ] 기존 스위트가 그대로 통과한다
