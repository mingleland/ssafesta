## 설명

## 배경

S15P21A604-480 의 8각도 시각 acceptance(MR !453)에서 확정된 known difference다. 결함이 아니라 v1 의 설계된 범위이지만, 원본 속성 하나가 재현되지 않아 SURVEY_KIOSK_DEFAULT 가 PARTIAL 에서 못 올라간다.

## 현상

SURVEY_KIOSK_DEFAULT 런타임 GLB 의 materials 배열 길이가 1이다. 원본은 셋이다.

| 원본 재질 | 쓰이는 곳 | 런타임 |
|---|---|---|
| PlasticWhite.mat | Counter01 계열 | 이것만 남는다 |
| Tablet.mat (baseColor = Tablet.jpg, 화면 이미지) | Tablet.prefab | 유실 |
| AluminiumBrushed.mat | Counter01 · Tablet 일부 | 유실 |

결과: 상판 위 태블릿이 검은 화면이 아니라 흰 판이 된다.

형상·자리는 정확하다 — 태블릿은 prefab override m_LocalPosition (0, 0.9233265, 0.02) 대로 상판 위에 평평히(0.173 × 0.26 × 0.0043 m) 놓여 있고, intermediate GLB 에 자식 5개(Counter01 · Counter01Top · Counter01Cloth01 · CounterShelf · Tablet)가 전부 있다. 틀린 것은 색이지 자리가 아니다.

## 원인

자산 설정이 자산당 대표 .mat 하나를 지정하고(festa-frontend/tools/assets/booth-assets.config.mjs 의 material:), 컴파일러가 그 하나를 런타임 재질 서술로 옮긴다(compiler/material.mjs). 조립체 자산에서 자식별 재질이 다를 때 그 차이가 사라진다.

## 범위

1. 자식 노드별 재질 참조를 원본 계층에서 해석한다 — prefab 의 `m_Materials.Array.data[n]` override 포함. SurveyKiosk.prefab 이 실제로 이 override 를 쓴다
2. 재질별 텍스처 세트를 각각 변환하고 GLB materials 를 복수로 낸다
3. 예산 관리 — 재질이 늘면 텍스처 장수와 바이트가 늘어난다. 자산당 상한과 초과 시 동작(합치기 / 경고)을 정한다
4. parity-report.mjs 가 재질별 대조를 내도록 확장
5. gate-matrix D-2 의 "다중 재질 보존" 행을 FAIL → PASS 로, parity 문서 §3 의 known difference 제거

## 범위 밖

- normal map 화면 기여 판정 — 별개다. Booth Studio 줌 상한 120% · 오브젝트 0.5 m 라 이 밀도에서 요철을 분리할 수 없다. 화면/뷰어 문제이지 컴파일러 문제가 아니다
- thumbnail / Asset Library 연결 — gate-matrix D-3 의 의도적 defer 유지. 벤더 라이선스 게이트(B-1) 소관
- 대상 자산 확대 — TARGET_ASSET_CODES 2종 제한은 그대로. 확대는 GitLab #146 회신(게임 파트 부스 에셋 목록) 뒤에 별도로 잡는다

## 완료 조건

- SURVEY_KIOSK_DEFAULT 런타임 GLB 의 materials 가 2개 이상이고, 태블릿 면에 Tablet.jpg 유래 baseColor 가 붙는다
- 8각도 캡처에서 태블릿이 상판과 구분되는 색으로 보인다 (06_visual-review/evidence/ 에 갱신본 추가)
- FURNITURE_CHAIR02_WHITE(단일 재질)에 회귀가 없다 — 바이트 · tri · 8각도 동일
- parity-report.mjs 가 재질별로 원본 .mat ↔ 런타임 대조를 낸다
- gate-matrix D-2 "다중 재질 보존 = PASS", SURVEY_KIOSK_DEFAULT 재판정

## 검증 방법

```
node festa-frontend/tools/assets/build-booth-assets.mjs
node festa-frontend/tools/assets/parity-report.mjs
```

시각 확인은 -480 에서 확립한 경로를 그대로 쓴다 — CDP 스크린샷이 아니라 페이지 안에서 canvas.toDataURL(), VITE_R3F_VISUAL_ACCEPTANCE=true 로 프레임 구동. 절차는 parity 문서 §0 "캡처를 어떻게 뚫었나".
