## 설명

# 작업 목적

Game Studio 서버 편집 모드(`serverAuthoringEnabled`)에서 이미지/타일셋 업로드가 실제로는 호출조차 되지 않는다. `EditGamePage.tsx:41`이 이 모드일 때 `assetRepository`를 명시적으로 `null`로 넘기기 때문이다. 이미 완성된 FE 3단계 업로드 어댑터(`remoteAssetRepository.ts`)를 실제로 연결하고, 로컬 백엔드+오브젝트 스토리지에 대해 시작→업로드→완료 전체 흐름을 검증한다.

# 배경

- FE 어댑터(`remoteAssetRepository.ts:120-171`)와 BE 3개 endpoint(`GameAssetController.java` — `POST /assets`, `POST /assets/{id}/complete`, `GET /assets/{id}/content`)는 계약(`specs/019-game-studio/contracts/game-asset-upload.md`)대로 이미 코드로 완성돼 있다. 연결만 안 돼 있다.
- 현재 증상: `EditGamePage.tsx:41`이 서버 모드에서 `assetRepository`를 `null`로 강제하고, `GameStudioShell.tsx:751-754`가 그 상태에서 업로드 시도 시 **"이 브라우저에서는 로컬 자산 저장소를 사용할 수 없습니다"**를 띄운다 — 실제 원인(서버 미연결)과 무관한 오해 소지 있는 메시지다. `useResolvedAssetUrls.ts:26-28`도 `repository === null`이면 항상 빈 URL을 반환해, 새 업로드뿐 아니라 **이미 서버에 저장된 커스텀 자산도 캔버스에 안 보인다**(builtin 자산은 별도 경로라 무관).
- `README.md:36-40`의 "아직 연결하지 않은 외부 경계" 목록은 일부 stale하다 — 같은 목록의 "Draft/Publish/Published 서버 endpoint"는 `S15P21A604-697`·`-701`에서 이미 실연동 검증이 끝났다. "서버 소유 Asset upload/reference resolver" 항목만 코드로 재확인한 결과 여전히 사실이다.
- 로컬 오브젝트 스토리지가 없어(`backend/compose.yaml`엔 Postgres·Redis만 있음) 테스트 전 별도 MinIO 컨테이너를 준비해야 한다(팀 공유 세팅 없음 확인, 이번에 새로 구성).

# 작업 내용

1. `EditGamePage.tsx:41`을 고쳐 `serverAuthoringEnabled`일 때 `createApiGameAssetRepository()`를 실제로 연결한다 (다른 server 포트들과 동일한 `useMemo` 패턴).
2. 로컬 MinIO 컨테이너 준비 + `backend/.env`에 `MINIO_*` 값 설정, `AI_STORAGE_ACTIVE_WRITE_PROVIDER=MINIO_LOCAL` 전환.
3. 위 배선으로 실제 업로드(시작→PUT→완료) 흐름을 로컬 백엔드+MinIO에 대해 검증한다.

# 완료 조건

- [ ] `EditGamePage.tsx`의 `assetRepository` 배선이 연결되어 서버 모드에서 실제로 서버 업로드를 호출함
- [ ] 로컬 MinIO 환경이 준비되어 `POST /assets → PUT uploadUrl → POST /complete` 3단계가 끝까지 성공함을 확인
- [ ] 업로드된 이미지가 캔버스/팔레트에 정상 표시됨을 확인
- [ ] 거절 케이스(용량 초과·미지원 형식·미지원 종류) 각각의 에러 코드가 FE에 정확히 전달됨을 확인
- [ ] 배선 연결로 "이 브라우저에서는 로컬 자산 저장소를 사용할 수 없습니다" 오표시가 더 이상 뜨지 않음을 확인
- [ ] 새로고침 후 기존 커스텀 자산이 여전히 보임(`GET .../content` 재조회)을 확인
- [ ] `README.md:36-40`의 "아직 연결하지 않은 외부 경계" 목록 갱신 필요 여부 기록

# 선행 작업 / Dependency

- 없음. FE·BE 코드 모두 이미 있어 신규 설계 불필요, 배선 연결만 필요하다.
- 로컬 MinIO 세팅은 팀 공유 방법이 없어 이번 작업에서 새로 구성한다(`backend/compose.yaml`은 건드리지 않고 별도 컨테이너로 준비).

# 테스트 방법

1. 로컬 MinIO 준비 → `.env`에 `MINIO_*` 채우고 provider 전환 → 백엔드 재기동
2. `EditGamePage.tsx` 배선 연결 후 "이미지 추가"로 실제 파일 업로드 → Network 탭에서 3단계가 순서대로 성공하는지 확인
3. 업로드 후 캔버스/팔레트에 이미지가 실제로 렌더링되는지 확인
4. 허용 안 되는 파일(과대 용량·미지원 형식)로 시도해 거절 코드가 FE에 그대로 전달되는지 확인
5. 새로고침 후 기존 커스텀 자산이 여전히 보이는지 확인
