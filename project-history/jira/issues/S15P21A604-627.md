## 설명

h3. 작업 목적

사용자가 플레이 중 *부스에서 나가는 법을 찾지 못했다*(2026-09-10 감사 항목 15). 출구는 Unity 포털 + {{F}} 하나뿐이라 마우스만 쓰는 사용자에게는 그 경로가 보이지 않는다.

FE 혼자서는 해결할 수 없었다 — "지금 부스 안인가"를 FE 가 알 방법이 없다.

|| FE 가 가진 값 || 실제 뜻 || 왜 대용이 안 되는가 ||
| {{WorldUiState.focus}} | 초점 카메라 활성 | 부스 밖에서도 켜지고 안에서도 꺼져 있다 |
| {{WorldUiState.minigame}} | Unity 미니게임 HUD | 위와 같다 |
| {{SetInputLocked}} owner-set | React 화면이 입력을 잠갔다 | FE 자신의 상태다. 위치와 무관 |
| {{BOOTH_*_INTERACT}} 이력 | 오브젝트를 눌렀다 | 눌렀다고 안에 있는 것도, 안 눌렀다고 밖인 것도 아니다 |

그래서 GitLab #174 로 계약을 요청했고, *확정됐다.* Unity 송신부는 이미 develop 에 있다(S15P21A604-623 · MR !659 · 0642b7dc).

h3. 확정 계약

*Unity → FE* — 기존 {{onBoothInteract}} 채널(새 채널 0)

{code:json}
{"type":"WORLD_BOOTH_CONTEXT","insideBooth":true,"boothId":3}
{"type":"WORLD_BOOTH_CONTEXT","insideBooth":false}
{code}

*밖일 때 {{boothId}} 키가 아예 없다* — {{0}} 을 실으면 언젠가 "0번 부스"로 읽히기 때문이다({{BoothInteractBridge.SendBoothContext}} 실측). {{insideBooth}} 로만 가른다.

송신 시점은 로컬 플레이어 생성 직후 1회 + 안↔밖 전이 시에만. 판정은 Unity 가 {{Interior_NN}} 방 볼륨으로 한다.

*FE → Unity* — 기존 {{WorldUiBridge}} 오브젝트

{code}
SendMessage('WorldUiBridge', 'RequestExitBooth', 'exit-button')
{code}

부스 밖이면 무시(멱등). 성공 콜백 없음 — 퇴장이 끝나면 {{insideBooth:false}} 가 나온다. 퇴장은 기존 {{Portal_Int_NN}} → {{ReturnPoint_NN}} 경로 그대로다.

h3. 작업 내용

# {{unity/bridge/events.ts}} — {{WorldInteractEvent}} union 에 {{WORLD_BOOTH_CONTEXT}} 추가. {{boothId}} 는 optional
# {{features/world/model/worldContext.ts}} 신규 — module store({{insideBooth}}, {{boothId}}). {{hostPhase}}·{{gameClientUi}} 와 같은 관례
# {{features/interaction/dispatcher.ts}} — case 1개. *오버레이를 열지 않는다* — 위치 알림이다
# {{unity/host/worldUiBridge.ts}} — {{requestExitBooth()}} 추가
# {{features/world/ui/BoothExitButton.tsx}} 신규 — {{insideBooth}} 가 참일 때만 렌더. 하단 중앙
# {{unity/host/UnityHost.tsx}} — boot 마다 {{resetWorldContext()}}. 새 인스턴스는 부스 안에 있지 않다
# {{features/world/ui/MockInteractionBar.tsx}} — dev 검증 항목 2개(안/밖)
# {{docs/LJH/ui-design/00_context/hud-decisions.md}} — *컨텍스트 액션* 범주 명문화

h3. 설계 판단

*{{WorldUiState}} 에 합치지 않는다.* {{hasUnityModal()}} 이 {{focus || minigame}} 이라, {{insideBooth}} 를 그 인터페이스에 넣으면 부스 안에 있다는 이유만으로 "Unity 모달이 떠 있다"로 오판해 ESC 가 GameMenu 를 못 여는 회귀가 즉시 난다. #174 본문에 적었고 게임 파트도 동의했다.

*store 를 {{features/world/model/}} 에 둔다.* 이 값은 dispatcher 를 거쳐 온다. dispatcher 는 이미 {{worldScreen}}·{{gameClientUi}} 를 부르고, 반대로 {{unity/bridge/}} 를 부르면 레이어 방향이 역행한다. {{worldUiState.ts}} 는 전용 콜백을 직접 받으므로 bridge 에 있는 것이 맞다 — 경로가 다르다.

*버튼은 하단 중앙.* HUD 네 모서리가 모두 차 있다(좌하단 조작 안내 · 우하단 이용 안내 · 우상단 상담 Quick Access). 하단 중앙은 제품에서 비어 있는 유일한 자리이고, 부스 안에서만 뜨는 일시 요소라 상시 자리를 뺏지 않는다. dev 상호작용 바와는 dev 환경에서만 겹치므로 그보다 위로 띄운다.

*{{WorldHud}} 안에 둔다.* {{hostPhase === 'ready'}} 게이트(S15P21A604-613)를 그대로 얻는다 — 캐릭터 선택·로딩 중에는 뜨지 않는다.

h3. 하지 않는 것

* *기존 포털 + {{F}} 제거* — 절대 하지 않는다. 이건 대체가 아니라 추가 경로다
* *새 Unity 계약* — 확정된 둘 외에 아무것도 요청하지 않는다
* *퇴장 성공/실패 콜백* — 게임 파트가 만들지 않았고 필요도 없다
* *{{boothId}} 로 화면을 가르는 로직* — 지금은 로그·분석용이다. 버튼은 {{insideBooth}} 만 본다

h3. 완료 조건

# {{WORLD_BOOTH_CONTEXT}} 를 받아 {{worldContext}} 에 반영한다. 밖 payload({{boothId}} 키 없음)도 정상 처리한다.
# {{insideBooth}} 가 참일 때만 나가기 버튼이 뜬다.
# 버튼 클릭이 {{SendMessage('WorldUiBridge','RequestExitBooth',...)}} 를 1회 보낸다.
# 새 인스턴스 boot 에서 컨텍스트가 초기화된다.
# 기존 포털·{{F}}·ESC·input-lock 계약에 회귀가 없다.
# 캐릭터 선택 HUD 숨김(S15P21A604-613)에 회귀가 없다.
# {{npx tsc -b --noEmit}} · 전체 {{vitest run}}(mock on/off) · {{npm run build}} · {{oxlint}} green.
# mock/dev 환경에서 버튼 노출·해제를 육안 확인한다.

h3. 이 작업 범위 밖 — 실 Unity 왕복

실 Unity 에서 {{insideBooth:true}} → 버튼 노출 → {{RequestExitBooth}} → {{insideBooth:false}} 왕복은 *GitLab #174 의 실환경 acceptance* 로 남긴다. FE 완료조건은 위 8항까지이고, 종료 시 *실 Unity 왕복 미확인 / #174 acceptance 잔여* 를 명시한다.

게임 파트 데모가 {{world.*}} 접근 문제(#142 · MR !660)로 막혀 있는 것은 FE blocker 로 되돌리지 않는다.
