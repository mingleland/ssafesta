## 설명

## 증상

프론트에서 SSAFY 로그인을 누르면 `https://api.ssafesta.world/oauth2/authorization/ssafy` 에서 멈춘다. `project.ssafy.com` 으로 가는 두 번째 리다이렉트가 나오지 않는다. Google·Kakao 는 정상이다.

## 실측 (배포본, 2026-09-14)

| 경로 | 응답 |
|---|---|
| `/oauth2/authorization/google` | 302 accounts.google.com |
| `/oauth2/authorization/ssafy` | 401 |
| `/oauth2/authorization/nope` (없는 이름) | 401 |
| `/api/v1/auth/oauth/nope` | 404 OAUTH_PROVIDER_NOT_SUPPORTED |
| `/api/v1/auth/oauth/ssafy` | 302 → `/oauth2/authorization/ssafy` |

`ssafy` 가 존재하지 않는 provider 이름과 완전히 같은 응답을 낸다. 실행 중인 앱의 ClientRegistrationRepository 에 `ssafy` 가 없다는 뜻이다.

## 원인

`OAuthAuthorizationController` 가 `OAuthProvider` enum 만 보고 302 를 내보낸다. 이름을 아는 것과 실제로 로그인할 수 있는 것은 다르다. registration 은 application.yml 과 배포 환경변수가 함께 만든다.

registration 이 없으면 다음 홉에서 Spring Security 의 `DefaultOAuth2AuthorizationRequestResolver` 가 `InvalidClientRegistrationIdException` 을 던진다. 이 예외는 `AuthenticationException` 이 아니라 `IllegalArgumentException` 이라 어느 필터도 잡지 않고 500 이 된다 (spring-security-oauth2-client 7.1.0 에서 확인). 그 500 이 클라이언트에 보이는 모양은 별도 티켓의 ERROR dispatch 문제다.

결과적으로 실패가 한 홉 뒤로 밀려, 프론트가 실제로 호출하는 경로의 응답에는 원인이 전혀 남지 않는다.

## 조치

시작 경로에서 registration 존재까지 확인하고, 없으면 `OAUTH_PROVIDER_NOT_SUPPORTED` 로 거부한다. 죽은 302 를 내보내지 않으므로 프론트가 받는 응답에 이유가 남는다. Swagger 의 404 설명에 "배포 환경변수 누락" 경우를 명시했다.

변경 파일: `backend/src/main/java/com/example/ssafesta/auth/OAuthAuthorizationController.java`

## 검증

`OAuthAuthorizationControllerTest` 에 "enum 에는 있지만 registration 이 없는 provider 는 여기서 거부된다" 단정을 추가했다. 가드를 제거하면 `Expected ApiException to be thrown, but nothing was thrown` 으로 떨어지는 것을 먼저 확인했다.

## 이 티켓이 끝나도 남는 것

이 패치는 증상을 읽히게 할 뿐 SSAFY 로그인을 동작시키지 않는다. 배포 환경변수 `SSAFY_CLIENT_ID`·`SSAFY_CLIENT_SECRET`·`SSAFY_REDIRECT_URI` 3종이 들어와야 한다. `docs/HDD/09-08_서버_사전세팅_체크리스트.md` 의 필수 env 표에 SSAFY 행이 빠져 있었고(S15P21A604-357 이 09-07 에 설정을 추가했지만 인프라 인계 목록은 Google·Kakao 그대로였다) 이번에 추가했다. 인프라 반영은 별도로 요청한다.

기록: `docs/HDD/트러블슈팅.md` T-160

## 아직 닫히지 않은 모순 — 컨테이너를 봐야 확정된다

"배포 env 3종 누락" 은 정황 증거가 강하지만 아직 증명되지 않았다. 반대 증거가 하나 있다.

env 가 정말 없다면 **애플리케이션이 기동 자체를 못 해야 한다.** `application.yml` 의 `${SSAFY_CLIENT_ID}` 는 기본값이 없고, 빈 문자열이어도 Spring Boot 4.1 의 `OAuth2ClientProperties.afterPropertiesSet() → validate()` 가 막는다 (클래스 실측으로 확인). 그런데 앱은 떠 있고 Google·Kakao 로그인은 정상이다.

정황 증거 쪽:

- `docs/HDD/09-08_서버_사전세팅_체크리스트.md` 의 필수 env 표에 SSAFY 행이 없었다
- GitLab #117(인프라 인계 목록, 최종 갱신 2026-09-05)의 회신 8건 어디에도 `SSAFY_CLIENT` 문자열이 한 번도 나오지 않는다. S15P21A604-357 은 09-07 이다

이 모순을 푸는 정보는 저장소에 없다. 컨테이너의 환경변수와 jar 안 설정을 함께 봐야 한다.

```
docker exec $(docker ps -qf name=back) sh -c 'env | grep -i SSAFY; unzip -p /app/app.jar BOOT-INF/classes/application.yml | grep -A8 "          ssafy:"'
```

- env 3종이 없다 → 인계 누락 확정. 인프라에 주입 요청
- jar 안에 `ssafy:` 블록이 없다 → 배포 이미지가 S15P21A604-357 이전이라는 뜻이다. enum 은 최신인데 설정만 옛것인 조합이므로 빌드·배포 경로를 따로 확인해야 한다
- 둘 다 멀쩡한데 여전히 401 이다 → 기동 로그의 `ssafy` 관련 줄이 필요하다

이 티켓의 코드 변경은 어느 쪽이든 유효하다. 실패가 프론트가 호출하는 경로에서 읽히는 코드로 나오게 하는 것이 목적이고, 로그인을 동작시키는 것은 위 확인 결과에 달렸다.
