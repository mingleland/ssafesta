## 설명

## 작업

목적 NPC 상담 답변 생성(372)의 GMS 크레딧은 호출당 정액(예: gpt-4.1-mini=4.0)이라 출력 토큰을 줄여도 비용이 안 줄어든다(실측: SHORT 프리셋으로 응답 토큰 71.6% 줄여도 estimated_credits 동일). 비용을 줄이려면 LLM 호출 횟수 자체를 줄여야 한다. 운영 시간·위치·연락처처럼 정형화된/자주 묻는 질문은 LLM 호출 없이 rule-based로 즉시 응답해 호출 수를 줄인다.

## 작업 내용

- 정형 질문 후보 식별 — Booth 메타데이터로 바로 답이 되는 질문(프로젝트 소개, 대상 사용자, 사용 기술 등)
- 매칭 방식 결정 — 문자열 매칭 vs 임베딩 유사도 매칭(370/371/372 스파이크의 임베딩 인프라 재사용 가능) vs intent 분류, 각각의 오탐률 비교
- Rule 매치 시 LLM 호출 스킵하고 즉시 응답, 매치 실패 시 기존 RAG+LLM 파이프라인으로 폴백
- 크레딧 절감 효과 실측 — LLM 호출 스킵 비율 기준, GMS 콘솔 실사용량 대조

## 완료 조건

- 정형 질문 목록에 대해 rule 매치 정확도(오탐·미탐률) 실측
- 호출 스킵률에 따른 크레딧 절감 추정치 산출
- 엉뚱한 질문에 rule 답이 잘못 걸리는 오탐 케이스가 사용자 경험을 해치지 않는지 확인

## 선행/참고

- 372(RAG 답변 생성 LLM 품질·지연·비용 비교)가 최종 모델·파이프라인을 확정해야 이 rule-based 폴백의 대상 파이프라인이 정해짐 — 조사는 병행 가능하나 최종 통합은 372 이후
- spikes/ai-rag/config/generation-grid.json — credit_per_request가 요청당 고정값이라 요청 수 감소가 유일한 비용 레버라는 근거 실측 기록
