## 설명

### 작업 목적

Unity 광장 슬롯머신(S15P21A604-439, 완료)이 서버 판정을 전제로 만들어져 있는데 BE에 대응 엔드포인트가 없고, 이 공백을 추적하는 티켓도 없었다. docs/26에는 결정 요청 행으로만 남아 있어 보드에서는 보이지 않았다. 추적을 위해 신설한다.

### 현재 상태

- Unity는 `ISlotMachineClient` 경계까지 구현하고 `ServerFirstSlotMachineClient`에 404 폴백을 넣어 두었다. BE가 열지 않아도 동작에 구멍은 없고 HUD에 "체험판 · 코인 미반영"으로 표시된다
- 게임 파트 제안 계약: `POST /api/v1/minigames/slot-machines/{machineId}/spins` (광장 `plaza-slot-01`·`-02`, 베팅 10코인, 최대 보상 50코인) — GitLab #134 §1
- develop(7d0ba208) 기준 BE 미구현. `/api/v1/minigames/timer-stop/**`만 존재한다

### 착수 조건 — 승인 없이는 구현하지 않는다

헌법 28조와 spec 014 FR-009가 **미니게임 1종**으로 제한하고, 그 1종은 타이머 정지 게임이다. 서버 판정·코인 지급을 붙이는 것은 미니게임을 2종으로 늘리는 범위 확대라 구현자가 정할 수 없다(헌법 30조). docs/26 "미니게임 슬롯머신 — 2종으로 늘릴 것인가" 행의 리드 결정이 선행이다.

- 승인하지 않는 경우 → 슬롯머신은 코인 미반영 체험판으로 유지하고 **이 티켓을 닫는다**
- 2종으로 승인하는 경우 → 헌법 28조·spec 014 FR-009 개정이 먼저이고, 이어서 기획이 확률표·RTP·일일 보상 한도를 확정해야 한다. 그 값 없이는 구현할 수 없다

### 작업 내용 (승인 시에만)

- `POST /api/v1/minigames/slot-machines/{machineId}/spins` — 서버 판정, 베팅 차감과 보상 지급을 한 트랜잭션에서
- 원장 사유 신설 및 멱등 처리 (spec 003 규칙)
- 일일 보상 한도 — timer-stop과 합산인지 별도인지 확정 필요
- 잔액 부족·미등록 machineId·한도 초과 응답 정의

### 완료 조건 (승인 시에만)

- [ ] 베팅 차감과 보상 지급이 원장에 남고 합이 맞는다
- [ ] 같은 spin 요청 재전송이 두 번 차감·지급하지 않는다
- [ ] 클라이언트가 보낸 결과를 신뢰하지 않는다 (서버 판정)
- [ ] 한도 초과 시 게임은 되고 보상만 0이 된다
