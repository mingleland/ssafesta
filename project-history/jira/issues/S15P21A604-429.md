## 설명

배경 (GitLab #128, 2026-09-05 통합 실측): Unity WebGL 은 정상 기동해 캐릭터 로비까지 보이지만, 로비에서 월드 입장을 누른 뒤 main 씬 로드에 50~84초가 걸린다. 그 구간에 아무 안내가 없어 사용자가 '멈추었다' 로 오인한다. 09-08 사용자 테스트의 주 동선이다.

이것은 장애가 아니라 정상인 장시간 작업이다. boot watchdog(-426)과 역할을 섞지 않는다 — watchdog 은 장애 감지, 이번 UX 는 정상 대기 안내다.

기존 신호 조사 결과: FE 가 지금 받는 것은 createUnityInstance 의 progress(boot 구간)와 onWorldGateReady(게이트 개방 = main 씬 로드·스폰 완료 후) 둘뿐이라, 인스턴스 준비 이후~게이트 전까지가 '로비 체류(사용자 시간)' 인지 'main 로딩(대기 시간)' 인지 구분되지 않는다. 그래서 시작 시점 신호 1개만 Unity 에 요청한다.

구현
1. 브리지에 월드 로드 시작 신호 수신부를 둔다(window.FestaUnity.onWorldLoadStart). Unity 가 보내지 않으면 현재와 똑같이 동작한다 — 이 MR 은 Unity 수정 없이 단독으로 머지된다.
2. UnityHost 상태에 preparing-world 를 추가한다. booting → (로비, 표시 없음) → preparing-world → ready.
3. 안내 문구 3단계: boot 중 '게임을 준비하고 있어요'(진행률 있음) → main 로딩 '축제장을 불러오고 있어요' → 장시간 지속 시 '월드를 준비하고 있습니다. 잠시만 기다려 주세요.'
4. 진짜 진행률 신호가 없는 구간은 indeterminate 로 그린다. 가짜 백분율(35%·80%·99%)을 만들지 않는다.
5. 이 안내는 Overlay Bus 밖의 UnityHost 상태 층이다 — ESC 우선순위·focus 소유권(-428)을 건드리지 않는다.

Unity 에 요청할 것(별도 티켓으로 조율): CharacterLobby 가 main 씬을 로드하기 직전에 브리지 함수를 1회 부른다. 진행률을 줄 수 있으면 선택적으로 보내고, 없으면 시작 신호만으로 충분하다.

완료 조건: 로비 체류 중에는 안내가 뜨지 않는다 / 월드 로딩 시작 후에만 안내가 뜨고 게이트 ready 에 즉시 사라진다 / 가짜 진행률 없음 / boot watchdog 의 장애 판정과 섞이지 않는다 / 단위 테스트로 고정.
