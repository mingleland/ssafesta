## 설명

[증상]
CharacterLobby 씬(빌드 인덱스 0, WebGL 첫 씬)을 실행하면 콘솔에 "[ApiServices] Init — mock=True spring=" 이 뜨고 ApiServices.IsMock == true 이다. ApiConfig.asset 은 useMockApi=false 인데도 그렇다. 2026-09-05 에디터 플레이 모드에서 실측.

[원인]
ApiConfig 를 읽어 ApiServices.Init 을 부르는 것은 GameBootstrap 하나인데, 그 오브젝트(@GameBootstrap)는 main.unity 에만 있고 CharacterLobby.unity 에는 없다(씬 파일 grep: main 1 / CharacterLobby 0). 로비가 부르는 ApiServices.EnsureInitialized() 는 "if (Booth == null) Init(true, \"\", \"\")" — 부트스트랩이 없으면 조용히 Mock 으로 초기화한다. T-24 가 금하는 조용한 기본값 복귀다.

[영향 — 배포 차단 수준]
- 로비의 GetMyProfileAsync 가 Mock 프로필(sk_01)을 받아 실사용자의 저장 외형이 로비에서 복원되지 않는다 (P0 WORLD-04 "저장된 외형은 재접속 시 복원").
- -412 의 카탈로그 조회가 Mock 이라 로비가 DevUnlockedAll 로 동작 → 실사용자에게 유료 파츠가 전부 열려 보이고, 월드에서 저장하는 순간 409 AVATAR_ITEM_NOT_OWNED 로 거부된다.
- main.unity 에 들어가면 GameBootstrap 이 실서버로 재초기화하므로 월드는 정상 — 로비만 깨진다. 그래서 지금까지 놓쳤다. -168(Avatar 저장·복원 검증)이 해야 할 일로 남아 있는 이유와 같다.

[작업]
1. CharacterLobby.unity 에 main.unity 와 같은 @GameBootstrap 오브젝트(ApiConfig 참조 포함)를 넣는다. GameBootstrap 은 이미 싱글톤 + DontDestroyOnLoad 라 main 진입 시 두 번째 인스턴스는 스스로 파기된다.
2. ApiServices.EnsureInitialized() 가 Mock 으로 떨어질 때 에러 로그를 내게 한다 — "부트스트랩 없이 시작됨, Mock 으로 동작 중" 이 콘솔에 반드시 보이게.
3. 에디터 로비 단독 실행에서 IsMock 이 ApiConfig 값을 따르는지 확인.

[완료 조건]
- CharacterLobby 씬 단독 실행 시 ApiServices.IsMock == ApiConfig.useMockApi
- main 진입 후 GameBootstrap 인스턴스 1개(중복 없음)
- EnsureInitialized 의 Mock 폴백이 에러 로그로 드러남

[관련]
-412(카탈로그 owned), -168, -333, T-24. 월요일(09-08) 배포 선행 — 없으면 실사용자 아바타 복원·잠금이 전부 깨진다.
