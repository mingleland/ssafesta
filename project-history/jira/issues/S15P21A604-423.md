## 설명

## 배경

2026-09-08 수동 배포 후 서비스 E2E 검증을 돈다. backend/bruno 컬렉션은 endpoint 47개를 요청 52개로 이미 덮고 있지만, 환경 파일이 local 하나뿐이라 배포 서버를 겨눌 수 없다. README 의 실행 순서도 로컬 회원 API 기준이라 배포 검증에서 어느 순서로 눌러야 하는지가 한 줄로 정해져 있지 않다.

지금 없는 것은 컬렉션이 아니라 배포 서버를 가리키는 환경 파일과 실행 순서다.

## 변경 범위

- backend/bruno/environments/dev.bru 추가. baseUrl 은 OAuth 콘솔 등록값과 짝이 되는 배포 API 호스트를 쓴다 (GitLab #117 에서 인프라가 이번 배포 기준으로 확정). 토큰, handoff 등 자격증명 성격의 값은 빈 칸으로 두고 커밋하지 않는다.
- backend/bruno/README.md 에 dev 서버로 돌리는 절을 추가한다. 환경 선택, 실행 전 확인할 값, E2E happy path 실행 순서 한 줄, 로컬과 다른 지점(OAuth 는 브라우저 단계가 필연, frontendOrigin 은 서버의 FRONTEND_BASE_URL 과 같아야 refresh 가 Origin 검증을 통과, world-session 응답은 wss 와 world 호스트로 나온다).

## 검증

- Bruno 에서 dev 환경을 선택해 인증이 필요 없는 요청(슬롯 목록 조회, 공개 프로젝트 조회)이 배포 서버에 도달하는지 확인한다. 서버 기동 전에는 도달 실패가 정상이므로, 실제 왕복 검증은 09-08 배포 후에 한다.
- 코드 변경이 없으므로 회귀 대상이 없다.

## 주의

Access Token, Refresh Token, OAuth handoff, 서비스 토큰, Redis 및 DB 자격증명은 환경 파일에 넣지 않는다 (헌법 15조). dev.bru 에 들어가는 것은 호스트 주소와 식별자 기본값뿐이다.
