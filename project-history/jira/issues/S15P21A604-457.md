## 설명

### 재현 (2026-09-06 16:00)

에디터 클라이언트에 로컬 MEMBER 토큰(user 1)을 넣고 Docker 서버 `festa-world:cf83e396` 에 접속:

```
StartClient
→ OverflowException: Writing past the end of the buffer,
  size is 1172 bytes but remaining capacity is 1114 bytes
→ [Disconnect] no reason
→ WorldReconnector 무한 재시도
```

서버 로그에는 client 28/29/30 이 'disconnected, session cleaned' 로 남고 Approved 가 없다. **게스트는 정상 접속된다.**

### 원인

NGO 의 `ConnectionRequestMessage` 는 **분할되지 않는** 메시지라 `MaximumTransmissionUnitSize`(기본 1296, payload 여유 약 1114 B)에 묶인다. Spring 이 내려주는 회원 `connectionToken` 은 1,094자다(클레임에 avatarCode 411자 포함 — 게스트 토큰은 643자). 여기에 클라이언트 payload JSON 이 nickname·avatarCode 를 다시 담아 1,172 B 가 된다. **저장된 아바타가 긴 회원은 전부 월드에 들어올 수 없다.**

### 조치 (Unity)

- 클라이언트·서버 양쪽에서 Start* 전에 `NetworkManager.MaximumTransmissionUnitSize` 를 4096 으로 올린다(UTP 는 자기 MTU 위로는 분할한다).
- 서버가 무시하는 값이므로 클라이언트 payload 의 avatarCode·nickname 은 빈 값으로 보낸다(신원은 토큰 클레임이 정본이다).
- BE 에는 월드 입장 grant 에서 avatarCode 클레임을 뺀다고 요청한다(GitLab #138) — 외형은 스폰 뒤에 클라이언트가 따로 올린다.

### 검증

회원 토큰으로 에디터 클라이언트가 기존 서버 이미지에 접속되는지 확인. WebGL 회원 경로는 배포 뒤 확인.
