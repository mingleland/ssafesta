## 설명

## 작업 목적

Swagger UI와 Bruno 컬렉션을 처음 보는 사람이 **이 API가 무엇이고 어떻게 호출하는지** 알 수 있게 만든다. 지금은 둘 다 그 역할을 못 한다.

측정한 현재 상태:

- **Swagger 주석이 0건이다.** REST 컨트롤러 23개 · endpoint 47개인데 `@Operation`·`@Tag`·`@ApiResponse`·`@Schema` 사용 횟수가 각각 0이다. Swagger UI에는 메서드 이름에서 유추한 `slots_1` 류의 operationId와 필드 이름만 나오고, 인증이 필요한지, 어떤 오류 코드가 나오는지, 값의 단위와 범위가 무엇인지가 전혀 없다.
- **Bruno가 endpoint 47개 중 20개만 덮는다.** 요청 23개가 auth·users·wallet·booth-lease·booth-layout·world-session에 몰려 있고, Game Studio 9개·AI Agent 5개·Project 4개·Catalog 2개·Document 2개 등 **27개 endpoint에는 요청이 아예 없다.**
- 기존 Bruno `docs` 블록은 품질이 갈린다. `04-booth-lease/부스 임대`는 트랜잭션 경계와 응답 코드 표까지 있어 이 작업의 기준으로 쓸 만하고, 반대로 8개는 300자 안팎으로 호출법만 적혀 있다.

## 작업 내용

### 1. Swagger (springdoc 주석)

- `OpenApiConfiguration`에 서버 정보·인증 방식 설명·태그 목록을 채운다. 게스트 토큰과 회원 토큰의 차이, 내부 서비스 토큰(`/internal/**`)이 별개라는 사실을 여기서 한 번 설명한다.
- 컨트롤러 23개에 `@Tag`(도메인 이름 + 한 줄 설명)를 붙인다.
- endpoint 47개에 `@Operation(summary, description)`을 붙인다. `summary`는 목록에서 읽는 한 줄, `description`은 **호출 조건·선행 요청·부수효과**를 적는다. 예: 임대는 코인 차감과 한 트랜잭션이라는 사실, world-session 발급은 멱등이 아니라는 사실.
- `@ApiResponses`로 실제로 나오는 상태 코드와 `ErrorCode` 이름을 적는다. 같은 상태 코드에 여러 사유가 있으면 사유별로 나눈다 — 슬롯 임대의 409 3종(`BOOTH_SLOT_NOT_RENTABLE`·`BOOTH_SLOT_ALREADY_LEASED`·`ACTIVE_LEASE_LIMIT`)이 대표적이다.
- 요청·응답 record에 `@Schema(description, example)`을 붙인다. 단위와 상한이 있는 값(코인, `durationDays`, `avatarCode` 3800자, 페이지 크기 1~100)은 반드시 적는다.
- 인증이 필요한 endpoint에 `@SecurityRequirement`를 붙여 Swagger UI의 자물쇠 표시가 실제 정책과 일치하게 한다.

### 2. Bruno

- 요청이 없는 27개 endpoint를 추가한다. 폴더는 기존 번호 규칙을 이어간다 (Game Studio·AI Agent·Document·Project·Catalog·Avatar).
- 새 요청의 `docs` 블록은 `부스 임대` 수준으로 적는다: 무엇을 하는 API인지, 선행 요청과 필요한 환경변수, 성공 응답 모양, 응답 코드별 사유, 주의할 부수효과.
- 300자 안팎인 기존 8개를 같은 기준으로 보강한다.
- `bruno/README.md`의 폴더 표와 실행 순서를 현재 API 표면에 맞게 갱신한다. 지금 표에는 구현이 끝난 도메인이 "추후 작업"으로 남아 있다.

### 3. 회귀 방지

`/v3/api-docs`를 읽어 **모든 operation이 summary를 갖고 응답이 2개 이상 문서화되어 있는지** 검증하는 테스트를 추가한다. 주석 없이 추가된 endpoint가 조용히 통과하지 않게 한다.

**반복은 코드로 접었다** — 오류 봉투 스키마와 `401` 은 `OpenApiCustomizer` 두 개가 자동으로 붙인다. 반대로 사유가 endpoint 마다 다른 `403`·`404`·`409` 는 자동화하지 않았다. 그것이 문서의 실제 내용이다.

**작업 중 회귀 테스트가 잡은 것 2건 (둘 다 이 MR 에서 수정)**

1. springdoc 은 설명만 있는 `4xx` 응답에 그 핸들러의 **성공 반환형**을 채워 넣는다. customizer 를 "본문이 있으면 건드리지 않는다"로 두었더니 모든 오류 응답이 성공 DTO 를 가리켰다 — 문서상 `409` 에 `LeaseResponse` 가 온다고 약속하는 셈이었다. `4xx`·`5xx` 는 덮어쓰도록 바꿨다.
2. 기존 `AiBoothAccessApiIntegrationTest` 가 문서 전체에서 `"/internal/"` **문자열**을 찾고 있어서, `info.description` 에 "`/internal/**` 은 이 문서에 나오지 않는다"는 설명을 적은 것 때문에 실패했다. `paths` 키를 보는 구조 검사로 고쳤다 — 경로가 실렸는지와 산문이 접두사를 언급했는지는 다른 사실이다. T-99 를 지키려는 원래 의도와 javadoc 은 유지했다.

**규칙 하나를 좁혔다** — "모든 operation 에 실패 응답"으로 시작했는데 `POST /auth/guest`·`GET /booth-slots` 는 인증도 인자도 없어 거절할 것이 없다. 억지로 적으면 없는 분기를 클라이언트에 약속하게 되므로 "인증·파라미터·본문이 하나라도 있으면 실패를 적어라"로 바꿨다.

**부수 정리** — 테스트 픽스처 `BeanValidationProbeController` 가 컴포넌트 스캔에 잡혀 공개 문서에 실리고 있었다. API 가 아니므로 `@Hidden` 을 붙였다.

`docs/08_Backend_API_명세서.md` 가 계약 정본이고 이 작업은 그것을 대체하지 않는다. 같은 내용을 코드 옆(Swagger)과 실행 도구(Bruno)로 옮긴 것이며, 정본과 어긋난 곳은 발견하지 못했다.
