이 이슈의 작업 내용과 Unity 쪽 기대(S15P21A604-75)가 일치하는지 대조했고, 어긋나는 부분은 없습니다.

- Access Token 은 Unity 가 `IAccessTokenProvider` 로 주입받는 구조입니다 (S15P21A604-75 작업 내용)
- MEMBER 만 전달, 게스트는 미전달 — Unity 는 게스트를 열람 전용으로 처리합니다
- Refresh Token 은 Unity 로 전달하지 않습니다
- Unity 는 `GET /api/v1/users/me` 응답의 `avatarCode` 를 소비하고 `PUT /users/me/avatar` 로 저장합니다 (별도 `GET /users/me/avatar` 없음 — 8/25 확인 내용과 동일)

추가로 한 가지: 미저장 회원이면 `avatarCode` 필드/claim 자체가 빠질 수 있다고 황덕 님이 GitLab #99 에서 알려주셨는데, 이 경우 **Unity 가 기본 외형으로 처리**합니다. FE 에서 별도 채워 보낼 필요는 없습니다.

S15P21A604-75 (HttpUserApiClient 구현) 가 이 이슈에 걸려 있습니다. wiring 이 develop 에 올라가면 알려주시면 바로 이어가겠습니다.

MR !266 develop 병합 완료 (2026-09-05).

게스트 세션도 Access Token 을 Unity AuthBridge 로 전달하도록 고쳤다. BE 는 게스트 AT 로도 POST /world-sessions 에 GUEST grant(200)를 주고 무토큰은 401 이다(GitLab #128 §2 실측). kind 분기를 없애고 토큰 유무만 본다 — 회원·게스트 동일 경로, 비로그인만 Clear. Refresh Token 은 여전히 미전달(헌법 13조).

검증: authBridge 단위 테스트 5건(회원 Set / 게스트 Set / anonymous Clear / 로그아웃 Clear / refresh 재 Set), develop head 기준 tsc 0 · vitest 487/487 · vite build 통과.

완료 전환하지 않는 이유: 이 이슈의 완료조건은 실 WebGL AC 실증이다. Unity Editor·배포 환경이 없어 회원·게스트 월드 진입 왕복을 실행하지 못했고, 09-08 통합 실측에서 회수한다. Closes 미사용.
