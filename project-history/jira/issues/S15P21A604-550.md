## 설명

## 증상

develop 전체 스위트에서 아래 한 건이 red 다. **단독 실행하면 통과한다.**

```
src/app/router/__tests__/unit/rootRoute.test.tsx
  > 루트 경로 `/` > 비로그인 방문자가 화면을 클릭하면 로그인 화면으로 간다

TestingLibraryElementError: Unable to find an element with the text: 게스트로 둘러보기
소요 1058 / 1066 / 1098 ms
```

## 원인

`rootRoute.test.tsx:45` 이 타임아웃을 지정하지 않아 testing-library 기본값 **1000ms** 를 쓴다. 그런데 그 단언이 기다리는 화면은 **lazy 라우트 경계 뒤**에 있다.

```
클릭 "화면을 클릭해 시작하기"
  -> LandingPage.start() -> navigate('/app/world')
  -> /app/world 는 lazy 라우트 (router/index.tsx, "무거운 로더 코드를 메인 번들에서 뺀다")
  -> 그 chunk 가 해석된 뒤에야 RequireAuth 가 /login 으로 되돌린다
  -> LoginPage 렌더 -> '게스트로 둘러보기' 등장
```

실패 시 DOM 에는 Landing 이 그대로 남아 있다(ScreenControls 만 잡힌다). 렌더 실패가 아니라 dynamic import 가 1초 안에 안 끝난 것이다.

소요가 1058~1098ms 로 **한계선을 갓 넘는다.** 스위트가 커질수록 재현율이 오른다 — 오늘 develop 테스트가 917 -> 943 으로 늘면서 간헐(LJH T-67 기록)에서 상시 red 로 굳었다.

## 확인한 것

| 실험 | 결과 |
|---|---|
| 그 파일 단독 실행 | 4/4 통과 (2.88s) |
| develop HEAD 전체 (변경 0) | 3/3 실패 |
| 무관한 브랜치 기여 제외 후 전체 | 그대로 실패 |
| vite dev server 2개 종료 후 | 그대로 실패 — 외부 부하 아님 |

단일 원인 커밋이 없다. lazy 라우트(-247/-470)와 이 테스트(-271/-379/-406)가 오래 공존했고, 스위트 규모가 임계를 넘긴 것이다.

과거 같은 부류 선례: `S15P21A604-352`(테스트 닉네임이 전체 스위트에서만 1건 실패).

## 고칠 것

`findByText` 에 명시적 타임아웃을 준다. 이 테스트의 목적은 라우팅 semantics 검증이지 성능 측정이 아니다.

```ts
await screen.findByText('게스트로 둘러보기', {}, { timeout: 5000 })
```
