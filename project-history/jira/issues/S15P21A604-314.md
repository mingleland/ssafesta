## 설명

## 증상

Linux 데디케이티드 서버 컨테이너 로그가 아래 경고로 덮인다.

```
Trying to access a shader but no shaders were included in the build
because Dedicated Server Optimizations is enabled.
OnGUI function detected on MonoBehaviour, but not called, because IMGUI module is stripped.
```

부스가 만들어질 때마다 반복돼 실제 서버 로그(`[ConnectionManager] Approved client=...` 등)를 밀어낸다.

## 왜 문제인가

동작은 하고 있다 — 서버는 정상 기동하고 접속 승인도 된다. 그래서 **급하진 않지만 방치하면 비싸진다**:

- 장애 대응 때 읽어야 할 로그가 묻힌다. 로그가 안 보이면 원인 추적이 몇 배로 길어진다
- 서버는 렌더링하지 않는데 머티리얼 생성 경로를 타고 있다는 뜻이다 — 불필요한 CPU·메모리다. 40인 동접 목표에서 값이 붙는다

## 조사할 것

1. 어느 코드가 서버에서 머티리얼을 만드는지 특정 (`BoothObjectFactory`·아바타 조립 경로가 유력)
2. 그 지점을 `#if !UNITY_SERVER` 또는 런타임 분기로 건너뛰게 할 수 있는지
3. `OnGUI` 쪽은 `DevConnectionHud` 가 유력하다 — 이미 `Application.isBatchMode` 가드가 있는데도 경고가 뜨는지 확인

## 주의

서버에서 머티리얼 생성을 건너뛸 때 **콜라이더·트랜스폼까지 같이 빠지면 안 된다.** 서버는 충돌·위치 권위를 갖는다. 시각 요소만 골라내야 하고, 잘못 자르면 벽 뚫림이 서버 쪽에서 재발한다.

조용히 기본값으로 되돌리는 처리는 금지다 (T-24).
