## 설명

src/game-studio/__tests__/unit/playGamePageAssetWiring.test.tsx 의 3건이 개발자 로컬 환경에 따라 붉어졌다 하얀다 한다.

[재현]
.env.local 에 VITE_USE_MOCK=true 면 3건 실패, false 면 통과한다. 코드 변경 없이 환경변수 하나로 결과가 뒤집힌다.

VITE_USE_MOCK=true  npx vitest run src/game-studio/__tests__/unit/playGamePageAssetWiring.test.tsx  -> 3 failed | 1 passed
  VITE_USE_MOCK=false npx vitest run src/game-studio/__tests__/unit/playGamePageAssetWiring.test.tsx  -> 4 passed

실패 메시지:
  "익명 Published 플레이에서 asset:// 참조를 서버로 조회한다"          expected [] to deeply equal [ StringContaining{...} ]
  "조회한 자산을 object URL 로 만들어 플레이어까지 내린다"              expected "vi.fn()" to be called 1 times, but got 0 times
  "자산 조회가 404 여도 오류 화면 대신 게임을 그린다"                expected <main class="grp-loading"> to be null

[원인]
PlayGamePage.tsx:14 이 모듈 로드 시점에 플래그를 읽어 분기한다.

const browserPublicationEnabled = import.meta.env.VITE_USE_MOCK === 'true'
    && import.meta.env.VITE_GAME_STUDIO_API_ENABLED !== 'true';
  const browserPublicationPorts = browserPublicationEnabled ? createBrowserPublicationPorts() : null;

mock 이 켜져 있으면 브라우저 publication 경로를 타서 서버 fetch 가 일어나지 않는다. 테스트는 전역 fetch 를 stub 해 "페이지가 resolver 를 넘기는가" 를 보는데, 그 경로 자체가 꿼져 버린다.

테스트가 전제로 삼는 값을 자기가 고정하지 않고 개발자 .env.local 에 맡긴 것이 문제다.

[발견 경위]
S15P21A604-473 작업 중 mock 환경으로 전체 테스트를 돌렸다가 드러났다. -473 의 변경과 무관하다 — stash 상태에서도 그대로 재현된다. 같은 유형을 S15P21A604-467 에서 내가 한 번 만들었다(테스트가 .env.local 값에 의존하는 단언) — 그때는 판정 규칙을 재현해 잠그는 것으로 고쳤다.

[방향]
테스트가 VITE_USE_MOCK 값을 자체로 고정한다. PlayGamePage 가 모듈 로드 시점에 플래그를 읽으므로 vi.stubEnv 만으로는 부족하고(이미 평가된 모듈은 값을 재읽지 않는다) 순서가 중요하다 — stubEnv 를 먼저 두고 동적 import 로 페이지를 불러오는 형태가 되어야 한다. 구현 시 실측으로 확인한다.

[완료 조건]
1. VITE_USE_MOCK 이 true 여도 false 여도 같은 결과가 나온다
2. npm run build / vitest 전체 / tsc / oxlint green
3. 프로덕션 코드 무변경 — 테스트만 고친다

[범위 밖]
PlayGamePage 의 분기 구조 재설계 · 다른 테스트의 환경 의존 전수조사(별건으로 다룰 수 있다)
