## 설명

Survey BE endpoint 6개가 전부 develop 에 도달했다 (b5ac19dc, MR !439 !440 !443). 계약은 specs/010-survey/contracts/survey-api.md 이고 §9 가 FE 어댑터 변환표를 통째로 준다. FE 는 지금까지 mock 하나로만 돌고 있었다 (api.select.ts 에 VITE_USE_MOCK 삼항이 없다).

범위
1. 신규 entities/survey/types.ts (wire DTO) · mapper.ts (양방향 매핑 + 오류 매핑) · api.ts (surveyHttpPort)
2. api.select.ts 를 집 관례 VITE_USE_MOCK 삼항으로
3. Port 재설계 — getRun/getDraft/saveDraft/getResult 는 boothId 로 받고, surveyId 는 snapshot 으로 돌려준다. 합성 id booth-{n} 이 사라진다
4. submitAnswers 반환 void → { rewardedCoin }. 완료 화면에 지급 코인 표시
5. surveyId 는 number (wire id 가 전부 number 다). 문항·선택지 id 는 string 유지 — Builder 가 서버 id 이전에 q-1 을 스스로 채번하기 때문이고, 그 이유를 타입 경계에 적는다
6. SurveyQuestionAggregateVM 에 answeredCount 추가, average 를 nullable 로. 비율은 서버가 안 준다 — count/answeredCount 로 화면이 계산한다
7. SurveyResultSnapshot 에 totalResponses 추가 — perQuestion 이 응답 0건에도 전 문항을 실어 오므로 기존 빈 판정(perQuestion.length === 0)이 안 걸린다
8. 화면 — SurveyOverlay 의 응답 저장은 준비 중입니다 플레이스홀더 제거, 게스트 x 보상 설문 사전 안내, 결과 화면 분모 교체·null average 크래시 수정·오류 문구 분리

함께 고치는 결함
- builder.ts 검증이 빈 선택지 라벨을 통과시켜 진단 불가능한 400 이 된다
- SurveyManagementPage 의 0응답 별점 average.toFixed() 크래시

모르는 wire 유형 처리
- 결과 집계의 텍스트 3유형은 계약 §9 가 명시적으로 허용한 제외라 거른다 (이름으로 열거해서)
- 6개 밖의 값은 명시적 mapping error 로 던진다. 조용히 버리지 않는다

이번에 하지 않는 것
- Builder 의 rewardCoin/description/closesAt 입력 — S15P21A604-520 이 그 티켓이고 키 부재 규칙이 있어 FE 가 안 건드려도 값이 보존된다
- BE 개선 요청 2건(booths/{id}/survey/results 별칭, perQuestion 에 문항 문구) 은 #133 회신에서 요청만 한다. 확정 전 계약을 가정해 코드를 만들지 않는다 — getResult 는 booths/{id}/survey → surveyId → surveys/{id}/results 2단계 그대로 구현한다
- 실 transport 는 붙이되 문항 문구를 FE 에서 조인하지 않는다
