## 설명

## 증상

데모 환경(demo.ssafesta.world)에서 부스 소유자가 프로젝트 관리 화면에 "서비스 주소"를 저장한 뒤, 부스 안 노트북 오브젝트를 클릭하면 "아직 홈페이지가 준비되지 않았습니다" 안내만 나온다. 같은 값이 프로젝트 전시판에서는 정상적으로 보인다. (2026-09-14 보고)

## 원인

노트북이 읽는 값과 소유자가 입력하는 값이 서로 다른 컬럼이다.

| 여는 것 | 읽는 값 | 설정하는 화면 |
|---|---|---|
| 노트북 | `booths.homepage_url` (spec 016) | 없음 |
| 프로젝트 전시판 | `projects.deploy_url` 외 6필드 (spec 009) | 프로젝트 관리 |

노트북 오버레이는 `GET /api/v1/booths/{boothId}` 의 `homepageUrl` 하나만 본다(spec 016 C-01, GitLab #97 확정). 그런데 `booths.homepage_url` 은 등록 endpoint(`PUT /api/v1/booths/{boothId}/homepage`)만 구현돼 있고 **이를 호출하는 화면이 프론트엔드에 없다.**

- 등록 데이터층 `festa-frontend/src/features/studio/model/homepage.ts` 는 존재하지만 어느 컴포넌트도 import 하지 않는다.
- `festa-frontend/src/features/studio/ui/PropertiesPanel.tsx:143` 은 "홈페이지 주소는 부스 설정(외관 모드)에서 등록합니다" 라고 안내하는데, 정작 외관 모드인 `FacadePanel.tsx` 에는 해당 입력 칸이 없다(테마·대표색·간판 문구·로고 URL 4필드뿐).

따라서 이 컬럼은 실서비스에서 항상 비어 있었고, 노트북은 어느 부스에서도 동작한 적이 없다.

## 결정 (2026-09-14)

노트북은 등록값이 없으면 **그 부스 프로젝트의 **`deployUrl`(서비스 주소)로 폴백한다. 소유자가 자기 서비스 주소를 실제로 입력하는 칸은 프로젝트 관리의 "서비스 주소" 하나뿐이고, 그것이 소유자가 노트북에서 열릴 것으로 기대하는 주소다.

| 등록값 `homepage_url` | 프로젝트 `deploy_url` | 응답 `homepageUrl` |
|---|---|---|
| 있음 | 무엇이든 | 등록값 (등록값이 이긴다) |
| 없음 | 있음 | 프로젝트 `deployUrl` |
| 없음 | 없음 / 프로젝트 없음 | `null` |

의도적으로 유지한 세 가지:

1. **게시 게이트 유지** — 미게시 부스에는 클릭할 노트북 자체가 없으므로 폴백도 게이트 뒤에 둔다.
2. **등록값 우선** — 폴백은 빈 자리만 메운다. 등록 화면이 생기는 날 등록값이 자동으로 이기므로 되돌릴 작업이 없다.
3. `GET /booths/mine`(소유자 프리필)에는 폴백 미적용 — 등록한 적 없는 값을 폼에 채우면 소유자가 그것을 다시 저장해 한 주소가 두 컬럼으로 복제되고, 이후 한쪽만 고치면 값이 갈린다.

## 별건으로 남는 것

1. **프론트엔드가 저장 실패 사유를 버린다.** 제보자가 처음 저장에 실패했을 때 화면은 "저장하지 못했습니다. 잠시 후 다시 시도해 주세요." 만 표시했다. 실제 서버 응답은 `400 VALIDATION_FAILED` 였고 사유가 두 가지 있었다 — 프로젝트 이름이 비어 있음(`errors[0].field = name`), 서비스 주소에 scheme 없음(`ssafy.com` → `errors[0].field = deployUrl`, "배포 주소 형식이 올바르지 않습니다."). `festa-frontend/src/features/project/model/edit.ts` 의 `saveProject` catch 절이 오류 객체를 인자로 받지도 않고 버린다. 같은 화면의 로드 실패(403 포함)도 동일하게 뭉개진다. 재현 테스트는 `ProjectApiIntegrationTest.theReportedScreenIsRefusedForItsOwnReasonsAndStoresNothing` 에 고정해 두었다. FE 파트 티켓 필요.
2. `booths.homepage_url` 등록 화면을 신설할지 여부. 신설하면 이 폴백은 그대로 두어도 자동으로 뒤로 물러난다.
