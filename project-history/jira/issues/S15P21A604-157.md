## 설명

작업 목적

검증된 Draft를 불변 Published version으로 승격하고 현재 공개 pointer를 원자적으로 갱신한다.

작업 내용

- validate → version append → current pointer 변경을 단일 트랜잭션으로 수행
- 실패 시 부분 version·pointer 변경 0건 보장
- 동시 Publish에서 version 번호와 pointer 경합 처리

완료 조건

[x] 검증 실패·DB 실패 주입 뒤 이전 Published가 그대로 실행된다.

[x] Published document와 asset 참조는 게시 뒤 불변이다.

[x] 동시 Publish 결과가 중복 version 없이 결정적으로 정리된다.

[x] 승인된 공개 중단·삭제 정책을 위반하지 않는다.

Verified 2026-08-26 (MR !33 + !39, develop)

| 조건 | test |
|---|---|
| 1 | GamePublishApiIntegrationTest.aRefusedPublishLeavesNoVersionAndNoPointer + GamePublishRollbackIntegrationTest.aFailureAtThePointerStepRollsBackTheAppendedVersion |
| 2 | GamePublishApiIntegrationTest.republishingAppendsRatherThanUpdating · theDraftSurvivesPublishing (+ updatable=false) |
| 3 | GameConcurrencyIntegrationTest.concurrentPublishesLeaveNoDuplicateVersion @RepeatedTest(5) |
| 4 | GameLifecycleApiIntegrationTest (11) |

DB fault injection: `games.save` (the pointer step) throws after `published.saveAndFlush` has run, so the append is already flushed when the transaction dies. The validation-failure test cannot reach that ordering — it refuses before writing. `UNIQUE(game_id, version_no)` is what actually makes concurrent publishes safe; `highest + 1` only picks the candidate number.
