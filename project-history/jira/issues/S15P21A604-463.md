## 설명

Landing/Login(Unity 밖) 화면에 BGM 을 넣고, 우상단에 mute 컨트롤을 둔다. World 진입 시 화면 오디오를 Unity 로 넘긴다.

[전제 정정]
Landing/Login BGM 은 인게임 BGM 이 아니다. World 진입 지점은 11F 이고 Unity WorldBgm.ZoneWeights 기준 11층 방(z < -118)은 Algorithmic Morning 100% / Midnight Circus 0% 다. 따라서 같은 곡의 변주가 아니며 곡 연속성·긴 crossfade 를 전제하지 않는다. 화면 공간 -> 11F 공간으로 오디오 소유권을 넘기는 전환으로 설계한다.

[구조]
- screenAudio.ts — audio instance / play / stop / fade / mute preference (module-level store + useSyncExternalStore, 저장소 관례)
- ScreenAudioController — browser interaction + Unity lifecycle 연결
- ScreenControls — 사용자 mute UI (Landing/Login 공통 우상단)

라우트 내부 <audio> 금지. / -> /login -> /app/world 전환에서 음악이 유지되어야 한다.

[전환 규칙]
- onWorldLoadStart: transition pending 만 기록. 즉시 종료하지 않는다
- onWorldGateReady(실제 11F 진입 확정): 짧게 fade-out 후 완전 stop, Unity 11F BGM 으로 이관
- 고정 2.5초 조기 fade 금지 / beat·phrase sync 가정 금지 / 두 곡 장시간 중첩 금지
- fade 는 0.8~1.5초를 시작점으로 실브라우저 조정

[결정 사항]
- 기본 소리 켜짐. Landing 첫 클릭을 audio unlock + 재생 시작 지점으로 사용
- /login 딥링크: autoplay 실패를 삼키지 않고 pending 으로 두고 첫 사용자 interaction 에서 재생
- mute 는 localStorage 에 저장. 향후 ESC Client Settings 의 Music 설정이 그대로 승계하도록 키·형태를 설계
- 효과 토글(구름·열기구·불꽃놀이)은 이번에 렌더하지 않는다. 다중 control 을 담을 container 만 준비
- Landing 전체화면 <button> 내부가 아니라 형제 overlay 로 배치. 형제 구조이므로 stopPropagation 을 필수로 두지 않는다
- 자산 로드 전략(idle preload / metadata / gesture-load)은 미리 확정하지 않고 Unity warm-up 과의 네트워크 경합을 실측해 결정

[완료 조건]
1. Landing 클릭 시 재생 시작
2. Login 이동 시 끊김 없음
3. /login 딥링크 진입 후 첫 interaction 에서 재생
4. mute 가 새로고침 후에도 유지
5. 11F 진입 시 두 곡 겹침·긴 무음·갑작스러운 cut 없이 종료되고 Unity BGM 으로 전환
6. ScreenControls 가 로그인 레퍼런스 기하(로고 13.3% / 패널 56.4~91% / 푸터 96~98%)를 밀지 않는다
7. 전체 vitest green / tsc 0 / oxlint 신규 경고 0

5번은 실 WebGL 왕복이 필요하므로 로컬 통합 스택 실측으로 확인한다.
