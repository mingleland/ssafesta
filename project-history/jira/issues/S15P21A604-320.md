## 설명

## 증상

로비 사물함 벽에서 **도어락이 전부 안 보인다.** 거울·알루미늄 디테일도 같이 없고, `content-introduction` 패널에서는 파란 요소가 빠졌다.

사용자가 씬 뷰 스크린샷으로 지적해서 발견했다.

## 원인

-281 데시메이션 산출물이 **서브메시 5개를 1개로 뭉갰다.**

```
원본 wall-elevatorside (combined)  1,068,490 정점 / 서브메시 5
  [0]  36,000 삼각형   벽 본체        ← 유일하게 살아남음
  [1]  20,000          [Mirror 01]
  [2]   2,800          [Metal Aluminum Anodized]
  [3] 256,800          doorlock-gray   ← 자물쇠
  [4] 218,088          black

-281 산출물 wall_elevatorside_dec.obj  40,559 정점 / 서브메시 1
```

렌더러의 **재질 슬롯은 5개 그대로인데 메시 서브메시가 1개**라, 슬롯 1~4 는 그릴 인덱스가 없어 통째로 미출력된다. **유니티는 이걸 에러로 알리지 않는다 — 조용히 안 그린다.**

원본 533,688 삼각형 → 16,870. 97% 감소인데 **줄어든 대부분이 자물쇠·디테일 지오메트리**였다. 데시메이션이 아니라 내용물 삭제였다.

## 왜 안 걸렸나

-281 의 할 일은 "교체 후 UV2 생성·콜라이더 부착 확인"이었고 **재질 정합은 확인 항목에 없었다.** 정점 수만 보면 성공으로 보인다.

같은 커밋에서 **UV2 도 깨져 있었다** — 활용률 3.4E-5 로, 1024² 라이트맵에서 삼각형 하나가 0.24 텍셀이었다. 라이트맵을 구울 수 없는 상태였다.

## 해결

`SubmeshPreservingDecimator` (`Assets/_Project/Scripts/Editor/`) 를 추가했다. **서브메시마다 독립적으로** 정점 클러스터링을 돌려 그룹 간 정점을 섞지 않으므로 개수·순서가 유지된다. 셀 크기는 서브메시별 목표 삼각형 수에 맞춰 이분 탐색한다.

|  | 원본 | -281 | 수정 후 |
|---|---|---|---|
| 정점 | 1,068,490 | 40,559 | **13,678** |
| 삼각형 | 533,688 | 16,870 | 48,240 |
| 서브메시 | 5 | **1** | **5** |
| 자물쇠 | 있음 | **없음** | **있음** |

정점은 -281 보다 3배 더 줄었는데 디테일은 전부 살아 있다. `content-introduction (combined)` 도 3개 서브메시 복원 (`SSAFY_Blue`·`skyblue`), 정점 280,586 → 3,646.

블렌더를 쓰려 했으나 개발 머신에 실행 파일이 없어 유니티 안에서 처리했다. 오히려 이쪽이 낫다 — 내보내기/가져오기 왕복이 없으니 애초에 서브메시가 날아간 지점을 안 거치고, 재질 정합을 코드로 즉시 검증할 수 있으며, 스크립트가 커밋되어 재현 가능하다.

## 재발 방지

씬 전체에서 **재질 슬롯 수 > 서브메시 수**인 렌더러를 세면 이 부류가 한 번에 드러난다. 수정 후 **0건** 확인.

```csharp
var mf = r.GetComponent<MeshFilter>();
if (r.sharedMaterials.Length > mf.sharedMesh.subMeshCount) // 안 그려지는 재질이 있다
```

**규칙: 메시를 교체하면 정점 수만 보지 말고 서브메시·재질 슬롯 정합을 확인한다.**

경위는 `docs/KHS/25_트러블슈팅.md` T-223.
