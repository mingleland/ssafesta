## 설명

배경 (GitLab #128, 2026-09-05 통합 실측 — 강형순): WebGL 이 캐릭터 로비까지는 정상 기동하는데, 로비에서 월드 입장 후 main 씬 로드에 50~84초가 걸린다. FE 는 이 구간의 안내 UX 를 별도로 처리하지만, 시간 자체를 줄이는 것은 Unity 소관이다.

첫 목표는 최적화가 아니라 계측이다. 'WebGL 이 느리다' 수준에서 임의로 고치지 않는다.

1. 타임스탬프 확보
T0 main 씬 로드 시작 / T1 씬·에셋 데이터 준비 / T2 씬 활성화 / T3 Awake·OnEnable·Start 초기화 완료 / T4 월드·세션·네트워크 준비 / T5 첫 playable 프레임. T0→T1, T1→T2, T2→T3, T3→T4, T4→T5 를 숫자로 보고한다.
완료 조건 1: 50~84초 중 가장 큰 병목 구간 확정.

2. 빌드 설정 조사
LoadScene vs LoadSceneAsync / Compression Format / Data Caching / Name Files As Hashes / Decompression Fallback / Development 여부 / Debug Symbols. 권장 후보는 LoadSceneAsync·Brotli·Data Caching ON·Name Files As Hashes ON 이지만 서버 조건(#127 Nginx Content-Encoding·MIME)과 함께 판단한다.

3. Data Caching 실동작 확인
첫 방문 다운로드 → 재방문 IndexedDB 재사용이 실제로 일어나는지 browser storage·network 기준으로 확인. 대형 .data 재다운로드가 반복 방문의 체감을 지배하는지 가른다.

4. 병목이 Scene·초기화일 때만 적용
GameObject 수·Texture·Mesh·Collider·Animator/NPC·Awake·OnEnable·Start·Shader variant·Material·동시 Spawn 중 가장 큰 항목부터 줄인다. 전부 한꺼번에 만지지 않는다.

5. 장기 방향(제안, 병목 확인 후 선택)
Main Scene 전체 로드 자체가 병목이면 Persistent World Shell 방향을 검토한다 — 플레이어·필수 지오메트리·상호작용을 먼저 playable 로 올리고 Booth·NPC·장식을 점진 로딩. 후보는 Additive Scene·AssetBundle·Addressables·점진 Spawn.

FE 연결(별도 티켓): FE 가 '축제장을 불러오고 있어요' 를 띄우려면 **월드 로드 시작 시점 신호 1개**가 필요하다. CharacterLobby 가 main 씬을 로드하기 직전에 브리지 함수를 1회 부르면 된다(기존 FestaNotifyWorldGateReady 와 같은 jslib 패턴). 진행률을 줄 수 있으면 선택적으로, 없으면 시작 신호만으로 충분하다. FE 수신부는 이미 준비해 둔다.

완료 조건: T0~T5 확보 / 병목 구간 확정 / build·Data Caching 상태 확인 / 1차 개선 / cold·warm 재측정.

FE 쪽 실측 2건을 계측 입력으로 먼저 올린다 (이정헌, 2026-09-05).

1) 대형 .data 는 브라우저 HTTP 캐시가 보관하지 않는다 — §3 Data Caching 을 우선으로 보시기 바란다.

FE 컨테이너에 가짜 산출물(loader 200KB · framework 2MB · wasm 6MB · data 25MB)을 올려 실 브라우저로 재방문을 측정했다. Cache-Control: public, max-age=31536000, immutable 을 붙인 상태에서
- loader·framework·wasm(합 8.2MB): 재방문 시 요청 자체가 사라짐(transferSize 0)
- data 25MB: 매번 전량 재다운로드. 재현 3회 동일. navigator.storage.estimate() usage 도 0 이라 IndexedDB 에도 없었다

즉 서버 캐시 헤더로는 대형 .data 를 못 살린다. 경계는 6MB~25MB 사이다. 실 빌드의 .data 는 200MB 급이므로 반복 방문 체감은 Unity Data Caching(IndexedDB) 이 결정한다. 그래서 §3 이 이 티켓에서 가장 이득이 큰 항목일 가능성이 높다.

2) FE 가 요청하는 신호 1개 — 월드 로드 시작.

S15P21A604-429(World Preparing UX)를 develop 에 머지했다(MR !273). 로비 체류에는 안내를 안 띄우고 월드 로드가 시작된 뒤에만 띄우는데, 그 시작 시점을 FE 가 알 방법이 없다. CharacterLobby 가 main 씬을 로드하기 직전에 FestaNotifyWorldLoadStart() 를 1회 부르면 된다 — 기존 FestaNotifyWorldGateReady 와 같은 jslib 패턴이고 인자는 없다. 진행률을 줄 수 있으면 선택이고 없어도 무방하다.
