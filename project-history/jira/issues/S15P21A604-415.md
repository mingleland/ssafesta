## 설명

Contract Gap G-2. Survey Overlay 와 상태 모델은 완비돼 있고 World 진입 트리거만 없다.

## 배경

Visitor 기능 6종 중 LAPTOP·AI 는 Unity 송신부가 있고, PROJECT 는 계약이 확정돼 송신부만 남았으며(-343), GAME 은 별도 blocked 이다. Survey 는 **이벤트 계약 자체가 없다** — OverlayType 리터럴만 있고 unity/bridge/events.ts 의 BoothInteractEvent union 에 해당 타입이 없다.

## 목표 Flow

World Survey Object / Kiosk -> Unity F Prompt -> F -> Unity event -> FE dispatcher -> Survey Run Overlay -> Close -> 같은 World

## 현재 상태 (2026-09-04 실측)

- FE consumer: 준비 완료. features/survey/model/run.ts 상태 기계(6유형·required·progress·submit)와 SurveyOverlay 가 develop 에 있다(S15P21A604-413, !240).
- Unity producer: 없음.
- 계약: 없음.
- 별개 의존: 실 응답 저장은 BE Survey API 대기(G-6, -130·-131·-132·-190·-191·-192·-193). 이 티켓은 **진입 경로**만 다룬다 — 둘은 독립적으로 진행할 수 있다.

## 결정할 것

- event name (기존 관례 BOOTH_*_INTERACT)
- payload: boothId·objectId 외에 surveyId 같은 identifier 가 필요한가. Project 는 부스당 1개라 boothId 만으로 충분했고(C-01), AI 는 configId 를 썼다 — Survey 가 부스당 1개인지 여러 개인지가 payload 를 가른다
- Unity 측 Survey Object / Kiosk 배치와 부스당 개수

## 완료조건 초안

- event name 확정
- boothId/objectId 및 필요한 identifier 확정
- Unity sender 구현
- FE dispatcher mapping 추가
- 실제 Survey Overlay 진입 end-to-end 검증

## 주의

FE 가 임의 이벤트를 발명하지 않는다. 문항 6유형은 spec 010 FR-002 확정분이며 새 유형을 만들지 않는다.

확정한 계약
  type: "BOOTH_SURVEY_INTERACT"
  boothId: number
  objectId: string

surveyId 를 보내지 않습니다. MVP 는 부스당 활성 설문 1개로 다루지만 그것을 boothId == surveyId 로 모델링하지 않았습니다. boothId 는 설문의 ID 가 아니라 설문을 resolve 하기 위한 context 입니다. 부스에 설문이 여러개가 되는 시점에는 함께 보내는 objectId 로 특정 설문에 binding 하면 되고, 그때 Unity 계약은 바뀌지 않습니다.

구현
- Unity: BoothInteractBridge.SendSurveyInteract, SurveyKioskInteractable.cs 신규, BoothObjectFactory 자동 부착
- FE: events.ts 에 BOOTH_SURVEY_INTERACT 추가, dispatcher 에서 SURVEY 오버레이 라우팅

확인 부탁드릴 것
- Unity Editor 컴파일 검증 미실행 (이 환경에 Editor 가 없습니다)
- 씬 배치 불필요 (Factory 가 런타임에 붙입니다)

FE 동작은 dev 상호작용 바로 실제 Unity JSON 을 흘려 설문 오버레이 문항 렌더까지 확인했습니다.
