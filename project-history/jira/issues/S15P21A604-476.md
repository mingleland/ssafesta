## 설명

S15P21A604-473 이 닫은 것은 "단일 FBX 하나 -> GLB -> R3F" 다. 그 때 SURVEY_KIOSK 를 일부러 제외했다 — 단일 메시가 아니라 조립체였기 때문이다. 이번에 그것 하나를 대상으로 잡는다.

묻는 것은 하나다 — Unity 의 prefab transform 계층을 FE 에셋으로 재현할 수 있는가.

[대상]
SURVEY_KIOSK. 구조는 이런 모양이다(실측):

SurveyKiosk.prefab
  +- Tablet     (PrefabInstance) localPos (0, 0.9233265, 0.02)  localRot quat(0.00000003, 0.7071068, 0.7071068, -0.00000003)
  +- Counter01  (PrefabInstance) localPos (0, 0.00000009, 0)     localRot quat(-0.7071068, 0, 0, 0.7071068)

그리고 Counter01.prefab 은 다시 4개 FBX 를 참조하는 중첩 prefab 이다:
  Counter01.FBX · Counter01Top.FBX · Counter01Cloth01.FBX · CounterShelf.FBX (+ ithappy Frame.fbx)

즉 이번에 풀어야 하는 것은 세 가지다.
1. PrefabInstance 의 m_Modifications 에서 localPosition/localRotation/localScale 을 꺼낸다
2. m_SourcePrefab 의 GUID 로 원본을 찾아 재귀적으로 따라간다 (.meta 의 guid 역인덱스 필요)
3. 그 계층을 합성해 GLB 하나로 굽는다 — 런타임이 prefab 을 알 이유가 없다

[범위]
조립체 1종만. 지원 범위는 정적 구조에 한정한다 — child prefab 참조 · local position/rotation/scale · 단순 parent/child 그룹. MonoBehaviour · Animator · Particle · 복잡한 Variant override 는 지원하지 않고, 만나면 조용히 넘기지 않고 경고한다.

[검증 항목]
1. 계층 — Tablet 이 Counter01 위 제자리에 오는가 (localPos y 0.9233 이 살아 있는가)
2. 회전 — 자식의 quaternion 이 그대로 먹는가 (Tablet 은 -90도 회전이 걸려 있다)
3. 중첩 — Counter01 안의 4개 FBX 가 전부 들어오는가
4. 치수 — 합성 결과 bbox 가 계약 OBJECT_LOCAL_BOUNDS.SURVEY_KIOSK (+-0.31 x 0.93 x +-0.16) 와 얼마나 맞는가
5. 피벗 — 바닥(min.y=0) 중앙
6. 선택/회전/bounds — 기존과 같은가
7. 성능 — 청크 크기 · tri 수 · draw call
8. 지원 밖 요소를 만났을 때 무시하지 않고 드러내는가

[범위 밖]
전 타입 확장 · 텍스처(다음 단계) · 정적 배포 · Registry 자동화 · Unity 신규 작업 · Shell/Inspector 재설계

[불변 규칙]
도메인 bounds 는 계약 AABB 가 정본이다. 실제 모델 크기를 근거로 저장·이동·bounds 규칙을 바꾸지 않는다.

[라이선스]
벤더 에셋 웹 재배포 확인 전이므로 GLB 산출물을 커밋하지 않는다(.gitignore · .dockerignore 유지).

[품질 게이트]
npm run build / vitest / tsc / oxlint green.

[이번 라운드 범위]
구현 -> 검증 -> 커밋 -> 원격 branch push -> STOP. MR/merge 는 별도 지시 전까지 대기.
