## 설명

증상
데모에서 월드 진입이 안 된다. world.ssafesta.world 가 / /health /index.html 없는파일.html — 전 경로 403 이고, WebSocket Upgrade 도 403 이다(계약상 101 이어야 함).

측정 (2026-09-11)
- 응답 본문이 nginx 기본 403 페이지이고 서명은 nginx/1.24.0 (Ubuntu) — Cloudflare 자체 차단이 아니라 오리진 nginx 거부다.
- 없는 파일도 404 가 아니라 403 이다 — vhost 가 파일을 찾는 단계까지 가지 못하고 기본 서버에서 막힌다.
- demo 와 api 는 200 으로 정상이다. world 만 죽어 있다.

원인
infra/unity-server/nginx/world.conf.template 14번 줄에 http2 on; 이 있다. 그 디렉티브는 nginx 1.25.1 부터 생겼고 배포본은 1.24.0 이라 unknown directive 로 nginx -t 가 실패한다. 그래서 world vhost 가 올라오지 못하고 요청이 기본 서버로 떨어진다.

같은 줄을 world-dev.conf.template 에서는 09-07 에 이미 제거했다 (2a86e2be, S15P21A604-228 dev Nginx HTTP/2 호환성 보정). world.conf.template 은 08-26 이후 손대지 않아 그 보정을 못 받았다. 저장소의 다른 템플릿 3개는 전부 listen 443 ssl; 만 쓴다.

조치
- world.conf.template 에서 http2 on; 제거.
- public-wss.sh 에 회귀 가드 추가 (dev-runtime.sh 36번 줄과 같은 형식).
- 배포 측: nginx -t 후 reload 하고 verify-public-wss.sh 로 101 확인.

후속 (별건)
world.conf.template 은 렌더 세트(infra/environments/nginx/sites/)에 없고 런북이 손으로 심볼링크를 걸라고 안내한다. 게이트웨이 재렌더가 그 수제 링크를 다시 날릴 수 있다.
