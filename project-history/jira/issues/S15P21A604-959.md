## 설명

## 문제

`GET /api/v1/admin/booths` 는 관리자 소유 부스만 돌려준다. 회원 부스는 목록에 나오지 않는다.

권한 쪽은 이미 열려 있다. `BoothAccessGuard.requireEditor` / `requireModifier` 가 소유자·스태프가 아니어도 전역 관리자면 통과시키고(spec 004 FR-023), `POST /api/v1/admin/booths/{boothId}/unpublish` 도 `boothId` 만 있으면 회원 부스에 그대로 동작한다. 막혀 있는 것은 목록 하나뿐이라, 관리자 콘솔이 회원 부스의 `boothId` 를 얻을 경로가 없다.

원인은 `BoothQueryService.listAdminBooths()` 의 `booths.findByAdminOwnedTrue()` 한 줄이다 (S15P21A604-933 에서 관리자 콘솔 전용 목록으로 만들 때의 전제).

## 변경 사항

- `BoothQueryService.listAdminBooths()` 가 `findAll()` 로 전체 부스를 읽는다.
- `AdminBoothView` 에 `adminOwned` 를 추가한다. 콘솔이 두 종류를 구분해야 하기 때문이다 — 마스터 개인 부스는 `MASTER_PROTECTED` 로 조작이 거부되고, 회원 부스의 강제 비공개는 draft·컨텐츠를 보존하는 반면(spec 004 FR-010) 관리자 부스는 반납이 곧 삭제다(S15P21A604-905).
- `AdminBoothView` 에 `leaseEndsAt` 을 추가한다. 관리자 부스는 상설 임대라 만료가 없어서 지금 뷰에 없지만, 회원 부스는 만료가 운영 판단의 핵심 값이다. 관리자 부스 행에서는 `null` 이다.
- 엔드포인트는 늘리지 않는다. 한 목록에 플래그를 얹는 쪽으로 결정했다 (2026-09-22).

## 테스트 방법

- `AdminPermanentLeaseIntegrationTest` — 기존 관리자 부스 목록 단정에 회원 부스 행이 함께 나오는지, `adminOwned` 가 두 행에서 갈리는지 추가한다.
- 회원 부스 행의 `leaseEndsAt` 이 채워지고 관리자 부스 행은 `null` 인지 확인한다.
- 비관리자 호출이 여전히 403 인지는 기존 단정을 유지한다.

## 영향 범위

- 프론트 `festa-frontend/src/entities/admin/types.ts` 의 `AdminBoothView` 타입에 두 필드가 늘고, 주석의 "관리자 부스만 나온다" 전제가 깨진다.
- `festa-frontend/src/features/admin/ui/OverviewSection.tsx` 의 "공개 중인 관리자 부스" 통계가 이 목록을 그대로 세므로, 회원 부스까지 포함된 수를 보여주게 된다. `adminOwned` 로 걸러야 한다.
- 이번 작업은 백엔드만 다룬다. 프론트 수정은 GitLab 이슈로 FE 파트에 통보한다.
