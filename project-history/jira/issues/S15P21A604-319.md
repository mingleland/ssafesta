## 설명

## 증상

웹 빌드에서 미니게임이 열린 상태로 **"정지" 버튼을 마우스로 누르면** 결과(오차)가 표시되지 않고 **게임 화면이 닫히면서 뒤 월드 카메라가 회전**한다.

**Space 키로는 정상 동작한다** — 시작·정지·오차 표시·결과 보고까지 완주한다 (목표 7.10초 / 정지 4.03초 / 오차 3.064초 확인).

## 추정 원인

`TimerStopGameHud` 는 캔버스 전체를 덮는 암막(`Backdrop` Image, alpha 0.93)을 깔아 뒤 월드 클릭을 막도록 만들었다. 그런데 클릭이 새고 있다.

의심 지점:

- 암막 `Image` 의 `raycastTarget` 이 꺼져 있거나, `GraphicRaycaster` 가 클릭을 삼키지 못함
- 월드 클릭 처리(`BoothInteractionInput`)가 **uGUI 이벤트 시스템과 무관하게** `Physics.Raycast` 를 직접 쏜다 — UI 위에서 눌러도 그대로 월드 레이캐스트가 나간다. 이쪽이 유력하다
- 카메라 회전도 같은 경로로 새는 것으로 보인다

`BoothInteractionInput` 은 `OnMouseDown` 을 못 쓰는 사정(T-166) 때문에 포인터를 직접 읽어 레이캐스트하는 구조다. 그래서 **UI 가 떠 있는지 여부를 스스로 판단해야 한다** — `EventSystem.current.IsPointerOverGameObject()` 류의 가드가 빠진 것으로 보인다.

## 재현

1. 웹 빌드에서 월드 진입
2. 관리자 게임 부스 클릭 → 게임 열림
3. "시작" 후 **"정지" 를 마우스로 클릭**
4. → 결과가 안 뜨고 게임이 닫히며 카메라가 돌아간다

## 영향

게임을 마우스로 끝낼 수 없다. 키보드를 모르는 사용자는 게임을 완료하지 못한다 — **기본 조작 경로가 막힌 것**이라 우선순위가 낮지 않다.

## 고칠 방향

월드 레이캐스트 전에 포인터가 UI 위에 있는지 확인하고 있으면 건너뛴다. 게임 화면뿐 아니라 **모든 uGUI 위 클릭**에 해당하므로 `BoothInteractionInput` 쪽에서 한 번에 막는 것이 맞다.

## 발견 경위

[[S15P21A604-284]] 미니게임 웹 빌드 검증 중 발견. 그 외 전 경로(로비 → 게이트 → 월드 → 부스 → 게임 완주)는 정상이었다.

### 강형순 · 2026-08-29 00:52 KST

## 정정 — 이 이슈의 원래 진단은 틀렸다

**"암막이 클릭을 못 막는다"는 사실이 아니다.** 재측정 결과:

```
화면 중앙 UI 레이캐스트 히트 = 3  (Label / Panel / Backdrop)
Image Backdrop raycastTarget = True
Image Panel    raycastTarget = True
```

uGUI 레이캐스트는 정상이고 암막도 제 역할을 하고 있다. 처음에 "0건"이 나온 것은 **내가 버튼 화면좌표를 잘못 계산한 것**이었다.

브라우저에서 게임이 닫힌 것도, 클릭 좌표를 **브라우저 뷰포트 기준**으로 준 탓으로 보인다. Unity 캔버스는 페이지 안의 부분 영역이라 실제로는 다른 지점(십중팔구 "나가기")이 눌렸다. 재현 없이 버그로 단정했다.

## 대신 실재하는 문제를 찾았다 — 사거리 미검사

`BoothInteractionTarget.MaxDistance`(35 unit = 3.5 m)가 있는데도 **디스패처가 그것을 검사하지 않았다.** 화면에 보이기만 하면 아무리 멀어도 눌렸다.

실측: 부스에서 **6.5 m 떨어진 위치에서 클릭했는데 게임이 열렸다.**

또 하나 — `CanInteract` 는 **카메라 기준**으로 거리를 잰다. 3인칭이라 카메라가 플레이어보다 몇 m 뒤에 있어서, 카메라 거리로 재면 눈앞의 대상도 사거리 밖으로 판정된다.

## 수정 (사용자 제안 반영)

사용자가 *"애초에 클릭이 아니라 F키로 상호작용이어야 하는 거 아닌가"* 라고 지적했다. 타당하지만 **문서가 클릭을 명시**하고 있다 — `docs/02` RUNTIME-06(P0), `spec 016` User Story·Independent Test. 클릭을 빼면 FE 계약과 어긋난다.

그래서 **클릭을 유지한 채 F 를 함께 받는** 쪽으로 갔다.

- 사거리 검사 추가 — 클릭·F 둘 다 적용
- 거리 기준을 **카메라 → 플레이어**로 (없으면 카메라로 폴백, 조용히 잠그지 않음)
- `F — 상호작용` 근접 힌트 (로비와 같은 폰트, `raycastTarget=false`)
- 클릭·F 가 같은 `Dispatch()` 를 타도록 정리

## 검증 (실측)

| 상황 | 결과 |
|---|---|
| 부스에서 290 unit | `IsInRange = False` (차단) |
| 부스에서 20 unit (2 m) | `IsInRange = True` |
| 부스에서 60 unit (6 m) | `IsInRange = False` — **전에는 여기서도 열렸다** |
| 힌트 | `'F — 상호작용'`, MalgunGothicLight, raycastTarget=false, 대상 없으면 자동 숨김 |
