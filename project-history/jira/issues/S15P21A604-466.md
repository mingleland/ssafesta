## 설명

개발 환경에서 게스트로만 들어갈 수 있어 회원 전용 오버레이를 테스트할 수 없다. Google 로그인은 액세스 차단으로 막혀 있다.

[진단]
게스트 차단은 4층이다 — 라우트 가드(guard.ts:16), 컴포넌트 분기(isMember 8곳), 쿼리 enabled, 그리고 서버 403 MEMBER_ONLY. FE 만 뚫으면 서버가 403 을 주므로 반쪽이고, -458 에서 고친 게스트 403 무한 재시도가 되살아난다.

mock 모드는 그 4층을 전부 해결한다 — mockStartOAuth 가 OAuth 왕복 없이 kind='member' 세션을 만들고(api.mock.ts:114), mock API 12종이 전 오버레이 데이터를 준다.

그런데 VITE_USE_MOCK 하나가 두 가지를 동시에 가른다:
- api.select.ts (12종) -> API mock  [원하는 것]
- WorldSurface.select.ts -> Unity 정지 화면  [원하지 않는 것]
- loader.select.ts -> 메모리 mock 로더  [원하지 않는 것]

그래서 "mock 모드 + Unity 연동" 이 구조적으로 불가능하다.

[나머지 조각은 이미 갖춰져 있다]
serve.mjs 는 /api/v1/world-sessions 를 토큰 검사 없이 자체 서명해 발급한다(POST 여부만 확인). Unity 는 자기가 서빙된 origin(8000)으로 호출하므로 BE 없이도 게임 서버에 붙는다. 즉 mock 회원 세션의 가짜 토큰이어도 Unity 연동은 성립한다.

[범위]
- Unity mock 여부를 VITE_USE_MOCK 에서 분리한다. 신규 플래그가 명시되면 그 값을 쓰고, 없으면 VITE_USE_MOCK 을 따른다 — 미설정 시 기존 동작이 그대로 유지된다(하위 호환)
- 판정을 한 곳으로 모은다. 지금은 WorldSurface.select.ts 와 loader.select.ts 가 각자 같은 문장을 적어 둔다 — 하나만 고치면 엇갈린다
- 조합별 의미를 문서로 남긴다

[완료 조건]
1. mock API + 실 Unity 조합으로 회원 로그인 후 월드 진입이 된다
2. 그 상태에서 회원 전용 오버레이(부스 관리 · Studio · 지갑 · 내 정보)가 열리고 데이터가 채워진다
3. Unity 게임 서버 접속(onWorldConnectionState connected)이 확인된다
4. 플래그 미설정 시 기존 동작 무변화 — VITE_USE_MOCK=true 면 Unity 도 mock, false 면 둘 다 실물
5. 전체 vitest green / tsc 0 / oxlint 신규 경고 0

[범위 밖]
- BE dev 전용 로그인 엔드포인트 신설: BE 파트 합의 사안이다. 실 BE 데이터가 꼭 필요해지면 그때 요청한다
- FE 에 "회원인 척" 플래그: 서버가 403 을 주므로 반쪽이고 프로덕션 유출 위험이 있다

[진단]
게스트 차단은 4층이다 — 라우트 가드(guard.ts:16), 컴포넌트 분기(isMember 8곳), 쿼리 enabled, 서버 403 MEMBER_ONLY. FE 만 뚫으면 반쪽이고 -458 에서 고친 무한 재시도가 되살아난다. 그래서 mock 모드가 유일한 길인데, VITE_USE_MOCK 하나가 API mock 과 Unity mock 을 함께 갈라 "mock 모드 + Unity 연동" 이 구조적으로 불가능했다.

[구현]
Unity 쪽 판정만 떼 낸다. VITE_MOCK_WORLD 를 명시하면 그 값을 쓰고 없으면 VITE_USE_MOCK 을 따른다 — 미설정 시 기존 동작 그대로다. 판정을 shared/config/unity 한 곳으로 모았다(전에는 WorldSurface.select 와 loader.select 가 같은 문장을 각자 적어 두어 화면과 로더가 엇갈릴 수 있었다).

조합:
  USE_MOCK=false                   실 BE + 실 Unity      통합 실측
  USE_MOCK=true                    mock API + 정지 화면   화면·데이터만
  USE_MOCK=true, MOCK_WORLD=false  mock API + 실 Unity    회원 세션으로 Unity 연동 확인

세 번째가 성립하는 이유: Unity 는 world-session 을 자기가 서빙된 origin 으로 요청하고 개발용 정적 서버가 토큰 검사 없이 발급한다.

[실측]
onWorldLoadStart 205567ms -> onWorldConnectionState connected 206557ms -> onWorldGateReady 207456ms, POST /api/v1/world-sessions 200.
- Unity 자산 전부 200, canvas 1920x1080, 아바타 로비 렌더
- 11층 방에서 다른 아바타(MockUser) 동기화 확인 — 게임 서버 접속 확증
- 회원 세션: 계정 메뉴에 닉네임·Google·코인 200(게스트면 WalletBadge 가 조회 자체를 안 한다)
- 회원 전용 오버레이: 내 부스 관리가 게스트 안내가 아니라 회원 화면(부스 임대하기)로 열린다. 프로젝트 전시·AI 직원·설문도 정상
