## 설명

## 작업 목적

- `playGamePageAssetWiring.test.tsx` 3건이 실행 환경의 `.env.local`(`VITE_USE_MOCK` 값)에 따라 통과/실패가 갈리는 테스트 격리 결함 수정

## 작업 내용

- `PlayGamePage.tsx`의 `browserPublicationEnabled`(`VITE_USE_MOCK==='true' && VITE_GAME_STUDIO_API_ENABLED!=='true'`)가 true면 실제 API 대신 브라우저 로컬 mock 게시 저장소(`localPublicationRepository.ts`)로 라우팅되는데, 이 테스트는 global fetch만 스텁해서 로컬 mock 경로에서는 스텁이 무의미해짐 — 로컬 mock 저장소는 game #123이 게시된 적 없어 항상 `아직 게시되지 않은 게임입니다`를 던짐
- `playGamePageAssetWiring.test.tsx`에 `vi.stubEnv('VITE_USE_MOCK', 'false')`(및 필요시 `VITE_GAME_STUDIO_API_ENABLED`)를 고정해서, 개발자 로컬 `.env.local` 값과 무관하게 항상 실제 API 경로(테스트 fetch 스텁이 실제로 개입하는 경로)를 타도록 수정
- `afterEach`의 기존 `vi.unstubAllGlobals()`와 같은 자리에 `vi.unstubAllEnvs()` 추가

## 완료 조건

- [ ] `playGamePageAssetWiring.test.tsx` 4건 모두 `.env.local`의 `VITE_USE_MOCK` 값과 무관하게 항상 통과한다
- [ ] `VITE_USE_MOCK=true`인 로컬 환경(현재 이 checkout)과 그 값이 없는/false인 환경 양쪽에서 재현 확인
