## 설명

h3. 증상 (5173 · OAuth 회원 · 실 Unity 9a977c0d 실측, 2026-09-11)

{code}
/app/world → /app/profile → back → /app/world
  Unity canvas 는 같은 노드 (재부팅 0)          ← S15P21A604-620 정상
  document.activeElement === BODY
  W 키 30회 → 위치 (-30,27,-208) 불변          ← 캔버스를 클릭하기 전까지 WASD 가 안 먹는다
{code}

캔버스 클릭 한 번이면 풀리지만 사용자는 그걸 모른다. 라우트 왕복이 즉시가 된 만큼(-620) 이 결함이 그대로 드러난다.

h3. 원인

{{UnityHost}} 의 focus effect 가 {{[instanceReady]}} 만 본다(-450, #132 — 최초 월드 진입 시 캔버스에 focus). -620 이전에는 라우트 복귀 = {{UnityHost}} 재마운트 = 그 effect 재실행이었는데, 지금은 마운트가 유지되므로 다시 돌지 않는다.

{{captureAllKeyboardInput=false}}(!279) 라 canvas 에 focus 가 없으면 WASD·F 가 Unity 에 들어가지 않는다.

h3. 수정 — 기존 effect 하나

{{worldMount}} 의 {{visible}} 을 좁게 구독해 의존성에 더한다. hidden → visible 전이 시 다음을 모두 만족하면 {{canvasRef.current.focus()}}:

* {{instanceReady}} — 인스턴스가 서 있다
* {{screen === 'world'}} — 오버레이·메뉴가 떠 있지 않다 (기존 조건. 떠 있으면 그쪽이 키보드 주인이다)
* {{document.activeElement}} 가 body/null — React 입력창이 focus 를 갖고 있으면 침범하지 않는다

{{screen}} 은 그대로 의존성에서 뺀다 — 오버레이를 닫을 때의 focus 복구는 -428(OverlayFrame)이 이미 하고, 여기서 또 하면 두 곳이 다툰다.

h3. 하지 않는 것

* Unity 재부팅·새 store·timeout
* WorldPage ESC / InputBridge 구조
* 전역 {{querySelector}} — canvas 는 {{canvasRef}} 그대로

h3. 완료 조건

# world hidden → visible + instance ready + screen==='world' → canvas focus 1회
# hidden 인 동안 focus 0 · instance 미준비에서 throw 없이 0 · overlay 열린 채로는 탈취 0 · input 이 focus 를 가진 채로는 침범 0
# showWorld 재호출에 boot 재호출 0
# 5173 실환경: 라우트 왕복 후 **캔버스 클릭 없이** WASD 즉시 동작
# {{npx tsc -b --noEmit}} · 전체 {{vitest run}}(mock on/off) · {{npm run build}} · {{oxlint}} green
