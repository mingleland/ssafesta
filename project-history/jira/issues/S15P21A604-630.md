## 설명

## 작업 목적

- 데이터 탭 → ASSETS → "내 자산으로 교체"의 "이미지 추가"가 클릭 한 번에 파일 1장만 추가되어, 배경·인물·오브젝트용 이미지를 여러 장 준비한 경우 파일 선택 창을 장 수만큼 반복해서 열어야 한다. 한 번에 여러 장을 선택해 순차 추가할 수 있게 한다.

## 작업 내용

- `ProjectDataPanel.tsx`의 "이미지 추가" input(`type="file"`)에 `multiple` 속성 추가, `onChange`가 선택된 `FileList` 전체를 순회하도록 변경
- `GameStudioShell.tsx`의 `uploadAsset` 호출부를 파일 배열에 대해 **순차**(`for...of` + `await`)로 처리하도록 래핑 — `uploadAsset` 내부 로직(`nextStableId` → `assetRepository.save` → `addAssetReference`) 자체는 변경하지 않는다
- "타일셋 추가" 버튼은 대상에서 제외 — 세트당 아틀라스 이미지 1장이 기본 단위라 기존처럼 단일 파일 업로드 유지
- 처리 중 "n/총 처리중" 형태의 간단한 카운터 표시 (파일 1장이면 기존과 동일하게 즉시 완료, 카운터 미표시)
- 완료 시 배치 요약 토스트로 교체 — 성공 개수 + 실패 시 파일명과 사유(용량 초과/형식 불일치/자산 상한 등) 리스트
- 자산 300개 상한에 도달하면 상한을 채우는 지점까지만 처리하고, 넘는 나머지 파일은 실패로 안내

## 완료 조건

- [ ] "이미지 추가"에서 여러 이미지 파일을 한 번에 선택하면 전부(또는 상한 내에서 가능한 만큼) 자산으로 추가된다
- [ ] 처리 중 "n/총" 카운터가 보인다 (1장일 때는 기존과 동일하게 즉시 완료)
- [ ] 완료 후 성공/실패 개수와 실패 사유를 담은 배치 요약이 뜬다
- [ ] 자산 300개 상한을 넘는 배치는 상한까지만 추가되고 초과분은 실패로 명확히 안내된다
- [ ] 순차 처리로 구현되어 동시 업로드로 인한 자산 ID/blob 충돌(다른 파일 내용으로 뒤바뀌는 오염)이 발생하지 않는다
- [ ] "타일셋 추가"는 기존과 동일하게 단일 파일 업로드로 유지된다

## 선행 작업 / Dependency

- 없음

## 테스트 방법

1. `npm test` — 기존 `onUploadAsset` 목킹 테스트(`projectDataPanelAssetThumbnail.test.tsx` 등)가 시그니처 변경 후에도 통과하는지 확인
2. 신규 유닛 테스트: 파일 3장 순차 처리 시 `nextStableId`가 충돌 없이 배정되는지, 카운터·배치 요약 문구가 정확한지
3. 신규 유닛 테스트: 실패 파일 혼합(5MB 초과 등) 시 나머지는 계속 처리되고 실패 사유가 요약에 남는지, 300개 상한 근접 시 상한까지만 성공하는지
4. 수동 확인: 브라우저에서 이미지 3~5장 동시 선택 → 각 자산이 올바른 파일명·썸네일로 등록되는지(내용이 뒤바뀌지 않는지) 데이터 탭에서 직접 대조
5. `npm run build`
6. `npx tsc --noEmit`
