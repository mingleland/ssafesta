### 김가현 · 2026-09-08 12:52 KST

담당자를 황덕으로 변경함 — Redis는 백엔드가 관리하는 공용 자원이라(docs/07 아키텍처 그림, Spring/FastAPI 둘 다 같은 Redis 인스턴스에 연결), 이 작업은 AI 파트 단독 몫이 아니라고 판단해 이관함.

현재 상태: 코드 구현은 이미 완료된 상태다(feat/S15P21A604-142-rate-limit-capacity-service, MR https://lab.ssafy.com/s15-metaverse-game-sub1/S15P21A604/-/merge_requests/450 미어지). 사용자 동시성 1(1인당)·AI 직원 동시성 5·전역 20+FIFO 대기열 30/10초를 Redis INCR/DECR/ZSET/BLPOP으로 구현했다(asyncio.Semaphore는 단일 프로세스에서만 정확해 다중 replica 전역 한도를 못 지키므로 배제 — research.md §2 근거).

황덕님이 확인해야 할 것: 새 key 패밀리(`ratelimit:*`)와 BLPOP 블로킹 호출이 공용 Redis 용량·연결 풀 계획에 영향을 주는지, 기존 `conversation:*`(126번, AI 소유)와 namespace 충돌이 없는지 검토 부탁드립니다.
