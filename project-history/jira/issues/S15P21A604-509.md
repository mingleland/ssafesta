## 설명

부스 꾸미기 assetCode 어휘가 네 벌 있고 어느 것도 정본이 아니다. FE 팔레트가 쓰는 7종은 저장소 어디에도 정의가 없고, 에셋 파이프라인이 만드는 4종과 교집합이 0이다. 그 결과 팔레트 15종 중 실제 Unity 모델이 뜨는 것은 설문 키오스크 1종뿐이고 나머지는 파라메트릭 박스로 떨어진다.

접근을 "결정을 먼저 받는다"에서 "목록을 받아 FE 가 검증하고 표를 만들어 돌려준다"로 잡는다. 어휘 정본·잠금 정책 같은 결정은 그 표가 나온 뒤에 붙이는 편이 근거가 있다.

실측 조사: docs/LJH/verify/booth-asset-mapping-gap.md

[현재 어휘 — 실측]
- Unity BoothObjectRegistry : ObjectType → prefab 11개, assetCode 개념 없음
- 계약 layout-api.md : assetCode?: string (자유 문자열, 검증 없음)
- FE 팔레트 visualAssets.ts : WALL_PLAIN·COUNTER_GRAPHIC·SHELF·TRUSS_BEAM·TRUSS_PILLAR·TRUSS_GATE·PLANT (정의처가 이 파일뿐)
- 파이프라인 booth-assets.config.mjs : DECORATION_DEFAULT·FURNITURE_CHAIR01·FURNITURE_CHAIR02_WHITE·SURVEY_KIOSK_DEFAULT
- 서버 catalog_items : 97행 전부 AVATAR_PART, 부스 장식 0건

[선행 조건 — GitLab Issue 로 요청]
게임 파트에 "부스 꾸미기에 쓰는(쓸) 오브젝트 전체 목록"을 요청한다. 파일 자체는 이미 저장소에 있으므로(Art/Booth 233 · Prefabs/Booth 11 · ScriptableObjects 108) 필요한 것은 전송이 아니라 "무엇이 부스용인지"의 판정이다.
- 부스용 prefab/FBX 경로 + 한 줄 설명
- 장식형(FURNITURE·DECORATION) 외형 후보와, 타입당 prefab 1개인 현재 구조를 Unity 가 어떻게 확장할 계획인지
- ExpoKit(22) / CarnivalKit(42) 중 부스 범위
- 저장소에 아직 없는 것이 있으면 그 목록

[작업 범위]
1. 받은 목록을 booth-assets.config.mjs 에 태워 전량 변환 시도
2. 항목별 판정표 산출 — 변환 가부 / AABB 대 계약 축별 오차(mm) / 텍스처 3채널 도달 여부 / tri·바이트 / 실패 시 이유
3. 그 표를 GitLab Issue 에 회신 (이 Task 의 주 산출물)
4. 확정된 매핑으로 visualAssets.ts 의 assetCode 를 정합
5. TARGET_ASSET_CODES 를 검증 범위만큼 연다
6. 팔레트 코드와 파이프라인 코드가 어긋나면 붉어지는 테스트를 넣는다 (지금은 어긋나도 조용히 박스로 떨어져 아무도 모른다)

[완료 조건]
- 받은 목록 전 항목에 대해 "되는 것 / 안 되는 것 + 이유"가 표로 남는다
- 팔레트에 assetCode 가 붙은 항목이 파이프라인 산출물과 1:1 로 연결된다
- 어긋난 코드를 넣으면 테스트가 붉어진다
- 라이선스 게이트로 막힌 항목은 "막혔다"가 코드가 아니라 기록으로 남는다

[범위 밖]
- assetCode 어휘 정본을 어디서 관리할지 (기획 결정 — 표 회신 후 별도 상신)
- 트러스 3종 잠금·가격 정책 (기획 결정)
- 배포 반입 — ExpoKit 이 REVIEW_REQUIRED 라 라이선스 판정 전에는 로컬 Spike 범위를 못 벗어난다. 이 Task 는 "매핑이 성립하고 검증 가능하다"까지다
