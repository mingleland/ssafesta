## 설명

배포본 3bc7de33 실측: 진입 구간에서 DisplayRefreshAdapter 로그가 54건 쌓이며 120Hz 확정 → 예산 100% 미스 → vSync 1→2 → 주사율 변경 120Hz→60Hz 판정 재시작 → vSync 2→1 → 다시 120Hz 판독 → 반복.

기전: 로딩 중에는 메인 스레드가 포화돼 모든 rAF 간격이 16.7ms 이상으로 늘어나, 프로브의 하위 10% 분위마저 16.7ms 가 되어 120Hz 화면을 60Hz 로 읽는다. 미스율 가드가 그걸 막으라고 있는데, vSync 2 로 내린 직후에는 프레임이 실제로 싸져 미스율이 0 이 되고 버퍼에 남은 낡은 60Hz 판독이 그때 통과한다. 가드가 화면이 바뀐 것과 우리가 나눈 것을 구분하지 못한다.

조치: Apply() 로 vSyncCount 를 바꾼 뒤 4초(프로브 버퍼 180표본이 새 리듬으로 갈릴 때까지) 주사율 판독을 받지 않는다.

정정: 처음에는 무한 왕복이라고 보고했으나 90초 정지 실측에서 med 16.6ms 고정·로그 증가 없음을 확인했다 — 왕복은 진입 구간에 한정된다. vSync 가 프로브 판독을 나눈다는 가설도 틀렸다(vSync 2 에서도 프로브는 116~120Hz 로 정확히 읽는다).
