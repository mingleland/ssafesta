## 설명

### 작업 목적

`docs/10_Frontend_설계서.md` §3 Route 설계의 Booth 행 2개가 구현과 다르다. 디자인 레퍼런스 조사가 이 표를 IA 입력으로 읽으므로 조사 전에 정합한다.

```text
docs/10:87  /app/booths/slots
docs/10:88  /app/booths/mine
구현        /app/booths   (router/index.tsx:42, SlotListPage)
```

### 판정 근거 (2026-08-27 실측)

- **프론트엔드 라우트로서 **`/app/booths/slots`·`/app/booths/mine` 을 참조하는 곳은 `docs/10` 두 줄뿐이다. 전수 grep 결과 나머지 `booths/mine` 은 전부 API endpoint(`GET /api/v1/booths/mine`)이고 FE 라우트가 아니다.
- 구현 쪽은 `/app/booths` 로 4곳이 일관된다 — `router/index.tsx:42`, `SlotListPage.tsx:1` 파일 역할 주석, `StudioPage.tsx:100` 링크, `docker/nginx.conf:13` SPA fallback 주석.
- `/app/booths/mine` 은 별도 화면으로 만들어진 적이 없다. 내 부스는 `SlotListPage` 안의 섹션이다(`myBoothQuery` + "내 부스" 블록).
- docs/10 §3 은 구현 이전의 계획 문구다. 2026-08-23 커밋 `69a67b0`(docs(10): §3 라우트 실구현 정합)이 `/app/games/*`·`/auth/callback` 을 맞췄지만 Booth 행은 그대로 뒀는데, 그 시점에 `SlotListPage` 가 아직 없었기 때문이다(spec 004 구현은 08-24 `440769a`).

**결론: **`/app/booths` 가 정본이다. docs/10 두 줄을 최종 상태 문장으로 교체한다.

### 완료 조건

- [ ] `docs/10` §3 의 Booth 행이 `/app/booths` 하나로 교체된다
- [ ] FE 라우트로서 `/app/booths/slots`·`/app/booths/mine` 을 쓰는 곳이 0건임을 grep 으로 확인한다
