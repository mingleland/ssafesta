## 설명

BE 가 GitLab #133 (2026-09-08 10:41) 에서 S15P21A604-528 코드의 결함 3건을 통보했다. 세 건 다 코드로 재현 확인했고 지적이 맞다.

1. saveSurveyBuilder 에 늦은 응답 가드가 없다
   loadSurveyBuilder 에는 state.boothId !== boothId 가드가 있는데 저장 경로에만 빠졌다.
   저장 중 부스를 옮기면 이전 부스의 늦은 응답이 새 부스의 dirty 를 해제해 저장 버튼이 꺼지고
   미저장 변경이 사라진다. 실패 응답이면 반대로 새 부스가 error 가 된다.
   run.ts 의 submitSurveyRun 이 이미 같은 모양이라 그 패턴을 그대로 쓴다.

2. SurveyTextAnswerPage.items 가 string[] 이라 questionId 를 버린다
   서버는 {responseId, questionId, text} 를 주는데 Port 가 string 만 남긴다.
   텍스트 문항이 2개 이상인 설문에서 어느 질문의 답인지 복구할 수 없다.
   items 를 { questionId: string; text: string }[] 로 바꿈다. 이 questionId 는 서버 wire id 를 담은
   string 이고 run 경로 문항 id 와 같은 공간이다 — Builder 로컬 id(q-1)와는 무관하다.
   그 사실을 타입 주석에 명시한다. questionId 필터(계약 §8)는 쓰지 않는다.

3. firstRespondedAt · lastRespondedAt 이 Port 에 없다 — spec 인수 조건이다
   specs/010-survey/spec.md:36 US2 시나리오 1 이 전체 응답 수·최초·최근 응답 시각을 요구한다.
   -528 에서 이번에 하지 않는 것으로 분류했는데 그 판단이 틀렸다.
   Port·snapshot·state 에 더하고 결과 화면에 실제로 표시한다.
   포맷 책임은 UI 한 곳이다 — snapshot·state 는 wire ISO 원형을 유지하고 null 은 끝까지 null 이다.
   공유 날짜 util 을 새로 만들지 않는다 — 저장소에 없고 세 화면이 각자 Intl.DateTimeFormat 을 인라인으로 쓴다.

파급: mapper·mock·fixtures·result.ts 누적 로직·SurveyManagementPage 렌더·기존 테스트
