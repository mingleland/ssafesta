## 설명

## 작업 목적

- 데이터 탭 ASSETS 섹션의 "내 자산" 목록이 종류 배지·파일명·id만 보여주고 실제 업로드한  
   이미지는 전혀 렌더하지 않아, 커스텀 자산이 전부 똑같은 배지로만 보이는 문제를 해결한다.  
   바로 위 빌트인 그리드와 "재료함"(AssetPickerModal)은 실제 썸네일을 보여주는 것과 대조된다.

## 작업 내용

- `ProjectDataPanel`에 `assetUrls` prop 추가
- `GameStudioShell.tsx`가 이미 계산해둔 `assetUrls`(`useResolvedAssetUrls`)를 InspectorPanel·  
   DialogueEditor에 하던 것과 동일하게 ProjectDataPanel에도 전달
- `.gss-asset-list` 각 행에서 IMAGE는 `resolveStaticImageVisual(asset, assetUrls)` +  
   `staticImageBackgroundStyle`로, TILESET은 기존 import된 `tileBackgroundStyle`로 실제 썸네일  
   스와치 렌더(`gss-builtin-library`와 동일 패턴) — AUDIO는 이미지가 없으므로 기존 배지만 유지

## 완료 조건

- [ ] 데이터 탭 "내 자산" 목록에서 IMAGE 자산이 실제 업로드한 이미지로 표시된다
- [ ] TILESET 자산이 실제 타일셋 이미지로 표시된다
- [ ] AUDIO 자산은 기존과 동일하게 배지만 표시된다(회귀 없음)
- [ ] `assetUrls`가 아직 해석되기 전(로딩 중)에도 레이아웃이 깨지지 않는다
- [ ] `npx vitest run`, `npm run build`, `npx tsc --noEmit`, `npm run lint` 통과

## 선행 작업 / Dependency

- 없음

## 테스트 방법

1. 커스텀 이미지 업로드 → 데이터 탭 자산 목록에서 실제 이미지 썸네일이 보이는지 확인
2. 타일셋 업로드 → 타일셋도 실제 썸네일(첫 타일)로 보이는지 확인
3. AUDIO 자산(있다면) → 기존처럼 배지만 표시되고 깨지지 않는지 확인
4. `assetUrls`가 아직 해석되기 전(로딩 중) 상태에서도 레이아웃이 깨지지 않는지 확인
5. `npx vitest run`, `npm run build`, `npx tsc --noEmit`, `npm run lint` 통과
