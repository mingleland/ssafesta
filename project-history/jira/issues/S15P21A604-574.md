## 설명

Unity WebGL 빌드·배포·타 파트 공유 구조를 실제 저장소·GitLab·Jenkins 기준으로 실측하고, 최적 구조(F안)를 검증해 Infra 로 이관한다.

범위
- 현행 Unity 빌드 절차·Package Registry·Jenkins/GitLab CI·Unity Agent·환경별 WebGL 배포 구조 실측
- 후보 A~F 비교와 F안(기존 Unity Agent 산출물을 release/deploy 파이프라인에 연결) 검증
- provenance manifest 와 배포 검증·rollback 계약 정리
- infra-001 T022A~T022F 를 최신 Linux Unity Agent 실측 기준으로 재기술하는 제안 작성
- GitLab #142(Infra 인계)·#163(Dev route·scheme) 게시

범위 밖
- T022 실제 구현(스크립트·compose·nginx·pipeline 변경)은 포함하지 않는다. Infra 소관이다.
- Unity PlayerSettings 변경, Package 업로드, CI 설정 변경 없음.

산출물
- docs/LJH/verify/unity-webgl-build-deploy-pipeline-0910.md (조사 근거)
- scratchpad/unity-webgl-cicd-infra-review.md (Infra 공유 검토안)

판정 고정
- Linux Unity CI 자체가 막힌 상태는 아니다.
- FBX 이관 이후 Jenkins #42/#52 가 약 40분 실행되어 validate/test 를 지나 ci/build 까지 진입한 정황이 강하다.
- 다만 최신 Builds/webgl 완성 여부와 #52 의 정확한 실패 stage 는 미확정이다.
- 따라서 F안은 현재 최적 구조로 유지하되 "Jenkins 가 WebGL 을 정상 완주한다" 로 확정해 쓰지 않는다.

### 이정헌 · 2026-09-10 10:57 KST

조사·게시 완료. T022 구현은 범위 밖이라 이 티켓은 Infra 회신 대기 상태로 둔다.

산출물
- docs/LJH/verify/unity-webgl-build-deploy-pipeline-0910.md — MR !561 develop 병합 (72912661)
- GitLab #142 note 2784296 — F안 전체 검토안 15장
- GitLab #163 note 2784302 — Dev route·scheme 결정 요청 2건

핵심 실측
- Jenkins Unity Agent 가 이미 develop 병합마다 WebGL 을 빌드한다. 끊긴 곳은 산출물 미반출·webglArtifactUri 미사용·deploy 필터의 game 제외 셋이고 전부 파이프라인 배선이다.
- webglArtifactUri 는 release-manifest 스키마에 이미 선언돼 있고 build-release-manifest.sh:41 이 통과시키는데 생산자·소비자가 0 이다.
- deploy-webgl-release.sh 는 infra-001 T022C 로 이미 계획돼 있다(미착수). T022A~F 는 Windows 빌드 PC 전제라 재기술이 필요하다.
- Jenkins 빌드 지속시간이 실패 지점을 갈랐다. FBX 이관 전 game 빌드는 2~3분(#16 2.6 / #21 2.1), 이후는 40분(#42 42.6 / #52 39.7) 이다.
- Dev 는 평문 HTTP + insecureHttpOption 0 이라 Release WebGL 이 월드까지 못 간다. 근본 해결은 Dev HTTPS 로 보고 PlayerSettings 완화는 제안하지 않았다.

철회한 가설
- front/back/game 공통 Candidate Manifest 실패 — 지속시간 분포와 맞지 않아 철회했다.

Infra 회신 대기 (F안 착수 판정에 필요한 것)
- #52 로그의 정확한 실패 stage
- Unity Agent workspace 의 Builds/webgl 4종 완성 여부
- shared volume 재사용 여부 · webglArtifactUri 확정 · Dev HTTPS · /unity 경로 계약

### 이정헌 · 2026-09-10 14:29 KST

이관 surface 를 옮겼다. Unity WebGL 자동 배포의 정본은 이제 GitLab #165 이다.

h3. 왜 옮겼나

조사도 끝나고 Game·FE 선행분도 끝났는데 논의가 #142 안에 27개 코멘트로 묻혀 있었다. #142 는 원래 [game→infra] 라이선스·Dedicated Server 인수 이슈고 그 위에 WebGL 릴리스 왕복 5일치가 쌓였다. Infra 가 그 스레드를 열어 지금 무엇을 착수할 수 있는가를 뽑아내려면 전부 읽어야 했다.

h3. #165 에 옮긴 것

판단에 필요한 것만이다 — Infra 선행 확인 2건(#52 실패 stage · Builds/webgl 4종 완성 여부)을 맨 위에 두고, blocker 3건을 파일·행까지 인용했고(component.groovy:32 · build-release-manifest.sh:41 · develop.groovy:32), 권고 F안·provenance 계약·T022A~F 재기술안·역할 경계·완료 조건을 붙였다. 조사 전문은 복붙하지 않고 !561 로 링크했다.

h3. 새로 찾은 사실 1건

infra/jenkins/agents/compose.yaml 실측 — unity-agent 에만 image_transfer 볼륨이 안 붙어 있다. linux-docker-agent 와 deploy-agent 는 붙어 있고 image-transfer-init 컨테이너도 이미 있다. 권고 handoff 의 첫 삽이 compose 한 줄이라는 뜻이다. 재사용할지 전용 볼륨을 팔지는 Infra 결정이라 제안까지만 적었다.

h3. 선행 완료 확인

Game 몫 manifest provenance 가 !578 로 develop 에 도달했다 — FestaWebBuilder.cs 에 schemaVersion·sourceCommit·dirty·unityRevision·buildProfile·apiEnvironment·compression·builtAt 8필드. 로더 URL 4종은 그대로라 FE 소비 코드 영향이 없다.

h3. 이 티켓

상태는 진행 중 유지한다. FE 조사·이관은 끝났고 T022 구현은 범위 밖이며, 남은 것은 Infra 선행 확인 2건이다. #163 route 결정은 그대로 #163 이 정본이고 #165 T022F 가 그것을 소비한다.
