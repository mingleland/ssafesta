## 설명

### 작업 목적

임차인이 24시간을 기다리지 않고 자기 임대를 스스로 끝내고 슬롯을 반납할 수 있게 한다. 지금은 임대를 끝내는 경로가 만료뿐이라, 자리를 잘못 고른 사람은 24시간 동안 다른 자리로 옮길 수 없다 (`ACTIVE_LEASE_LIMIT`).

**코인은 돌려주지 않는다.** spec 004 D06·FR-013 이 금지하는 것은 변심에 의한 *환불*이고, 이 작업은 환불 없이 슬롯만 조기 해제한다. 따라서 팀 재결정 없이 진행 가능하다.

### 작업 내용

- `LeaseStatus` 에 `CANCELLED` 추가 — `booth_leases.status` 는 `VARCHAR(20)` 이고 CHECK 제약이 없으므로 **마이그레이션 불필요**
- `BoothLease.cancel()` 추가 (`expire()` 와 같은 자리, 상태 값만 다름)
- `BoothLeaseService` 의 private `expire(BoothLease)` 를 `release(BoothLease, LeaseStatus)` 로 일반화하고, 만료 경로 3곳(`expireStaleLeases`·`releaseStaleLeases`·`releaseStaleLeasesOfMember`)은 `EXPIRED` 로 그대로 호출
- `BoothLeaseService.cancel(userId)` 신설 — `@Transactional`, `wallets.lockOwner(userId)` 로 `lease()` 와 같게 직렬화, `findValidByLesseeUserId` 로 본인 활성 임대를 찾아 `release(lease, CANCELLED)`
- `BoothSlotController` 에 `DELETE /api/v1/booth-slots/{slotId}/leases/mine` 추가 (게스트 `403 MEMBER_ONLY`)
- `ErrorCode` 에 "활성 임대가 없다" 1종 추가

기존 `expire()` 가 이미 한 트랜잭션에서 세 가지를 처리한다 — 임대 상태 전이 · `booth.detachSlot()` · `aiDocuments.deactivate(boothId)`. 취소는 상태 단어만 다른 같은 세 가지이므로 그 메서드를 재사용한다. `BoothLeaseRepository` 의 유효성 쿼리는 전부 `status = ACTIVE` 로 걸려 있어 `CANCELLED` 는 **쿼리 수정 없이** 모든 판정에서 빠진다.

### 테스트 방법

1. 슬롯 A 임대 → 잔액 100 차감 확인
2. `DELETE /api/v1/booth-slots/{A}/leases/mine` 호출
3. 슬롯 A 가 `AVAILABLE`, 잔액은 **차감된 그대로**(환불 없음) 확인
4. 곧바로 슬롯 B 임대 → `201` 성공 확인
5. 다시 슬롯 A 임대 → 이전 부스 콘텐츠가 Draft 로 보존되어 있는지 확인
