## 설명

h3. 배경
2026-09-08(월) 사용자 테스트 전에 게임 파트를 FE(5173)·BE(8080)·AI(8001)·게임 서버(7777)와 한 스택으로 붙여 실측해야 한다. 지금까지의 실측은 WebGL 단독 페이지(같은 오리진 :8000)에서만 했고, FE 가 Unity 를 임베드하는 실제 경로(5173 → 8000)는 한 번도 돌려 보지 않았다.

h3. 발견
* Tools/mock-api/serve.mjs 는 CORS 헤더가 없어 FE 페이지에서 로더·데이터 파일 fetch 와 Authorization 을 든 /api/v1 호출이 막힌다. 허용 오리진을 명시하는 옵션이 필요하다(와일드카드 금지 — Spring 의 FRONTEND_BASE_URL 단일 허용 정책과 같은 결).
* manifest.json 의 URL 4종이 상대경로인데 FE resolver/loader 는 값을 그대로 script.src·createUnityInstance 에 넘긴다 → FE 오리진 기준으로 해석돼 404. GitLab #127 에 FE 측 해석(BUILD_BASE 기준 new URL) 을 제안한다.

h3. 할 일
* serve.mjs 에 --allow-origin <origin> 옵션(지정 시에만 CORS 헤더·OPTIONS 응답)
* 릴리스 WebGL(Local env) + --spring 프록시 + FE 임베드로 로그인→로비→월드→관리 데스크(414)·설문 키오스크(415) 진입 E2E
* Development WebGL 로 PerfHud·StressSpawner 실측, 결과를 docs/24 와 -206·-76 근거로 기록
