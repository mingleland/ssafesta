## 설명

## 작업 목적

Unity 가 S15P21A604-434(!279)로 G-8 입력 잠금 계약을 develop 에 넣었으나 FE 호출부가 없어 계약이 발동하지 않는다. 강형순 님 2026-09-05 23:00 실측에서 두 결함이 확인됐다.

1. 관리 오버레이가 열린 상태에서 WASD 가 월드로 새어 들어간다 — SetInputLocked 배선이 없다.
2. /app/world 진입 직후 document.activeElement 가 SECTION 이라 첫 키 입력이 무시된다. 캔버스를 한 번 클릭해야 움직인다. !279 로 WebGLInput.captureAllKeyboardInput=false 가 들어가면서 생긴 의도된 변화의 뒷면이다(설문·상담 입력창을 살리기 위한 것).

## 작업 내용

- OverlayHost open  -> unityInstance.SendMessage('InputBridge', 'SetInputLocked', '1')
- OverlayHost close -> SendMessage('InputBridge', 'SetInputLocked', '0')
- 최초 월드 interactive 진입 시점(acquireUnitySession resolve 또는 onWorldGateReady)에 canvas.focus() 1회. canvas 는 tabIndex=-1 이라 프로그램 focus 가 된다(S15P21A604-421).

InputBridge 는 AuthBridge 와 같은 자동 등록 오브젝트이고 씬 무관·상태 static·멱등이라 중복 호출과 순서 어긋남에 안전하다. 실제 API 이름·시그니처는 GitLab #132 와 develop 의 Unity 코드 기준으로 확인하고 추측하지 않는다.

## 완료 조건

1. Overlay open 시 Unity 월드 입력이 잠긴다
2. Overlay close 시 잠금이 풀린다
3. 기존 S15P21A604-428 focus 복구 회귀 없음
4. 최초 월드 진입 시 canvas 에 focus 가 간다
5. ESC 우선순위 회귀 없음
6. Overlay Bus 구조 훼손 없음
7. 키보드 소유권 중복 로직 없음 — Unity 가 이미 하는 판정을 FE 가 다시 만들지 않는다
8. unit test
9. tsc 0
10. vitest 전체 green
11. oxlint 신규 경고 0

실 WebGL 왕복(WASD·F 상호작용·ESC·React 입력창·overlay open/close)은 Unity 빌드 환경 부재로 2026-09-08 통합 acceptance 로 이월한다. 그때까지 Jira Done 으로 전환하지 않고 Closes 도 쓰지 않는다.
