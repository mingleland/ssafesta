## 발생 환경

- Branch: develop (인프라 설정/자격증명 범위 — 코드 아님)
- Build: demo/production (`api.ssafesta.world`)
- Account: 소유자 계정(어느 계정이든, 어느 파일 크기든 재현)

## 재현 방법

1. `POST /api/v1/games/{gameId}/assets`로 업로드 시작 — 정상적으로 `assetId`·`uploadUrl` 발급됨.
2. 응답의 `uploadUrl`에 `PUT`으로 파일을 올린다(74byte짜리 최소 PNG로도 재현됨 — 크기 무관).
3. R2가 요청 자체를 거부한다.

## 기대 결과

presigned PUT이 성공하고, 이어서 `POST /{assetId}/complete`가 `status: READY`를 반환해야 한다.

## 실제 결과

```xml
HTTP/1.1 403 Forbidden
<Error><Code>AccessDenied</Code><Message>Access Denied</Message></Error>
```

이후 `complete` 호출은 `STORAGE_UNAVAILABLE`을 반환한다(업로드된 바이트가 없으니 당연한 결과).

**추정 원인** — 코드/설정 조사 결과:

- `infra/environments/storage/r2/buckets.example.yaml`(예: `origin/docs/S15P21A604-155-r2-signing-record`)에는 R2 버킷이 `documentBucket`(AI 문서용)·`backupBucket`(DB 백업용) 2개만 정의돼 있고, 게임 자산용 버킷은 없다.
- `ObjectStorageProperties.java` 클래스 주석: *"Object storage for ****AI document originals**** (spec 007 C-07, C-10)"* — 이 R2 클라이언트는 애초에 AI 문서 전용으로 설계됨.
- 그런데 `GameAssetService`(Game Studio, spec 019)가 스프링 DI로 이 **동일한 **`ObjectStorage` Bean을 그대로 재사용하고 있다(별도 구현체·설정 분기 없음).
- 즉 R2 자격증명(Cloudflare API 토큰)의 권한 범위가 `documents/...` 접두사에만 주어져 있고, `GameAssetService`가 실제로 쓰는 `games/{gameId}/assets/...` 접두사는 범위 밖일 가능성이 높다.

## 로그 / Screenshot

presigned URL 버킷명이 `festa_documents`로 찍힘(AI 문서 버킷으로 추정) — 게임 자산 경로(`games/2/assets/...`)와 불일치.
