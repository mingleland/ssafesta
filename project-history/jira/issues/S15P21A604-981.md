## 설명

## 배경

현재 프로젝트 소개는 운영자 입력값을 그대로 사용하고, 대상 사용자- 기술 스택은 문서 Chunk 키워드 순위로 한 번 추출합니다. Demo 스냅샷에서 대상 사용자- 기술 스택 보유율은 2/11이며, 기술 근거가 뒤쪽 Chunk에 있으면 누락됩니다.

## 목표

운영자 검토 없이 문서 처리 완료 후 AI 직원에게 질문하듯 기존 RAG 검색- 생성 경로로 정형답변을 만들고 저장합니다.

## 범위

- 문서 READY 후 비동기 enrichment 실행
- 고정 질문: 프로젝트 소개, 주요 대상 사용자, 기술 스택
- boothId + agentId 필터를 강제하고 활성 문서 전체를 검색
- 답변 본문과 출처 document/chunk 식별자, 생성 버전을 저장
- 새 세 항목 생성이 성공한 경우에만 한 세트로 교체
- 문서 추가- 삭제- 비활성화 시 재생성
- 생성 중에는 기존 값을 유지하고, 값이 없으면 기존 RAG 경로로 fallback
- 사용자가 작성한 projects.description은 덮어쓰지 않음

## 완료 조건

1. READY 문서의 근거가 있으면 세 정형 질문이 저장값으로 즉시 응답한다.
2. 근거가 없는 항목은 추측하지 않고 null로 남아 일반 RAG로 처리된다.
3. 타 부스- 타 Agent Chunk가 섞이지 않는다.
4. enrichment 실패가 문서 READY를 실패로 바꾸지 않으며 원인이 로그에 남는다.
5. 재시도와 중복 실행이 멱등이고 오래된 실행이 최신 결과를 덮지 않는다.
6. 기존 projectFacts 계약과 수동 프로젝트 설명이 하위 호환된다.
7. AI- Backend 단위 및 통합 테스트로 생성- 저장- fallback- 최신성- 격리를 검증한다.
