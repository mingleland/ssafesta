## 설명

## 배경

GitLab 이슈 #117 에서 배포 프로파일을 `application-infra.yml` 로 가기로 확정됐고, 그 파일이 `-170`(MR !150, 커밋 `a51f88a0`, 2026-08-31 12:36)으로 develop 에 실제로 들어왔다. 그런데 그 파일만으로 배포하면 애플리케이션이 기동하지 않는다.

## 실측 (origin/develop 기준)

| 파일 | 내용 |
|---|---|
| `backend/src/main/resources/application.properties` | `spring.profiles.default=local`, 로깅 패턴. 설정 없음 |
| `backend/src/main/resources/application-local.yml` | **96줄. 공통 설정이 전부 여기 있다** |
| `backend/src/main/resources/application-infra.yml` | **5줄.** `app.world.scheme/host/port`, `app.world.connection-token-secret` 뿐 |

`application-local.yml` 이 담고 있는 것:

```
spring.datasource / spring.jpa / spring.flyway / spring.data.redis / spring.security.oauth2
app.auth / app.wallet / app.world / app.lease / app.game / app.internal / app.agent
```

## 문제

Spring 의 `application-{profile}.yml` 은 해당 프로파일이 활성일 때만 로드되고 프로파일 간에 누적되지 않는다. 배포에서 `SPRING_PROFILES_ACTIVE=infra` 로 띄우면 `application-local.yml` 96줄이 통째로 로드되지 않는다. `spring.datasource.url` 이 없어 JPA·Flyway 자동설정이 실패하고 애플리케이션이 기동하지 않는다.

#117 이 처음 보고한 문제(compose 가 환경변수를 하나도 넘기지 않는다)보다 나쁜 상태다. 환경변수를 전부 주입해도 그 값을 읽을 설정이 없다.

## 완료 조건

- [ ] 프로파일 중립 설정을 `backend/src/main/resources/application.yml` 로 옮긴다 — `spring.datasource`, `spring.jpa`, `spring.flyway`, `spring.data.redis`, `spring.security.oauth2`, `app.*`
- [ ] 공용 위치에는 비밀값 기본값을 두지 않는다. `${POSTGRES_PASSWORD}` 형태로 두고 값이 없으면 기동이 실패하게 한다. 로컬 기본값(`change-me-local-only` 등)은 `application-local.yml` 이 덮는다
- [ ] `application-local.yml` 에는 `spring.config.import`(`.env` 읽기)와 로컬 기본값만 남긴다
- [ ] `spring.data.redis` 에 `username`·`password` 주입 자리를 만든다 — infra-002 T015 가 Redis 기본 사용자를 비활성화하고 ACL 을 켜므로 현재 설정(host·port 만)으로는 연결이 거부된다
- [ ] `SPRING_PROFILES_ACTIVE=infra` 와 필요한 환경변수만으로 기동하는지 확인한다
- [ ] `docs/08_Backend_API_명세서.md` §20 환경변수 표를 갱신한다 — `ROOT_DOMAIN` 추가(`-170` 이 들여왔고 표에 없다), 프로파일 정답값 `SPRING_PROFILES_ACTIVE=infra` 명시

## 검토한 대안

`SPRING_PROFILES_ACTIVE=local,infra` 로 두 프로파일을 겹쳐 띄우면 코드 변경이 없다. 기각한다 — 배포 환경에서 `local` 프로파일이 활성이 되고, `change-me-local-only` 같은 로컬 기본값과 `.env` 파일 import 가 프로덕션 설정 경로에 남는다. #117 이 경고한 "배포에서도 local 이 뜬다" 를 정식화하는 셈이다.

## 범위 밖

infra-002 T059(`RedisKeyspaceProperties.java` 신설)·T060(`MemberSessionService`·`OAuthHandoffService`·`DailyCoinGrantService` 의 Redis 키에 환경 네임스페이스 prefix)은 BE 파일을 건드리지만 담당이 정해지지 않았다. #117 에서 확인 중이며 이 작업에 포함하지 않는다.
