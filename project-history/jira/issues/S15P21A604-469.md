## 설명

develop 에서 npm run build (= tsc -b && vite build) 가 tsc -b exit 2 로 멈춘다. && 라서 vite build 는 실행조차 되지 않고, festa-frontend/Dockerfile:28 이 이 명령을 돌리므로 FE 이미지 빌드가 실패한다.

[에러 6건]
queryRetryPolicy.test.ts:22       TS2345  retry(failureCount, error) - TanStack retry 2번째 인자는 TError(기본 Error)인데 unknown 을 넘김
screenAudio.test.ts:26            TS1294  constructor(public src: string) - parameter property, erasableSyntaxOnly 위반
screenAudioUi.test.tsx:25         TS1294  동일
globalSelectionPolicy.test.ts:6,7,8  TS2591  node:fs / node:url / node:path 타입 미해결

[원인]
tsconfig.app.json 이 include: ["src"] 라서 src/**/__tests__/** 도 앱과 같은 프로젝트로 컴파일된다. 테스트가 앱과 같은 types: ["vite/client"] 와 erasableSyntaxOnly: true 를 상속받는다.
- types 에 "node" 가 없다 -> @types/node 가 devDependency 로 이미 설치돼 있는데도 node:fs 가 안 잡힌다. 설치 문제가 아니라 노출 문제다
- erasableSyntaxOnly 는 타입만 지우면 JS 가 되는 문법만 허용한다. parameter property 는 값 할당 코드를 생성하므로 금지다

vitest 는 esbuild 로 타입을 벗겨 내고 실행하므로 660/660 이 전부 통과한다. 두 도구가 보는 것이 다르다.

[유입 시점 - worktree 로 커밋별 실측]

3건 전부 내 MR 이다. -463~-467 에 "tsc 0" 으로 보고한 것은 사실이 아니었다 - npm run build 가 아닌 명령으로 확인했다. .gitlab-ci.yml 은 러너가 없어 파이프라인이 정지 상태라 아무도 대신 잡지 못했다.

[해결 - 4파일 9줄, 설정 무변경]
1. retry(failureCount, error as Error)
2. parameter property 2건을 필드 선언 + 대입으로 전개
3. globalSelectionPolicy.test.ts 최상단에 /// <reference types="node" />

[검토했다가 버린 안 2가지]
- tsconfig.app.json 의 types 에 "node" 추가: 앱 코드에서도 node 빌트인이 타입상 허용된다. 브라우저 번들의 경계를 여는 대가가 테스트 한 파일보다 크다
- 테스트 전용 tsconfig.test.json 분리: 옳은 방향이지만 이번 복구에는 과하다. 삼중 슬래시 지시자는 그 파일에만 node 타입을 연다

또 index.css?raw 로 node 의존을 없애는 안을 실제로 시도했는데, vitest 는 기본 css: false 라 빈 문자열이 돌아와 9건이 붉어졌다. 폐기했다.

[완료 조건]
1. npm run build exit 0
2. vitest 660/660
3. oxlint 신규 경고 0
4. tsconfig 무변경

[재발 방지]
MR 전 게이트는 npm run build 다. tsc -p tsconfig.app.json 이나 vitest 단독은 Dockerfile 이 도는 것을 재현하지 못한다. 러너가 없어 CI 로 강제할 수단은 현재 없다.
