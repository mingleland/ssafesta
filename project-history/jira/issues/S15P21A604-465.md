## 설명

알림을 레이아웃 밖 공통층으로 빼낸다. 계기는 로그인 저해상도 결함이지만, 그것을 고치는 방식이 아니라 먼저 공통층을 깔고 그 위에 올린다.

[문제]
vh 500 에서 로그인 패널은 기본 249px, 푸터 여유 +28px 다. alert 가 붙으면 상단 notice +49px, 하단 guestError +68px 로 자라 푸터를 뚫는다(둘 다 뜨면 366px, 푸터 -90px). alert 하나를 흐름 밖으로 빼는 것만으로는 두 개가 겹칠 때 다시 넘친다.

[정본 - 새로 발명하지 않는다]
- 소관: React 확정 (02_audit/ui-ownership-matrix.md:13)
- 위치: 우상단, Consultation Quick Access 아래(일시적) (04_prototypes/screen-specifications.md:404)
- 계층: world < screen-ui < overlay-dim < overlay < toast < system (03_foundation/visual-dna.md:42)
- HUD 예산: 총 점유 15% 미만, 모서리 배치
- 현황: 공통 구현 없음, feature-local 3계보 혼재 (02_audit/screen-inventory.md:41)

[z-index 실측]
PageShell 0/1, WorldHud 20, MockInteractionBar 30, ScreenControls 40, GameMenu 80, OverlayFrame 100, GameOverlay 10000. toast 자리가 비어 있다 -> 200.

[범위 - Phase 1]
- src/shared/ui/toast/ : toastStore.ts (module-level store + useSyncExternalStore), ToastHost.tsx, toast.css
- AppProviders 에 ToastHost 마운트(라우터 밖)
- index.css 에 z-index 계층 토큰 4개 정의. 기존 14곳 치환은 하지 않는다 - 다음 작업이 점진 이행한다
- LoginPage 의 login-alert 3종(notice 2 + guestError) 을 showToast 로 이관
- 화면별 기준점은 --festa-toast-top 변수로 흔수한다(로그인: ScreenControls 아래 / 월드: Consultation 아래)

[정책]
- 수명: info/success 는 4초 자동, error 는 자동 소멸하지 않고 닫기 버튼으로만 닫는다(서버 오류를 못 읽고 놓치면 안 된다)
- 중복 억제: 같은 message+kind 는 쌓지 않고 기존 id 를 돌려준다(게스트 버튼 연타 방어)
- 최대 3개. 초과하면 가장 오래된 것을 밀어낸다(HUD 예산 15%)
- 접근성: 컨테이너 role=region aria-label 알림, 각 토스트 role=alert. 포커스를 빼앗지 않는다. Esc 는 월드에서 걸지 않는다(worldScreen.closeTopScreen 소유, -450)
- 모션: opacity + 8px translateY 하나만. prefers-reduced-motion 에서는 즉시 표시

[이관 범위 판정]
role=alert 14곳을 전수 조사해 LoginPage 3종만 옥긴다. UnityHost 2(화면 자체 상태), FacadePanel 4(필드 검증), LeaseConfirmDialog 2, NicknameForm 1, GameOverlay 2, Game Studio 4 는 제자리가 맞다. 공통층을 만든다고 전부 끌어오면 3계보가 4계보가 된다.

[완료 조건]
1. vh 500 에서 오류 발생 전후 패널 높이 249px 불변, 푸터 여유 +28px 유지
2. notice + guestError 동시 상황에서도 동일
3. 1920x1080 버튼 4종 좌표 무변화 (x 38.8%, y 58.8/66.7/74.59/82.49%)
4. 토스트가 ScreenControls 와 겹치지 않는다
5. error 는 자동으로 사라지지 않고 info/success 는 4초에 사라진다
6. 전체 vitest green / tsc 0 / oxlint 신규 경고 0

도입 근거는 OnSent 주석에 명시돼 있다 — "FE 가 없는 단독 실행에서는 화면 변화가 없어 안 된다 로 보인다". 즉 단독 실행 디버깅용인데 게이트가 없어 배포본까지 나간다.

[제시한 선택지]

B. 제거하고 React 가 맡는다 — 정본상 소관은 React 지만 FE 는 실제로 띄울 계획이 없다(오버레이가 곷바로 열려 띄울 것이 없다). 사실상 "그 안내를 없앵다" 와 같다
C. 그대로 둔다 — 의도라면 ui-ownership-matrix 충돌 2번을 "해소: 의도된 Unity 소관" 으로 닫는다

[함께 구분한 것]
