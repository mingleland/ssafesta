## 설명

#206 긴급 규약으로 FE 작업이 front 에 배칭된 뒤 develop 에 닿지 못하고 누적됐다.

기존 front→develop MR(!992)은 .gitlab-ci.yml 의 workflow.rules 1번이 소스 브랜치를 ^(feat|feature|fix|refactor|test|docs|chore|build|ci|hotfix|perf)/ 로 제한해 파이프라인이 생성되지 않는다. front 는 그 정규식에 맞지 않아 detailed_merge_status=ci_must_pass 로 영구히 막힌다(infra S15P21A604-807).

BE 가 같은 상황을 chore/S15P21A604-825-back-to-develop 로 풀었고, frontend-hold 도 chore/S15P21A604-798-frontend-hold-to-develop 로 들어갔다. 같은 방식으로 규약에 맞는 브랜치를 front 에서 떼어 develop 행 MR 을 만든다.

front 는 develop 을 전부 포함한 상태(0 behind)로 맞춘 뒤 분기하므로 AGENTS.md 8조가 막는 '부분 트리 머지로 타 파트 파일 삭제' 는 발생하지 않는다.
