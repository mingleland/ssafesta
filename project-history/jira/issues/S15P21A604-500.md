## 설명

작업 목적

infra 가 실행한 R2/MinIO reconcile 검증 결과를 Spring 이 받아 storage_reconciliation_log 와 문서 storageProvider 에 반영한다 (GitLab Work Item #100). OpenAPI 계약은 확정돼 있는데 Spring 수신단 구현이 0줄이다.

작업 내용

- specs/007-ai-agent-document/contracts/spring-storage-reconciliation-api.yaml 을 그대로 구현한다. 서버 prefix 는 /internal/storage 이고 infraServiceToken 으로 인증한다.
- 동일 runId + documentId 재전송은 상태를 다시 반영하지 않고 멱등하게 성공한다.
- VERIFIED 상태만 문서 storageProvider 를 변경한다.
- documentId 가 없으면 404, 요청 형식 검증 실패는 422 를 낸다.

완료 조건

- 계약의 204·404·422 응답이 계약대로 나온다.
- 같은 runId + documentId 재전송이 상태를 다시 바꾸지 않는다.
- VERIFIED 가 아닌 상태로는 storageProvider 가 바뀌지 않는다.

선행 작업 / Dependency

- 없음. 서버 없이 구현·테스트가 끝난다.

참고

- specs/007-ai-agent-document/contracts/spring-storage-reconciliation-api.yaml
- 기존 내부 API 인증 구현: backend/src/main/java/com/example/ssafesta/internal/ai/ (AiInternalSecurityConfiguration, InternalServiceTokenFilter)

비고

infra 쪽 실행·운영 몫은 S15P21A604-215 다. 이 이슈는 그 결과를 받는 Spring 수신단이고, 그 토큰은 AI 용 내부 토큰과 별개다.
