## 설명

게임 파트가 GitLab #166(2026-09-10)으로 타이밍 스톱 미니게임 화면을 Unity 에서 FE 오버레이로 넘기겠다고 통보했다. Unity 는 F 상호작용 이벤트만 보내고 게임 진행·서버 판정 호출·결과 표시를 FE 가 맡는다. 계약은 note 2787303 으로 확정했다.

BE 는 이미 끝났다 — S15P21A604-502 가 develop 에 도달했고 specs/014-minigame/contracts/minigame-api.yaml 이 정본이다.

[범위]
1. events.ts 의 WorldInteractEvent union 에 WORLD_MINIGAME_INTERACT 추가 (gameId, machineId)
2. dispatcher.ts 에 case 추가 — openVisitorOverlay('MINIGAME', ...)
3. OverlayType 에 MINIGAME 추가, OverlayHost 분기 추가
4. entities/minigame/api.ts — 세션 발급·결과 제출
5. features/minigame/ — TimerStopOverlay + 상태 모델
6. MockInteractionBar 에 dev 항목 1개(프로덕션 미노출)

새 .jslib·callback·input-lock API·오버레이 shell 을 만들지 않는다. transport 는 기존 onBoothInteract 를 그대로 쓰고, 배타·ESC·입력잠금·focus 반환은 worldScreen·UnityHost·OverlayFrame 이 이미 하는 것을 그대로 따른다.

[설계를 지배하는 서버 제약]
TimerStopService 가 |serverElapsed - stoppedSeconds| > 2.0초 면 세션을 REJECTED(터미널)로 만든다. 그래서 세션을 발급해 두고 사용자가 기다리는 READY 구간을 두지 않는다 — 시작 버튼을 누른 뒤 발급하고 201 이 오는 즉시 달린다. 정지 즉시 제출한다.

[FE 가 계산하지 않는 값]
errorSeconds·tier·timedOut·rewardedCoins·dailyLimitReached·dailyRemainingCoins·accepted 는 전부 서버 값을 그대로 쓴다. FE 가 만드는 값은 stoppedSeconds 하나다.

[게스트]
서버가 403 MEMBER_ONLY 로 세션 발급 단계에서 거부한다. FE 도 발급 전에 막고 로그인을 유도한다 — 플레이시킨 뒤 401·403 을 보여주는 흐름은 만들지 않는다.

[완료조건]
1. MockInteractionBar 에서 실 BE 세션 발급·결과 제출·판정 렌더까지 왕복이 돌아간다
2. 게스트 차단이 세션 발급 전에 동작한다
3. 결과 variant · 400 · 404 처리가 테스트로 잠긴다
4. 중복 제출이 1회로 막힌다
5. OpenAPI required 필드와 FE 타입이 어긋나면 테스트가 붉어진다
6. tsc · vitest 전체 · build · lint green
7. 오버레이 닫기 후 worldScreen 이 world 로 복귀한다

[범위 밖 — 별도 HOLD]
실 Unity F → WORLD_MINIGAME_INTERACT 송신 왕복은 송신부가 develop 에 도달한 뒤에 확인한다. 현재 origin/develop 에 송신 코드가 0건이고, 그것은 최종 acceptance blocker 이지 FE 구현 blocker 가 아니다.
GitLab #135 WORLD_ARCADE_INTERACT 수신부는 기다리지 않는다.
