## 설명

GitLab #214 (FE 요청). 목표 시간이 길어 한 판 대기가 지루하다는 실플레이 피드백이고, 수치 정본이 spec 이라 FE 가 임의로 바꾸지 않고 요청으로 올렸다.

작업 범위

- application.yml 의 app.minigame.timer-stop.target-min-seconds 5.0 → 2.0, target-max-seconds 10.0 → 4.0.
- fail-margin-seconds 3.0 은 그대로 둔다. 판정이 단측(failAfterSeconds = target + margin, stopped > failAfter)이라 목표를 줄여도 음수 하한이 생기지 않고, 실패 임계가 5~7초로 함께 짧아진다.
- TimerStopJudgeTest 의 CONFIG 미러와 헬퍼가 5.0/10.0 리터럴이므로 함께 내린다.
- 문서 수치 동기화: specs/014-minigame/spec.md FR-001a 및 관련 줄, contracts/minigame-api.yaml, plan.md, tasks.md, docs/08, docs/02, docs/00, docs/26.
- elapsed-tolerance-seconds 2.0 은 이번에 조이지 않는다. 절대값이라 라운드가 짧아지면 라운드 길이 대비 비중이 커지는데, 같은 값이 정상 플레이의 왕복 지연 예산이기도 해 실측 없이 조이면 느린 회선의 정상 플레이가 거부된다. docs/26 의 해당 결정 요청 행에 재검토 필요만 덧붙인다.

완료 조건

- 세션 발급이 2.000~4.000초 범위의 목표를 준다.
- 기존 미니게임 테스트가 그대로 통과한다(범위는 주입된 설정과 비교하도록 이미 작성돼 있다).
- spec·계약·문서에 5~10초 문구가 남지 않는다.

보류

- 분포를 가운데로 모으는 변경(두 난수 평균, 삼각 분포)은 이번에 넣지 않고 FE 에 의견을 묻는다.
