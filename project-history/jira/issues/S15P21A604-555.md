## 설명

## 발생 환경
- 배포 구성: infra/deploy/compose/dev/ai.compose.yaml

## 증상
- dev AI 컨테이너 healthcheck가 http://127.0.0.1:8000/health 를 호출한다.
- FastAPI가 제공하는 실제 liveness endpoint는 GET /ai/v1/health/live 이다.
- 컨테이너가 정상 기동해도 healthcheck 실패로 unhealthy가 되어 배포 및 E2E 검증을 막을 수 있다.

## 원인
- Compose healthcheck 경로와 FastAPI router prefix(/ai/v1) 사이의 불일치.

## 작업 내용
- dev AI Compose healthcheck를 실제 liveness endpoint로 정정한다.
- 변경 경로를 검증하는 구성 테스트를 추가 또는 갱신한다.

## 완료 조건
- [ ] dev AI healthcheck가 GET /ai/v1/health/live 에 대해 성공한다.
- [ ] 실제 FastAPI liveness endpoint와 Compose 설정의 경로가 일치한다.
- [ ] Docker Compose config 및 관련 검증이 통과한다.

## 테스트 방법
1. dev AI Compose를 기동한다.
2. 컨테이너 health 상태가 healthy인지 확인한다.
3. GET /ai/v1/health/live 가 200 {"status":"UP"}을 반환하는지 확인한다.

## 영향 범위
- 개발 환경 AI 배포 상태 확인 및 문서 업로드→채팅 E2E 사전 조건.
