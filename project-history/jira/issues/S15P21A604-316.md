## 설명

## 증상

배포 빌드(`Builds/web-release`, Development **OFF**)로 월드에 들어가면 **벽·바닥·엘리베이터 등 정적 지오메트리가 전혀 보이지 않고 스카이박스(밤하늘·불꽃)가 그대로 보인다.**

보이는 것 / 안 보이는 것이 갈린다:

- **보인다**: 천장 조명 패널(밝은 프레임), 부스 이름 텍스트(BOOTH 05/09/10), 케이블, 불꽃, 아바타
- **안 보인다**: 벽, 바닥, 엘리베이터, SSAFY 조형물 — 요컨대 라이팅 받는 정적 메시 전부

플레이어는 정상 이동하고 애니메이션도 돈다. **월드는 존재하는데 그려지지 않는 것**이다.

## 대조 실험 — GPU·브라우저 문제가 아니다

**같은 브라우저·같은 탭**에서 두 빌드를 연속으로 띄웠다.

|  | `Builds/web` (Development **ON**) | `Builds/web-release` (Development **OFF**) |
|---|---|---|
| 월드 렌더링 | **정상** — SSAFY 조형물·카펫·벽·엘리베이터 문·커튼 전부 보임, FPS 79.3 | **깨짐** — 스카이박스만 |
| `Hidden/CoreSRP/CoreCopy ... not supported on this GPU` | 있음 | 있음 |
| `Hidden/Universal/HDRDebugView ... not supported` | 있음 | 있음 |

두 셰이더 오류는 **양쪽 모두**에 있으므로 원인이 아니다(기존 노이즈).

## 범위 좁히기

배포 빌더가 개발 빌드와 다르게 주는 것은 셋뿐이다.

1. `BuildOptions.Development` OFF
2. WebGL 압축 Brotli + Decompression Fallback
3. 출력 디렉터리

②는 **전송 방식일 뿐 압축 해제 후 바이트가 동일**하므로 렌더링에 영향이 없다. ③은 무관하다.
→ **남는 변수는 Development OFF 하나**이고, 그때만 켜지는 것은 코드·셰이더 스트리핑이다.

씬 내용 차이도 배제했다. 두 빌드 사이 `main.unity` 변경은 `@Network` 에 컴포넌트 1개 추가(13줄)뿐이다.

## 이미 확인해서 배제한 것

- `StripUnusedMeshComponents: 0` — Optimize Mesh Data 는 꺼져 있다 (릴리즈 전용 동작이라 1순위로 의심했으나 해당 없음)
- `m_OcclusionCullingData: {fileID: 0}` — 오클루전 데이터 없음, T-217 재발 아님

## 남은 후보

- `stripEngineCode: 1` — Strip Engine Code 는 **비개발 빌드에서만** 동작한다
- URP 셰이더 배리언트 스트리핑 (URP Global Settings)
- `managedStrippingLevel: {}` (기본값) 로 인한 관리 코드 스트리핑

## 다음 단계 (권장)

**Development 만 ON 으로 두고 나머지는 배포 설정 그대로** WebGL 을 한 번 뽑아 비교한다. 렌더링이 살아나면 스트리핑이 확정되고, 그때 `stripEngineCode` → URP 배리언트 스트리핑 순으로 하나씩 끄며 범인을 특정한다. 빌드 1회 약 19분.

## 영향

**배포 차단 이슈다.** 지금 상태로는 배포용 WebGL 산출물을 올릴 수 없다. 개발 빌드는 정상이라 시연·테스트는 가능하다.

## 발견 경위

[[S15P21A604-312]]·[[S15P21A604-313]] 수정을 실제 웹 빌드에서 검증하다 발견했다. 그 두 건은 같은 배포 빌드에서 정상 동작을 확인했다 — 게이트가 로비 경로에서 생성돼 `[WorldEntryGate] 개방 — 준비 완료 (1.2s)` 로 열렸고 승인 콜백 예외는 0건이었다.

이 프로젝트에서 **Development OFF WebGL 을 뽑은 것이 [[S15P21A604-311]] 배포 빌더가 처음**이다. 즉 새로 생긴 결함이 아니라, 여태 아무도 배포 설정으로 빌드한 적이 없어서 드러나지 않았던 것으로 보인다.

## 원인 규명·수정 완료 — MR !98

https://lab.ssafy.com/s15-metaverse-game-sub1/S15P21A604/-/merge_requests/98 (커밋 `9f32ecc`)

### 원인

빌드에 `Mobile_RPAsset` 이 실리지 않았다.

```
정상:  Shaders 6.7 mb / 2 URP assets — Mobile_RPAsset + PC_RPAsset
불량:  Shaders 5.7 mb / 1 URP asset  — PC_RPAsset 뿐
```

텍스처·메시·사운드는 동일하고 셰이더만 1 MB 빠진다.

Mobile 품질 레벨은 `excludedTargetPlatforms: [Standalone]` 인데, URP 빌드 전처리기는 **에디터의 현재 활성 타깃** 기준으로 품질 레벨을 거른다. 평소 활성 타깃이 Linux Server(=Standalone) 라 그 상태에서 WebGL 을 빌드하면 Mobile 레벨이 통째로 제외된다. **WebGL 기본 품질은 0 = Mobile** 이므로 런타임이 쓸 파이프라인이 빌드에 없어진다.

`BuildPlayer` 에 타깃을 넘기는 것으로는 늦다 — 전처리기는 그 전에 결정한다.

**방아쇠는 [[S15P21A604-311]] 배포 빌더**가 빌드 후 타깃을 Linux Server 로 복원하게 만든 것이다. 이후 모든 WebGL 빌드가 Standalone 에서 시작했다.

### 수정

- `FestaReleaseBuilder`·`FestaWebBuilder` 둘 다 `BuildPlayer` **전에** `SwitchActiveBuildTarget(WebGL)`, 실패 시 빌드 중단
- 빌드 후 `BuildReport.packedAssets` 에서 `Mobile_RPAsset` 확인 — 이 결함은 빌드가 성공으로 끝나므로 검증이 없으면 조용히 재발한다

### 검증

재빌드 결과 `2 URP assets`, 셰이더 **6.7 MB**, Total User Assets **401.4 MB** — 정상본과 정확히 일치. 브라우저에서 벽·카펫·SSAFY BOARD·커튼·엘리베이터 정상 렌더링 확인.

### 반성 (T-219 로 기록)

답은 **T-216 첫 단락**에 이미 있었다 — *"에디터는 PC(레벨 1), WebGL 은 Mobile(레벨 0) 로 돈다. 에디터에서 안 나는 렌더링 버그는 먼저 퀄리티 레벨부터 갈라 봐라."* **T-214** 는 증상 문장까지 거의 같다.

그런데도 문서를 읽지 않고 Development·압축·게이트·빌드캐시·소스 이분탐색을 **빌드 5회·한 시간 넘게** 태웠다. 전부 빗나갔다. 사용자 지적으로 문서를 찾고서야 5분 만에 끝났다.

규칙: **"에디터 정상 / 빌드만 이상" 을 확인한 순간, 코드보다 품질 레벨과 RP 에셋을 먼저 대조한다.**
