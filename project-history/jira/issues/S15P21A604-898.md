## 설명

Booth Studio 폐기 후 관리창에서 바로 게시하는 흐름. BE 무변경 — 기존 draft/publish/publishedLayoutVersion 계약을 FE 내부 publication 계층(composer + state + mutation)으로 재사용한다.

사용자 흐름: 임대 → 프로젝트 등록 → 게시 → 운영 중 → presentation 변경 시 변경사항 적용. draft/revision/version은 노출하지 않는다.

범위:
- presentationComposer(순수): compose/fromLayout/toLayout/equals. canonical Presentation 모델 비교.
- useBoothPublicationState(조회)와 useBoothPublish(mutation) 분리.
- 성공 시 booth-detail·published-layout 캐시 setQueryData 후 invalidate, notifyBoothSlotChanged.
- 409 LAYOUT_REVISION_CONFLICT는 최신 revision 재조회로 재시도 가능하게. publish 실패 시 기존 운영본 유지.
- 관리창 bm-identity 카드 오른쪽 액션(게시/변경사항 적용), 상태 배지 준비 중/운영 중, 프로젝트 미등록은 bm-gate 다이얼로그 재사용.
- AI_AGENT publication capability 플래그 기본 OFF. 게임 파트 authored 중복 spawn 제거(GitLab 이슈) 도달 후 ON → 기존 게시본과 diff가 나 변경사항 적용으로 연결.

검증: 미등록/미게시/최초 게시/프로젝트 텍스트 수정(재게시 없음)/presentation 변경/publish 실패/revision conflict 7시나리오 vitest.
