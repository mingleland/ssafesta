## 설명

걸을 때 프레임이 출렁이는 원인 둘 중 게임 파트 몫이다. 나머지 하나는 해상도 과잉이고 S15P21A604-484 / GitLab #143 에서 FE 가 맡는다.

실측 (FE 임베드, 게스트 접속, 개발 빌드, 보이는 탭)

아케이드 골목(벽이 시야를 막는 자리) 드로우콜 136 / SetPass 35 / 삼각형 168 K
부스 거리 개활지 드로우콜 724 / SetPass 120 / 삼각형 1.32 M

같은 씬에서 시야가 트일 때마다 5.3배로 뛴다. 걸으면서 느려졌다 빨라졌다 하는 체감의 나머지 절반이 여기다.

원인 — 오클루전 컬링이 사실상 꺼져 있다

main.unity 의 m_OcclusionCullingData 가 {fileID: 0} 이다. 베이크된 데이터가 씬에 연결돼 있지 않고, 프로젝트에 오클루전 에셋 파일 자체가 없다. 카메라는 m_OcclusionCulling: 1 로 컬링을 요청하지만 볼 데이터가 없어 아무것도 가려지지 않는다. 벽 뒤 오브젝트가 전부 그려진다.

베이크 버튼만 눌러서는 해결되지 않는다. 정적 플래그 분포가 이렇다.

m_StaticEditorFlags: 0  → 426개 (플래그 없음)
m_StaticEditorFlags: 16 → 168개 (ContributeGI 만)
m_StaticEditorFlags: 18 → 7개
m_StaticEditorFlags: 22 → 1개

16 은 ContributeGI 뿐이라 Occluder Static 도 Occludee Static 도 아니다. 즉 베이크할 대상이 하나도 지정돼 있지 않다. 플래그를 먼저 잡아야 베이크가 의미를 갖는다.

작업

1. 벽·건물·지형처럼 시야를 막는 큰 정적 메시에 Occluder Static + Occludee Static 을 준다.
2. 소품처럼 가려지기만 하는 정적 메시에 Occludee Static 을 준다.
3. 움직이는 것(플레이어·NPC·풍선 등)은 그대로 둔다 — 정적이 아니다.
4. 오클루전 베이크. smallestOccluder / smallestHole 은 현재 20 / 5 인데 씬 스케일(1 m = 10 unit)에 맞는지 함께 본다.

검증

같은 두 지점에서 드로우콜을 다시 잰다. 개활지 724 가 유의미하게 내려가야 한다. 그리고 벽 너머가 잘못 잘려 보이지 않는지 눈으로 확인한다 — 컬링이 과하면 있어야 할 물체가 사라진다. 수치가 아니라 보이는 품질이 판정 기준이다.

주의: 씬을 저장할 때 URP UniversalAdditionalLightData 자동 부착이 836줄씩 딸려 들어온 이력이 있다. 저장 전 diff 를 확인한다.
