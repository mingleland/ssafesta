## 설명

## 배경

GitLab #100 에서 Infra 가 2026-09-10 13:42 에 다음을 확정했다.

- `storage-failover.sh` 의 Provider 전환과 reconcile 실행 전체에 단일 실행 lock 을 적용한다
- 진행 중인 reconcile run 이 있으면 다음 Provider 전환과 reconcile 시작을 거부한다
- 따라서 문서당 진행 중 reconcile run 은 최대 하나이고, 이전 run 이 끝나기 전에 다음 전환을 시작하지 않는다

그리고 "이 전제를 spec 007 FR-035·C-10, Spring reconcile API 계약, Infra T076 및 docs/15 에 반영했다" 고 적혀 있다. 즉 BE 소유 계약 문서의 전제가 타 파트 손으로 바뀐 상태이며, 그 스레드에 BE 회신이 아직 없다.

## 할 일

1. `POST /internal/storage/reconciliation-runs` 수신 구현(S15P21A604-500, MR !568)이 "문서당 동시 run 최대 1" 전제와 실제로 맞는지 대조한다. 특히 같은 문서에 run 이 겹쳐 들어올 때의 처리(멱등·거부·덮어쓰기 중 무엇인지)가 문서와 코드에서 같은 말을 하는지 확인한다
2. spec 007 FR-035·C-10 과 Spring reconcile API 계약 문서에서 Infra 가 바꾼 문장을 읽고, BE 구현이 그 전제 위에서 성립하는지 판단한다. 어긋나면 어느 쪽을 고칠지 판단해 올린다
3. lock 이 Infra 스크립트 쪽에만 있고 서버는 아무것도 강제하지 않는 구조라면, 스크립트를 거치지 않은 호출에서 무엇이 깨지는지 한계를 계약 문서에 명시한다
4. 결과를 GitLab #100 에 회신한다

## 완료 조건
