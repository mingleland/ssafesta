## 설명

### 작업 목적

브랜치·MR·merge 이벤트에 따른 Jira 상태·라벨 자동화를 실행할 GitLab Runner를 준비한다.

### 작업 내용

- `.gitlab-ci.yml`의 기존 jira-* 잡 실행용 Runner 등록
- 브랜치 push→진행 중, MR→in-review, merge→ready-for-deploy 자동화 검증
- 제품 빌드·배포 CI/CD는 Jenkins가 담당
- jira-* 잡과 stage 구조를 삭제·우회하지 않음
- Jira/GitLab 자격증명 Secret 마스킹

### 완료 조건

- jira-* 잡이 Runner에서 실행된다.
- 샘플 브랜치/MR/merge에서 상태·라벨 매핑이 규칙대로 반영된다.
- 제품 이미지 빌드·배포가 GitLab Runner로 중복 구현되지 않는다.
- Secret이 로그에 노출되지 않는다.

### 선행 작업

GitLab Runner 실행 권한과 Jira 연동 변수

### 참고

- `docs/jira-gitlab-workflow.md`
- `docs/18_Jira_운영_가이드.md`
- `specs/infra-001-ci-cd-pipelines`

### 테스트 방법

테스트 이슈 키가 포함된 브랜치/MR로 jira-* 잡을 실행해 상태·라벨 자동화를 확인한다.
