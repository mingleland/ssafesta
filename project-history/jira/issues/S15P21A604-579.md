## 설명

배경: 부스 안 프로젝트 전시 판넬은 F 를 누르면 웹 화면으로 넘어간다. 월드 안에서 바로 영상이 재생되면 흐름이 끊기지 않는다.

하고 싶은 것: 전시 오브젝트를 키우고 그 사이에 화면 판을 두어, 상호작용하면 웹으로 나가지 않고 그 판에서 영상이 재상되게 한다(비디오 스크린).

지금 있는 것: 부스 내부에 VideoScreen 타입 오브젝트(Booth*_screen-1)가 이미 자리를 잡고 있고 현재는 상호작용 없는 준비 중 안내만 뜬다. 이 자리를 그대로 쓰면 배치 작업이 없다.

WebGL 제약(사전 확인):
1. VideoClip 에셋 사용 불가. Unity VideoPlayer 는 WebGL 에서 URL 재상만 지원. HTTP(S) 서빙, 형식은 MP4(H.264)/WebM.
2. 영상 호스트에 CORS 헤더 필요.
3. 소리는 브라우저 자동재상 정책에 걸린다. 음소거 자동재상만 허용. 소리는 사용자 제스처 필요(Unity 내부 F 는 제스처로 인정되지 않을 수 있음).
4. 빌드 용량 유리 — 스트리밍이라 .data(147 MB)가 커지지 않는다.

필요한 결정: 영상 호스팅 위치/URL 규약(BE/인프라), 게시본 영상 URL 필드(FE/BE), 소리 정책.

범위(게임): VideoPlayer -> RenderTexture 를 화면 오브젝트 재질에 물리고 상호작용 시 재상/정지.

작업 지시 전 기록용. 일정 추후 협의. GitLab #164 에 먼저 올렸다가 Jira 로 옮김.

### 강형순 · 2026-09-12 17:01 KST

현황 정리 (2026-09-12 확인) — 아직 플레이스홀더만 있고, 그 앞에 결정 한 가지가 막아 서 있다.

지금 있는 것: VideoScreenPlaceholder 는 configId 를 로그로 찍고 끝난다. 재생 코드가 없다.

막힌 지점: 프로젝트의 videoUrl 이 지금 YouTube 링크다(로컬 픽스처 확인). Unity 의 VideoPlayer 는 YouTube 페이지 URL 을 재생할 수 없다 — 직접 재생 가능한 미디어 URL(mp4 등)이거나 FE 오버레이로 넘기는 방식이어야 한다. spec 009 C-02(영상 제공자 범위)가 미결로 등재돼 있는 것이 정확히 이 문제다(커밋 9014efd6).

FE 쪽은 이미 YouTube 임베드와 새 탭 대안을 구현해 둔 상태다(커밋 38916ab7). 그래서 선택지는 둘이다.

① 월드 안에서 재생하려면 직접 재생 가능한 URL 을 계약에 받아야 한다(BE/기획 결정).
② 그게 어려우면 영상은 FE 오버레이로 넣고, Unity 는 상호작용 이벤트만 보낸다(노트북·패널과 같은 결).

범위가 정해지기 전에 Unity 쪽을 구현하면 두 번 만들게 된다.
