## 설명

## 문제

`ci/README.md` 는 **"Game: **`festa-unity/ci/` 의 Unity 전용 adapter" 라고 명시하고, 루트 `ci/build` 는 `bash festa-unity/ci/build --target all` 로, `infra/jenkins/pipelines/unity.groovy` 는 `festa-unity/ci/build --target <타깃>` 으로 호출한다.

**그런데 **`festa-unity/ci/` 디렉터리 자체가 없었다. 게임 파트 CI 는 시작하자마자 실패한다. AI·백·프론트는 루트 어댑터의 기본 명령(pytest·gradle·npm)으로 도는데 게임만 구멍이었다.

테스트도 **하나도 없었다** — `.asmdef` 0개라 `ci/test` 의 game 분기가 부를 대상이 없다.

## 추가한 것

`festa-unity/ci/build` — `--target webgl|linux-server|all`, 배치 모드로 유니티 실행
`festa-unity/ci/test` — EditMode 테스트 + JUnit XML, 실패 시 실패 테스트명만 추려 출력

`CiBuild.cs` — CI 전용 배치 진입점. 기존 메뉴 빌더는 `DisplayDialogComplex` 로 사용자에게 물어 `-batchmode` 에서 못 쓴다.

- WebGL 은 빌드 **전에** 활성 타깃을 전환한다 — URP 가 포함할 RP 에셋을 그 시점에 결정하므로 `BuildPlayer` 에 타깃만 넘기면 늦다 ([[S15P21A604-316]])
- 서버는 `standaloneBuildSubtarget = Server` 로 `UNITY_SERVER` 확보 (T-182)
- 산출물 `index.html`·`Build`·`TemplateData` 자체 검증 — 파이프라인이 나중에 볼 것을 앞당겨 실패를 빨리 낸다
- **예외를 삼키지 않는다** — `catch` 에서 로그 + `Exit(1)`. 조용히 0 으로 끝나면 CI 가 초록으로 넘어간다

`Festa.Tests.Editor` + 회귀 방지 테스트 3종. 전부 실제로 터졌던 사고에서 나왔고, 셋 다 **유니티가 에러를 내지 않아 사람 눈으로만 발견**됐던 것들이다.

| 테스트 | 막는 사고 |
|---|---|
| 재질 슬롯 ≤ 서브메시 | T-223 — 데시메이션이 서브메시를 뭉개 자물쇠 미출력 ([[S15P21A604-320]]) |
| `.cs` ↔ `.meta` 짝 | T-221 — 받는 쪽에서 새 GUID 발급 → Missing Script |
| Missing Script 부재 | 참조 끊긴 컴포넌트는 플레이 전까지 조용하다 |

## 테스트가 실제로 잡는지 검증했다

**통과하는 테스트는 아무것도 증명하지 않는다.** -281 회귀를 일부러 재현했다.

1차 시도는 씬을 메모리에서만 바꿨는데 **테스트가 통과**했다 — 테스트 실행이 도메인 리로드를 일으켜 저장 안 한 변경이 날아간 것이다. 디스크에 저장하고 다시 돌리니 정확히 잡혔다:

```
서브메시 1 < 재질슬롯 5
미출력: [Mirror 01], [Metal Aluminum Anodized], doorlock-gray, black
```

씬은 git 으로 복구했다.
