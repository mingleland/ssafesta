## 설명

## 작업 목적

같은 우상단 자리에 사는 컨트롤이 화면마다 크기·위치 기준·색·모서리가 전부 다르다. Landing/Login 은 화면 비율에 반응하는 토큰을 쓰고, World 는 px 고정값을 쓴다. (2026-09-10 플레이 중 실측)

| 속성 | Landing·Login (ScreenControls) | World (ConsultationQuickAccess) |
|---|---|---|
| 크기 | `clamp(48px, 4vh, 72px)` | `40 × 40px` 고정 |
| 위치 | `top: 3vh / right: 2vw` | `top: 20px / right: 20px` |
| 모서리 | `clamp(12px, 1.3vh, 20px)` | `13px` |
| 배경 | `rgba(20,22,46,.42)` | `rgba(12,16,34,.72)` |
| 테두리 | `rgba(255,255,255,.24)` | `rgba(255,255,255,.14)` |

토스트도 어긋난다 — `--festa-toast-top` 이 `control-size` 기준으로 계산되는데 World 가 그 변수를 덮지 않아, 우상단 주민의 실제 높이와 토스트 시작 높이가 서로 다른 기준으로 계산된다.

## 작업 내용

`features/world/ui/consultationQuickAccess.css` 가 `--festa-control-size` · `--festa-control-radius` 와 `top: 3vh / right: 2vw` 를 쓰게 한다. 배경·테두리·hover·focus 도 ScreenControls 와 같은 값으로 맞추고, 아이콘이 버튼과 함께 자라게 한다(고정 20px 이면 커진 버튼 안에서 점처럼 보인다).

토큰을 통일하면 `--festa-toast-top` 기본값이 그대로 맞으므로 World 에서 변수를 덮을 필요가 없어진다.

## 완료 조건

1. 세 화면(Landing·Login·World)에서 우상단 컨트롤이 같은 크기·같은 여백에 뜬다
2. 토스트가 그 아래에 정렬된다
3. 상담 상태 점(`.cqa-dot`)·라벨·비활성 표현에 회귀가 없다
4. mock dev 환경 DOM 실측으로 48×48 / top 3vh / right 2vw / radius 12px 확인
5. tsc 0 / vitest 전체 green / oxlint 신규 경고 0
