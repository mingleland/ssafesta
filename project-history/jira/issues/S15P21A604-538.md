## 설명

오늘 FE 에 들어간 실질 변경 셋의 실서버 왕복 검증이 부분적으로만 끝났다.
- S15P21A604-528 / -531 Survey mock -> 실 HTTP 어댑터: 정상 경로 일부와 시각 2필드만 봤다. 오류 경로·6문항 유형·게스트 경로 미검증.
- S15P21A604-524 Unity 렌더 해상도 상한: 게임 파트 실측만 있고 FE 가 직접 브라우저로 본 적이 없다.
- S15P21A604-518 release gate: 성능 측정치 0건 (GitLab #73 잔여).

목표: 실 BE(8081)·실 DB·실 브라우저로 FE 전 화면을 훑고 Survey 계약의 모든 분기를 재현한다.
"될 것만 확인" 이 아니다 — 가능한 건 끝까지 관통하고, 안 되는 건 어느 포인트에서 막히는지 재현 가능한 형태로 남긴다.

결과 어휘: PASS / FAIL / BLOCKED_AT_<POINT> / NOT_EXECUTED.
BLOCKED_AT_ 에는 6항 필수 — 재현 단계, 마지막 성공 단계, 최초 실패 단계, HTTP/error 원문, 관련 route/file/config, 다음에 필요한 외부 조건.

범위 (Phase 0~6):
0. 기준선 — vitest 141 files / 900 tests, npm run build (= tsc -b && vite build — 이것이 타입 게이트다).
   DEV 플래그 2개를 켜야 설문 오버레이·회원 진입구가 생긴다 (VITE_DEV_INTERACTION_BAR, VITE_DEV_ENTRY).
1. DB 시드 — 8080·8081 이 같은 postgres 를 보므로 전체 restore 를 기본값으로 쓰지 않는다.
   모든 row 에 E2E0908- 표식을 박고 내가 만든 row 만 선별 삭제한다.
2. 관통 시도 — OAuth 3종(+#114 SSAFY 최초 동의), AI FastAPI 기동, Consultation 경계 특정, #73 5인 사용성 설계.
   OAuth 는 redirect URI 를 임의로 바꾸지 않는다 — provider console 등록 여부 확인이 먼저고,
   등록 안 돼 있으면 기존 8080 인스턴스로 관통한다(설정 미변경).
3. Survey 계약 전수(curl) — 오류 11종을 Survey-native 6 / Dependency-derived 5 로 가른다.
   PUT 검증 10규칙 + 제출 검증 8규칙. PUT 본문 키 부재 단언(T-97) 필수.
4. 브라우저 회귀 — route 12 + 오버레이 6. 각 화면을 ENTRY/AUTH/DATA/RENDER/INTERACTION/CONSOLE/NETWORK 7칸으로.
   진입 실패도 결과다 — 건너뛰지 않고 어느 단계에서 막혔는지 적는다.
5. Unity WebGL 실측 — -524 는 backing buffer / CSS size 비율로 판정(effectiveDpr <= 1.5).
   #73 성능은 런타임 FPS 와 에디터 interaction p95 를 같은 숫자로 섮지 않는다.
6. 원복·기록 — DB row 만 삭제(seed SQL 파일은 산출물로 남긴다).
   docs/LJH/verify/fe-full-regression-0908.md 결과표 + seed SQL.

산출물은 검증 기록 문서와 시드 SQL 뿐이고 코드 변경 0 을 목표로 한다.
결함이 나오면 별도 Jira 키로 분리한다 — 검증과 수정을 한 MR 에 섮으면 "무엇을 검증했나" 가 diff 에 묻힌다.
