## 설명

## 증상

배포 빌드를 돌린 뒤 CharacterLobby 씬을 열고 Play 를 누르면 커스터마이징 화면 대신
엘리베이터(월드)가 나온다. 씬을 잘못 연 것이 아니다.

## 원인

FestaReleaseBuilder 는 빌드 전 타깃을 기억했다가 finally 에서 그대로 되돌린다.
그런데 되돌리는 대상이 Linux Server 면 에디터에 UNITY_SERVER 가 정의된 상태로 남는다.

CharacterLobbyController.Awake() 첫 줄이 이걸 본다:

```
#if UNITY_SERVER
    SceneManager.LoadScene(WorldSceneName);   // → main
    enabled = false;
    return;
#endif
```

원래 이 분기는 데디케이티드 서버 빌드가 로비 씬을 첫 씬으로 잡는 것을 막으려고 넣었는데,
에디터에서도 심볼이 정의되므로 같이 걸린다 (T-182 와 같은 함정).

T-219 는 이 복원 동작을 이미 "방아쇠" 로 지목해 뒀다. 당시에는 빌드 직전 전환만 고쳤고
복원 대상은 그대로 뒀다.

## 왜 그냥 두면 안 되나

서버 타깃으로 쉬는 상태는 두 가지를 동시에 깨뜨린다.

1. 에디터에서 캐릭터 커스터마이징을 아예 확인할 수 없다
2. 그 상태에서 WebGL 을 빌드하면 Mobile_RPAsset 이 통째로 빠진다 (T-219) —
   빌드는 성공으로 끝나고 화면만 깨진다

"원래대로 되돌린다" 가 원래가 고장난 상태면 고장을 보존하는 셈이다.

## 조치

FestaReleaseBuilder 와 FestaWebBuilder 의 복원 지점에서, 복원 대상이 Standalone+Server 면
WebGL 로 되돌린다. 이 프로젝트의 클라이언트는 WebGL 이므로 쉬는 상태도 WebGL 이어야 한다.
벗어난 경우 경고 로그로 이유를 남긴다.

CiBuild(배치 모드)는 해당 없음 — 헤드리스라 에디터 상태가 남지 않고, all 경로는 서버 뒤에
WebGL 을 빌드해 WebGL 로 끝난다.
