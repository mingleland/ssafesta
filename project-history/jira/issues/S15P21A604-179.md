## 설명

작업 목적

Draft API의 충돌·권한·검증 오류 계약을 통합 테스트로 고정한다.

작업 내용

- stale revision, 비Owner, schema/semantic validation 실패
- Draft 부재, 손상된 저장 문서, 중복 재시도

완료 조건

[x] 모든 응답의 status, code, errors[].field/rule이 S15P21A604-217 계약과 일치한다.

[x] 422 등 미승인 숫자나 코드명을 테스트가 선행 확정하지 않는다.

[x] 실패 요청 뒤 revision과 저장 문서가 변하지 않는다.

선행 작업 / Dependency

BLOCKED BY: S15P21A604-112·178·217

테스트 방법

계약 fixture 기반 통합 테스트를 실행하고 응답 스냅샷을 검토한다.

---

검증 근거 (2026-08-26, MR !33 develop 머지)

GameDraftApiIntegrationTest 9 건 + GameFixtureContractTest 7 건

- 계약 일치: 상황별 status·code·errors[].rule 을 전부 단언한다. 부재 204 · 최초 저장 revision 1 · stale 409 GAME_REVISION_CONFLICT + CURRENT_REVISION(상한이 아니라 실제 값) · 비Owner 403 GAME_FORBIDDEN · 부재 게임 404 GAME_NOT_FOUND. fixture 8/8 은 rule 이름까지 대조한다
- 미승인 코드 안 씀: 테스트가 쓰는 status 는 200·201·204·304·403·404·409 뿐이고 **422 사용은 0 건**이다. GAME_DRAFT_NOT_FOUND 도 쓰지 않는다 — #104 결정으로 폐기된 이름이고 부재는 204 다
- 실패 뒤 불변: aRejectedSaveLeavesTheStoredDocumentUntouched — 충돌 응답이 현재 revision 을 말하는 것만으로는 부분적으로 쓴 서버와 구분되지 않으므로, GET 으로 되읽어 revision 과 project.title 이 그대로인지 확인한다
- 자동 보정 안 함: aProjectClaimingAnotherGameIsRefusedNotCorrected(경로가 진실이고 몸을 고치지 않는다, FR-034) · anUnknownFieldIsRefusedRatherThanDropped

추가로 들어오게 된 것

이 태스크의 3 번 조건을 실제로 훑어보다 저장 문서를 되읽는 테스트가 없는 것을 발견해 추가했다. 충돌 응답만 보는 테스트는 "거부해놓고 문서를 반쯤 쓴" 서버를 통과시킨다
