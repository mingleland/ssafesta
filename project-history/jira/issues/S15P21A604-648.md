## 설명

h3. 증상 (5173 · OAuth 회원 · 실 Unity 9a977c0d · develop 401066d6 실측, 2026-09-11)

두 경로에서 같은 결과가 났다 — 마우스로 HUD 버튼을 누른 뒤 *캔버스를 다시 클릭하기 전까지 WASD 가 죽는다.*

{code}
④ 부스 나가기 버튼 클릭
   [WorldUiBridge] RequestExitBooth(exit-button) → 부스 6 퇴장   ← 퇴장은 정상
   insideBooth:false → 버튼 언마운트
   activeElement === BODY · W 25회 → 위치 (-530,28,94) 불변

⑤ 이용 안내 버튼 클릭 → 오버레이 → ESC
   [InputBridge] 월드 입력 해제                               ← 잠금 해제는 정상
   activeElement === BUTTON(이용 안내) · W 25회 → 위치 불변
{code}

h3. 원인 — 하나

브라우저는 마우스로 버튼을 누르면 그 버튼에 focus 를 준다. World HUD 의 버튼은 전부 React 요소라 클릭 순간 canvas 가 focus 를 잃는다. 그 뒤가 갈린다.

* ④ 버튼이 사라지면 focus 가 body 로 떨어진다. 누구도 canvas 로 돌려주지 않는다 — S15P21A604-643 은 라우트 복귀(visible 전이)만 본다.
* ⑤ S15P21A604-428 은 "오버레이를 연 요소로 돌려준다"가 계약이고, 그 주석은 *"월드에서 F 로 연 경우 이전 요소가 곧 canvas"* 를 전제한다. 마우스로 HUD 버튼을 눌러 열면 이전 요소가 그 버튼이라 거기로 돌아간다.

{{captureAllKeyboardInput=false}}(!279)라 canvas 에 focus 가 없으면 WASD·F 가 Unity 에 들어가지 않는다.

h3. 수정 — 한 곳

{{WorldHud}} 루트에 {{onMouseDown={(e) => e.preventDefault()}}} — *HUD 안 버튼은 마우스로 눌러도 focus 를 가져가지 않는다.* 게임 HUD 의 표준 처리다.

* ④ 클릭해도 canvas 가 focus 를 유지한다 → 퇴장 뒤에도 그대로 canvas
* ⑤ 클릭해도 canvas 가 focus 를 유지한다 → 오버레이가 열릴 때 previous = canvas → -428 이 계약 그대로 canvas 로 돌린다

-428·-643·WorldPage ESC·InputBridge 는 건드리지 않는다. click 은 mouseup 뒤에 정상 발생하므로 버튼 동작은 그대로다. Tab 으로 HUD 버튼에 가는 키보드 경로도 그대로다 — 막는 것은 mousedown 의 focus 이동뿐이다.
