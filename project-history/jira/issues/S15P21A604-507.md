## 설명

## 작업 목적

Spring의 S15P21A604-399 Agent 추론 설정 조회 API를 FastAPI RAG 경로에 연결하고, 운영 코드의 `MockAgentConfigProvider`를 제거한다. 현재 상태로 배포하면 모든 Agent가 동일한 GUIDE/FRIENDLY 고정 persona로 답한다.

## 작업 내용

- `GET /internal/ai/agent-config?boothId=&agentId=` 호출용 Spring Agent Config client 구현
- `INTERNAL_AI_TO_SPRING_TOKENS`의 현재 송신 토큰으로 인증하고 기존 공용 `httpx.AsyncClient` lifecycle 재사용
- `found:true` 응답의 `role`, `tone`, `responseLength`, `systemPrompt`, `forbiddenTopics`를 `AgentPromptConfig`로 엄격 변환
- `found:false`의 `AGENT_NOT_IN_BOOTH`·`AGENT_INACTIVE`를 명시적 도메인 오류로 변환하고 검색·LLM 호출 전 Fail Closed
- 계약대로 캐시하지 않고 질문마다 1회 조회
- Spring timeout·네트워크 오류·계약 위반 응답 시 Provider 원문이나 내부 예외를 사용자 응답/로그에 노출하지 않음
- `main.py`에서 `MockAgentConfigProvider` 대신 실제 Provider를 주입하고 종료 시 공용 리소스 lifecycle 유지
- spec 007 C-16과 docs/26의 임시 Mock 기록을 최종 계약 상태로 갱신

## 완료 조건

- [ ] 운영 `create_app()` 경로에서 `MockAgentConfigProvider`를 사용하지 않는다
- [ ] 질문 1건당 Agent 설정 조회가 정확히 1회 수행되고 캐시하지 않는다
- [ ] 타 Booth Agent와 INACTIVE Agent 요청은 검색·Embedding·LLM을 호출하지 않는다
- [ ] 정상 응답의 다섯 설정 필드가 PromptBuilder 입력에 그대로 반영된다
- [ ] 401·timeout·5xx·잘못된 응답을 Fail Closed로 처리한다
- [ ] Service Token·systemPrompt·forbiddenTopics·사용자 질문 원문을 로그에 남기지 않는다
- [ ] Spring OpenAPI 계약과 FastAPI client 계약 테스트가 필드·거부 코드 단위로 통과한다
- [ ] AI 전체 unit/contract 회귀가 통과한다
