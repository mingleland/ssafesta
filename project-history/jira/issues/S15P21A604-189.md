### 김가현 · 2026-09-07 11:07 KST

구현 완료.

착수 전 확인해보니 118(Chat UI)과 182(SSE 렌더링)가 이미 상당부분 구현되어 있었습니다 — `features/ai/ui/AiChatOverlay.tsx`는 406(World UX 재구성) 작업 때 만들어졌고, `entities/conversation/stream.{types,parser,mock}.ts`는 Issue #32 SSE 계약 타입·파서를 이미 갖추고 mock 스트림만 소비하는 상태였습니다. 그래서 이번 티켓은 실서버 결선만 좌혀 처리했습니다.

구현 내용:
- `shared/config/runtime.ts`에 `aiApiBaseUrl()` 추가 (unityBuildBase와 동일 패턴 — 런타임 주입 정본 + `VITE_AI_API_BASE_URL` fallback). 인프라 라우팅은 아직 없어 `docs/26`에 미결 등록함
- `entities/conversation/api.ts`(신규) — `createConversation`·`streamMessage`(SSE 본문을 `AsyncGenerator<string>`으로 그대로 흘려보내 mock과 동일한 소비 형태 유지)
- `entities/conversation/errorMessages.ts`(신규) — HTTP 단계 오류(401/403/404/429/503)와 SSE `error` 이벤트를 같은 모양(headline/retryable/retryAfterSeconds)으로 정규화, `LLM_TIMEOUT`은 timeoutPhase로 첫 응답/전체 응답 지연 문구 구분
- `AiChatOverlay.tsx`: Conversation은 첫 질문에서 지연 생성후 재사용, 403/404에서만 재생성하도록 초기화(429/503은 같은 Conversation 유지). SSE sequence 결번 감지(182 완료조건과 겹침) 추가, 오류 버블에 재시도 버튼 추가

범위 밖: Conversation 명시적 종료(DELETE) 미호출 — 127(close 엔드포인트) 아직 To Do라 30분 Redis TTL에 맡김. 429 대기 카운트다운은 텍스트 안내까지만 함(초 단위 타이머는 과잉한 범위로 판단).

테스트: api.test.ts 7건, errorMessages.test.ts 10건, AiChatOverlay.test.tsx(jsdom) 5건 신규. 전체 회귀 vitest run 113 files/682 tests 통과, tsc -b 클린.

참고: S15P21A604-118과 182는 이미 실질적으로 충족되어 있어 보여 각 티켓에도 같은 내용으로 코멘트를 남깁니다 — 상태 전환은 리뷰에게 맡깁니다.
