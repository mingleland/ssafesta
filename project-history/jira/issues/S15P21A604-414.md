## 설명

Contract Gap G-1. FE 는 소비 seam 까지 준비돼 있고 Unity producer 와 이벤트 계약만 없다.

## 배경

Booth Owner 관리 기능은 ESC 가 아니라 World 안의 Booth Management NPC 를 통해 진입한다(user-flow-decisions §14, D-08). Booth Management Overlay 는 구현돼 develop 에 반입됐으나(S15P21A604-413, !240), 제품 진입 경로가 없어 현재는 DEV_ONLY 트리거로만 열린다.

## 목표 Flow

World -> Booth Management NPC 접근 -> Unity F Prompt -> F -> Unity producer event -> FE dispatcher -> Booth Management Overlay -> Close -> 같은 NPC 앞 World

## 현재 상태 (2026-09-04 실측)

- FE consumer: 준비 완료. features/world/model/gameClientUi.ts 의 openBoothManagement() 가 진입 seam 이다. 계약이 오면 features/interaction/dispatcher.ts 에 case 하나를 추가하는 것으로 끝난다 — Overlay·모델은 무변경.
- Unity producer: 없음. BoothInteractBridge.cs 의 송신 함수는 SendLaptopInteract·SendAiAgentInteract 2종뿐이다.
- 계약 문서: 없음. unity/bridge/events.ts 의 BoothInteractEvent union 에도 해당 타입이 없다.

## 결정할 것

- event name (기존 관례는 BOOTH_*_INTERACT)
- payload 필드 — boothId 가 필요한가? 관리 NPC 는 공용 운영 진입점이므로 특정 부스에 종속되지 않을 수 있다. 그 경우 objectId 만 보내거나 payload 가 비어 있을 수 있다 — 이 판단이 이 티켓의 핵심이다
- Unity 측 NPC 배치 위치(Spawn 근처·중앙 광장·운영 데스크 등)
- F Prompt 문구

## 완료조건 초안

- event name 확정
- payload 확정 (필요한 identifier 포함 여부)
- Unity producer 송신 위치 확정
- FE dispatcher mapping 추가
- 실제 World -> Management 진입 end-to-end 검증
- 검증 후 DEV_ONLY 트리거 의존 제거

## 주의

FE 가 임의 이벤트를 발명하지 않는다. 계약 확정 전에는 제품 HUD 에 관리 진입 버튼을 만들지 않는다(hud-decisions: 기능 Launcher 금지).
