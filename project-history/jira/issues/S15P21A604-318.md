## 설명

## 증상

봇 25기가 붙은 데디케이티드 서버에 클라이언트가 **접속을 완료하지 못한다.** 서버는 승인을 내주는데(`Approved client=32 slot=25 nickname=Measure`) 클라이언트는 `IsConnectedClient=false` 로 남고 플레이어가 스폰되지 않는다.

콘솔:

```
Insufficient space in receive queue, consider increasing receiveQueueCapacity.
Receive queue is full, some packets could be dropped, consider increase its size (128).
```

## 원인

`UnityTransport.MaxPacketQueueSize` 가 **기본값 128**이다. 동접이 25명을 넘어서면 한 틱에 도착하는 스냅샷·스폰 메시지가 큐를 넘겨 **패킷이 버려지고**, 접속 핸드셰이크·스폰 동기화가 완료되지 않는다.

CPU·대역폭이 아니라 **큐 용량이 병목**이다. 같은 시점 서버는 CPU 28~55%, 메모리 295 MB 로 여유가 있었다.

## 확인한 것 (실측)

`MaxPacketQueueSize` 를 **128 → 1024** 로 올린 뒤 재접속:

|  | 128 (기본) | 1024 |
|---|---|---|
| 접속 | **실패** | 성공 |
| 보이는 플레이어 | 0 | **26** (봇 25 + 본인) |
| 큐 경고 | 계속 발생 | **사라짐** |
| FPS | — | 43.4 (평균 23.0 ms) |
| 수신 | 0 | 8,216 KB/s |

## 남은 문제 — 이걸로 다 해결되지는 않았다

큐를 올려 **접속·렌더링은 됐지만 약 20초 뒤 클라이언트가 다시 끊긴다.**

- 클라이언트 콘솔에 오류 없음 (큐 경고도 사라진 상태)
- 서버 로그에 거부·`SERVER_FULL` 없음
- 호스트 메모리 4.7 GB 여유 — 자원 고갈 아님

타임아웃으로 추정되나 **미확인**이다. 큐 상향은 필요조건이지 충분조건이 아니다.

## 다음 할 일

1. 끊김 원인 규명 — NGO 클라이언트 타임아웃 설정(`NetworkConfig.ClientConnectionBufferTimeout` 등) 확인
2. 적정 큐 크기 결정 — 1024 는 검증용으로 크게 잡은 값이다. 메모리 대비 실측으로 정할 것
3. 값을 씬의 `UnityTransport` 에 반영 (현재는 런타임에서만 바꿔 검증했다 — **커밋된 변경 없음**)
4. [[S15P21A604-237]] NetworkTransform 트래픽 완화와 함께 볼 것 — 26명에서 수신 8.2 MB/s, **1인당 약 316 KB/s** 는 과하다. 큐를 키우기 전에 트래픽 자체를 줄이는 게 근본이다
