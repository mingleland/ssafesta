## 설명

작업 목적

채널 1개당 동시 접속 20명 상한을 두고 채널을 여러 개 운영한다. 현재 POST /api/v1/world-sessions 는 WorldProperties.CHANNEL_ID 상수 하나("11F-01")와 endpoint 하나만 내려주며, preferredPartyId 는 받고 무시한다.

작업 내용

- app.world.channels[] 설정 도입 — 채널별 channelId·scheme·host·port. 헌법 8조(Unity 가 서버 주소를 하드코딩하지 않는다)가 이 응답에 의존하므로 채널 목록도 상수가 아니라 설정값이어야 한다.
- POST /world-sessions 가 여유 있는 채널을 골라 그 채널의 channelId 와 endpoint 를 발급한다.
- 전 채널이 상한에 도달하면 접속을 거부한다. spec 002 C-02 의 "만석이면 거부" 규칙은 그대로 유지하고, 대기열·자동 재시도는 만들지 않는다.
- WorldProperties.CHANNEL_ID 상수를 제거하고 WorldSessionResponse.channelId 를 배정 결과로 채운다.

완료 조건

- 채널 2개를 설정한 상태에서 상한을 넘긴 발급이 두 번째 채널로 배정된다.
- 전 채널이 만석이면 정해진 오류 코드로 거부되고 클라이언트가 사유를 표시할 수 있다.
- 설정만 바꿔 채널 수를 늘릴 수 있다(재빌드 불필요). spec 002 SC-003 과 같은 성질이다.

선행 작업 / Dependency

- 채널 점유 판정 방식 확정 (별도 이슈로 등록). 배정은 채널별 현재 인원 수치가 있어야 성립한다.

참고

- specs/002-world-session/spec.md C-02 (110행, 137행)
- docs/08_Backend_API_명세서.md §16
- backend/src/main/java/com/example/ssafesta/world/WorldSessionService.java, WorldProperties.java

비고

이 작업은 spec 002 C-02 의 "MVP 는 단일 채널이므로 대기열·자동 분배를 만들지 않는다" 중 '단일 채널' 전제를 뒤집는다. spec 002 와 docs/08 §16 갱신이 별도로 필요하다.
