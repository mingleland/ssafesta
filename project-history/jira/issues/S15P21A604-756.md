## 설명

## 현상

부스 이름(`booths.name`)을 바꾸는 경로가 백엔드에도 프런트에도 없었다.

- 값은 첫 임대 때 `BoothLeaseService.ownBooth()` 가 `new Booth(userId, "내 부스")` 로 한 번 박고 끝이었다. 엔티티에 이름 변경 메서드가 없었다.
- 외관 수정 API `PUT /api/v1/booths/{boothId}/facade` 가 다루는 필드는 `themeCode`, `primaryColor`, `signText`, `logoUrl` 네 개뿐이고 `name` 이 없었다.
- 스튜디오 `FacadePanel.tsx` 의 입력칸도 같은 네 개다.

결과적으로 모든 회원의 부스 이름이 `"내 부스"` 로 같았다. 이 값은 다음 응답에 그대로 실려 나간다.

- `GET /api/v1/booth-slots` 의 `SlotView.boothName` — 월드 간판·슬롯 목록이 읽는다
- 스태프 초대 생성/목록 응답의 `boothName`
- `GET /api/v1/booths/{boothId}` 의 부스 상세

월드 간판은 `signText` 를 먼저 보기 때문에 간판 문구를 넣은 부스에서는 가려져 지금까지 드러나지 않았다. 간판 문구를 비운 부스는 전부 "내 부스"로 보였다.

## 근거

- `specs/005-booth-studio-layout/spec.md:213` 이 이미 미구현 항목으로 적어두었다 — "③ 신규 FR 외부 설정(Facade) 편집 — 부스명·간판·로고·대표색·테마·영업 상태 … `docs/08` 에 저장 API도 없다".
- `docs/05_UIUX_디자인_가이드.md:211` — "외부 설정은 부스명, 간판, 로고, 테마, 대표색, 영업 상태만 편집한다". 부스명은 외관 편집에 속하므로 별도 엔드포인트를 만들지 않고 기존 facade PUT에 필드를 더한다.

## 구현된 계약 (MR !890)

`PUT /api/v1/booths/{boothId}/facade` 요청에 `name` 추가. 1~100자.

**착수 때 이 티켓은 **`name` 을 필수 필드로 적었으나, 구현에서 선택 필드로 바꿨다. 필수로 두면 이름 칸이 없던 시절의 요청 — 즉 지금 FE가 보내는 모양 — 이 전부 `400` 이 된다. 실측하면 기존 외관 통합테스트 18개 중 12개가 깨진다. 팔레트 화이트리스트를 소급하지 않기로 한 결정과 같은 선택이며, `specs/005-booth-studio-layout/contracts/layout-api.md` §6 에 명문화했다.

| 입력 | 결과 |
|---|---|
| 생략 또는 `null` | 현재 이름 유지. 이 필드만 "안 보내면 비운다" 의 예외다 (`booths.name` 이 `NOT NULL`) |
| 빈 문자열·공백만 | `400 VALIDATION_FAILED` — "부스 이름을 입력해 주세요." |
| 101자 이상 | `400 VALIDATION_FAILED` — "부스 이름은 100자까지입니다." |
| 1~100자 | 저장. trim 없이 원문 그대로 |

**응답은 바뀌지 않았다.** `facade` 는 4필드 그대로이고 `name` 이 들어가지 않는다. `FacadeView` 는 부스 상세와 슬롯 목록의 `facade` 에도 실리는데 두 응답 다 바깥에 `name`·`boothName` 을 이미 가지고 있어, 안에 또 넣으면 한 응답에 같은 이름이 두 벌 생긴다. 저장 직후 이름은 `GET /api/v1/booths/{boothId}` 또는 `GET /api/v1/booths/mine` 에서 읽는다.

변경 파일: `Booth.java`(`changeName` 신설), `BoothFacadeService.java`, `BoothFacadeController.java`, `BoothFacadeApiIntegrationTest.java`, `docs/08`, `layout-api.md` §6. DB 마이그레이션 없음 — 컬럼은 `VARCHAR(100)` 으로 이미 있었다.

## 검증

- `./mvnw -B test -Dtest=BoothFacadeApiIntegrationTest` — Tests run 18, Failures 0 (신규 4개 포함)
- `./mvnw -B test -Dtest='Booth*Test'` — Tests run 274, Failures 0
- 신규 테스트가 실제로 무엇을 잡는지 변이로 확인: `validatedName(command.name())` 을 `validatedName(null)` 로 바꾸면 신규 4개가 전부 실패하고, `name == null` 유지 분기를 죽이면 18개 중 12개가 실패한다.

신규 테스트 4개: 이름 변경이 부스 상세·`/booths/mine`·슬롯 목록 세 경로에 모두 반영됨 / 이름 없이 저장해도 기존 이름이 유지됨 / 공백 이름 거절 / 101자 거절.
