## 설명

Measured 2026-09-06. Three consecutive release builds ended with '[Release] Mobile_RPAsset 가 빌드 산출물에 없다 — 이대로 배포하면 월드가 평평하게 렌더링된다', so the builder stopped before writing manifest.json and before the Docker image step (3/3). The artifact was actually fine.

Evidence that the asset IS in the build:
1. Scanned the uncompressed player data Library/Bee/artifacts/WebGL/webgl.data (203 MB): 'Mobile_RPAsset' present, 'PC_RPAsset' absent (correct - WebGL keeps only the default quality level).
2. Loaded the release artifact in the browser: world renders with lighting and shadows, 75 fps at 1280x720, not flat.

Cause: VerifyRenderPipelineAssetsPacked scans BuildReport.packedAssets. On an incremental build Unity does not repack the player data, so packedAssets comes back empty and the guard reads that as 'asset missing'. The four earlier release builds were full builds, so the report was populated and the guard passed. Today the first build died on a Bee error mid-way, leaving a warm cache; every build after that reused it.

Fix: when packedAssets is empty, do not conclude failure - scan the uncompressed staged player data for the asset name and log which path confirmed it. Verified: scan returns true for Mobile_RPAsset, false for a bogus name, 588 ms over 203 MB. A missing staged file still fails closed.

Related: S15P21A604-316 (the original flat-render incident this guard was written for), T-126.
