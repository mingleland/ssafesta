## 설명

### 작업 목적

World grant(`connectionToken`)에서 `avatarCode` 클레임을 뺀다. 게임 파트 요청(GitLab 이슈 #138) 이며 2026-09-07 에 수용 회신했다(`note_2766860`).

Unity 는 grant 를 Netcode 연결 요청에 통째로 싣고, 그 메시지는 분할되지 않아 약 1,114 바이트가 상한이다. 회원 payload 가 1,172B 로 이를 넘겨 `OverflowException: Writing past the end of the buffer` 가 나고, 접속 실패 후 무한 재접속이 된다 — **외형을 저장한 회원이 월드에 들어가지 못한다.**

| 클레임 | 회원 | 게스트 |
|---|---|---|
| `avatarCode` | **411자** | 없음 |
| 페이로드(base64url) | 943자 | 492자 |

`avatarCode` 하나가 토큰의 절반이다. 게스트와 미저장 회원은 이 클레임 없이 들어오므로 회원만 막힌다.

**이 티켓이 필요한 이유** — `avatarCode` 는 상한 없는 `TEXT` 컬럼이라 커스터마이징이 늘수록 길어진다. 게임 파트가 Netcode MTU 를 1,296 → 4,096 으로 올려(`S15P21A604-457`, 완료) 당장은 넘어가지만, 그것은 봉투를 키운 것이고 토큰이 다시 커지면 같은 곳에서 막힌다. 클레임을 빼면 **grant 크기가 외형과 무관해져** 재발 경로가 사라진다.

### 왜 빼도 되는가

- **BE 는 이 클레임을 읽는 곳이 한 곳도 없다.** `WorldEntryTokenIssuer` 가 실을 뿐이고 검증은 게임 서버 몫이다(헌법 14조)
- Unity 서버는 스폰 직후 클라이언트가 보내는 외형 RPC 로 외형을 받는다. **게스트·미저장 회원은 이미 그 경로만 쓴다** — 검증된 유일한 경로이고 회원만 예외였다
- 첫 프레임에 기본 외형이 잠깐 보이는 것은 게임 파트가 감수한다고 명시했다(#138)
- GitLab 이슈 #131 의 재접속 흐름은 **매번 새 grant 를 받는다** — 토큰 크기가 한 번이 아니라 재접속마다 걸리므로 MTU 상향만으로 덮어 두면 안 된다

### 작업 내용

- `WorldEntryTokenIssuer` — `avatarCode` 클레임 2줄 제거, `WorldIdentity` 레코드에서 필드 제거
- `WorldSessionService` — `WorldIdentity` 생성 2곳(회원·게스트)에서 인자 제거
- `WorldEntryTokenIssuerTest` — 기대 클레임 갱신
- **계약 문서 정정** — `specs/infra-003-unity-server-deploy/contracts/world-entry-token.md` 의 `Required claims` 목록에서 `avatarCode` 를 뺀다. 코드만 바꾸면 문서와 어긋난다
- `docs/08_Backend_API_명세서.md` 의 grant 클레임 서술 점검

### 하지 않는 것

2026-09-07 회신에서 하지 않기로 제안한 항목이다 (#138 의 2번 요청).

- `sub`·`playerId` 중복 제거 — 회원 기준 절감이 2자뿐이다(게스트는 84자지만 게스트는 이미 한도 안). 어느 쪽을 남기든 게임 서버가 읽는 클레임이 바뀌어 양쪽 동시 배포가 필요하다
- `iss` 축약 — 10자 안팎을 줄이는 대신 `iss` 는 검증 대상이라(spec 002) 값이 바뀌면 구 빌드가 전부 거부된다

1번만으로 회원 페이로드가 게스트보다 작아지므로 2번의 절감이 필요해지는 시점이 없다. 나중에 grant 가 다시 커지면 `nickname` 을 빼는 쪽이 먼저다 — 검증 대상이 아니고 외형과 같은 RPC 경로로 보낼 수 있다.

### 확정되지 않은 것

- `world-entry-token.md:9` 가 `avatarCode` 를 `Required claims` 로 적고 있다. 게임 서버 검증기가 이 클레임의 **존재**를 요구하면 제거가 회원 입장을 아예 막는다 — 지금보다 나빠진다. 게스트는 이미 이 클레임 없이 들어오므로 optional 로 다루는 것으로 보이지만, 확인받지 않았다. **MR 리뷰에서 게임 파트 확인 필요**
- **반영 시점** — #138 에 물어 두었고 회신 대기 중이다. MTU 상향이 릴리스에 들어가므로 09-08 사용자 테스트는 그것으로 지나갈 것으로 보고 **테스트 이후 반영을 기본**으로 둔다

### 완료 조건

- [ ] 회원 grant 에 `avatarCode` 클레임이 없다
- [ ] 게스트 grant 는 이전과 동일하다 (원래 없었다)
- [ ] 나머지 클레임(`jti`·`sub`·`role`·`playerId`·`nickname`·`sessionId`·`worldId`·`channelId`·`iat`·`exp`)이 그대로 실린다
- [ ] 회원 페이로드가 게스트(492자)보다 작다
- [ ] `world-entry-token.md` 의 `Required claims` 에서 `avatarCode` 가 빠졌다
- [ ] 기존 World Session 테스트가 전부 통과한다

### 선행 작업 / Dependency

- 관련: GitLab 이슈 #138 (요청·수용 회신) · `S15P21A604-457`(Unity MTU 상향, 완료) · GitLab 이슈 #131 (재접속 흐름 — 매번 새 grant)
- 관련: `S15P21A604-84`(World Session 발급 API, 완료 — 이 클레임을 넣은 티켓)

### 테스트 방법

1. 회원 계정으로 `POST /api/v1/world-sessions` → grant 를 디코드해 `avatarCode` 부재 확인
2. 페이로드(base64url) 길이를 회원·게스트 각각 측정해 회원 < 게스트 확인
3. 게스트 grant 클레임이 이전과 같은지 확인
4. `mvnw -Dtest='World*' test`
