## 설명

### 작업 목적

GitLab 이슈 #119에서 FastAPI가 Business DB를 조회하지 않기로 확정됐다. 추론에 필요한 Agent 설정도 Spring이 API로 내줘야 한다. 벡터 검색 API와 함께 이것이 FastAPI의 Business DB 직접 조회를 막는 마지막 경로다.

재료는 `ai_agents`에 이미 전부 있다 — `role_code`, `tone_code`, `system_prompt`, `response_length`, `forbidden_topics`.

### 작업 내용

- Agent 추론 설정 snapshot 조회 엔드포인트 구현. 경로는 `/internal/ai/agent-config` 계열로 제안하되 AI 파트와 합의해 확정한다
- 응답: `role_code`, `tone_code`, `system_prompt`, `response_length`, `forbidden_topics`, Agent 상태
- 인증은 벡터 검색 API와 동일한 `/internal/**` 체인 재사용 — `INTERNAL_AI_TO_SPRING_TOKENS`
- 타 booth 소속 Agent, 비활성(INACTIVE) Agent 요청을 서로 다른 코드로 거부
- OpenAPI 계약 신설, `docs/08_Backend_API_명세서.md` 반영

### 확정되지 않은 것

AI 파트 회신이 이 API의 티켓 분리에는 동의했지만(3-5), 경로·응답 형태·호출 빈도는 답하지 않았다. 구현 전에 확정해야 한다.

- 벡터 검색(`/internal/ai/chunk-search`) 응답에 Agent 설정을 함께 실을지, 별도 호출로 둘지. 별도 호출이면 FastAPI가 대화당 2회 호출한다. AI 파트가 캐싱 여부와 함께 정해 주면 그대로 따른다
- `system_prompt`처럼 길이가 큰 필드를 매 요청 실을지, 버전·해시로 캐시 무효화만 알릴지

### 완료 조건

- [ ] 타 booth Agent 조회가 차단된다
- [ ] INACTIVE Agent가 명시적 코드로 거부된다
- [ ] 토큰 4종 검증이 벡터 검색 API와 동일하게 동작한다
- [ ] 사용자 Access Token으로 접근 불가
- [ ] spec 007·008에 FastAPI가 Business DB를 직접 조회하는 전제가 남아 있지 않다
- [ ] 응답이 OpenAPI 계약과 필드 단위로 일치한다

### 선행 작업 / Dependency

- BLOCKED BY: 경로·응답 형태 합의 (GitLab 이슈 #119 §5)
- 관련: S15P21A604-105 [BE] AI Agent 도메인·CRUD API 구현 (완료 — 재료가 여기 있다)

GitLab 이슈 #119 §5 · S15P21A604-327(내부 API 인증 체인) · spec 008

2. 토큰 4종(정상·누락·오류·반대 방향)
3. 사용자 Access Token으로 호출 시 401
