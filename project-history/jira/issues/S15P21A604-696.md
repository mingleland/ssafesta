## 설명

## 작업 목적

GitLab #180에서 요청한 대로, Game Studio 테스트(src/game-studio/**, 75개 파일 / 371개 케이스, 전체 스위트의 28~38%)를 원격 front-test에서 제외해 파이프라인 지연을 줄인다. 이슈를 3일 전 등록했으나 응답이 없어, 코드 변경 범위가 작고(1줄) 로컬 검증만으로 확인 가능해 직접 반영하고 팀에 통보하는 방향으로 진행한다.

## 작업 내용

- `ci/test`의 `front)` 케이스에 vitest `--exclude 'src/game-studio/**'` 옵션 추가

```bash
# 변경 전
front) (cd "${component_dir}" && npm ci && npm test -- --run) ;;

# 변경 후
front) (cd "${component_dir}" && npm ci && npm test -- --run --exclude 'src/game-studio/**') ;;
```

- 로컬 `npm test`(package.json), `vite.config.ts`, `.gitlab-ci.yml`은 무변경 — 로컬은 지금처럼 Game Studio 포함 전체 실행
- Game Studio 테스트 파일 75개 자체도 무변경 — CI 실행 범위만 좁힌다

## 완료 조건

- [ ] `ci/test`의 `front)` 케이스에 `--exclude` 옵션이 반영된다
- [ ] front-test 파이프라인 로그에서 Game Studio 테스트가 스킵되는 것이 확인된다
- [ ] 로컬 `npm test`는 Game Studio 포함 전체 실행이 그대로 유지된다
- [ ] GitLab #180에 반영 완료 코멘트를 남기고 클로즈한다

## 선행 작업 / Dependency

- 없음 (GitLab #180 요청 내용 그대로 반영)

## 참고

- 관련 Issue: GitLab #180, #167, #168

## 테스트 방법

1. 로컬에서 `bash ci/test`를 `CI_COMPONENT=front`로 실행해 Game Studio 테스트가 스킵되는지 확인
2. 로컬 `npm test`(전체)는 그대로 Game Studio 포함해서 통과하는지 확인 — 이번 변경으로 로컬 검증 범위가 줄지 않았는지 재확인
3. 이 브랜치의 MR 파이프라인에서 front-test 잡 로그를 열어 Game Studio 테스트 파일들이 실행 목록에 없는지 확인
4. 전체 스위트(Game Studio 제외 나머지)가 CI에서 그대로 통과하는지 확인 — `--exclude` 패턴이 의도치 않게 다른 경로까지 건드리지 않았는지
