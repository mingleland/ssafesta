## 설명

### 증상

문서 업로드 뒤 Spring 이 FastAPI 로 보내는 처리 위임 요청(POST /ai/v1/documents/process)이 매번 400 또는 422 로 실패한다. dispatch sweeper 가 30초마다 재전송하지만 결과는 같다. 따라서 develop 에 코드가 다 들어가 있음에도 실제로 처리되는 문서가 없다.

AI 파트가 GitLab #161 로 보고했다.

### 원인

Spring 이 쓰는 JDK HttpClient 는 버전을 지정하지 않으면 HTTP/2 를 기본으로 잡는다. 평문(h2c) 연결에서는 먼저 HTTP/1.1 로 보내면서 Upgrade: h2c 헤더를 붙여 협상을 시도한다.

FastAPI 가 쓰는 uvicorn 은 h2c 업그레이드를 지원하지 않고, 그 요청을 해석하는 과정에서 본문을 잃는다. 결과적으로 필수 필드가 없는 요청으로 보여 422 로 거부된다.

해당 코드는 backend/src/main/java/com/example/ssafesta/ai/AiProcessingConfiguration.java 의 requestFactory() 이며, HttpClient.newBuilder() 에 version 지정이 없다.

### 조치

JDK HttpClient 를 HTTP/1.1 로 고정한다. 내부 호출 대상이 uvicorn 하나뿐이고 HTTP/2 로 얻을 이득이 없으므로 협상 자체를 하지 않는 편이 맞다.

### 완료 조건

- Spring 이 보내는 위임 요청에 Upgrade 헤더가 붙지 않는다
- 요청 본문이 온전히 전달되어 FastAPI 가 202 로 접수한다
- 위 동작을 고정하는 테스트가 있다
