## 설명

GitLab #194 ②. 게임 파트가 B(장식 강등)로 결정하고 Unity 커밋은 develop 에 있다(S15P21A604-881). docs/24 2026-09-17 항목에 "BE 는 VIDEO_SCREEN 의 requiresConfig 를 false 로 내린다 — 서버가 먼저 닿아야 한다" 로 적혀 있다.

계약 결정 (이 티켓에서 닫는다)

configId 가 실려 와도 허용하고 무시하며, CONFIG_UNVERIFIED 경고도 내지 않는다. 구버전 FE 가 아직 보낼 수 있어 거부는 과하고, 무시하면서 경고만 계속 뜨는 상태가 가장 애매하다.

작업 범위

- LayoutObjectType 의 VIDEO_SCREEN requiresConfig 를 false 로 내린다.
- LayoutValidator.checkContentLinks 에 장식형 조기 이탈을 넣는다. 그것 없이 플래그만 내리면 configId 가 실린 경우 belongsToBooth(미판정 타입은 true) 뒤 isVerifiable 이 false 라 CONFIG_UNVERIFIED 경고가 그대로 남는다. FURNITURE·DECORATION 도 같은 규칙으로 정리되므로 타입별 예외가 늘지 않는다.
- 파급: LayoutPassageChecker 의 관람 정면(FRONT_BLOCKED) 검사에서 빠진다. 장식에는 관람할 정면이 없다는 기존 규칙과 일치한다. LocalBounds 는 그대로 둔다.
- 주석·문서 정리: LayoutValidator·LayoutConfigResolver 의 "게임 결정 대기" 문구, specs/005-booth-studio-layout 의 타입 표(FE/data-model, spec, BE/data-model, BE/tasks, contracts/layout-api), docs/02, docs/08, docs/26, backend/bruno/05-booth-layout.
- 테스트: BoothLayoutConfigLinkIntegrationTest 의 "미판정 대표" 를 RECRUITMENT_BOARD 등으로 옮기고, 장식형 + configId 가 경고 0건임을 단정하는 케이스를 새로 넣는다. 공용 픽스처(BoothLayoutTestSupport)가 configId 를 실은 VIDEO_SCREEN 이라 경고 개수를 단정하는 호출부가 있는지 확인한다.

완료 조건

- VIDEO_SCREEN 을 configId 없이 저장·게시해도 CONFIG_NOT_LINKED 가 나지 않는다.
- configId 를 실어도 저장되고 경고가 없다.
- 회전 기하(AREA_OUT_OF_BOUNDS) 판정은 바뀌지 않는다.
