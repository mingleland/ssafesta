## 설명

개발 중 회원 세션으로 들어가는 길이 제품 버튼(Google 로그인)을 빌려 쓰고 있고, 그 상태가 화면에 드러나지 않는다. 진입 자체를 이름 있는 개념으로 분리한다.

[배경]
로컬에서 회원이 되는 유일한 길이 mock OAuth 이다(실 Google 은 액세스 차단). 그러다 보니 개발 진입이 제품 동선을 타게 됐다.

실측으로 프로덕션 노출 위험은 없음을 먼저 확인했다 — .env.example 기본값 false, Dockerfile·Jenkinsfile·CI 에 VITE_USE_MOCK 명시 0건, .dockerignore 가 .env* 차단, 그리고 VITE_USE_MOCK=false 프로덕션 빌드 산출물에 mockStartOAuth·mock-handoff·StaticMockWorld 가 전부 0건이다(Vite 상수 치환 + tree-shaking).

그럼에도 남는 약점 2가지:
1. VITE_USE_MOCK 은 "mock 데이터로 개발한다" 로 읽히지 "인증을 우회해 회원이 된다" 로는 읽힌지 않는다. 이름이 의도를 말하지 않는다
2. mock 회원으로 들어가도 UI 가 실제 회원과 똑같아 스크린샷·시연에서 구분되지 않는다

[플래그 역할 분리]
VITE_USE_MOCK   mock 데이터 소스
VITE_MOCK_WORLD Unity World mock 여부 (S15P21A604-466 에서 분리)
VITE_DEV_ENTRY  개발자 전용 진입 여부 (이번 신규)

VITE_DEV_ENTRY 는 import.meta.env.DEV 와 AND 로 묶는다 — IS_DEV_INTERACTION_BAR(gameClientUi.ts:19)가 이미 쓰는 관례고, 프로덕션 빌드에서 상수 false 가 돼 번들에서 사라진다.

[개발자 진입]
- 로그인 화면에 제품 로그인과 분리된 "개발자로 입장" 을 둔다
- 개발자 진입 세션은 회원 고정
- 게스트 테스트는 기존 "게스트로 둘러보기" 제품 경로를 쓴다
- Google·SSAFY 등 실제 제품 로그인 버튼을 개발 진입용으로 재사용하지 않는다

[DEV 상태 표시]
- 우상단 사용 금지 — 향후 사운드·그래픽 효과 등 사용자 액션 컨트롤 영역으로 유지한다
- DEV 배지는 좌상단 고정. 클릭 기능 없는 상태 표시 전용
- 화면 가장자리 top/left 고정으로 제품 콘텐츠와 분리
- IS_DEV_ENTRY 조건 하나로 컴포넌트 전체 ON/OFF

영역 경계:
  우상단 -> 사용자 사운드/그래픽 액션
  좌상단 -> 개발 환경 표시

[완료 조건]
1. IS_DEV_ENTRY=false 일 때 로그인 화면이 지금과 동일하다
2. 개발자로 입장 -> 회원 세션으로 /app/world 진입, 회원 전용 오버레이가 열린다
3. 좌상단 DEV 배지가 보이고 클릭되지 않는다
4. 프로덕션 빌드 산출물에 개발자 진입구·배지 문자열이 0건이다
5. Login reference 기하 무변화 — 1920x1080 버튼 4종 x 38.8% · y 58.8/66.7/74.59/82.49%
6. 전체 vitest green / tsc 0 / oxlint 신규 경고 0

[범위 밖]
- 가드(guard.ts · isMember · 쿼리 enabled) 수정: 손둘 이유가 없다
- BE dev 로그인 엔드포인트: BE 파트 합의 사안
- 제품 레이아웃·Login reference 기하 변경
