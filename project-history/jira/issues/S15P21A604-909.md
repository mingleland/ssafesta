## 설명

### 작업 목적

브라우저에서 관리자 코인 조정 API를 호출할 수 없는 문제를 고친다.

### 현상

`POST /api/v1/admin/wallets/{userId}/adjustments` 를 브라우저(fetch)로 호출하면 CORS 오류로 차단된다. curl로는 정상 동작한다.

### 원인

`SecurityConfiguration.corsConfigurationSource` 의 허용 헤더 목록이 `Authorization`, `Content-Type` 두 개뿐이다.

```java
cors.setAllowedHeaders(List.of("Authorization", "Content-Type"));
```

코인 조정 API는 `Idempotency-Key` 를 필수 헤더로 요구한다. 커스텀 헤더이므로 브라우저가 preflight(OPTIONS)를 보내고, 서버 응답의 `Access-Control-Allow-Headers` 에 해당 이름이 없어 본 요청이 나가기 전에 차단된다. 관리자 승격(`POST /api/v1/admin/admins/{userId}`)처럼 표준 헤더만 쓰는 API는 정상이라 지금까지 드러나지 않았다.

즉 서버 구현과 OpenAPI 문서는 이 헤더를 필수로 선언하는데, CORS 설정이 그 헤더의 사용을 막고 있다. FE가 코인 조정 화면을 붙이는 순간 반드시 막힌다.

### 작업 내용

- 허용 헤더 목록에 `Idempotency-Key` 를 추가한다.
- 통합 테스트로 preflight 응답을 검증한다 — `OPTIONS` 요청의 `Access-Control-Allow-Headers` 에 `Idempotency-Key` 가 포함되는지 확인.

### 완료 조건

- [ ] 브라우저 fetch로 코인 조정 API 호출 시 CORS 차단이 발생하지 않는다.
- [ ] preflight 응답의 허용 헤더에 `Idempotency-Key` 가 포함된다.
- [ ] 기존 CORS 동작(허용 오리진 단일, credentials 허용)은 변하지 않는다.

### 참고

- `backend/src/main/java/com/example/ssafesta/auth/SecurityConfiguration.java`
- `backend/src/main/java/com/example/ssafesta/wallet/AdminWalletController.java`

### 테스트 방법

1. 백엔드 기동 후 허용 오리진 페이지에서 fetch로 `POST /api/v1/admin/wallets/{userId}/adjustments` 호출 (`Idempotency-Key` 포함).
2. 200 응답과 잔액 변동 확인. 콘솔에 CORS 오류가 없어야 한다.
3. 통합 테스트 실행.
