## 설명

## 발생 환경

- Branch: develop (인프라 설정 — 코드 아님)
- Build: demo/production (`api.ssafesta.world`)
- Account: 소유자 계정(어느 계정이든 재현)

## 재현 방법

1. Game Studio에서 게임을 만든다.
2. Draft를 1,048,577 byte(1MiB+1) 이상으로 키워 저장을 시도한다(오브젝트를 충분히 늘리면 재현됨).
3. `PUT /api/v1/games/{gameId}/draft` 요청을 보낸다.

## 기대 결과

애플리케이션은 Draft를 2,000,000 byte까지 지원하도록 설계돼 있다(`GameProjectJson.MAX_PROJECT_BYTES`). 2,000,000 byte 이하면 저장되거나, 초과 시 우리 앱의 JSON 에러(`PROJECT_SIZE_INVALID`)로 거부돼야 한다.

## 실제 결과

1,048,576 byte(정확히 1MiB)를 넘는 순간 애플리케이션에 도달하지도 못하고 nginx가 `413 Request Entity Too Large`(HTML)로 자른다. 실측:

- 1,048,576 byte → `200`/앱 에러 (정상, 앱까지 도달)
- 1,048,577 byte → `413`(nginx)

`infra/environments/nginx/sites/api.conf.template`(예: `origin/docs/S15P21A604-155-r2-signing-record` 브랜치)를 확인한 결과 `client_max_body_size` 지시어가 아예 없다 — nginx 기본값(1m)이 그대로 살아있는 것으로 보인다. 팀 결정 문서(`docs/26_팀_결정_필요사항.md`)에도 이 값을 의도적으로 1MiB로 두기로 했다는 기록은 없다.

## 완료 조건

- [ ] `api.<domain>` nginx 설정에 `client_max_body_size`가 애플리케이션 상한(2MB) 이상으로 명시된다.
- [ ] 1,048,577~2,000,000 byte 사이 Draft 저장이 nginx 413이 아니라 정상 처리(또는 앱의 `PROJECT_SIZE_INVALID`)로 응답한다.
- [ ] dev·demo 양쪽에서 확인한다.
