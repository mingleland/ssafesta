## 설명

## 문제

`WorldChatPresenceListener.onConnected` 가 인증된 STOMP `SessionConnectedEvent` 마다 `WorldChatService.announceJoin` 을 부른다. 이 경로에는 전송 제한이 없다(주석에도 "일반 채팅 rate limit은 적용하지 않는다"로 명시되어 있다).

그래서 연결을 끊고 다시 붙기를 반복하면 JOIN 시스템 알림이 무제한으로 `/topic/world/chat` 에 실린다. 일반 채팅은 S15P21A604-891 로 0.8초 최소 간격 · 10초 5회 · 1분 20회로 막혔지만, 같은 토픽을 JOIN 으로 밀어올리는 경로는 그대로 열려 있다. 네트워크가 불안정한 사용자가 의도 없이 같은 결과를 만들 수도 있다.

GitLab #223 §5-5 에서 FE 가 "이번 범위에 넣을지, 별도로 볼지" 물었고 BE 판단에 맡긴 항목이다.

## 범위

- 같은 회원의 입장 알림을 일정 간격에 한 번만 방송한다(제안: 60초). 제한에 걸린 연결은 조용히 방송하지 않을 뿐, 연결 자체는 정상이다.
- 판정은 Redis 에 두고 원자적으로 한다. 채팅 제한과 같은 이유다 — 동시에 도착한 두 연결이 서로의 기록을 보기 전에 둘 다 통과하면 막으려던 것이 새어 나간다.
- Redis 가 답하지 않으면 방송하지 않는다(fail-closed). 입장 알림은 없어도 기능이 성립하고, 판정 불가 상태에서 열어 두면 Redis 가 흔들릴 때 토픽이 밀린다. 대신 경고 로그를 남긴다(조용히 삼키지 않는다).
- 클라이언트 계약 변경은 없다. JOIN payload(`WorldChatJoinNotice`)와 오류 큐는 그대로다. `announceJoin` 은 SEND 응답 경로가 없어 거절을 돌려줄 자리 자체가 없다.

## 하지 않는 것

- 일반 채팅(`say`)의 제한값은 손대지 않는다 — S15P21A604-891 에서 확정된 값이다.
- 퇴장 알림은 범위 밖이다(현재 기능 없음).

## 완료 조건

- 같은 회원의 연속 재연결에서 첫 연결만 JOIN 이 방송된다.
- 간격이 지나면 다시 방송된다.
- 다른 회원의 입장은 서로 막지 않는다.
- Redis 장애 시 방송하지 않고 예외가 연결 이벤트 리스너 밖으로 새지 않는다.
- 위 항목을 검증하는 테스트를 `WorldChatIntegrationTest` 에 추가한다.
