## 설명

요청 배경
- prod 의 92MB data.unityweb 가 cf-cache-status DYNAMIC 이고 demo 는 HIT 다. 접속자마다 서울 원본에서 92MB 를 통째로 받아 입장 시간의 대부분을 차지한다. 어제 10건에서 오늘 80건으로 늘며 체감으로 드러났다.

원인
- 원본 응답 헤더는 prod·demo 동일하다(public, max-age=31536000, immutable). nginx 문제가 아니다.
- Cloudflare 기본 캐시는 확장자 목록 기반이고 .unityweb 은 그 목록에 없다. 명시적 캐시 규칙이 있는 demo 만 캐시된다.

요청 사항 (존 관리자 권한 필요)
- prod 호스트의 /unity/ 경로에 Cache Rule 추가: Eligible for cache, Edge TTL 은 원본 헤더 존중.

같이 볼 것 (저장소 쪽 비대칭)
- demo.conf.template 에는 location /unity/Build/ 포괄 규칙이 있어 하위 파일 전부 immutable 인데, prod.conf.template 에는 없다. prod 는 (.wasm|.js|.data).(br|unityweb) 정규식에 걸리는 것만 immutable 이고 나머지는 location /unity/ 로 떨어져 no-cache 로 나간다. loader 스크립트와 비압축 폴백이 여기 해당한다.

영향
- 적용되면 prod 입장 시간이 demo 수준으로 내려간다. 릴리스 승격 시 파일 해시가 바뀌어 엣지 캐시가 비워지므로, 규칙을 먼저 적용한 뒤 승격하는 것이 좋다.

### 정승욱 · 2026-09-23 13:57 KST

적용 완료.

**Cloudflare** — prod `/unity/Build/` Cache Rule 추가(Eligible for cache, Edge TTL 원본 존중). 92MB `data.unityweb` 이 `cf-cache-status: HIT` 으로 전환됨을 확인. `/unity/manifest.json` 은 `no-cache` + `DYNAMIC` 유지라 릴리스 갱신 감지에 영향 없음.

**저장소 비대칭** — !1339 에서 `prod.conf.template` 에 `location /unity/Build/` 포괄 규칙 추가(loader 등 정규식 미매칭 산출물이 `no-cache` 로 나가던 문제). !1344 에서 후속 두 건 처리.

- Build 캐시 헤더에서 `always` 제거. 캐시 규칙을 켠 뒤로는 없는 해시의 404 에 `immutable`·`Content-Encoding: br` 이 붙어 엣지가 그 404 를 장기 보관할 수 있었고, 롤백으로 파일이 되살아나도 404 가 남는 경로였음. FE `/assets/` 가 같은 이유로 `always` 를 뺀 선례(LJH T-119)를 따름. prod·demo 동시 적용.
- prod `/ai/v1/` 에 demo 와 같은 `no-store` 추가.
- `production-runtime.sh` 에 두 계약 회귀 가드 추가.

**demo nginx 반영 완료** — 템플릿 렌더 후 `nginx -t` + reload. 오리진 직접 검증(`--resolve` 로 엣지 우회):

- `200` / `application/octet-stream` / `content-encoding: br` / `public, max-age=31536000, immutable`
- 없는 해시 요청은 `404` 이고 `Cache-Control` 헤더 없음

**반영 중 발견** — demo 는 `/etc/nginx/snippets/festa-unityweb.conf`, `festa-ai-v1.conf` include 로 수동 패치돼 있었고 저장소에는 없던 파일이었음. 템플릿이 동일 내용을 인라인으로 갖고 있어 기능 손실 없음(`.unityweb` 3종 MIME·br·immutable, `/ai/v1/` 프록시 헤더 전부 일치). prod.conf 는 snippet 미사용이라 승격 시 영향 없음.

**남은 것** — prod nginx 는 다음 production 승격 때 `activate-production-release.sh` 가 템플릿을 렌더·리로드하면서 자동 반영됨. 그 전까지 prod loader 는 `no-cache`(`REVALIDATED`) 로 매 요청 오리진 재검증 상태. 별도 수동 조치는 불필요.
