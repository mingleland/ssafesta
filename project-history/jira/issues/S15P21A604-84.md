### 정정 (2026-08-25) — GET → POST

제목과 작업 내용을 `GET` 에서 `POST` 로 고쳤다. 정본 3곳이 모두 POST 다.

- `docs/08_Backend_API_명세서.md` §16 — `### POST /world-sessions`
- `docs/21_착수전_기술결정_ADR.md`:210 — "MVP에서도 `POST /api/v1/world-sessions` 를 반드시 존재시키고"
- `specs/infra-003-unity-server-deploy/contracts/world-session.openapi.yaml` — `paths./api/v1/world-sessions.post`

의미상으로도 POST 다. 호출마다 새 1회용 토큰이 발급되므로 멱등이 아니고 캐시·프리페치 대상이 되어서는 안 된다. 이 이슈 본문(2026-08-21 작성)이 `docs/sdd/parts/BE.md`:68 의 초안 표기(GET)를 따라간 것으로 보이며, 그 브리프는 스스로 "권장안(공식 결정 아님)" 이라고 밝히고 있다.

### 구현 완료 (2026-08-25) — 리뷰 대기

MR: [!4](https://lab.ssafy.com/s15-metaverse-game-sub1/S15P21A604/-/merge_requests/4) (`feature/S15P21A604-84-world-session` → `back`)

- 전용 `CONNECTION_TOKEN_SECRET`(HS256) 로 서명 — Access Token 키(`JWT_SECRET`)와 분리. 게임 서버가 자체 검증하므로(헌법 14조) 그 키가 배포 컨테이너에 들어가고, 같은 키면 유출 시 Access Token 위조가 된다
- TTL 120초, claims 는 `world-entry-token.md` 계약 그대로
- 세션 저장소 0개 — `jti` 소비 원장은 게임 서버 소유 (S15P21A604-170 참조)
- `worldId` optional 수용, `11F` 만 유효 (헌법 9조·FR-012·GitLab #31)
- 검증: `./mvnw test` **247 passed / 0 failed**, `/v3/api-docs` 노출 확인, 게스트 발급 실환경 스모크 통과
- 신규 환경변수 `CONNECTION_TOKEN_SECRET` (Base64, 디코드 ≥32바이트) — 없으면 앱이 기동되지 않는다. 배포 전 주입 필요
