## 설명

## 배경

spec 013 은 확정 상태지만 C-01(카테고리·항목 수)과 C-03(용량 목표)은 "값"이 아니라
"산출 방법"으로 확정됐다 — C-01 은 에셋 실조사 산출물로, C-03 은 현재 Web 빌드를 기준으로 역산.
즉 남은 것은 결정이 아니라 실측 실행이다.

## C-01 실조사 결과

카테고리 8종, 항목 105개 (Head 8 / Hair 31 / Hat 11 / Glasses 2 / Top 26 / Bottom 12 /
Outfit 8 / Shoes 7), 팔레트 16색.

## C-03 — 기준선 자체가 틀렸다

spec 은 "현재 Web 빌드(약 87MB)" 를 기준선으로 잡았는데, 실제 배포 빌드는 138.78 MB 다.
이미 59% 초과 상태였다.

## 발견 — UI 아이콘·썸네일이 빌드의 47%

Resources/Avatar/UI 의 49개 파일이 빌드에서 65.70 MB 를 차지했다.

원인 두 가지가 겹쳤다.

1. 원본이 1254x1254 다 — 목록 칸에 188x156 으로 그려지는 그림인데.
2. 1254 는 2의 거듭제곱이 아니라(NPOT) 블록 압축을 못 써 RGBA32 무압축으로 들어간다.
   1254*1254*4 = 6.0 MB — 관측치 6.1 MB 와 일치.

그리고 결정적으로 런타임 코드가 이미 스스로 줄여 쓰고 있었다. CharacterLobbyController 는
원본을 RenderTexture 로 blit 하면서 상한을 건다 — 일반 썸네일 224, 색상 아이콘 256,
얼굴 시트 셀당 320. 1254 는 화질에 기여하지 않고 로드 직후 버려진다.

## 조치

런타임 상한에 맞춰 maxTextureSize 조정 — 얼굴 시트만 1024(셀 512, 상한 320 초과 확보),
나머지 256. 41개 파일 변경.

## 결과

65.7 MB → 8.7 MB (57.0 MB 절감). 빌드 리포트와 런타임 계측 두 경로가 65.7 MB 로 일치했다.

화질 A/B: 같은 파일을 옛 설정과 새 설정으로 각각 임포트해 실제 표시 크기(188x156)에서 비교.
평균 차이 0.58~2.97 / 255 — 육안 구분 불가 수준.

## 도구

반복 실행 가능한 Editor 도구 4종을 남겼다 (카탈로그 실조사 / 빌드 리포트 에셋별 용량 /
UI 텍스처 예산 / 화질 A-B).
