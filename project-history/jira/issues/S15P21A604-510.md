## 설명

## 작업 목적

게임 흐름 화면(씬 단위 그래프 플로팅 윈도우)의 마우스 조작이 클릭과 shift+휠(가로 스크롤)뿐이라, 브라우저 기본 스크롤 박스처럼 보이고 스크롤바도 그대로 노출됨(Notion QA id=32). 노드 클릭은 그대로 두고, 배경 드래그로 화면을 이동하고 휠로 커서 위치 기준 확대/축소하는 팬/줌 캔버스 방식으로 바꿔 "떠있는 창 안의 지도"에 가까운 조작감을 준다.

## 작업 내용

- `SceneFlowGraph.tsx`(또는 감싸는 wrapper)에 내부 팬/줌 상태(오프셋 `{x, y}`, 배율 `scale`) 추가
- 배경 영역(노드가 아닌 곳)에서 pointerdown~pointermove~pointerup 드래그로 팬 구현 — `FloatingPanel`의 `setPointerCapture` 드래그 패턴 재사용
- 휠 이벤트로 확대/축소 — 커서 위치를 고정점으로 삼아 `scale`을 바꾸고 오프셋도 같이 보정(확대해도 커서 아래 지점이 화면상 그대로 유지)
- 배경 hover 시 `cursor: grab`, 드래그 중 `cursor: grabbing`(표준 팬 캔버스 관례). 노드 위 커서/클릭 동작은 기존 그대로 — 노드 위에서 시작한 pointerdown은 팬으로 잡지 않음
- `.gss-flow-graph-scroll`의 `overflow: auto`(네이티브 스크롤) 제거, 콘텐츠 전체를 `transform: translate() scale()`로 이동·확대 — 스크롤바 자체가 생기지 않음
- 최소/최대 줌 배율 clamp
- 뷰를 초기 위치로 되돌리는 리셋 기능은 이번 범위 제외(QA에서 확인)
- `FloatingPanel` 자체의 드래그(제목 표시줄)/리사이즈(모서리)는 별개 컴포넌트라 이번 범위 밖

## 완료 조건

- [ ] 배경(노드 외 영역)을 드래그하면 그래프 내용이 드래그하는 대로 이동한다
- [ ] 배경에 마우스를 올리면 `grab` 커서, 드래그 중에는 `grabbing` 커서로 바뀐다
- [ ] 노드 위 커서와 클릭 동작은 기존과 동일하게 유지된다(회귀 없음)
- [ ] 휠을 돌리면 커서 위치를 기준점으로 확대/축소된다
- [ ] 스크롤바가 보이지 않는다
- [ ] 관련 테스트 통과 + `tsc --noEmit` 통과
