## 설명

## 작업 목적

- 숫자 입력칸 8개(발사 간격·생성 간격·닿을 때 피해·최대 체력·이동 범위·피해량·동시 최대·상호작용 거리)가 키 입력마다 즉시 엄격한 범위 검증을 거쳐서, 최소값이 2자리 이상인 필드(발사 간격 100, 생성 간격 250)는 처음부터 다시 타이핑하는 게 사실상 불가능하다. 타이핑 중에는 자유롭게 입력되게 하고, 포커스가 벗어날 때만 범위를 보정하도록 바꾼다.

## 작업 내용

- `CommitInput.tsx`와 같은 커밋-온-블러 패턴의 숫자 전용 컴포넌트를 새로 만든다 — 타이핑 중엔 숫자(0-9)만 입력받고 자릿수·범위 제한은 없음, 포커스가 벗어날 때(blur)만 정수로 정리 + `min`~`max` 범위로 자동 보정한다. 완전히 비운 채 벗어나면 최소값으로 보정한다.
- 8개 필드 전부 최소값이 1 이상이라 마이너스는, 전부 정수 전용이라 소수점은 의미가 없다 — 두 문자 다 타이핑 자체를 막는다.
- `InspectorPanel.tsx`의 대상 8개 필드(닿을 때 피해 1~999 · 최대 체력 1~9999 · 이동 범위 1~100 · 피해량 1~999 · 발사 간격 100~10000 · 생성 간격 250~60000 · 동시 최대 1~100 · 상호작용 거리 1~100)를 이 컴포넌트로 교체한다.
- 그 외 필드(씬 크기, 오브젝트 좌표, scale, zIndex, 획득 점수, 게임 목표값)는 이미 문제가 없어 그대로 둔다.

## 완료 조건

- [ ] 8개 필드 전부 타이핑 중에는 범위 제한 없이 자유롭게 입력된다(숫자 0-9만 허용, 마이너스·소수점 불가)
- [ ] 포커스가 벗어나면(blur) 범위를 벗어난 값이 최소/최대값으로 자동 보정된다
- [ ] 완전히 비운 채 blur하면 최소값으로 보정된다
- [ ] Enter로 커밋, Escape로 되돌리기가 기존 `CommitInput`과 동일하게 동작한다
- [ ] 나머지 필드(씬 크기·오브젝트 좌표·scale·zIndex·SCORE_VALUE·목표값)는 기존 동작 그대로 유지된다(회귀 없음)

## 선행 작업 / Dependency

- 없음

## 테스트 방법

1. 각 8개 필드에서 값을 지우고 최소값보다 자릿수가 적은 중간값을 거쳐 최종 목표값까지 타이핑했을 때, 중간에 값이 되돌아가지 않고 끝까지 입력되는지 확인한다(특히 발사 간격 100, 생성 간격 250).
2. 각 필드에서 최대값보다 큰 값을 입력하고 포커스를 벗어났을 때 최대값으로 보정되는지 확인한다.
3. 각 필드를 완전히 비운 채 포커스를 벗어났을 때 최소값으로 보정되는지 확인한다.
4. 각 필드에서 숫자가 아닌 문자(글자·소수점·마이너스)를 타이핑해도 입력되지 않는지 확인한다.
5. Enter로 즉시 커밋되는지, Escape로 원래 값으로 되돌려지는지 확인한다.
