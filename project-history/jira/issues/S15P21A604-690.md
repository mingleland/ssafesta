## 설명

BE 가 부스 방문·체류 계측을 열었다(S15P21A604-240). POST /api/v1/booths/{boothId}/visits 로 입장, POST /api/v1/booths/{boothId}/visits/{visitId}/exit 로 퇴장이다.

FE 는 WORLD_BOOTH_CONTEXT{insideBooth, boothId} 를 이미 받아 features/world/model/worldContext.ts 에 들고 있어 입장·퇴장 시점을 갖고 있다. 막힌 것은 입장 본문의 worldChannel 이다 — 값이 서버 상수(WorldProperties.CHANNEL_ID = 11F-01)이고 Spring Access Token 클레임에는 없으며(sub·role·jti·sid), channelId 를 담은 world entry token 은 게임 서버로 간다. WorldSessionService 는 세션을 저장하지 않아 서버가 사용자별로 조회할 경로도 없다.

선행조건
- worldChannel 출처가 정해지기 전에는 착수하지 않는다. GitLab #186 에 세 안을 올린다: (A) 서버 상수 파생 (B) Unity 가 WORLD_BOOTH_CONTEXT 에 실어 주기 (C) Unity 발신.
- FE 가 서버 상수를 하드코딩하는 형태로는 구현하지 않는다.

구현 범위(A 확정 시)
- 발신 지점은 worldContext 전이 한 곳.
- 입장은 회원·게스트 모두 호출. 퇴장은 회원 세션에서만 호출한다 — 서버가 게스트 방문을 닫지 못하고 403 FORBIDDEN 을 낸다(BoothVisitService.exit 의 mine 판정이 visitorUserId != null 을 요구한다).

완료조건
- 단위 3건: 입장 1회만 발신, 퇴장에서 visitId 소비, 게스트는 퇴장 미호출.
- 로컬 왕복 1회. demo BE 에는 이 경로가 아직 없다.

팀 공유·논의 정본: GitLab #186
