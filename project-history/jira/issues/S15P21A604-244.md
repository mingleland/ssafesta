## 2026-08-27 — 삭제 반입 검증 케이스 실행 결과 (MR !48)

이 이슈가 검증하려던 케이스를 실제 반입에서 겪었기에 결과를 남긴다.

## 확인된 위험

`game` 은 부분 트리다. `origin/develop` 대비 diff 를 뜨면 **822 파일 / 69,300줄 삭제**가 나온다 — `backend/`, `specs/`, `.claude/`, `Jenkinsfile` 등 타 파트 산출물 전체다. 통째 머지는 절대 불가.

## 방식별 판정

| 방식 | 삭제 반입 | 타 파트 안전 | 판정 |
|---|---|---|---|
| `git merge game` | — | ❌ 69,300줄 삭제 | 금지 |
| `git checkout game -- <경로>` | ❌ **삭제를 반입 못 함** | ⚠ 경로 안에 타 파트 파일이 있으면 되레 삭제 | 조건부 |
| `git cherry-pick <커밋>` | ✅ 커밋에 담긴 삭제 그대로 | ✅ 커밋이 건드린 파일만 | **권장** |

## 실제 사례 — checkout 방식이었다면 사고

`docs/KHS/` 를 통째로 checkout 했다면 develop 에만 있는 `27_Game_Studio_작업일지.md` · `28_Game_Studio_트러블슈팅.md` · `29_Game_Studio_GitLab_이관_준비.md` 3종이 삭제됐을 것이다(game 브랜치에 없는 파일이므로). 체리픽으로 반입해 3종 모두 보존을 확인했고, develop 대비 삭제 파일은 **0건**이었다.

## 권장 절차 (초안)

1. `git fetch origin` 후 `git diff --stat origin/develop <part-branch>` 로 **삭제 규모를 먼저 확인** — 부분 트리 여부 판별
2. develop 에서 작업 브랜치 생성
3. **반입할 커밋을 체리픽** (경로 checkout 금지 — 삭제 미반입 + 타 파트 삭제 위험)
4. 검증: `git diff --name-status origin/develop HEAD --diff-filter=D` 가 **비어 있어야** 한다. 비어 있지 않으면 의도한 삭제인지 한 건씩 확인
5. 완료 이슈만 `Closes` 트레일러 → MR

경로 checkout 이 불가피한 경우(커밋이 뒤엉킨 과거분 등)는 4번 검증을 반드시 통과시키고, 삭제분은 별도로 `git rm` 해야 한다.
