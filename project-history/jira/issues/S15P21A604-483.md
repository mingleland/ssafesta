## 설명

## 작업 목적

Game Studio의 JSON 가져오기가 파일에 박힌 gameId와 현재 화면의 gameId가 다르면 하드 에러로 막고 있음. 그런데 `GameProject`는 scenes/assets/items/variables가 전부 인라인인 자기완결적 콘텐츠라 gameId는 "어느 게임에서 내보내졌는지"를 나타내는 출처 메타데이터일 뿐 콘텐츠 유효성과 무관함. 사용자는 파일을 열어보지 않는 한 그 안의 gameId를 알 방법이 없어, 이 하드 블록이 사실상 "무엇을 넣어야 통과하는지 알 수 없는 검증"이 되어 기능을 못 쓰게 만듦. "게임 초기화"/"시작 템플릿"은 이미 항상 현재 화면의 gameId로 프로젝트를 교체하는데 JSON 가져오기만 반대 규칙(파일 값 존중)을 써서 세 기능 간 일관성도 없었음(Notion QA id=26).

## 작업 내용

- `GameStudioShell.tsx`의 `importProject`에서 `if (imported.gameId !== gameId) throw new Error(...)` 하드 블록 제거
- gameId 불일치 시 에러 대신 현재 화면의 gameId로 덮어써서(coerce) 적용 — "게임 초기화"(`createBlankProject`)/"시작 템플릿"(`createProjectFromTemplate`)과 동일한 "항상 현재 화면 gameId로 교체" 패턴으로 통일
- `GameProject` 스키마(`contracts/gameProject.ts`)의 `gameId` 필드 자체는 유지 — 계약 변경 없음(스키마에서 gameId를 아예 빼는 방안은 이번 스코프에서 제외, 필요 시 별도 티켓)
- `gameAuthoringApi.ts`의 서버 draft 로드 응답 검증 로직(서버가 엉뚱한 게임 응답을 준 게 아닌지 확인하는 무결성 체크)은 관심사가 달라 이번 변경에서 건드리지 않음

## 완료 조건

- [ ] gameId가 화면과 다른 JSON을 가져와도 에러 없이 로드된다
- [ ] 가져온 프로젝트의 gameId는 파일 값과 무관하게 항상 현재 화면 기준으로 맞춰진다
- [ ] 기존 "gameId 일치" 케이스도 회귀 없이 동일하게 동작한다
- [ ] 관련 단위 테스트 통과 + `tsc --noEmit` 통과
