## 설명

[증상]
FestaReleaseBuilder·FestaWebBuilder·CiBuild 어느 것도 ApiConfig 를 건드리지 않는다 — 빌드 시점의 에셋 값이 그대로 WebGL 에 들어간다. 커밋된 ApiConfig.asset 은 useMockApi=1, activeEnvironment=Local(localhost:8000) 이고, Prod 항목은 https://api.example.com / https://ai.example.com 자리표시다. 2026-09-05 develop head 배포 빌드 실측 — 로컬 에셋이 useMockApi=0 이어도 Local 환경이라 WebGL 이 http://localhost:8000 을 부른다.

[예상 결과]
깨끗한 체크아웃에서 배포 빌드를 뽑으면 실사용자 WebGL 이 Mock API 로 동작한다 — 프로필·카탈로그·부스 레이아웃 전부 가짜. useMockApi 만 끄면 localhost 나 example.com 을 부른다. -418 과 같은 결(조용한 Mock)이고, -418 을 고쳐도 이것이 남으면 월요일(09-08) 배포가 성립하지 않는다.

[작업]
1. ApiConfig.asset 의 Prod 항목을 실제 도메인으로 채운다 — spring https://api.ssafesta.world, ai https://ai.ssafesta.world (#30 서브도메인 결정). Dev 항목은 EC2 dev 인그레스 https://ci.ssafesta.world/__dev/api (dev.conf). 커밋본 기본값(Mock+Local)은 에디터 개발 편의를 위해 그대로 둔다.
2. FestaReleaseBuilder.BuildWebGL 이 빌드 직전에 useMockApi=false, activeEnvironment=Prod 로 강제하고 끝나면 원값으로 복원한다 — 이미 압축 설정을 같은 방식으로 다루고 있다.
3. CiBuild 에 -festaEnv prod|dev|local 인자를 두고(기본 prod) 같은 강제를 한다. Mock 은 CI 에서 항상 false.
4. 빌드 로그에 "이 WebGL 은 <env> / mock=<bool> / spring=<url>" 을 반드시 남긴다 — 뭐로 뽑았는지 산출물만 보고 알 수 있게.

[완료 조건]
- 깨끗한 develop 체크아웃에서 배포 빌드 → WebGL 이 https://api.ssafesta.world 를 부른다 (브라우저 네트워크 탭 실측)
- 빌드 후 에디터 ApiConfig 가 원값(Mock+Local)으로 복원된다
- CiBuild -festaTarget webgl 도 같은 결과

[관련]
-418(로비 부트스트랩), -417(manifest), -82/#127(WebGL 서빙), GitLab #30(서브도메인). 월요일 배포 선행.
