## 설명

## 배경

배포용 빌드 경로가 손으로만 있었다. `Festa/부하테스트/WebGL 빌드` 는 **측정 전용**(Development ON · 압축 Disabled)이라 배포에 쓰면 안 되는데, 그 사실이 코드 주석에만 있었다. Linux 데디케이티드 서버는 메뉴 자체가 없어 Build Settings 에서 타깃을 손으로 바꿔 뽑고 `docker build` 를 따로 쳐야 했다.

단계가 많으면 빠뜨린다. 특히 **서버만 빌드하고 웹을 잊거나 그 반대**가 쉬운데, 그 조합의 증상은 "고쳤는데 그대로"라서 원인 추적에 시간을 다 쓰게 된다 (T-23/T-25).

실제로 지금 걸려 있는 사례: -283 의 엘리베이터 앞 스폰은 **서버 권위**라 WebGL 만 다시 뽑으면 반영되지 않는다.

## 작업 내용

`Festa/배포/` 메뉴 2종 신설 (`FestaReleaseBuilder.cs`).

- **배포 빌드 (Linux 서버 + WebGL + Docker 이미지)** — 셋을 한 흐름으로. 하나라도 실패하면 그 자리에서 멈춘다 (절반만 갱신된 산출물이 제일 나쁘다)
- **Docker 이미지만 갱신 (기존 서버 빌드)** — 코드 변경 없이 이미지만 다시 말 때

## 설계 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| Development | OFF | 릴리즈에 F3/F6 계측 도구가 남으면 실사용자가 아바타 40기를 소환할 수 있다 |
| WebGL 압축 | Brotli + **Decompression Fallback ON** | 저장소 어디에도 `Content-Encoding` 설정이 없다. 헤더 없는 정적 서버에 Brotli 만 올리면 로드 자체가 실패한다. Fallback 은 로더가 JS 로 풀어서 어디든 뜬다 — 배포 경로 확정(인프라 #30) 후 false 로 내린다 |
| 웹 출력 경로 | `Builds/web-release` (측정본과 분리) | Unity 가 이전 해시 파일을 안 지워 섞인다. 배포 디렉터리는 매번 비우고 시작 |
| 서버 씬 목록 | Build Settings 그대로 | 첫 씬 CharacterLobby 에 NetworkManager 가 없지만 `CharacterLobbyController.Awake` 의 `#if UNITY_SERVER` 리다이렉트가 처리한다. 지금 도는 이미지가 이 구성이라 **증명된 경로를 바꾸지 않았다** |
| 이미지 태그 | `festa-world:dev` + `festa-world:<git-sha>` | "지금 도는 컨테이너가 어느 코드냐"에 답할 수 있어야 한다. 커밋 안 된 변경이 섞이면 `-dirty` 를 붙여 재현 불가를 숨기지 않는다 |
| 디버그 산출물 | `.dockerignore` 자동 생성 | Dockerfile 이 `COPY . /app` 이라 `*_BurstDebugInformation_DoNotShip`·`*.debug` 가 이미지에 실려 갔다. 파일을 지우는 대신 걸러낸다 |
