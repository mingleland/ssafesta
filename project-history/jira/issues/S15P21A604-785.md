## 설명

GitLab #181 에서 BE 가 footprint 를 9.4 × 6 × 5.9 (x ±4.7) 로 확정하고 FE 선행을 요청했다. BE 는 자기 MR(S15P21A604-698) 병합을 이 FE MR 에 걸었다 — BE 가 먼저 닿으면 FE 가 허용한 배치를 서버가 거부해 사용자가 다 꾸미고 게시에서 막힌다.

범위
1. resolveLocalBounds(object, assets) 도입 — 정본은 runtime manifest 의 assets[].bounds. pickAsset 의 해석 순서(assetCode 정확일치 → typeDefault)를 그대로 쓰고, manifest 에 자산이 없는 기능형 오브젝트와 manifest 미로드 구간만 OBJECT_LOCAL_BOUNDS 로 떨어진다. 손으로 옮긴 상수 표를 새로 만들지 않는다.
2. OBJECT_LOCAL_BOUNDS 직접 조회 프로덕션 13곳을 해석기로 교체.
3. passage.ts 통행 격자의 6m 정사각형 하드코딩(GRID_SIZE 120 · HALF_EXTENT 3)을 bounds 기반 x/z 분리로. 9.4×6 이면 188 × 120, x 첫 셀 중심 −4.675.
4. flood fill 큐의 shift() 를 head 인덱스 전진으로 — 격자가 1.57배 커진다.
5. BOOTH_SIZE_FALLBACK 과 entities/layout/api.mock.ts 의 6×6×2.72 리터럴 교체. 서버 template.footprint 가 오는 정상 경로는 코드 변경 0.

회전 클램프(S15P21A604-754)는 재구현하지 않는다.

완료 조건
- 허용 중심 범위를 booth half extent − rotated object half extent 로 계산하는 경계 테스트 (절대 좌표 단언 금지)
- 6×6 을 넣으면 기존 120×120 판정과 완전히 동일 (회귀 잠금)
- 높이는 배치 좌표가 아니라 오브젝트 상단(world.max.y) 기준임을 테스트로 고정
- vitest / tsc / build green

남은 외부 항목 — BE 의 표는 Unity 프리팹 실측, FE 는 GLB 변환 후 manifest 라 축별 허용오차 합의가 필요하다. #181 에 통보한다.
