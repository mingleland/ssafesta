## 설명

### 작업 목적

MockUserApiClient 를 실서버 클라이언트로 교체해 Avatar 외형을 Spring 에 영구 저장한다.

### 작업 내용

- HttpUserApiClient 구현 — GET /api/v1/users/me 의 avatarCode 소비, PUT /users/me/avatar 저장
- WebGL 호스트의 Access Token 을 IAccessTokenProvider 로 주입 (Refresh Token 은 Unity 전달 금지)
- ApiServices.Init 의 Mock 교체 스위치

### 완료 조건

- [ ] 로그인 사용자의 avatarCode 가 월드 입장 시 조회된다
- [ ] 외형 변경 시 PUT 저장이 2xx 로 완료된다
- [ ] 401 시 Mock 폴백 없이 명시적 오류 표면화

### 선행 작업 / Dependency

### 강형순 · 2026-08-28 09:23 KST

구현 develop 도달 (MR !83, squash). 상태는 **진행 중 + ready-for-deploy** 유지 — 완료 조건 3개 중 1개가 배포 대기다.

**완료 조건 현황**

- [x] **401 시 Mock 폴백 없이 명시적 오류 표면화** — 계약대로 응답하는 스텁 서버로 실제 클라이언트 구동. 헤더 미부착→401(`LastAuthError` 세팅), `Bearer guest`→403 MEMBER_ONLY 확인
- [x] **외형 변경 시 PUT 저장이 2xx 로 완료** — 저장 True → `GET /users/me` 왕복 **바이트 일치**. 추가로 **echo 변조(트림·대문자화) 시 False 반환** 확인 — 왕복 무손실 계약(data-model §2) 위반을 클라이언트가 감지한다. 빈 문자열은 요청 자체를 내지 않음(스텁 로그 교차 확인)
- [ ] **로그인 사용자의 avatarCode 가 월드 입장 시 조회된다** — 실서버 E2E. **FE Token wiring(****[S15P21A604-91](https://ssafy.atlassian.net/browse/S15P21A604-91)****) 미완료로 토큰이 주입되지 않아 대기 중**

**구현 노트**

- `AuthBridge` 로 호스트→Unity Access Token 주입: `SendMessage('AuthBridge','SetAccessToken', <token>)` / 해제 `ClearAccessToken`. **Refresh Token 은 받지 않는다.** 씬 무수정(RuntimeInitializeOnLoad+DontDestroyOnLoad)이라 CharacterLobby·main 양쪽에서 잡힌다. 토큰 값은 로그에 남기지 않고 길이만 찍는다.
- FE 쪽은 로그인 직후·토큰 갱신 시 위 SendMessage 만 호출하면 된다 — 별도 계약 추가 없음.
- `POST /api/v1/world-sessions` 도 같이 실 HTTP 로 전환(spec 002 BE plan 계약).
