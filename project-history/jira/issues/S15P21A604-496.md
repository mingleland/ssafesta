## 설명

작업 목적

임대 만료된 Booth의 처리 중인 Job·문서 상태를 정합성 있게 종료 처리한다 (spec 007 FR-015, FR-041).

작업 내용

- Booth Lease 만료 감지(자체 sweep 또는 AI가 보내는 failed(BOOTH_LEASE_EXPIRED, retryable=false) 수신) 시 활성 Job을 CANCELLED로, Document를 DISABLED로 전환
- 실행 중인 FastAPI 작업에 멱등 cancel 전달 시도 — 전달 실패가 DB 정합성을 막아서는 안 됨
- 늦게 도착하는 FastAPI 결과(attemptNo 불일치)는 기존 409/410 fencing으로 거부 (S15P21A604-400에 이미 구현됨)

완료 조건

- 만료된 Booth의 활성 Job이 CANCELLED로 전환된다
- 만료된 Booth의 문서가 DISABLED로 전환된다
- 만료 이후 도착한 FastAPI 결과가 있어도 Document가 READY로 바뀌지 않는다

선행 작업 / Dependency

- S15P21A604-149 (AI 쪽 처리 시작·finalize 직전 Lease 이중 확인 — 완료, finalize 자체를 막아 READY 전환은 방지하지만 CANCELLED/DISABLED 전이는 하지 않음)
- S15P21A604-400 (결과 수신 API, 완료)

참고

- specs/007-ai-agent-document/plan.md §8
- specs/007-ai-agent-document/spec.md FR-015, FR-041

비고

S15P21A604-149는 AI(FastAPI)가 DB를 소유하지 않아(S15P21A604-449) Job/Document 상태를 직접 쓸 수 없다는 제약 때문에 AI 쪽 방어 로직(이중 확인 후 finalize 미호출)까지만 처리했다. 실제 CANCELLED/DISABLED DB 전이는 이 이슈에서 Spring이 구현한다.
