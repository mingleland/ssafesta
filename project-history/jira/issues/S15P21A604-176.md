## 완료 조건 2개 — 둘 다 충족

| 조건 | 근거 테스트 |
|---|---|
| 공개 게임 asset 익명 조회 가능 | `GameAssetApiIntegrationTest.aGuestReadsAPublishedAssetAndIsRefusedAPrivateOne` — Authorization 헤더 없는 GET 이 200, `Content-Type: image/png` |
| 미공개 게임 asset 차단 | 같은 테스트 후반(403) · `aStrangerCannotReadAnAssetOfAPrivateGame` · `onlyTheAssetsTheseVisitorsCanSeeInThePublishedGameAreReadable` |

비소유자 판정은 네 가지를 모두 요구합니다 — 게임이 `PUBLIC` 이고, 공개본이 있고, 그 공개본이 이 asset 을 참조하고, asset 이 `READY` 입니다. "게임이 PUBLIC 이면 그 자산도 공개" 로 두면 발행되지 않은 Draft 에만 있는 이미지가 노출되므로, 공개 게임의 미참조 `READY` 자산도 403 입니다.

401 이 아니라 403 인 이유는 로그인해도 달라지지 않기 때문입니다. 호출자의 신원이 문제가 아니므로 로그인하라고 하면 아무 효과 없는 일을 시키는 것이 됩니다.

**익명 조회는 SecurityConfiguration 한 줄에 걸려 있었습니다.** `/api/v1/games/*/assets/*/content` 가 `permitAll` 목록에 없어 `.anyRequest().authenticated()` 에 잡혔습니다. 서비스에는 optional authentication 판정이 있는데 필터가 그 앞에서 401 을 냅니다. 2026-08-28 #69 회신에 "필터에서는 경로를 열고 판정은 서비스에서 optional authentication 으로 걸겠습니다" 라고 적고 구현에서 빠뜨린 줄이고, 이것이 `-176` 이 `-107` 에 BLOCKED BY 로 걸려 있던 실체입니다.

## 작업 내용 1번 항목에 대한 정정 — "서빙 URL 해석 API" 는 만들지 않았습니다

티켓 작업 내용 첫 줄이 *"asset://{gameId}/{assetId} → 서빙 URL 해석 API"* 인데, **그 이름의 endpoint 는 만들지 않았습니다.** 만들면 안 되는 것이라 판단했습니다.

계약 `specs/019-game-studio/contracts/game-asset-upload.md` §3.4 가 해석을 **FE 쪽 문자열 치환**으로 정했습니다. `-116` 어댑터가 이미 그렇게 구현되어 있습니다.

```
asset://game/{gameId}/{assetId}  →  /api/v1/games/{gameId}/assets/{assetId}/content
```

`festa-frontend/src/game-studio/studio/assets/remoteAssetRepository.ts:147-150` 에서 `parseStableAssetSource` → `assetContentPath` 두 줄입니다. 해석 endpoint 를 서버에 두면 FE 가 그것을 부를 자리가 없고, 왕복이 이미지 1장당 1회에서 2회로 늘고 아무도 쓰지 않는 endpoint 가 유지 대상으로 남습니다.

**서버가 담당하는 "해석" 은 endpoint 가 아니라 두 곳에 있습니다.**

1. `/content` 가 그 주소의 목적지라는 것 자체 — asset:// 의 `{gameId}`·`{assetId}` 가 `game_assets` 조회 조건에 그대로 들어가고(`UNIQUE (game_id, asset_id)`), 소유권 판정이 그 조회 안에 포함됩니다. 다른 게임의 assetId 를 붙이면 행이 없어 404 입니다.
2. `GameProjectValidator` 가 Draft·Publish 양쪽에서 `asset://` 문자열을 검증합니다(`ASSET_SOURCE_INVALID`). 이 MR 에서 `READY` 상태 스냅샷 기준으로 완화됐습니다 — **그전까지 서버는 **`asset://` 를 전부 거부했습니다(2026-08-26 #69 §1 에 예고).

계약 §10 후속에 batch presign(`POST .../assets/resolve`)이 적혀 있지만, 그것은 목록 화면에서 병목이 실측될 때 붙이는 것이고 지금은 소비할 목록 UI 자체가 없습니다.

**즉 이 티켓은 "해석 API 하나" 가 아니라 "접근 제어 + 전달" 로 닫힙니다.** 제목만 읽고 없는 endpoint 를 찾는 일이 없도록 여기 근거를 남깁니다.
