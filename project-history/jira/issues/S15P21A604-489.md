## 설명

## 작업 목적

Spring이 전달한 문서 처리 요청을 FastAPI 백그라운드 Worker가 실제로 실행하고, 중복 요청·서버 종료·Worker 장애에서도 Spring Job lease를 기준으로 안전하게 복구되도록 한다.

## 작업 내용

- FastAPI lifespan에서 문서 처리 Worker 자원 초기화 및 graceful shutdown
- POST /ai/v1/documents/process 수락 후 jobId + attemptNo 단위 백그라운드 실행
- 동일 jobId + attemptNo 중복 요청의 동시 실행 방지
- 동시 처리량 제한 및 진행 중 heartbeat 실행
- S15P21A604-184 Embedding 계산과 S15P21A604-124 batch/finalize/failed 전달 연결
- 종료 시 신규 작업 수락 중단, 진행 작업 정리 및 Spring lease 회수 경로 보장
- HTTP/Redis 등 공유 client 정상 종료와 readiness 상태 반영

## 완료 조건

- 동일 jobId + attemptNo가 동시에 한 번만 처리된다.
- 정상 처리 시 heartbeat → chunk batch → finalize 경로가 완료된다.
- 처리 실패 시 정제된 failureCode로 failed가 전달된다.
- FastAPI 강제 종료 후 Spring lease sweeper가 Job을 회수해 새 attempt로 재처리할 수 있다.
- 종료 과정에서 잘못된 finalize 또는 READY 전환이 발생하지 않는다.
- startup/shutdown 및 중복 요청 테스트가 통과한다.

1. 동일 처리 요청을 동시에 두 번 보내 Worker 실행 횟수 1회 확인
2. 처리 중 heartbeat 주기 확인
3. 정상 처리에서 batch/finalize 순서 확인
4. 파싱·Embedding·Spring 전송 실패를 각각 주입해 failed 및 재시도 확인
5. 처리 중 FastAPI 종료 후 Spring lease 회수와 새 attempt 재처리 확인
