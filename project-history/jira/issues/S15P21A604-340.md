## 설명

## 증상

유니티 게임 서버가 **실제 Spring 백엔드가 발급한 world-session grant 를 전부 "aud 불일치" 로 거부한다.** 목 서버로는 접속되는데 실 백엔드로는 원리적으로 접속이 불가능한 상태였다.

## 발견 경위

env 파일을 받아 백엔드·프론트를 전부 올려 종단 테스트하던 중 발견. 실 백엔드에서 게스트 로그인 → `POST /api/v1/world-sessions` → 발급된 connectionToken 을 열어 보니:

```
alg: HS256 | iss: ssafesta-backend | aud: "ssafesta-world"   ← 단일 문자열
```

목 서버(`Tools/mock-api/serve.mjs`)와 에디터 서명기(`WorldEntryTokenSigner`)는 `aud: ["ssafesta-world"]` **배열**로 보낸다.

## 원인

RFC 7519 §4.1.3 은 `aud` 를 **배열·단일 문자열 둘 다** 허용한다. 그런데 `WorldEntryTokenVerifier.Claims.aud` 가 `string[]` 하나뿐이라, JsonUtility 가 문자열형을 **조용히 null 로 두고** `HasAudience` 가 거부한다.

유니티에서 실측 (실제 Claims 타입에 리플렉션으로 두 형태를 파싱):

```
배열형(목 서버·테스트) — aud [ssafesta-world] → 통과
문자열형(실제 백엔드)  — aud null → HasAudience 거부
```

**왜 여태 못 잡았나:** 검증기 주석은 "단일 문자열도 받는다" 고 적혀 있었지만 코드는 그렇지 않았고, 목 서버·테스트(`WorldEntryTokenTests`)가 전부 배열형만 만들어서 이 경로가 한 번도 검증된 적이 없다. 실 백엔드를 올려 종단으로 치기 전까지는 드러날 수 없는 구조였다.

## 수정 (유니티 쪽만 — 타 파트 규약에 맞춘다)

- `WorldEntryTokenVerifier.NormalizeAudience` 추가: 파싱 전에 문자열형 `aud` 만 배열형으로 고쳐 쓴다. 값 안의 이스케이프(`\"`)를 건너뛰며 문자열 끝을 찾는다. 배열형·aud 없음·형식 밖은 원문 그대로.
- 검증 강도는 그대로다 — 형태를 받아 주는 것이지 대상 검사를 약화하는 것이 아니다.
- 목 서버도 실물과 같은 **단일 문자열**로 바꾼다 — 목이 실물과 다른 형태를 보내면 이런 결함을 정확히 가린다.
- 테스트 3개 추가: 단일 문자열 aud 수락 / 단일 문자열이라도 대상 다르면 거부 / 정규화가 aud 밖을 건드리지 않음.

## 서버 빌드 종단 검증 완료 (2026-08-31)

MR !152 머지 후, 남아 있던 마지막 완료 조건("게임 서버 빌드로 실 BE grant 접속")을 확인했다.

**경로 (전 구간 실물, 목 없음):**

1. 실 Spring (`localhost:8080`, JDK 21 컨테이너) → `POST /api/v1/auth/guest` → 게스트 AT
2. `POST /api/v1/world-sessions` → grant 발급 (`aud` 단일 문자열, jti=`00e1a702-…`)
3. 새로 빌드한 게임 서버 (`festa-bot.exe`, develop 8ac553f, `NormalizeAudience` 포함 확인 — DLL 에서 심볼 실측) 를 backend/.env 와 같은 `CONNECTION_TOKEN_SECRET` 으로 기동
4. 에디터 클라이언트가 그 grant 로 접속

**서버 로그:**

```
[ConnectionManager] Approved client=1 slot=0 pos=(-29.50, 0.18, -248.00) nickname=게스트-c2ec
```

- `aud` 단일 문자열 grant 를 새 검증기가 수락 — 이 이슈의 수정이 서버 빌드에서 동작한다
- nickname 이 클라이언트 payload("RealBeVerify")가 아니라 **토큰 클레임**("게스트-c2ec")에서 왔다 — 서버가 클라이언트 주장보다 토큰을 신뢰하는 것도 정상 동작 확인

**부수 확인 — world-session 응답 DTO 전체 대조:** `sessionId / worldId / channelId / endpoint{scheme,host,port} / connectionToken / expiresAt` 6필드가 유니티 `WorldSessionDto` 와 이름·구조·타입까지 일치. grant 의 `aud` 가 유일한 어긋남이었다 (자가리뷰 약점 ⑤ 해소).
