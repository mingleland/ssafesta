## 설명

## 증상

`https://api.ssafesta.world/oauth2/authorization/ssafy` 하나가 클라이언트에 따라 다른 응답을 냈다. 같은 URL, 같은 시각, 같은 컨테이너다.

- 로그인 세션이 있는 브라우저: Whitelabel Error Page (500, HTML)
- 세션 없는 curl: `{"code":"UNAUTHORIZED","message":"Access Token이 필요합니다."}` (401, JSON)

두 응답 모두 실제 실패 원인과 무관하다. 한동안 재배포 중 상태 변화로 오해했다.

## 원인

둘 다 컨테이너의 ERROR dispatch 다. 필터에서 나온 예외가 500 이 되어 `/error` 로 재디스패치되는데, Spring Boot 는 `springSecurityFilterChain` 을 REQUEST·ERROR·ASYNC 세 dispatcher type 에 등록한다. 그래서 그 재디스패치가 시큐리티 체인을 한 번 더 타고, `/error` 는 어느 permitAll 에도 없어 `anyRequest().authenticated()` 에 걸린다.

- 익명이면 거부되어 401 봉투가 나간다. 실패 원인과 상관없는 코드를 그럴듯하게 돌려주는 셈이다.
- 인증된 세션이면 통과해서 Boot 의 `BasicErrorController` 가 Whitelabel HTML 을 렌더한다. docs/08 §1.3 오류 봉투 계약 이탈이다.

오류 봉투를 벗어나는 경로가 반복해서 나온 지점이다 (T-113 계열, S15P21A604-402 도메인 예외 6종, S15P21A604-693 필터의 sendError). 이번은 컨테이너 ERROR dispatch 계층이고, 이 경로는 필터가 던진 예외·`sendError`·허용 경로의 404 를 전부 받는다.

## 조치 3건

1. `ApiErrorController implements ErrorController` 신설. `/error` 를 오류 봉투로 답한다. 원 예외는 이미 사라진 시점이므로 `jakarta.servlet.error.status_code` 만 보고 `ErrorCode.of(status)` 로 코드를 고른다. 내부 정보는 내보내지 않는다.
2. 시큐리티 체인에 `dispatcherTypeMatchers(DispatcherType.ERROR).permitAll()`. 거부한 채로 두면 위의 위장 401 이 그대로 남는다.
3. `RequestIdFilter` 가 ERROR dispatch 에서도 동작하도록 `shouldNotFilterErrorDispatch()` 를 false 로. `OncePerRequestFilter` 기본값이 skip 이라 MDC 가 비어 이 경로의 봉투는 `requestId` 가 전부 null 이었다. id 는 새로 만들지 않고 요청 attribute 로 넘겨 재사용한다. 새로 만들면 이미 보낸 `X-Request-Id` 헤더와 어긋난다.

곁들여 `GlobalExceptionHandler` 의 private status→code 매핑을 `ErrorCode.of(HttpStatus)` 로 올려 두 곳이 같은 표를 쓴다.

변경 파일: `common/ApiErrorController.java`(신설) · `common/RequestIdFilter.java` · `common/ErrorCode.java` · `common/GlobalExceptionHandler.java` · `auth/SecurityConfiguration.java`

## 검증

`ErrorEnvelopeIntegrationTest` 에 ERROR dispatch 단정 1건을 추가했다. 세 조치를 하나씩 되돌려 각각 다른 이유로 떨어지는 것을 확인했다.

- permitAll 제거 → `Status expected:<500> but was:<401>` (운영에서 관측한 그 모양)
- ApiErrorController 제거 → `No value at JSON path "$.code"` (Whitelabel HTML)
- RequestIdFilter 되돌림 → `"requestId":null`

## 예방

오류가 클라이언트에 닿는 경로는 셋이다. `@RestControllerAdvice`(컨트롤러 밖으로 나온 예외), `ApiErrorWriter`(시큐리티 entry point), `ApiErrorController`(컨테이너 ERROR dispatch). 셋 중 하나가 비면 그 경로만 다른 모양으로 나간다. status 만 단정하는 테스트는 이 이탈을 잡지 못한다.
