## 설명

빌드의 60.5%가 텍스처다. 그런데 텍스처 539장 중 523장(97%)이 maxTextureSize 2048 — 유니티 기본값 그대로다. 아무도 임포트 예산을 정한 적이 없다.

빌드 리포트 (릴리스 41107ee2, 143.8 MB):

- 텍스처 227.1 MB / 60.5%
- 메시 110.7 MB / 29.5%
- 셰이더 11.8 MB / 3.2%
- 사운드 7.5 MB / 2.0%
- 총 사용 에셋 375.2 MB

텍스처는 상위 몇 장에 몰려 있지 않고 523장에 넓게 퍼져 있다. 그래서 개별 최적화보다 예산을 정해 일괄 적용하는 것이 맞다.

2048에서 1024로 내리면 픽셀이 1/4이 되고 텍스처 용량도 대략 1/4이 된다. 텍스처 227 MB 가 60~70 MB 로, 빌드가 143 MB 에서 80~90 MB 로 줄어들 것으로 본다.

이것이 어드레서블보다 먼저인 이유: 어드레서블은 총량을 줄이지 않고 분할·캐시로 미룬다. 지금은 총량 자체가 과하고, 그 원인이 설정 부재다. 게다가 어드레서블 도입은 main.unity 에 직접 배치된 320 MB 를 프리팹으로 들어내는 씬 구조 변경이 선행돼야 한다.

범위: 벤더 에셋 포함 (사용자 승인 2026-09-07). 원본 파일은 건드리지 않고 .meta 임포터 설정만 바꾼다.

검증: 빌드 용량 비교 + 육안 품질 확인. 품질 저하가 보이는 텍스처는 개별로 되돌린다. 특히 가까이서 보는 것(노트북, 아케이드 화면, 바닥·카펫 타일)을 먼저 본다.

주의: 동작이 아니라 보이는 품질로 판단한다. 용량만 줄고 화면이 나빠지면 실패다.

### 강형순 · 2026-09-07 10:48 KST

실측 결과 효과가 0이었다. 되돌렸다.

측정 방법: 변경 전후 빌드 리포트의 "Used Assets" 목록을 같은 방식으로 합산해 비교했다. 요약 줄만 믿지 않고 항목을 직접 더했다.

|  | 텍스처 | 장수 | 전체 |
|---|---|---|---|
| 이전 41107ee2 | 219.6 MB | 413 | 372.2 MB |
| 478 적용 | 219.6 MB | 413 | 372.2 MB |
| 차이 | 0.0 MB | 0 | 0.0 MB |

빌드도 143 MB 그대로다. Library/Bee·PlayerDataCache·BuildPlayerData 를 모두 지우고 43.9분 클린 빌드를 돌린 결과라 캐시 탓이 아니다.

전제가 틀렸다. "97%가 maxTextureSize 2048 이라 방치돼 있다"는 것은 .meta 의 설정값이었고, 실제 임포트 결과는 이미 그보다 작았다. 원본 파일 크기와 빌드 기여는 무관했다 — laptop_d.tga 는 원본 16 MB 인데 빌드에는 683 KB 로 들어가고 있었다.

중간에 한 번 잘못 읽었다. T_B_H_Booth_BaseColor 가 5.9 MB 에서 1.3 MB 로 줄었다고 봤는데, 5.9 는 원본 PNG 파일 크기이고 1.3 은 빌드 기여분이다. 서로 다른 두 값을 전후로 착각했다. 이전 리포트에서도 그 텍스처는 1.3 MB 였다.

되돌림: f99e5923 (89장 .meta 원복). develop 에는 들어간 적이 없다.

이번에 확인된 사실 — 텍스처 219.6 MB 가 413장에 고르게 퍼져 있고 평균 0.53 MB, 최대 5.3 MB 다. 개별 해상도를 낮추는 방식으로는 안 줄어든다. 남은 후보는 안 쓰는 에셋 제거, crunch 압축(현재 92% 꺼짐 — 런타임 메모리가 아니라 다운로드 크기를 줄인다), 메시 110.7 MB 다.

다음에 할 때는 텍스처 몇 장만 극단값으로 바꿔 리포트가 실제로 움직이는지 먼저 재고 전체에 적용한다. 이번에는 그 단계를 건너뛰어 45분짜리 빌드를 세 번 썼다.
