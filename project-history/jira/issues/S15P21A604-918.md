## 설명

## 발생 환경

- Branch: develop
- Build: dev 배포본
- 화면: 내 부스 관리 > AI 직원 관리

## 재현 방법

1. AI 직원 관리에서 문서를 업로드한다.
2. 문서 상태가 `QUEUED(대기)`로 표시되는 것을 확인한다.
3. 문서 처리 완료를 기다려도 관리 화면을 다시 조회하지 않는다.

## 기대 결과

- `QUEUED` 또는 `PROCESSING` 문서가 있으면 목록을 주기적으로 재조회한다.
- 서버 상태가 `READY` 또는 `FAILED`로 바뀌면 별도 재진입 없이 화면에 반영된다.
- 모든 문서가 종결 상태가 되면 불필요한 폴링을 중단한다.

## 실제 결과

- 업로드 직후 한 번만 목록을 무효화하고 이후 상태를 재조회하지 않아 `대기` 표시가 유지된다.
- 서버에서 실제로 `QUEUED`에 고착되는 문제는 별도 백엔드·AI 진단 대상이며, 이 이슈는 프론트 상태 갱신만 다룬다.

## 완료 조건

- [ ] `QUEUED`/`PROCESSING` 문서가 존재할 때만 상태 조회 폴링
- [ ] `READY`/`FAILED`/`EXPIRED`/`DISABLED` 전환이 자동 반영
- [ ] 종결 상태만 남으면 폴링 중단
- [ ] 업로드·삭제 기존 동작 회귀 없음
- [ ] 상태 전환 폴링 단위 테스트 추가
