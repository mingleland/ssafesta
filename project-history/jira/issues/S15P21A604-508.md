## 설명

## 증상

걸어다니면 프레임이 빨라졌다 느려졌다 를 반복한다. 가만히 서 있으면 20초를 재도 최악 25ms 로 문제가 없다.

## 실측으로 알아낸 것 (HitchLogger)

이동과 회전 23.8초 동안 33ms 초과가 27회 났다. 그중 20건이 34~42ms 인데 드로우콜 증분 0, 삼각형 증분 0, GC 0 이었다.

CPU 가 새로 하는 일이 없는데 프레임만 길어졌다는 뜻이다. 34ms 는 16.7 의 두 배로 vsync 경계와 정확히 같다. 따라서 튀는 순간을 찾을 문제가 아니라, 상시 비용이 예산 경계에 걸려 있어서 60 과 30 을 오가는 문제다. 기본 비용을 경계 아래로 내려야 끝난다.

## 상시 비용 후보 (씬 실측값)

- 그림자 거리가 Mobile_RPAsset 기준 400m, 캐스케이드 2 다. 그림자 캐스터 682개 중 400m 안에 277개가 들어온다. 프레임마다 최대 550여 개의 추가 드로우다. 1024 크기 맵으로 400m 를 덮으니 그림자 품질도 어차피 뭉개진다.
- 활성 조명 233개 (Spot 93, Point 139, Directional 1). 그림자를 켠 것은 Directional 하나뿐이다. 가장 큰 무리는 World_11F 의 WorldCeilingLights 아래 Downlights 90개다.
- 렌더러 1155개 (불투명 1056, 투명 99), 파티클 45개.
- 작은 오브젝트: balloon 127, bulb 18, confetti 17, string 13.

## 방법

추측으로 고치지 않는다. 앞서 추측으로 텍스처 예산, 오클루전 컬링, Screen.SetResolution 을 건드렸다가 전부 되돌렸다.

RenderCostProbe 를 넣어서 한 빌드 안에서 구성을 바꿔가며 같은 이동 조건으로 잰다. F9 를 누르면 10가지 구성을 자동으로 돌면서 각 3.3초씩 측정하고, p50 과 p95 와 최악값, 16.9ms 초과 비율, 드로우콜, 삼각형 수를 표로 남긴다.

구성 목록: 기준 / 그림자 120m / 그림자 60m / 그림자 끔 / 천장 다운라이트 끔 / 추가 조명 전부 끔 / 풍선 끔 / 작은 장식 끔 / 파티클 끔(불꽃놀이는 유지) / 복합.

## 사용자 요청 사항

조명은 전부 하나로 합치지 말고 구역 단위로 묶을 것. 불꽃놀이는 남기고 풍선 같은 작은 물건만 정리 후보로 본다.

## 완료 기준

이동 중 16.9ms 를 넘는 프레임 비율이 뚜렷하게 줄고, 체감으로 출렁임이 사라질 것. 화면 품질이 나빠지는 것은 허용하지 않는다.
