-608 이 FE 구조를 끝냈고(!622, develop), BE 계약은 GitLab #173 으로 요청해 둔 상태다. 그것이 develop 에 도달한 뒤의 연결 검증이 이 티켓이다.

## 범위

1. docs/26 기획 결정사항 등재 — 이벤트 설문 응답과 회원 탈퇴(#173 Q2)
2. surveyKey 문자열 SSAFESTA_2026 을 단일 상수 지점에서만 관리. 지금은 surveyEntry.ts 와 api.mock.ts 두 곳에 문자열이 있다
3. #173 도달 후 최신 develop 기준 실 BE acceptance

## acceptance 목록

- 회원: Event Shop → [설문 참여하기] → 설문 조회 → 6종 문항 렌더 → 제출 → 저장 → 참여 완료 → 재진입 시 이미 참여 표시
- 같은 회원 2회 제출 차단(409)
- 게스트는 제출 전 로그인 안내
- 부스 설문 기존 경로 회귀 없음
- 이벤트 설문 id 를 부스 결과 API 에 넣어도 500 없음
- 부스 설문 id 를 이벤트 경로에 넣어도 거부
- 탈퇴 정책 기존 동작 유지 · 코인/지갑 변화 없음

## 하지 않는 것

새 OverlayType·shell·bridge·Unity callback, 추첨권·raffle 모델, 코인 지급, Event Shop 상품·코인 로직 변경, 운영 관리자 시스템(#173 ④ 보류), 가짜 boothId.

2. 실 서버 왕복은 demo에서 불가 — demo BE에 설문 endpoint가 없습니다.
GET https://api.ssafesta.world/v3/api-docs 는 200이고 path 41개인데 /api/v1/event-surveys/{surveyKey}/run 과 /api/v1/booths/{boothId}/survey/run 이 모두 빠져 있습니다. 게스트 토큰으로 직접 호출하면 403이 아니라 404 NOT_FOUND입니다(라우트 부재). demo가 구버전 빌드입니다. 남은 acceptance는 로컬 스택(FE + Spring) 왕복 4건입니다: 게스트 이벤트 차단, 회원 이벤트 제출, 보상 있는 부스 설문 게스트 차단, 문항 0개 404 문구.

3. surveyKey 상수 단일화 — 부분 완료.
실경로는 features/event/model/surveyEntry.ts 의 EVENT_SURVEY_KEY 한 곳입니다. 다만 mock 포트가 entities/survey/api.mock.ts 에 MOCK_EVENT_SURVEY_KEY 로 같은 문자열을 따로 들고 있어 값이 두 곳에 하드코딩돼 있습니다. 이 중복 제거가 남은 몫입니다.

### 이정헌 · 2026-09-13 23:28 KST

남은 로컬 왕복 acceptance 4건을 실 스택에서 확인했다. 코드 변경은 없다.

2. 회원 · 이벤트 설문 제출 — 성공. 화면에 "응답을 제출했습니다".
3. 게스트 · 보상 있는 부스 설문(rewardCoin=10) — 조회는 200 이고 rewardCoin 이 응답에 실린다. 제출은 403 MEMBER_ONLY("보상이 있는 설문은 회원만 참여할 수 있습니다."). FE 는 조회 응답만으로 미리 막아 제출 버튼을 잠그고 "코인이 걸린 설문이라 로그인해야 참여할 수 있습니다" 를 띄운다 — #173 에서 대조한 판정식이 그대로 동작한다.
