## 설명

## 작업 목적

게임 파트가 공유한 로컬 실행 패키지(festa-world-dev / festa-webgl-dev / serve.mjs)로 FE·BE·Unity 전체를 본 PC 에서 띄워 브라우저로 재현하려 했으나, 게임 서버 이미지가 amd64 전용이라 Apple Silicon 에서 기동 자체가 불가능했다.

Mono JIT 이 x86-codegen assertion(offset == (gint32)offset)으로 죽었고, Rosetta 전환·메모리 제한·ledger 경로 변경·MONO_ENV_OPTIONS 인터프리터 모드 전부 실패했다.

## 작업 내용

user-mode 번역 계층(QEMU binfmt·Rosetta)을 거치지 않는 전체 시스템 x86_64 VM 경로를 확립했다. 게스트 커널이 진짜 amd64 이라 Mono 가 네이티브로 돌고 assertion 이 사라진다.

- colima 프로파일(--arch x86_64 --vm-type qemu) 로 VM 기동
- lima-additional-guestagents 설치 필수 — Lima 2.2 가 guest agent 를 분리해 없으면 VM 이 죽는다
- 이미지를 표준입력으로 VM 안 docker 에 직접 주입(마운트 불필요)
- 결과를 공용 docs/25 에 T-127 로 등록하고 GitLab #127 에 공유

## 완료 조건

1. 게임 서버가 assertion 0건으로 기동하고 Dedicated server start=True port=7777 이 찍힌다
2. 호스트 127.0.0.1:7777 에 포트가 전달된다
3. 브라우저에서 게스트로 월드 입장까지 도달하고 서버 로그에 Approved·Spawned 가 남는다
4. 절차가 공용 트러블슈팅에 재현 가능한 형태로 등록된다
5. 팀이 읽고 답할 수 있게 GitLab #127 에 공유된다
