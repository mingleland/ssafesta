## 설명

## 작업 목적

`develop` 기준으로 오류 계약과 endpoint의 테스트 공백을 메운다. `ErrorCode` 67종 중 16종이 테스트에서 한 번도 단정되지 않고, endpoint 2개는 테스트가 경로를 한 번도 호출하지 않는다. 특히 슬롯 임대 실패 3종은 모두 HTTP 409라서 서로 뒤바뀌어도 현재 테스트가 통과한다 — 오류 코드는 FE가 분기 근거로 쓰는 계약이므로 상태 코드만으로는 고정되지 않는다.

측정 방법: `pom.xml`에 jacoco가 없어 커버리지 리포트 대신 두 지표를 썼다. (1) `ErrorCode` 상수별 테스트 소스 등장 여부, (2) 컨트롤러 매핑 경로별 테스트 소스 등장 여부.

## 작업 내용

1. 슬롯 임대 실패 3종을 코드로 구분한다. `BoothApiIntegrationTest`가 `status().isConflict()`만 보는 자리에 `jsonPath("$.code")`를 붙여 `BOOTH_SLOT_ALREADY_LEASED`, `ACTIVE_LEASE_LIMIT`, `BOOTH_SLOT_NOT_RENTABLE`을 각각 고정한다.
2. 게스트 인증 endpoint를 HTTP 경계에서 검증한다. `POST /api/v1/auth/guest`와 `POST /api/v1/auth/logout`은 현재 어느 테스트도 호출하지 않는다 — 기존 테스트들은 게스트 토큰을 `AccessTokenService`로 직접 만들어 쓴다. 발급 응답과 logout 이후 세션 폐기를 endpoint 경유로 고정한다. `POST /api/v1/auth/refresh`는 이미 커버돼 있어 대상이 아니다.
3. 남은 미단정 오류 코드를 단정한다.
   
   - `DOCUMENT_NOT_FOUND` — `AiDocumentNotFoundException`
   - `USER_NOT_FOUND` — `MyAccountController`, `WorldSessionService`, `InventoryService` 3곳
   - `WITHDRAWAL_NOT_CONFIRMED` — `MyAccountController`
   - `GAME_PROJECT_INVALID` — `GamePublishedQueryService`
   - `WALLET_NOT_FOUND`, `CONFIG_NOT_FOUND`, `OAUTH_PROVIDER_NOT_SUPPORTED`
4. 도달 불가로 판명된 코드가 있으면 테스트를 억지로 만들지 않고 그 사실을 근거와 함께 남긴다. 관측한 결과를 조용히 기본값으로 덮지 않는다.

- 3번 목록은 각 도메인의 기존 `*ApiIntegrationTest`에 케이스로 추가

**결과**

- 신규 테스트 10건, 강화된 단정 1건, **프로덕션 코드 변경 0건**

- 전체 `mvn -o test` 658 테스트 / 실패 0 / 오류 0 / 스킵 0

**단정 추가한 8종**

`BOOTH_SLOT_ALREADY_LEASED`, `ACTIVE_LEASE_LIMIT`, `BOOTH_SLOT_NOT_RENTABLE`, `DOCUMENT_NOT_FOUND`, `WALLET_NOT_FOUND`, `USER_NOT_FOUND`, `WITHDRAWAL_NOT_CONFIRMED`, `OAUTH_PROVIDER_NOT_SUPPORTED`

완료 조건의 "세 코드를 서로 바꿔치면 테스트가 깨진다"는 실제로 확인했습니다. `BoothSlotController`의 `SlotAlreadyLeasedException`·`ActiveLeaseLimitException` catch 절 코드를 교환하니 `leasingAnOccupiedSlotConflicts`와 `aSecondBoothIsRefusedWithTheLeaseLimitCode` 2건이 기대 코드 불일치로 실패했고, 되돌린 뒤 다시 통과했습니다.

게스트 endpoint 2개(`POST /auth/guest`, `POST /auth/logout`)는 신규 `GuestAuthApiIntegrationTest`가 덮습니다. logout은 쿠키 삭제·access token 거부·refresh token 무효화를 각각 단언하며, `SessionRevocationFilter`의 첫 테스트입니다.

**도달 불가 2종 — 테스트를 만들지 않고 근거를 남겼습니다** (완료 조건 4번)

- `GAME_PROJECT_INVALID` — 복합 외래키가 막아 소스 주석 스스로 unreachable이라 적고 있고, 계약도 500 서버 결함으로 규정합니다. 유발하려면 스키마가 지키는 불변식을 깨야 합니다.
- `CONFIG_NOT_FOUND` — 019 T053·T054(GAME_PORTAL Binding) 미구현으로 현재 던지는 코드가 없는 예약 코드입니다. 계약 문서에는 404로 이미 정의돼 있습니다.

**범위 밖으로 넘긴 것 — S15P21A604-107 쪽에 남습니다**

`GAME_ASSET_*` 6종 중 특히 **5 MiB 상한 거부(**`SIZE_EXCEEDED`) 테스트가 없습니다. `GameAssetImageValidatorTest`가 `DIMENSION_EXCEEDED`·`PIXEL_BUDGET_EXCEEDED`·`MIME_NOT_ALLOWED`·`DECODE_FAILED`·`EMPTY_CONTENT`·`DECLARED_SIZE_MISMATCH`·`ANIMATED_WEBP_UNSUPPORTED`는 모두 잡는데 크기 상한만 빠져 있고, 019 T102가 그것을 명시로 요구합니다. `GAME_ASSET_IN_USE`는 019 T105(soft delete) 미구현으로 아직 아무도 던지지 않습니다.

**트러블 T-106** — 새 워크트리는 `backend/.env`가 gitignore 대상이라 따라오지 않고, 그것 없이는 Spring 컨텍스트가 뜨지 않아 첫 실행에서 66건이 전부 컨텍스트 로딩 실패했습니다. 오류 메시지가 컨텍스트 설정 문자열만 뱉어 코드 문제처럼 보입니다. `docs/25`에 등록했습니다.
