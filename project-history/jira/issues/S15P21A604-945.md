## 설명

GitLab #261. back-test 3건이 동시에 돌 때 EC2 가 포화된다(load 11.21, CPU idle 13%, Testcontainers 45개, swap 3.5GiB, CPU PSI some 45.20%). 원인은 러너 동시 실행 수가 아니라 back-test 한 잡의 실행 비용이다.

원인

- TestcontainersConfiguration 이 PostgreSQL·Redis 를 @Bean 으로 만든다. 컨테이너가 빈이므로 Spring 컨텍스트 개수 = 컨테이너 세트 개수다.
- 컨텍스트는 애노테이션 조합으로 갈린다(정적 분석 13그룹, 실측 6~7개): @AutoConfigureMockMvc 유무, @MockitoBean/@MockitoSpyBean 정의, @TestPropertySource, @SpringBootTest(properties=), RANDOM_PORT.

작업

1. 컨테이너를 static 싱글턴으로 올린다. 잡당 PG 1 · Redis 1 · Ryuk 1. CI job 사이 재사용은 하지 않는다(#261 §6 금지).
2. 데이터 격리를 컨테이너 재시작이 아니라 리셋으로 바꾼다. 시드 6개 표(booth_slots·surveys·survey_questions·survey_options·catalog_items·admin_actions)는 지우지 않고, 테스트가 만드는 39개 표만 비운다. 시드 재삽입은 하지 않는다 — booth_slots id 1~12 를 앵커로 단언하는 테스트가 있고, 재삽입은 시드 정본을 마이그레이션과 테스트 두 곳으로 가른다.
3. Redis 는 테스트 사이 키 정리.
4. 위험 없는 컨텍스트 분기 축소 — @AutoConfigureMockMvc 누락 6곳.
5. Surefire forkCount/reuseForks 확인. 이미 맞으면 변경하지 않는다.
6. Before/After 측정 — 컨테이너 생성 횟수, 컨텍스트 수, wall time, 테스트 건수와 PASS/FAIL, JVM 수와 최대 RSS.

Before 실측 (파이프라인 210940)

- 잡 400초 = 체크아웃·캐시 14 + 컴파일 40 + 테스트 본문 121 + 컨텍스트 기동
- 콜드 컨텍스트 1개 53초(JPA 초기화 23.5초 포함), 추가 컨텍스트당 컨테이너+Flyway 4.5초 + Spring 8~18초
- 테스트 1701건

완료 조건은 GitLab #261 §15 를 따른다. 금지 항목(러너 동시 하향·EC2 증설·테스트 삭제·통합 테스트 생략·검증 강도 완화)은 건드리지 않는다.
