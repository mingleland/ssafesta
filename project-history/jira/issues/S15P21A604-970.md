## 설명

증상
- 오락실 20대가 생긴 뒤 대기 상태에서도 프레임이 떨어지고 GC 가 잦다.

원인 1 — 매 프레임 전수 탐색 (버벅임)
- BoothInteractionInput.Update → NearestInteractableInRange 가 활성 상호작용 대상 전부에 대해 TemporarilyBlocked 를 부른다. 이 호출이 거리 필터보다 먼저 일어난다.
- TemporarilyBlocked 는 오락기면 ArcadeMachineInteractable.IsOccupied, 의자면 BoothChairInteractable.IsOccupied 를 부르고 둘 다 FindObjectsByType<NetworkPlayer> 로 씬을 훑는다.
- 실측 구성 기준 오락기 20 + 착석 대상 48 = 약 68회 전수 탐색/프레임이며 매 호출이 배열을 할당한다. 오락실 도입 전에는 오락기 몫 20회가 없었다.

원인 2 — 정적 캐시 누적 (메모리)
- ArcadeRuntimeSuspension.Suspended 는 카메라 키 사전인데 Resume 에서만 제거한다. 씬이 내려가면 파괴된 카메라와 게임 오브젝트 목록 참조가 남아 월드 재진입마다 누적된다.
- ArcadeRankingBoard.ViewVersions 는 TextMeshPro 인스턴스 ID 를 키로 넣기만 하고 제거하지 않아 씬 로드마다 증가한다.

해결 방향
- 사거리 필터를 먼저 적용해 후보를 줄인 뒤에만 점유 판정을 한다.
- 점유 판정이 쓰는 플레이어 목록을 프레임 단위로 캐시해 중복 전수 탐색을 없앤다.
- 씬 언로드 시 오락실 정적 캐시를 비운다.

검증
- 프레임당 FindObjectsByType 호출 수, 대기 상태 프레임 시간, 월드 재진입 후 정적 캐시 크기.
