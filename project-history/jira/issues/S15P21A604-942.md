## 설명

## 작업 목적

오락실 캐비닛에 사용자가 자기 게임을 걸 수 있게 한다. 지금 arcade_machine_bindings 에 행을 만드는 공개 경로가 없어 운영자가 DB 에 직접 넣어야 한다. GitLab #256 의 BE 요청 2 이며, 요청 1(목록 조회)은 S15P21A604-940 으로 끝났다.

## 확정된 계약 (2026-09-19)

- 자리 선택은 게시 흐름 안에 둔다. POST /api/v1/games/{gameId}/publish 요청 본문에 machineId 를 선택적으로 싣고, 응답이 배정된 자리를 돌려준다. 게시와 자리 배정이 한 트랜잭션이라 "게시는 됐는데 자리는 못 잡은" 중간 상태가 없다.
- 1인 최대 2대. 서버가 강제하려면 잡은 사람을 알아야 하므로 arcade_machine_bindings 에 owner_user_id 를 추가한다. 게임 소유자를 타고 세면 게임 양도 시 셈이 흔들린다.
- 유효한 machineId 는 yml 에 등록한다. 슬롯머신 machine-ids 와 같은 방식이고, 기동 시 설정 검증도 같이 따라온다.
- 내리면 해제한다. v1 에 게시 취소 엔드포인트가 없으므로 해제 시점은 visibility PRIVATE 전환과 소프트 삭제 두 곳이다.
- 자리 이사는 내렸다 다시 올리며 재선택한다. 이미 자리를 가진 게임이 다른 machineId 로 게시하면 거절한다.

## 작업 내용

- 마이그레이션: arcade_machine_bindings 에 owner_user_id 추가. 기존 운영자 시드 행은 null 이며 한도 셈에서 빠지고 사용자가 회수할 수 없다.
- 오락실 캐비닛 20개 화이트리스트를 yml 에 두고 설정 검증을 붙인다.
- 게시 트랜잭션 안에서 자리를 잡는다. 같은 자리를 동시에 두 명이 고르면 기본키가 한 명만 통과시킨다.
- visibility PRIVATE 전환과 소프트 삭제에서 그 게임의 사용자 바인딩을 해제한다.

## 완료 조건

- [ ] machineId 를 실어 게시하면 그 캐비닛이 배정되고 응답에 실려 온다.
- [ ] 화이트리스트에 없는 machineId 는 404 MACHINE_NOT_FOUND 다.
- [ ] 남이 잡은 자리는 409 다. 같은 게임이 같은 자리로 다시 게시하면 그대로 유지된다(멱등).
- [ ] 세 번째 자리는 409 로 거절된다. 운영자 시드 행은 한도 셈에 들어가지 않는다.
- [ ] 이미 자리를 가진 게임이 다른 자리로 게시하면 409 다.
- [ ] visibility PRIVATE 전환과 소프트 삭제가 자리를 비운다. 목록 API 에서 사라지는 것으로 확인한다.
- [ ] 같은 자리를 동시에 두 명이 고르면 한 명만 성공한다.
