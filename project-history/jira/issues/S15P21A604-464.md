## 설명

배경·로고를 끌면 반투명 사본이 따라오고 라벨이 파랑게 잡힌다. 웹 문서의 기본값일 뿐 게임 화면에서 원하는 동작이 아니다.

[범위]
- body 에서 선택을 끄고, 사용자가 실제로 글자를 다뤄야 하는 자리만 다시 열는다:
  input / textarea / select / contenteditable / role="alert" / .selectable
- role="alert" 을 여는 이유: 오류 안내는 문의할 때 복사해야 한다
- 본문을 열고 싶은 곳은 `selectable` 클래스를 준다. 설문 문항이 그 첫 사례다
  (설문 응답 입력은 input·textarea 라 규칙만으로 이미 열려 있다)
- 이미지는 기본이 draggable 이라 CSS 로 따로 끔다. Firefox 는 -webkit-user-drag 를
  모르므로 dragstart 가드를 함께 둔다
- **draggable="true" 안에서 시작된 드래그는 통과시킨다** — Game Studio 의 오브젝트
  배치·액션 재정렬이 실제 drag&drop 이라 그것은 기능이다

[완료 조건]
1. 배경·로고 드래그 시 유령 이미지가 따라오지 않는다
2. 라벨·안내 문구가 드래그로 선택되지 않는다
3. 설문 응답·닉네임 등 입력은 그대로 선택·복사된다
4. 오류 안내(role="alert")는 복사된다
5. 설문 문항(.selectable)은 선택된다
6. Game Studio 의 drag&drop(오브젝트 배치·액션 재정렬)이 그대로 동작한다
7. 전체 vitest green / tsc 0 / oxlint 신규 경고 0

6번과 1~5번의 경계는 단위 테스트로 고정하고, 전 화면 육안 확인은 별도로 한다.

### 이정헌 · 2026-09-06 22:20 KST

MR !351 머지 완료 (develop).

[구현]
- index.css — body 에서 선택을 끄고, input · textarea · select · [contenteditable]:not([contenteditable='false']) · [role='alert'] · .selectable 만 user-select: text 로 되돌린다. role="alert" 을 여는 이유는 오류 안내를 문의할 때 복사해야 하기 때문이다. img 에는 -webkit-user-drag: none.
- shared/ui/imageDragGuard.ts (신규) — Firefox 는 -webkit-user-drag 를 모르므로 dragstart 를 한 번 더 막는다. draggable="true" 안에서 시작된 드래그는 통과시킨다.
- app/providers/index.tsx — 가드를 앱 시작 시 1회 건다.
- features/survey/ui/SurveyOverlay.tsx — 설문 문항(.sv-prompt)에 selectable 을 준다. 응답 입력은 input·textarea 라 규칙만으로 이미 열려 있다.

[Game Studio 예외]
그쪽은 실제 drag&drop 으로 동작한다(오브젝트 배치·액션 재정렬). target.closest('[draggable="true"]') 이 있으면 건드리지 않는다 — 그것은 기능이다.

[회귀 방어 — 두 갈래]
1. 가드 경계: 단위 테스트 5건. 맨 이미지는 막고, draggable="true" 안의 이미지·요소 자신은 통과, 이미지가 아닌 것은 비대상, 설치·해제 동작
2. 선택 개방 목록: CSS 규칙 검사 9건. jsdom 은 링크된 스타일시트를 적용하지 않고 user-select 를 계산하지도 않아 컴포넌트 테스트로는 잡히지 않는다. index.css 를 읽어 선택자와 선언이 남아 있는지 확인한다 — 규칙을 지우면 실패한다. 값 계산까지 검증하지 못하는 것이 한계다.

[검증] vitest 625/625 · tsc 0 · oxlint 신규 경고 0

전역 CSS 라 모든 화면에 닿는다. 전 화면 육안 확인이 남아 있다 — 특히 Game Studio 의 오브젝트 배치·액션 재정렬과 설문·닉네임 입력.
