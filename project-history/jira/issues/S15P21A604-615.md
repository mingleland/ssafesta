## 설명

GitLab #170 (게임 파트 요청, Jira S15P21A604-610 대응) 의 BE 몫.

슬롯 1 을 이벤트 부스로 쓰기로 게임 파트가 결정했다 (2026-09-10). 서버가 슬롯 종류를 알려주는 값이 없어 Unity 가 씬 설정에 하드코딩하고 있다.

## 범위

slot_type 에 EVENT 를 추가하고 슬롯 1 을 EVENT 로 전환하는 migration 하나.

- booth_slots.slot_type 은 현재 USER_RENTAL | ADMIN
- GET /api/v1/booth-slots 응답의 type 으로 이미 나가는 필드라 계약 shape 변화 없음
- BoothSlot.isRentable() 이 USER_RENTAL 만 통과시키므로 슬롯 1 임대는 BOOTH_SLOT_NOT_RENTABLE 로 자동 차단 (신규 코드 없음)
- FE SlotListPage 가 이미 비-USER_RENTAL 을 운영 부스로 표시하고 버튼을 잠그므로 FE 변경 없음
- 임대 가능 재고 12 에서 11 로

## 테스트

| 이름 | 확인 |
|---|---|
| slotListExposesEventTypeForSlotOne | GET /booth-slots 의 slotId 1 이 type=EVENT |
| leaseRejectedOnEventSlot | POST /booth-slots/1/leases 가 BOOTH_SLOT_NOT_RENTABLE |

## 범위 밖

- GET /booths/{boothId} 의 boothType — 소비자가 없어 담지 않는다 (GitLab #170 회신 note_2788916). 이벤트 화면은 boothId·slotId 를 소비하지 않고(FE), Unity 는 슬롯 키로 물으며, 슬롯 1 은 임대가 없어 boothId 자체가 없다. 소비자가 생기면 임대 슬롯의 slot_type 에서 파생해 한 줄로 추가한다
- AI 직원 role 서버 파생 (GUIDE / PROJECT_DOCENT) — 이벤트 안내 NPC 를 부스 직원으로 둘지 WORLD_GUIDE 처럼 부스 밖에 둘지 결정이 선행. GitLab #112 화이트리스트 검증 유지
- 이벤트 설문·상점 콘텐츠 경로 — GitLab #173 (S15P21A604-608) 별건
- 게임 전용 부스가 12자리 중 하나를 쓰는 경우의 슬롯 전환 — 게임 파트 통보 후 같은 방식으로 추가
