## 설명

### 작업 목적

문서 처리 상태(대기/처리중/READY/실패)를 운영자가 확인할 수 있게 한다.

### 작업 내용

- DocumentStatus 상태 머신 (spec 007 이원화 모델)
- 문서 목록·상태 조회 API·실패 사유 노출
- 1시간 EXPIRED sweep — 업로드 URL만 나가고 바이트가 도착하지 않은 행을 정리한다 (V17의 `uploaded_at`이 NULL인 행)

### 2026-09-02 경계 조정 (GitLab 이슈 #119)

`READY` 전이 자체는 이 티켓이 하지 않는다. 새 계약에서 READY는 S15P21A604-400의 finalize 로컬 트랜잭션 안에서 확정된다 — 검증 → 기존 chunk 교체 → `searchable = true` → Job `SUCCEEDED` → Document `READY`가 한 트랜잭션이다.

이 티켓이 소유하는 것은 상태 머신의 **규칙**(어떤 전이가 허용되는가), **조회 계약**, EXPIRED sweep이다. finalize는 이 규칙을 지키는 호출자다.

### 완료 조건

- [ ] 허용되지 않은 상태 전이 거부
- [ ] FE 폴링 소비 가능한 조회 계약
- [ ] finalize 트랜잭션이 이 상태 머신 규칙을 통과해 READY로 넘어간다
- [ ] 1시간 EXPIRED sweep이 `uploaded_at`이 NULL인 행만 대상으로 한다

### 선행 작업 / Dependency

- BLOCKED BY: S15P21A604-106 (완료)
- 관련: S15P21A604-400(finalize에서 READY 확정)

### 참고

specs/007 US2·data-model · GitLab 이슈 #119 §3 · `V17__ai_documents_upload.sql`

### 테스트 방법

1. 상태 전이 표 기반 케이스 테스트
2. finalize 경로를 통한 READY 전이 확인
3. `uploaded_at`이 NULL인 행과 아닌 행에 대한 EXPIRED sweep 동작 확인
