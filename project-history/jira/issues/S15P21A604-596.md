## 설명

배포가 어디까지 자동이고 어디서부터 사람 손인지를 한 화면에서 볼 수 있는 기록이 없다. 파트마다 다르고, 환경마다 다르고, 같은 파트 안에서도 산출물 생성과 전개가 갈린다.

직접적인 계기는 내 인식이 반나절 만에 낡은 것이다. 09-10 14:26 에 GitLab #165 를 열면서 deploy-webgl-release.sh 가 저장소에 없다고 적었는데, 15:02 에 S15P21A604-581 이 그 스크립트를 211줄로 develop 에 넣었다. 전용 Jenkins job·pipeline·테스트·nginx 템플릿까지 같이 들어왔다.

[조사 원칙]
1. 문서·Jira·spec 체크박스는 참고만 한다. 판정 근거는 origin/develop 코드, Jenkins job·pipeline 정의, 실제 실행 이력, 실제 배포 산출물이다.
2. 스크립트 존재 ≠ pipeline 호출 ≠ 무인 자동화. 호출 경로를 끝까지 따라가고 끊기는 지점을 명시한다.
3. 근거가 없으면 확인 불가로 남긴다. 추정하지 않는다.
4. 타 파트 소유 영역(infra, Jenkins, Unity)은 관측만 한다.

[조사 격자]
파트 FE / BE / AI / Game-WebGL / Game-DedicatedServer
환경 Local / Dev / Demo / Prod
단계 build / publish-transfer / deploy-switch (Local 의 3단계는 로컬 bring-up 으로 정의)
등급 자동 / 반자동 / 수동 / 없음 / 확인 불가
상태 정상 / 실패 중 / 미구축 / 확인 불가
등급과 상태를 분리해 적는다 — 설계는 자동인데 실환경 wire 가 없어 못 도는 칸이 실제로 있다.

[산출물]
docs/LJH/verify/deployment-status-survey-0910.md — 요약, 기준 SHA·원칙, 격자표, 파트별 호출 흐름, 수동 절차 목록, 확인 불가, 낡은 서술 정정, 후속 자동화 후보와 소유 파트
각 판정에 파일:행, Jenkins job 이름, pipeline id 같은 확인 가능한 근거를 붙인다.
