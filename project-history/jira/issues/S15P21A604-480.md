## 설명

Unity Prefab/FBX/Material/Texture 를 입력으로 받아 원본과 외형은 근사하지만 내부 구조와 용량은 웹 런타임에 맞게 재구성된 SSAFESTA Runtime Asset 을 생성하는 단일 build-time pipeline 을 검증한다.

[앞서 닫힌 것]
-470 R3F renderer / -473 Unity FBX->GLB->R3F (+ resolveAssetUrl seam 통일) / -476 Nested Prefab Assembly / -479 문서 정합화

설계 정본: docs/LJH/ui-design/04_prototypes/booth-studio-runtime-asset-compiler.md (PROPOSAL)
계획: docs/LJH/ui-design/05_technical-spikes/booth-studio-2_5d/runtime-asset-compiler-v1-plan.md

[사슬]
Unity Source -> Prefab Resolver(-476) -> Normalize/Intermediate(-473) -> Runtime Asset Compiler(신규) -> Runtime Asset -> R3F

[대표 입력 3종 — 확정됨, 늘리지 않는다]
SURVEY_KIOSK  Nested Prefab 조립체 대표
PlasticWhite  가장 흔한 일반 Material (~3.4MB)
Chair02b      무거운 Texture + Normal Map worst case (~10.9MB)

[Compiler 단계 — 한 함수에 몰지 않는다]
resolve / normalize / flatten / optimize geometry / bake material / optimize texture / strip metadata / emit runtime asset / emit thumbnail / emit manifest
기존 -473, -476 코드를 최대한 재사용한다.

[Intermediate 와 Runtime 분리]
Intermediate은 source conversion 결과이며 build-time 전용이다. git · production Docker · production serving 전부 금지.
Runtime Asset 은 Compiler 결과로 production candidate 이며 원본 topology · metadata 를 그대로 보존하지 않는다.

[Geometry 기준]
triangle 감소율은 성공 기준이 아니다. 외형 근사 유지 + 필요한 최소 geometry 가 기준이다.
SURVEY_KIOSK 는 이미 286 tri 다 — 이런 입력을 억지로 더 파괴해 시각 품질을 떨어뜨리지 않는다. Compiler 가 optimization benefit 대 visual degradation 을 판단할 수 있는 구조로 만든다.

[보존하지 않는 것]
original topology / hierarchy / UV / material layout / node naming / authoring metadata
런타임은 flattened · merged geometry, new/baked UV, regenerated normals, runtime material, runtime identifiers 를 쓴다.
이것은 런타임 최적화·원본 보호 목적이지 라이선스 우회 수단이 아니다. 코드 주석에도 그런 표현을 쓰지 않는다.

[불변 계약]
Domain Truth 는 OBJECT_LOCAL_BOUNDS 다. runtime geometry 에서 다시 추론해 정본화하지 않는다.
rotationY 는 세밀 값을 계속 지원한다 — 15도 snap 은 조작 편의일 뿐이고 24방향 sprite 같은 방식으로 퇴행하지 않는다.

[License Gate seam]
개별 에셋별 조건문을 코드에 넣지 않는다. source package 단위 runtimeCompilePolicy 로 다룬다.
상태: ALLOW_RUNTIME_COMPILE / REVIEW_REQUIRED / BLOCK
라이선스 판정이 끝나지 않은 실제 vendor package 를 임의로 ALLOW 로 선언하지 않는다. v1 은 localSpikeOnly 같은 안전 상태를 두어 production emission 을 막는다.

[이번 라운드 최소 성공 지점 — 완성이 아니라 착수]
1. compiler module/directory 구조 생성
2. source resolver -> compiler 입력 계약 정의
3. Intermediate / Runtime output 분리
4. SURVEY_KIOSK 를 compiler 입력으로 실제 통과
5. Geometry optimization stage 의 실행 가능한 첫 구현
6. Material/Texture stage 의 실제 source resolution 착수
7. Runtime manifest schema 또는 entry 구조 연결
8. thumbnail generation entrypoint/seam 생성
9. 최소 unit test 또는 fixture 추가
10. build 가능한 상태 유지

빈 인터페이스·문서만 만들고 착수로 보고하지 않는다. 최소 하나의 source asset 이 실제 Compiler 경로를 통과해야 한다.

[이번에 완결하지 않는 것]
전체 10종 변환 / 모든 prefab 지원 / 모든 Unity Material property / 24MB 전체 texture 처리 / 완전한 automated visual metric / Runtime custom pack / 암호화 / CDN delivery / D-05 채택

[안전선 유지]
Raw FBX · Unity Prefab · Original texture · Intermediate GLB 의 production 배포 금지. .gitignore · .dockerignore 경계 재확인.

[품질 게이트]
npm run build / vitest / tsc / oxlint green. 실행하지 못한 검증을 green 으로 보고하지 않는다.

[이번 라운드 범위]
updated -476 에서 분기 -> 구조 생성 -> 첫 asset flow 구현 -> 검증 -> commit -> 원격 push -> STOP.
MR 생성 금지 · merge 금지 · Closes 금지 · Jira Done 금지.
