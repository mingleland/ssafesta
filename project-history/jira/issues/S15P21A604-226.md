## 설명

### 작업 목적

호스트·볼륨 손실에도 PostgreSQL을 외부 백업에서 복구할 수 있게 한다.

### 작업 내용

- 암호화된 외부 대상에 주기 백업
- 보존·정리·무결성 확인
- 빈 환경으로 restore하는 runbook
- RPO/RTO와 최근 성공 시각 기록

### 완료 조건

- 백업 파일이 호스트 외부에 존재하고 암호화된다.
- 빈 DB에 복구 후 핵심 데이터 검증이 통과한다.
- 실패 백업이 성공으로 오인되지 않으며 알림이 발생한다.

### 선행 작업

PostgreSQL 환경별 격리와 백업 저장소

### 참고

- `specs/infra-002-runtime-environments`

### 테스트 방법

샘플 데이터 백업→원본과 분리된 빈 DB restore→건수·핵심 조회 비교를 수행한다.

### 정승욱 · 2026-09-15 22:28 KST

PostgreSQL R2 백업이 복구됐습니다. 09-13 이후 처음으로 백업본이 생성됐습니다.

원인 — 자격증명이 아니라 AWS CLI 의 기본 trailer checksum

AWS CLI 2.23 부터 S3 업로드에 CRC32 trailer checksum 을 기본으로 붙입니다(request_checksum_calculation 기본값 when_supported). 그러면 요청이 content-encoding: aws-chunked 와 x-amz-content-sha256: STREAMING-UNSIGNED-PAYLOAD-TRAILER 형태로 나가고, R2 가 그 서명을 SignatureDoesNotMatch 로 거절합니다.

왜 조사가 6번 빗나갔나

실패하는 것은 본문이 있는 요청뿐이었습니다. 진단에 쓰던 head-bucket 은 본문이 없어 checksum 이 붙지 않으므로 같은 credential 로 항상 성공합니다. 그래서 endpoint, bucket, clock skew, credential, path-style, 상속 AWS 환경을 아무리 검증해도 전부 정상으로 나왔습니다.

R2 가 체크섬 값 불일치는 BadDigest 로 돌려주는데 이번 건은 값이 아니라 헤더가 만든 서명 형태가 문제여서 SignatureDoesNotMatch 가 나왔고, 오류 코드만 보면 계속 자격증명 문제로 읽힙니다.

판별 근거

1. Cloudflare 대시보드 실측 — 버킷 festa-postgres-backups 존재, festa-postgres-backup-writer 토큰 scope 일치, Object Read & Write, Active
2. 같은 endpoint, bucket, path-style 설정에서 reader 와 writer 두 credential 로 head-bucket 실행 — 둘 다 BucketRegion APAC 성공
3. credential 형식 검사 — Access Key ID 32자 hex, Secret 64자 hex, 비-hex 문자 0개

즉 서명 자체는 성립하며 put-object 만 실패했습니다.

수정

infra/environments/postgres/backup/lib.sh 의 backup_init 이 만드는 AWS config 에 두 줄을 추가했습니다.

request_checksum_calculation = when_required  
response_checksum_validation = when_required

when_required 는 체크섬을 끄는 것이 아니라 S3 API 가 요구하지 않는 선택적 체크섬만 생략합니다. 백업 무결성은 manifest 의 SHA-256 이 계속 보장합니다. backup 과 restore 가 같은 초기화를 쓰므로 한 곳 수정으로 양쪽에 적용됩니다.

회귀 검사는 infra/environments/tests/failure/postgres-restore.sh 에 한 줄 추가했습니다.

검증

festa-postgres-backup #11 (dev / manual-test) 이 Finished: SUCCESS 로 종료했습니다. 직전 실패 #8 과 같은 파라미터, 같은 credential 이었고 달라진 것은 config 두 줄뿐입니다. dump.sh 는 set -euo pipefail 아래에서 데이터베이스별 dump 와 manifest 를 각각 put-object 하므로 종료 코드 0 은 모든 업로드 성공을 뜻합니다.

철회한 조치
