## 설명

### 증상

부스 내부에 들어가면 **공간과 오브젝트가 지나치게 크다.** 노트북이 아바타 키를 훌쩍 넘는 높이에 있어 **다가가도 상호작용 프롬프트가 뜨지 않는다** — 사실상 조작 불가다. 배포용 WebGL 빌드에서 실제 플레이 중 관측했다.

### 원인 (실측)

레이아웃 좌표는 **미터 단위**다. 슬롯 5 published 예:

```json
{ "objectId": "laptop-1", "type": "LAPTOP",
  "position": { "x": -1, "y": 0, "z": -1.6 } }
{ "objectId": "board-1",  "position": { "x": -1.35, "y": 0, "z": -2.8 } }
```

즉 부스 실사용 면적은 **약 6 × 6 m** 다.

`BoothObjectFactory` 는 이 값을 앵커의 **로컬 좌표**로 넣는다:

```csharp
go.transform.localPosition = ...   // 부모 = BoothSlot_N
```

그런데 실측한 앵커 스케일이 문제다:

```
BoothSlot_5 pos=(700, 0, 700) scale=(40, 40, 40)
Interior_05 렌더 바운즈 크기=(406, 232, 406)  → 40.6 × 40.6 m, 높이 23.2 m
```

**이 프로젝트의 월드 규약은 **`1 m = 10 unit` 이다(코드 주석 다수·아바타 스케일 기준). 레이아웃이 미터면 앵커 스케일은 **10** 이어야 한다. **40 이면 4배**다.

결과: 6 m 부스가 **24 m** 로 펼쳐지고, 앵커에 딸려 스케일되는 오브젝트 프리팹도 **4배**가 된다. 1 m 높이여야 할 노트북 거치대가 **4 m** 가 되어 아바타 머리 위로 올라가고 상호작용 거리 밖으로 나간다.

### 확인할 것 (내가 확정하지 않은 부분)

- 스케일 40 이 **의도**였는지 — 방 프리팹이 다른 기준 크기로 제작돼 앵커로 보정한 것일 수 있다. 그렇다면 고칠 대상은 앵커가 아니라 **방 프리팹 쪽**이다
- 슬롯 12개 전부 같은 스케일인지 (슬롯 5만 확인했다)

**둘 중 무엇이든 "레이아웃 1 미터 = 월드 10 유닛" 이 성립해야 한다** — 그것이 계약(spec 005)과 월드 규약이 맞물리는 지점이다.

### 완료 조건

- [ ] 레이아웃 좌표 1 = 월드 10 unit(=1 m) 로 성립 — 슬롯 하나에서 실측
- [ ] 노트북·NPC 에 걸어가 **F 프롬프트가 뜨고** 상호작용된다 — 실기
- [ ] 부스 12개 전부 동일 기준
