## 설명

부스 스튜디오 캔버스에서 오브젝트를 클릭만 해도 좌표가 커밋된다(0.25 m 스냅). 게임 파트가 클릭 전후 draft 를 대조해 실측했고, 손대지 않은 오브젝트의 좌표·회전까지 바뀐 사례가 함께 보고됐다(PROJECT_PANEL 회전 0 → 90).

코드 실측으로 좁힌 것
- 저장은 전체 objects 를 그대로 PUT 한다. 바뀐 값은 이미 에디터 상태에 들어와 있다는 뜻이다.
- findFreeSpot 은 오브젝트 추가 경로 전용이고 LOAD_DRAFT 는 서버 objects 를 그대로 싣는다 — 로드 시 재배치가 아니다.
- MOVE_OBJECT·ROTATE_OBJECT 는 커밋 즉시 dirty 를 세운다. 그래서 구경만 해도 저장되지 않은 변경이 뜬다.

진행 방식
- 두 증상을 각각 재현한다. ① 클릭만으로 좌표 커밋 ② 손대지 않은 오브젝트 변경.
- 재현 전에 수정안을 확정하지 않는다.

완료조건
- 증상별 원인을 각각 한 문장으로 확정.
- 원인마다 회귀 테스트 1건.
- 시드 초안 클릭 전후 GET /layouts/draft 덤프가 동일.

### 이정헌 · 2026-09-13 23:00 KST

원인 세 갈래를 계측으로 확정하고 고쳤습니다. MR !799 (pipeline 191868 success).

1. 커밋에 드래그 임계값이 없어 pointerdown 직후 첫 pointermove 가 그대로 커밋된다. 2px 이동만으로 (1.2,1.2) → (1.25,1.25). 이동 0px 인 순수 클릭은 값도 dirty 도 바꾸지 않는다.
2. 회전 그랩이 피벗 위면 각도가 정의되지 않는다. 피벗에서 0.004m 지점을 잡자 1px 이 44도, 2px 이 63도로 커밋됐다(15도 스냅과 맞물려 0 → 60). 제보의 0 → 90 이 이 경로다.
3. end() 가 바닥 평면 onPointerUp 에만 걸려 있어 캔버스 밖에서 버튼을 떼면 드래그 상태가 남는다. 버튼을 누르지 않고 커서를 캔버스로 되돌리기만 해도 좌표가 커밋되며, 실측에서 오브젝트가 6m 를 건너뛰었다. 제보의 1m 급 이동이 이 경로다.

조치는 드래그 임계값 5px, 회전 최소 그랩 반경 0.3m, window 의 pointerup·pointercancel 수신이다. 같은 두 가드를 SVG 폴백 렌더러에도 넣었다.

검증 일곱 갈래: 순수 클릭 / 1~3px 흔들림 / 의도적 드래그 / 기즈모·링 위 흔들림 / 피벗 위 회전 / 링에서 의도적 회전 / 캔버스 밖 릴리스 후 커서 복귀. 앞의 다섯은 변화 0, 뒤의 둘은 정상. 단위 7건 추가, tsc 0, 전체 215 files / 1392 tests 통과.

기즈모 히트 영역 축소는 이번 범위에서 제외했다 — 임계값만으로 스침 오조작이 사라지는 것을 실측으로 확인했고, 영역을 줄이면 의도적인 기즈모 조작이 같이 어려워진다.

MR 에 Closes 는 넣지 않았고 develop 병합 후 완료로 옮긴다.
