## 설명

배경 (GitLab #128 §3, 2026-09-05 통합 실측): UnityHost 는 인스턴스 생성 시점부터 WORLD_GATE_TIMEOUT_MS(60초) 안에 onWorldGateReady 가 오지 않으면 failed 로 바꾼다. 그런데 Unity 첫 씬이 캐릭터 로비이고 onWorldGateReady 는 사용자가 월드 입장을 누른 뒤 WorldEntryGate 개방 시점에 오므로, 로비에서 60초 이상 머물면 Unity 는 정상인데 캔버스 위에 실패 안내가 겹친다. 다시 시도를 누르면 인스턴스를 재생성해 로비를 처음부터 다시 한다.

원인: 타이머가 사용자의 페이지 체류 시간을 재고 있다. 실패를 감지해야 하는 구간은 Unity boot attempt(createUnityInstance 시작 ~ 인스턴스 resolve)다. 게이트 대기는 Unity WorldEntryGate 가 30초 강제 개방(자체 에러 로그) 후 onWorldGateReady 를 보내므로 호스트 타이머가 필요 없다.

수정: boot 구간에만 watchdog 을 건다 — 진행률 콜백이 멈춘 채 일정 시간이 지나면 failed, 인스턴스가 서면 watchdog 해제. 로비/게이트 대기 구간에는 타임아웃 없음. 재시도는 새 boot attempt 로 새 watchdog. 60초 값 자체의 적정성은 배포 환경 실측 후 별도 판단.

범위 밖: G-8 Input Lock, !250 Unity 검증, canvas id(-421), 게스트 AT(-91).

완료 조건: 로비 체류 시간과 무관하게 실패 안내가 뜨지 않는다 / boot 중 진행이 멈추면 failed 로 드러난다 / 재시도가 새 watchdog 으로 동작한다 / 단위 테스트로 세 경우를 고정한다.

MR !267 develop 병합 완료 (2026-09-05).

수명주기를 booting → waiting-gate → ready 로 나누고 watchdog 을 boot 구간에만 걸었다. 진행률 콜백마다 다시 재고(느린 회선의 239MB 다운로드는 진행 중인 한 실패가 아니다), 인스턴스가 서면 해제한다. 로비 체류·입장 게이트 대기에는 타임아웃이 없다. 재시도는 새 boot attempt 로 새 watchdog.

값 60초는 그대로 둔다 — 늘린 것이 아니라 측정 대상을 바꿨다. 게이트 상한은 Unity WorldEntryGate 의 30초 강제 개방이 이미 갖고 있고(BeginOpen → NotifyGateReady 코드 확인), 따라서 '월드 진입 시작' 브리지 이벤트를 신설하지 않았다. Unity 변경 0.

검증: UnityHost.test.tsx 신설 5건(로비 장기 체류 무실패 / boot 정지 failed / 진행 중 재측정 / 재시도 새 watchdog / boot 거부 즉시 failed). !266 병합본과 합쳐 통합 검증했고 develop head 기준 tsc 0 · vitest 487/487 · vite build 통과.

완료 전환하지 않는 이유: 실 WebGL 로비 60초+ 체류 실측과 60초 값 자체의 적정성 판단이 남아 있다. 09-08 통합 실측에서 회수한다. Closes 미사용.
