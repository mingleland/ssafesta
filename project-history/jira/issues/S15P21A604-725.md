## 설명

최신 demo(festa-front:cf7e85cc, 2026-09-14 16:10 실측)에서 회원 Google 세션으로 11F 진입 시 "실시간 연결이 끊겼습니다. 새로고침해 주세요" 토스트가 뜬다. 게스트가 아니라 토큰 발급 대상인 회원인데도 연결이 서지 않는다.

더 큰 문제는 원인을 읽을 수 없다는 것이다. 브라우저 콘솔에 realtime·ws-token·STOMP·WebSocket 관련 출력이 0건이라, ws-token 발급 / CONNECT / STOMP ERROR 프레임 / WebSocket close code / 재연결 중단 사유 가운데 어디서 끊겼는지 특정할 수 없다. S15P21A604-706 설계에는 "서버가 ERROR 프레임과 함께 끊으면 원인을 그대로 드러낸다"가 있었으나 실배포에서 그 경로가 화면에도 콘솔에도 남지 않는다.

대상은 shared/realtime 공용 transport 다. 채팅 UI 가 아니라 연결 계층이며, 상담 real 어댑터(S15P21A604-136·-137)가 같은 소켓 위에 올라올 예정이라 UI 결함보다 먼저 본다.

완료조건 두 가지. 1) 최신 demo 회원 세션에서 realtime 연결이 안정적으로 선다. 2) 끊기는 경우 WebSocket close code·reason, STOMP ERROR 프레임 내용, 재연결 중단 사유를 식별할 수 있다.

범위 밖: 채팅 입력창과 조작 안내 HUD 겹침은 원인이 달라 별도 티켓으로 분리한다. 실패를 조용히 삼키지 않는다는 원칙(T-24)이 이 티켓의 근거다.
