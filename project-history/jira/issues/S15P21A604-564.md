## 설명

## 배경

React 와 Unity 가 환경마다 다른 Backend 주소를 직접 알아야 하는 구조가 세 개의 사고를 낳았다.

1. Unity 무언 Prod fallback — 로컬에서 window.__FESTA_CONFIG__ 가 {} 라 Unity 가 빌드타임 https://api.ssafesta.world 로 가고, 그 호스트는 localhost:5173 Origin 에 CORS 헤더를 주지 않아 월드 진입이 조용히 실패한다.
2. 수동 주입 의존 — S15P21A604-557 acceptance 를 통과시키려고 매번 브라우저 콘솔에서 apiBaseUrl 을 손으로 주입했다.
3. insecureHttpOption 축 — Unity 평문 HTTP 차단이 비예외 호스트에서 터진다. FE 오리진이 곧 API 오리진이면 이 축이 사라진다.

09-09 전수 조사로 이 구조가 이미 절반 지어져 있음이 확인됐다. React 41개 호출은 이미 /api/v1/... 상대경로이고 base 조립점이 shared/api/client.ts 한 줄이다. Unity 11개 호출도 이미 {_baseUrl}/api/v1/... 이고 base 주입점이 ApiServices.Init 한 곳이다. Dev 는 이미 same-origin path gateway(PUBLIC_API_BASE_URL=/__dev/api)이고 WebGL 정적은 /unity/ 로 확정돼 있다. Local 만 게이트웨이가 없다 — vite.config.ts 에 proxy 블록이 없다.

## 범위 (FE 단독)

- Vite proxy: /api → Spring 8080, /unity → WebGL static 8000. /api 는 prefix rewrite 하지 않는다(쿠키 Path 보존). changeOrigin 은 끈다.
- runtime.ts 에 resolveHostApiBaseUrl 신설 — 미설정 시 FE 오리진으로 해석하고 브라우저에서 빈 문자열을 반환하지 않는다.
- publishHostApiBaseUrl() 을 Unity boot 전(loader.ts loadUnityBuild 최상단)에 호출해 window.__FESTA_CONFIG__.apiBaseUrl 을 채운다. Unity C# 변경 0.
- authBaseUrl() 분리 — OAuth·guest 계열 5곳은 쿠키 host/path 계약 때문에 일반 API 게이트웨이에 넣지 않는다.
- 테스트 + 로컬 실통합 검증(Chrome).

## 완료조건

1. localhost:5173 하나만 열어도 일반 API 정상
2. 수동 runtime config 주입 없이 Unity 월드 진입 성공
3. Unity 가 :8080 을 직접 알 필요 없음 (spring=http://localhost:5173)
4. React 일반 API 도 실제 BE host 를 모름
5. FE Host 를 통한 정상 boot 경로에서 config 누락 때문에 Prod API 로 조용히 fallback 하지 않음 (Unity C# 의 build-time fallback 자체는 삭제하지 않는다 — FE Host 밖 독립 WebGL 실행은 범위 밖)
6. /unity proxy 가 Content-Encoding: br 과 application/wasm 을 보존, T-19 미재발
7. S15P21A604-557 무회귀
8. Guest·OAuth 인증 경로가 기존 host/path/cookie 계약 그대로 (일반 API 와 별도 검증)
9. tsc · vitest 전체 · npm run build green

## 범위 밖

- Unity PlayerSettings·C# 변경, insecureHttpOption 선적용
- OAuth provider redirect URI 3종 변경
- 월드 WebSocket 을 Gateway 에 넣기 (dev-runtime.sh 가 계약으로 금지)
- presigned PUT proxy (서명 파손)
- infra nginx 파일 수정 — Dev/Demo/Prod 정렬은 infra-002 계약 변경이라 별도 협의 이관
