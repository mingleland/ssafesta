## 설명

### 작업 목적

월드에 접속한 회원끼리 텍스트로 대화한다. `docs/02` 의 WORLD 기능 목록에 음성채팅(WORLD-09)만 있고 텍스트 채팅은 어느 spec·문서에도 없는 신규 기능이다.

### 누가 보내고 누가 그리나

Unity 는 관여하지 않는다. Unity 는 Spring 과 통신하지 않고(2026-09-07 확정) 텍스트 UI 는 React 가 그린다(헌법). React 오버레이가 STOMP 로 보내고 받는다. **Unity 작업 0건.**

### 확정된 범위

| 항목 | 결정 |
|---|---|
| 저장 | **하지 않는다.** 표도 마이그레이션도 없다 |
| 대상 | **회원 전용.** WS Token 이 회원에게만 발급되므로 자동 성립 |
| 도배 방지 | Redis, 3초에 1건 |
| 길이 | `strip()` 후 **code point 기준 1~100자** |

`String.length()` 를 쓰면 이모지가 2자로 계산되므로 code point 로 센다. 방송되는 내용은 `strip()` 이 적용된 정규화본이다.

### 토픽은 하나다

`/topic/world/chat` — 채널별로 가르지 않는다. 지금 `channelId` 가 `11F-01` 상수이고 채널 배정(`S15P21A604-499`·`-498`)은 보류 상태다. 채널을 클라이언트가 지정하게 하면 **서버가 누가 어느 채널에 있는지 몰라 검증할 수 없다.** 채널이 실제로 생길 때 토픽을 쪼갠다.

### 계약

**보내기** — `SEND /app/world/chat`

```
{ "content": "안녕하세요" }
```

**받기** — `SUBSCRIBE /topic/world/chat`

```
{ "senderUserId": 7, "nickname": "덕", "content": "안녕하세요", "sentAt": "2026-09-13T20:10:00Z" }
```

**닉네임은 서버가 넣는다.** 클라이언트가 보낸 이름을 쓰면 사칭이 된다. 요청 본문에 `nickname` 이 실려 와도 무시한다.

**오류** — `SUBSCRIBE /user/queue/world/chat/errors`

`@MessageExceptionHandler` + `@SendToUser(broadcast = false)` 로 **SEND 를 발생시킨 세션에만** 보낸다. broadcast 를 켜면 같은 계정의 다른 탭까지 오류가 퍼진다.

| code | 조건 |
|---|---|
| `VALIDATION_FAILED` | 빈 내용·공백만, 100 code point 초과 |
| `CHAT_TOO_FAST` | 3초 안에 두 번째 |
| `CHAT_UNAVAILABLE` | Redis 장애 — 아래 참조 |

### Redis 장애 정책 — fail-closed

도배 방지가 이 기능의 필수 조건이므로, rate limit 판정이 불가능하면 **방송하지 않고** `CHAT_UNAVAILABLE` 을 해당 세션에 돌려준다. 열어 두면 Redis 가 흔들리는 순간 도배가 가능해진다.

### 일반화되는 계약 (이 티켓 소유)

|  |  |
|---|---|
| endpoint | `/ws` 신설. `/ws/consultation` 은 이미 통보한 경로라 유지 |
| 토큰 발급 | `POST /api/v1/realtime/ws-token` 정본, `POST /api/v1/consultation/ws-token` 호환 유지. 같은 로직 호출 |
| Security | `SecurityConfiguration` 에 `.requestMatchers("/ws", "/ws/**").permitAll()`. 현재 `/ws/consultation` 만 열려 있어 `/ws` 는 STOMP CONNECT 전에 HTTP 401 로 막힌다 |

인증은 열린 핸드셰이크 뒤 기존 `StompAuthChannelInterceptor` 가 담당한다.

### 선행

**S15P21A604-686** — 그 티켓이 모든 SEND 를 거부해 두면, 이 티켓은 허용 목록에 `/app/world/chat` **한 건만** 추가하는 일이 된다.

### 완료 조건

- [ ] 보낸 메시지가 `/topic/world/chat` 에 **서버가 조회한 닉네임과 함께** 나간다
- [ ] 요청 JSON 에 `nickname` 을 실어 보내도 무시된다 (메시지 변환 경계를 통과시켜 확인)
- [ ] `" 안녕 "` 이 `"안녕"` 으로 방송된다
- [ ] 빈 문자열·공백만 입력이 거부된다
- [ ] 101 code point 는 거부되고 이모지 100개는 통과한다
- [ ] 3초 안 두 번째가 거부되고 **토픽에 나가지 않는다**
- [ ] 서로 다른 두 회원이 서로의 3초 제한에 영향을 주지 않는다
- [ ] 오류가 `/user/queue/world/chat/errors` 로 **발생시킨 세션에만** 전달된다
- [ ] 정지·탈퇴된 회원의 잔존 WS Token 으로는 보낼 수 없다 (계정 `ACTIVE` 확인)
- [ ] Redis 키에 환경 접두가 붙고 TTL 이 3초다
- [ ] `/ws` 가 HTTP 인증에서 401 로 막히지 않는다 (Security 테스트)
- [ ] `/ws` 로 STOMP CONNECT 가 실제로 성립한다 (연결 테스트)

### 한계 (문서에 명시할 것)

- **단일 인스턴스 전제.** in-memory simple broker 라 서버를 2대로 늘리면 A 인스턴스 사람과 B 인스턴스 사람이 서로 보이지 않는다
- **저장하지 않으므로 재접속하면 이전 대화가 없다.** 인스턴스가 죽으면 그 대화는 사라진다
- **월드 접속 여부를 보지 않는다.** "유효한 WS Token 을 가진 회원" 이면 월드 밖에서도 보낼 수 있다. 서버가 접속 상태를 모르기 때문이며(`-499` 범위), 지금 범위에서는 수용한다
- **채널 소속 검증 없음.** 토픽이 하나라 지금은 무의미하지만 `-499` 가 서면 검증이 붙는다

### 안 하는 것

신고·차단·금칙어(운영 인력 전제) · DM·귓속말 · 읽음·타이핑 표시(저장하지 않아 뜻이 없다) · 채널별 분리(`-499` 뒤) · 스크롤백

### 문서

`docs/16` 은 한 절 추가로 부족하다. **§1·§8·§10 이후의 낡은 SEND·인증·오류 서술**이 §8 확정본과 이미 충돌하고 있어(상담 메시지 P2·인증 방식 TBD·P1 완료 조건의 Text Message) 이번에 함께 정리한다. `docs/02` 에 `WORLD-11` 한 줄, 계약은 `specs/002-world-session/contracts/` 에 파일 하나로 둔다 — 반나절짜리에 spec 한 벌은 과하다.
