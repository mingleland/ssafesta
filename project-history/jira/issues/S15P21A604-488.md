## 설명

## 작업 목적

Game Studio에서 씬을 추가하는 버튼 4개("탐색 맵"/"플랫폼"/"대화"/"연출")와 그로 생성되는 기본 씬 이름, InspectorPanel의 씬 타입 뱃지가 각 씬의 실제 기능적 특징(이동 방식이 TopDown인지 SideScroll인지, 표시 방식이 Overlay인지 Fullscreen인지)을 직관적으로 드러내지 못함. 특히 "플랫폼"은 씬 타입명(`PLATFORMER`)과 혼동 여지가 있고, "대화"/"연출"은 실제로는 같은 `DIALOGUE` 씬 타입의 표시 모드 차이일 뿐인데 이름만 보면 전혀 다른 종류처럼 보임(Notion QA id=28). 각 축(이동 방식/표시 방식)과 구체적인 값을 이름에 그대로 노출해 더 직관적으로 구분되게 한다.

## 작업 내용

- `GameStudioShell.tsx`의 씬 추가 버튼 4개 라벨 변경: "탐색 맵"→"맵-TopDown", "플랫폼"→"맵-SideScroll", "대화"→"대화-Overlay", "연출"→"대화-Fullscreen"
- `authoringCommands.ts`의 기본 씬 이름 패턴을 새 라벨 기준으로 통일: "새 맵-TopDown N" / "새 맵-SideScroll N" / "새 대화-Overlay N" / "새 대화-Fullscreen N"
   
   - TOP_DOWN/PLATFORMER는 기존처럼 타입별 독립 카운터 유지
   - DIALOGUE는 Overlay/Fullscreen이 내부적으로 같은 `DIALOGUE` 타입이므로, `presentation`까지 걸러서 세는 카운터를 새로 추가 — 두 표시 모드의 번호가 서로 독립적으로 매겨짐(하나를 공유하지 않음)
- `InspectorPanel.tsx`의 씬 타입 뱃지("탐색 맵"/"플랫폼 맵")도 같은 명칭("맵-TopDown"/"맵-SideScroll")으로 통일
- 계약(`contracts/gameProject.ts`)과 `id`(내부 식별자) 생성 로직은 변경하지 않음 — 사용자에게 보이는 라벨/기본 이름 문자열만 대상
- 이미 만들어진 기존 씬들의 이름·뱃지 표시는 변경하지 않음 — 이 변경 이후 새로 추가되는 씬부터만 새 패턴 적용(기존 씬 일괄 마이그레이션 아님)

## 완료 조건

- [ ] 씬 추가 버튼 4개 라벨이 "맵-TopDown"/"맵-SideScroll"/"대화-Overlay"/"대화-Fullscreen"으로 바뀐다
- [ ] 각 버튼으로 생성된 씬의 기본 이름이 "새 {라벨} {번호}" 형식이다
- [ ] 대화-Overlay와 대화-Fullscreen의 번호는 서로 독립적으로 매겨진다
- [ ] InspectorPanel의 씬 타입 뱃지도 새 명칭으로 바뀐다
- [ ] 기존에 이미 만들어진 씬들의 이름·뱃지 표시는 변경되지 않는다
- [ ] 관련 테스트 통과 + `tsc --noEmit` 통과
