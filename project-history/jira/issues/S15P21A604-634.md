## 설명

### 작업 목적

spec 012의 코인 소비처와 수익 배분이 구현되어 있지 않다. 2차 MVP 완료 판정 6번 "서비스 결제·수익 처리"(docs/02 §5.2)는 이 작업으로만 닫힌다.

2026-09-11 develop(7d0ba208) 기준으로 backend 전체에 revenue·수익·수수료 관련 코드가 0건이고, CoinReason에도 해당 사유가 없다. 9개 판정 기준 중 유일하게 Jira 티켓조차 없던 항목이라 추적을 위해 신설한다.

### 작업 내용

- AI 상담 이용료 차감 — 방문자 지갑에서 이용료를 차감하고 원장에 기록 (FR-001, FR-003)
- 운영자 수익 반영 — 차감액에서 플랫폼 수수료를 제한 금액을 부스 운영자 수익으로 기록 (FR-002)
- 수익 조회 — 운영자가 자기 부스의 수익 내역을 확인 (SC-005). spec 015 FR-005(대시보드 수익 지표)의 선행이다
- 멱등성은 spec 003 규칙을 따른다 — 같은 결제 요청이 중복 도착해도 1회만 반영
- CoinReason에 이용료·수익 사유 추가. 마이그레이션이 필요하면 V30부터 (V29까지 사용 중)

### 완료 조건

- [ ] 차감액 = 운영자 수익 + 플랫폼 수수료가 항상 일치한다 (SC-001)
- [ ] 모든 차감·수익이 원장에 남는다 (헌법 20조)
- [ ] 중복 요청이 두 번 차감하지 않는다
- [ ] 운영자가 다른 부스의 수익을 조회할 수 없다

### 선행 작업 / 결정 필요

착수 전에 아래 3건이 확정되어야 한다. 헌법 30조에 따라 구현자가 임의로 정하지 않고 docs/26 등재 후 팀 결정을 받는다.

1. 플랫폼 수수료율 — 미정 (docs/02 §6 미정 항목, spec 012 C-03)
2. 수익 정산 시점 즉시/일괄 — 미정 (spec 012 C-04, 문서상 추천안은 즉시)
3. AI 상담 과금 시점과 단위 — 대화 시작 단위인지 메시지 단위인지가 spec 008과 012 어디에도 없다

### 테스트 방법

1. 상담 이용 → 방문자 차감액, 운영자 수익, 플랫폼 수수료 3자 합 일치 확인
2. 동일 요청 2회 전송 → 1회만 반영되는지 확인
3. 타 부스 수익 조회 시 403
