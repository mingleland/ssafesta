# SSAFY FESTA 포팅 매뉴얼

> **기준**: `develop` `a16e29eb` (2026-09-23). 버전·설정은 저장소 파일과 배포 서버에서 직접 확인한 값이다.
> 이 문서는 저장소를 처음 받은 사람이 **무엇을 어떤 버전으로 어떻게 띄우고 배포하는지** 찾는 입구다. 운영 절차 상세는 각 절 끝의 링크를 따른다.
> **Secret 값은 이 문서와 저장소 어디에도 없다.** 변수 이름과 발급 위치만 적는다 (헌법 15조).

### 4-3. Frontend (`festa-frontend/.env.example`, 컨테이너 런타임 주입)

빌드 산출물 하나를 여러 환경에 쓰기 위해, 배포에서는 빌드타임 `VITE_*` 대신 컨테이너 기동 시 `PUBLIC_*` 를 `runtime-config.js` 로 주입한다 (`festa-frontend/docker/40-runtime-config.sh`).

| 배포 변수 (로컬 대응) | 용도 | 필수 | demo 값 | production 값 |

| `PUBLIC_AUTH_BASE_URL` (`VITE_AUTH_BASE_URL`) | OAuth·게스트·Refresh 주소 | X (비우면 API 주소) | `https://api.ssafesta.world` | `https://ssafesta.world` |

## 5. 주요 설정 파일

| 파일 | 무엇을 정하나 |
|---|---|
| `backend/src/main/resources/application.yml` | 공통 설정 — OAuth 제공자, 토큰 수명, 코인 정책, 저장소, 내부 토큰. 배포에서 조용히 뜨면 안 되는 키는 기본값이 없다 |
| `backend/src/main/resources/application-local.yml` | `local` 프로파일 — `backend/.env` 읽기, 로컬 기본값(DB 비밀번호, `FRONTEND_BASE_URL=http://localhost:5173` 등) |
| `backend/src/main/resources/application-infra.yml` | `infra` 프로파일(배포) — 월드 접속 주소(`WORLD_*`), Redis ACL 계정 |
| `backend/src/main/resources/db/migration/V*.sql` | DB 스키마 정본 (Flyway V1~V47, 기동 시 자동 적용) |
| `backend/compose.yaml` | 로컬 PostgreSQL(pgvector)·Redis |

## 7. 빌드·배포 흐름

상세 정본: [CI/CD·런타임 구조](../docs/infra/canonical/02_CURRENT_CICD_RUNTIME_ARCHITECTURE.md) · [팀 인프라 요약](../docs/infra/guides/00_TEAM_INFRA_SUMMARY_GUIDE.md)

### 7-1. Frontend · Backend · AI

```text
작업 브랜치 → MR (GitLab CI: mr-status + 바뀐 파트 test/build, 10~14초급 경량 검증)
→ develop 병합 (Squash)
→ Jenkins festa-gitlab-develop: 이미지 빌드 → demo 배포 → 자동 확인(Web·게스트 로그인·World manifest·AI health)
→ demo 확인·승인
→ develop → main (NON-SQUASH)
→ Jenkins festa-production-promotion 수동 시작: demo 에서 검증된 같은 이미지를 그대로 승격 → 자동 검증 → CURRENT → 사람 확인 → KNOWN-GOOD
```

production 에서는 다시 빌드하거나 repack 하지 않는다. 롤백은 KNOWN-GOOD / previous 기록을 기준으로 되돌린다 ([운영 불변조건](../docs/infra/canonical/05_OPERATIONS_RUNBOOK_AND_INVARIANTS.md)).

### 7-2. Unity MR 검증

`festa-unity/**` 를 바꾼 MR 은 GitLab CI 가 Jenkins `festa-unity-mr-validation` 을 호출해 Unity 6000.0.78f1 로 컴파일·EditMode 검사를 돌리고, 결과가 MR 필수 상태가 된다. 이 경로는 빌드·배포를 하지 않는다.

### 7-3. Unity 릴리스

Unity 는 라이선스 문제로 Jenkins 가 빌드하지 않는다. 담당자 PC 에서 굽고 Jenkins 는 받아서 배포만 한다.

```text
develop 에 있는 커밋을 clean checkout (dirty=false, LFS 수신 완료, Unity 6000.0.78f1, release profile)
→ WebGL 빌드 + Linux Dedicated Server 빌드
→ 게임 서버 이미지: docker build -t festa-game:<sha40> -f festa-unity/Docker/Dockerfile <Linux 서버 빌드 출력 폴더>
→ 릴리스 번들 4파일: festa-webgl-release-<sha8>.zip, festa-game-<sha8>.tar, webgl-manifest.json, image-metadata.json
→ GitLab Generic Package Registry 업로드 (업로드 후 재다운로드해 해시 대조)
→ Jenkins Consumer: 번들 검증 → WebGL current 교체, 게임 서버 컨테이너 교체 → 확인
```

상세 절차: [Unity 릴리스 배포 가이드](../docs/infra/guides/03_UNITY_RELEASE_DEPLOY_GUIDE.md), `infra/unity-server/runbooks/unity-release-bundle.md`, `infra/unity-server/runbooks/deploy-and-rollback.md`

## 8. 배포 시 주의사항

- **Unity 서버 이미지 빌드 컨텍스트**는 Linux 서버 빌드 출력 폴더다. Dockerfile 이 `COPY . /app` 이라 저장소 루트를 컨텍스트로 주면 `/app/festa-unity.x86_64` 를 찾지 못한다 (T-26).
- **월드 연결은 WSS 다.** 클라이언트는 서버 주소를 하드코딩하지 않고 `POST /api/v1/world-sessions` 응답(`WORLD_SCHEME`·`WORLD_HOST`·`WORLD_PORT`)으로 접속한다. demo 는 `demo.ssafesta.world` 루트 경로의 WebSocket Upgrade 를 Nginx 가 17777 로, production 은 `world.ssafesta.world` 를 27777 로 넘긴다. 확인은 Upgrade 요청이 `101` 을 받는지로 한다.
- **입장 토큰 키는 한 쌍이다.** Backend `CONNECTION_TOKEN_SECRET` 과 게임 서버 `CONNECTION_TOKEN_SECRET_FILE` 은 같은 값이어야 하고, 회전할 때는 둘을 같은 시점에 바꾼다.
- **TLS**: Cloudflare SSL 모드 Full (strict), 호스트 Nginx 는 Cloudflare Origin Certificate 를 쓴다. 인증서·개인 키는 서버에만 둔다.
- **옛 컨테이너 확인은 이름이 아니라 포트로** 한다: `docker ps -a --filter "publish=17777"`. 이름이 다른 옛 컨테이너가 포트를 잡고 있으면 새로 배포해도 옛 동작이 보인다 (T-25).
- **CURRENT 와 KNOWN-GOOD 를 동시에 갱신하지 않는다.** WebGL 은 current 를 바꿔 교체하고(demo `/srv/festa/webgl/current`, production `/srv/festa/webgl/prod/current`), 최근 5개(`WEBGL_RETENTION_COUNT`)와 CURRENT·KNOWN-GOOD·previous 를 보존한다.
- **캐시**: `/unity/manifest.json`·`index.html` 은 `no-cache`, `/unity/Build/*` 는 해시 파일명이라 1년 immutable. 브로틀리 파일은 `Content-Encoding: br` 헤더가 맞아야 WebAssembly 로딩이 된다 (T-19).
- **업로드 크기**: Nginx `/api/` 는 `client_max_body_size 4m` (Game Studio 초안 2,000,000 bytes 허용).
- **배포 확인**: `/actuator/health` = `UP`, `/ai/v1/health/ready` = 200, `/unity/manifest.json` 의 `sourceCommit` 이 배포한 커밋인지.

문제 대응: [인프라 트러블슈팅 빠른 가이드](../docs/infra/guides/05_INFRA_TROUBLESHOOTING_QUICK_GUIDE.md), [트러블슈팅](../docs/25_트러블슈팅.md)

## 9. DB 복원

`03_db_dump.sql` 은 demo 업무 DB 를 개인정보 마스킹 후 추출한 plain SQL 이다. 스키마(Flyway V1~V47), 데이터, `flyway_schema_history` 를 모두 담고 있어 복원한 DB 로 Backend 를 띄우면 Flyway 가 추가 적용 없이 통과한다. pgvector 확장과 psql 17.6 이상이 필요하므로 같은 이미지 안에서 복원한다.

```bash
docker run -d --name festa-db -e POSTGRES_USER=ssafesta -e POSTGRES_PASSWORD=<비밀번호> -e POSTGRES_DB=ssafesta -p 5432:5432 pgvector/pgvector:0.8.1-pg17
docker cp exec/03_db_dump.sql festa-db:/dump.sql
docker exec festa-db psql -U ssafesta -d ssafesta -v ON_ERROR_STOP=1 -f /dump.sql
```

복원 결과는 테이블 48개(업무 47 + `flyway_schema_history`), 마이그레이션 46건(V1~V47, V19 결번)이다. 구조 설명은 [ERD 현행 스키마](../docs/30_ERD_현행_스키마.md) 에 있다.
