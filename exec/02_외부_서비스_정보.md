# SSAFY FESTA 외부 서비스 정보

> **기준**: `develop` (2026-09-23). OAuth 콜백 주소는 배포 서버에 실제 로그인 요청을 보내 돌아온 `redirect_uri` 로 확인했다.
> 호출 방식·시간 제한·실패 처리는 [외부 API 연동 명세서](../docs/31_외부_API_연동_명세서.md) 가 정본이고, 이 문서는 **새 환경에서 각 서비스를 다시 연결하는 데 필요한 가입·발급 정보**만 모은다.
> 키·Secret·토큰 값은 적지 않는다. 발급한 값은 서버의 Jenkins Credentials 또는 Secret 파일에 넣는다 (헌법 15조).

## 한눈에 보기

| 서비스 | 사용 목적 | 쓰는 쪽 | 발급 ENV |
|---|---|---|---|
| Google OAuth | 소셜 로그인 | Backend | `GOOGLE_CLIENT_ID` `GOOGLE_CLIENT_SECRET` `GOOGLE_REDIRECT_URI` |
| Kakao 로그인 | 소셜 로그인 | Backend | `KAKAO_REST_API_KEY` `KAKAO_CLIENT_SECRET` `KAKAO_REDIRECT_URI` |
| SSAFY 로그인 | 소셜 로그인 | Backend | `SSAFY_CLIENT_ID` `SSAFY_CLIENT_SECRET` `SSAFY_REDIRECT_URI` |
| SSAFY GMS | AI 답변 생성(LLM), 문서 임베딩 | AI | `GMS_API_KEY` (`EMBEDDING_API_KEY` 선택) |
| Cloudflare R2 | 문서·게임 이미지·로고 저장, DB 백업 | Backend, AI, 백업 스크립트 | `R2_ENDPOINT` `R2_BUCKET` `R2_ACCESS_KEY_ID` `R2_SECRET_ACCESS_KEY` 외 |
| Mattermost Webhook | 운영 이상 알림 | Grafana, Jenkins | `MATTERMOST_WEBHOOK_URL` |

## 공통 — OAuth 콜백 주소

콜백 경로는 Spring Security 규약 `/login/oauth2/code/{google|kakao|ssafy}` 로 고정이다. 제공자 콘솔에 등록한 값과 `*_REDIRECT_URI` 가 한 글자라도 다르면 `redirect_uri_mismatch` 로 실패한다.

| 환경 | 콜백 주소 (제공자 콘솔에 등록) | 로그인 후 돌아가는 화면 (`FRONTEND_BASE_URL`) |
|---|---|---|
| production | `https://ssafesta.world/login/oauth2/code/{provider}` | `https://ssafesta.world` |
| demo | `https://api.ssafesta.world/login/oauth2/code/{provider}` | `https://demo.ssafesta.world` |
| 로컬 | `http://localhost:8080/login/oauth2/code/{provider}` | `http://localhost:5173` |

로그인 시작 주소는 `{API 주소}/api/v1/auth/oauth/{provider}` 이고, 흐름은 [OAuth 완료 계약](../specs/001-auth-user/contracts/oauth-completion.md) 에 있다.

## 1. Google OAuth

| 항목 | 내용 |
|---|---|
| 사용 목적 | Google 계정 소셜 로그인 (OIDC) |
| 관리 콘솔 | Google Cloud Console → API 및 서비스 |
| 생성할 리소스 | 프로젝트 1개, OAuth 동의 화면(외부), OAuth 클라이언트 ID (유형: 웹 애플리케이션) |
| 등록할 콜백·도메인 | 승인된 리디렉션 URI 에 위 표의 콜백 주소(`.../login/oauth2/code/google`)를 환경별로 추가. 승인된 도메인 `ssafesta.world` |
| 필요한 범위 | `openid` `profile` `email` |
| 발급 ENV | 클라이언트 ID → `GOOGLE_CLIENT_ID`, 클라이언트 보안 비밀번호 → `GOOGLE_CLIENT_SECRET`, 등록한 콜백 → `GOOGLE_REDIRECT_URI` |
| 주의사항 | 동의 화면이 "테스트" 상태면 등록한 테스트 사용자만 로그인된다. 실사용 전 게시 상태를 확인한다 |

## 2. Kakao 로그인

| 항목 | 내용 |
|---|---|
| 사용 목적 | 카카오 계정 소셜 로그인 |
| 관리 콘솔 | Kakao Developers → 내 애플리케이션 |
| 생성할 리소스 | 애플리케이션 1개, 카카오 로그인 활성화, 플랫폼 Web 도메인 등록 |
| 등록할 콜백·도메인 | 카카오 로그인 → Redirect URI 에 콜백 주소(`.../login/oauth2/code/kakao`)를 환경별로 추가. 플랫폼 Web 사이트 도메인에 `https://ssafesta.world`, `https://demo.ssafesta.world` |
| 필요한 동의항목 | `profile_nickname`(닉네임), `account_email`(이메일) |
| 보안 | 보안 → Client Secret 발급 후 **사용 설정을 켠다**. 토큰 요청을 `client_secret_post` 로 보낸다 |
| 발급 ENV | REST API 키 → `KAKAO_REST_API_KEY`, Client Secret → `KAKAO_CLIENT_SECRET`, 콜백 → `KAKAO_REDIRECT_URI` |
| 주의사항 | 사용자 식별자는 `id` 다. 이메일 동의항목은 앱 설정에 따라 선택 동의가 될 수 있다 |

## 3. SSAFY 로그인

| 항목 | 내용 |
|---|---|
| 사용 목적 | SSAFY 교육생 계정 소셜 로그인 |
| 관리 콘솔 | `https://project.ssafy.com` 의 SSAFY 로그인 API 앱 관리 (SSAFY 계정 필요) |
| 생성할 리소스 | 앱 1개 (상태 "사용중") |
| 등록할 콜백 | Redirect URI 에 콜백 주소(`.../login/oauth2/code/ssafy`)를 환경별로 등록 |
| 필요한 범위 | 없음 — **scope 파라미터를 보내면 안 된다**. 앱에 부여되는 정보는 `email` `name` `project` |
| 엔드포인트 | 인가 `https://project.ssafy.com/oauth/sso-check`, 토큰 `https://project.ssafy.com/ssafy/oauth2/token`, 사용자 정보 `https://project.ssafy.com/ssafy/resources/userInfo` |
| 발급 ENV | Client ID → `SSAFY_CLIENT_ID`, Client Secret → `SSAFY_CLIENT_SECRET`, 콜백 → `SSAFY_REDIRECT_URI` |
| 주의사항 | 사용자 정보 응답은 `{userId, email, name}` 평면 구조이고 식별자는 `userId` 다. 동의 단계 400 오류(T-104)는 2026-09-07 SSAFY 측 수정으로 해결됐다 |

## 4. SSAFY GMS (LLM · 임베딩)

| 항목 | 내용 |
|---|---|
| 사용 목적 | AI 직원 답변 생성, 부스 문서 임베딩, 상담 인계 요약 |
| 가입·발급 | SSAFY 가 교육생에게 지급하는 GMS API 키를 쓴다 (별도 결제 없음) |
| 엔드포인트 | `https://gms.ssafy.io/gmsapi/api.openai.com` (OpenAI 호환) — `/v1/chat/completions`, `/v1/embeddings` |
| 사용 모델 | 답변 `gpt-4.1-mini`, 임베딩 `text-embedding-3-large`(1536 차원) |
| 발급 ENV | `GMS_API_KEY` (임베딩에 다른 키를 쓸 때만 `EMBEDDING_API_KEY`). 함께 `LLM_PROVIDER=gms`, `EMBEDDING_PROVIDER=gms` |
| 네트워크 | AI 컨테이너가 외부 인터넷에 나갈 수 있는 Docker 네트워크에 붙어 있어야 한다 (내부 전용 망에만 있으면 이름 해석부터 실패한다) |
| 주의사항 | 임베딩 모델이나 차원을 바꾸면 기존 문서 벡터(`ai_document_chunks`)와 섞이지 않도록 문서를 다시 처리해야 한다. 키가 없으면 `mock` 으로 두고 개발할 수 있다 |

## 5. Cloudflare R2 (S3 호환 저장소)

| 항목 | 내용 |
|---|---|
| 사용 목적 | AI 원본 문서, Game Studio 이미지, 프로젝트 로고 저장. 별도 버킷에 DB 백업 |
| 관리 콘솔 | Cloudflare 대시보드 → R2 Object Storage (계정·결제 수단 등록 필요, 무료 사용량 내 운영) |
| 생성할 리소스 | 문서 버킷(비공개), 백업 버킷(비공개), 버킷별 API 토큰(Access Key ID / Secret Access Key) |
| 필요한 권한 | 문서 버킷: 객체 읽기·쓰기 (서버가 presigned PUT 을 서명하고 읽기는 서버가 중계). 백업 버킷: 쓰기용·복원용 토큰을 분리 |
| CORS | 문서 버킷에 브라우저 직접 업로드용 CORS 적용 — 정책 파일 `infra/environments/storage/r2/documents-cors.json` |
| 발급 ENV | `R2_ENDPOINT`(`https://<account-id>.r2.cloudflarestorage.com`) `R2_BUCKET` `R2_ACCESS_KEY_ID` `R2_SECRET_ACCESS_KEY` (AI 는 `R2_REGION=auto` 추가). 백업: `R2_BACKUP_ENDPOINT` `R2_BACKUP_BUCKET` + Jenkins credential `r2-postgres-backup-writer`·`r2-postgres-backup-reader` |
| 운영 스위치 | `AI_STORAGE_UPLOAD_GATE`(`OPEN`/`QUOTA_BLOCKED`/`UNAVAILABLE`)로 사용량 초과 시 신규 업로드만 막는다. 장애 시 `MINIO_*` + `AI_STORAGE_ACTIVE_WRITE_PROVIDER=MINIO_LOCAL` 로 전환 |
| 주의사항 | 버킷 정책 참고본은 `infra/environments/storage/r2/buckets.example.yaml`. 같은 Cloudflare 계정이 `ssafesta.world` DNS·Proxy·CDN 도 맡는다 (SSL 모드 Full strict) |

## 6. Mattermost Incoming Webhook

| 항목 | 내용 |
|---|---|
| 사용 목적 | 승인된 탐지 규칙에 걸린 운영 이상 알림 (일반 CI 성공·실패는 보내지 않는다) |
| 관리 콘솔 | Mattermost → 통합 → Incoming Webhook |
| 생성할 리소스 | 채널 `#festa-operations` 에 Incoming Webhook 1개 |
| 발급 ENV | Webhook URL 전체 → `MATTERMOST_WEBHOOK_URL` (Grafana), Jenkins 는 credential ID `mattermost-webhook`(`MATTERMOST_CREDENTIALS_ID`) 와 `MATTERMOST_HOST` |
| 주의사항 | Webhook URL 자체가 Secret 이다. Grafana contact point(`infra/observability/grafana/provisioning/alerting/contact-points.yaml`)는 Slack 호환 형식으로 보낸다 |
