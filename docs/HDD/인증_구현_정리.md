# 인증·회원 기능 구현 정리

최종 갱신: 2026-08-19
범위: `feature/auth-user` 백엔드 구현 및 Vite 프론트 연동 계약

## 구현 완료

### 소셜 로그인과 최초 가입

- Google·Kakao OAuth 로그인 시작: `GET /api/v1/auth/oauth/{google|kakao}`
- 제공자 식별자(`provider + subject`)로 기존 회원을 찾는다. 이메일은 계정 식별·자동 병합 근거로 사용하지 않는다.
- OAuth 성공 뒤 기존·신규 사용자는 모두 `/auth/callback`으로 이동한다.
- OAuth 결과는 URL query ticket이 아니라 Redis의 5분 1회성 handoff와 `oauth_handoff` HttpOnly cookie로 전달한다.
- 완료 API: `POST /api/v1/auth/oauth/complete`
  - 기존 회원: body 없이 호출하면 `AUTHENTICATED`, Access Token, 만료 시각을 반환한다.
  - 신규 회원: body 없이 호출하면 `NICKNAME_REQUIRED`를 반환한다.
  - 신규 회원은 `{ "nickname": "..." }`로 같은 API를 다시 호출해 가입·로그인을 완료한다.
- handoff cookie 누락은 `400`, 만료·재사용은 `410`으로 구분한다.

### 토큰·세션

- 일반 회원 로그인·OAuth 완료·refresh 응답은 Access Token을 **response body**로 반환한다.
- 보호 API 요청은 `Authorization: Bearer <Access Token>` 헤더를 사용한다.
- Refresh Token은 `refresh_token` HttpOnly cookie로만 전달하며 Path는 `/api/v1/auth/refresh`로 제한한다.
- Refresh는 `POST /api/v1/auth/refresh`이며, 브라우저가 Refresh cookie를 자동 전송한다.
- Refresh Token rotation·재사용 탐지와 사용자당 하나의 활성 브라우저 세션을 Redis로 구현했다.
- 새 브라우저 로그인, 로그아웃, 정지, 탈퇴 시 기존 member session과 Refresh Token을 폐기한다.
- 게스트는 `POST /api/v1/auth/guest`에서 Access Token만 받으며 Refresh Token과 영속 User 데이터는 만들지 않는다.

### 내 계정·회원 관리

- `GET /api/v1/users/me`: 내 닉네임·상태·연결 제공자 조회
- `PATCH /api/v1/users/me`: 금칙어·예약어·광고/개인정보 패턴·중복 검사 뒤 닉네임 변경
- `DELETE /api/v1/users/me`: `confirmed=true`일 때 즉시 hard delete Workflow 실행
- 탈퇴는 대기/복구 없이 세션·소유/참여 데이터·OAuth 연결을 즉시 삭제하는 정책이다.
- 관리자 정지·정지 해제, 관리자 권한 모델, 관리자 감사 API는 **추후 작업**이다. 현재 공개 관리자 endpoint는 제공하지 않는다.

### Swagger 로컬 검증

- Swagger: `http://localhost:8080/swagger-ui/index.html`
- local 기본 `FRONTEND_BASE_URL`은 Vite 프론트인 `http://localhost:5173`이다. OAuth 성공 후 기존·신규 사용자는 모두 `http://localhost:5173/auth/callback`으로 redirect한다.
- My Account API는 Swagger 우측 상단 **Authorize**에서 `bearerAuth`에 Access Token을 입력하면 Authorization 헤더가 자동으로 붙는다.
- `oauth_handoff`, `refresh_token`, Origin 같은 브라우저 자동 전달 값은 Swagger 수동 입력란에서 숨겼다.
- local profile은 HTTP localhost 검증을 위해 `AUTH_COOKIE_SECURE=false` 기본값을 쓴다. HTTPS 배포 환경에서는 반드시 `AUTH_COOKIE_SECURE=true`을 설정한다. Vite의 완료·refresh·logout 요청은 `credentials: 'include'`를 사용한다.

- `backend/mvnw.cmd test` 통과: 6 tests, failures 0, errors 0
- PostgreSQL(pgvector)·Redis Testcontainers 및 Flyway V1→V3 migration을 포함한다.

## 남은 연동 작업

- React `/auth/callback` 화면 구현: 완료 API 최초 호출, `NICKNAME_REQUIRED` 분기, Access Token 메모리 보관, refresh 재시도 처리
- 신규 Google/Kakao 계정으로 닉네임 가입 완료 E2E 검증
- HTTPS 배포 환경에서 Secure cookie·CORS origin·OAuth redirect URI 확정 및 검증
- 월드 세션 종료와 외부 파일·Vector·OAuth revoke/unlink의 실제 consumer 연동 검증
