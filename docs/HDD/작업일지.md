  - 3차(최종): 계약이 상태 기계를 **둘** 두고 있다는 것을 그제야 봤다. `usage-guard.schema.json` 의 `state`(얼마나 찼나)와 `object-storage-contract §Manual fallback` 의 상태(provider 를 쓸 수 있나)는 **둘 다 `UPLOAD_BLOCKED` 라는 값을 갖는데 뜻이 다르다** — 앞은 할당량 90%(507), 뒤는 R2 장애(503). 한 칸에 뭉치면 같은 값이 두 코드를 가리킨다. 설정을 `usage-state`·`storage-state` 로 나누고 각각 계약의 enum 을 전부 담았다(`WARNING` 포함 — 빼면 계약이 "일어난다" 고 적은 상태를 운영자가 못 옮긴다).
  - **yml 에 값을 박지 않고 env 로 뺐다.** 박아 두면 운영자가 이미지를 고쳐야 차단할 수 있고, "기본값 없음" 검사도 무의미해진다. 기본값을 되살리거나 두 축을 합치면 각각 테스트가 빨개지는 것을 실측했다.
  - `R2_RECONCILING` 은 임의 결정이 아니다 — docs/26 이 "P0 에서는 차단한 상태로 운영" 이라 이미 적어 두었다.
- ❌ **상태와 쓰기 provider 가 어긋난 채로 뜰 수 있었다.** `storage-state=LOCAL_ACTIVE` 로 옮긴 운영자는 업로드가 MinIO 로 간다고 믿는데, `active-write-provider` 가 R2 로 남아 있으면 **방금 못 쓴다고 선언한 저장소로 계속 들어간다.** 한 사실이 두 곳에 적혀 있으면 갈릴 수 있다 — `per-booth-limit` ↔ V15 유니크 인덱스와 같은 유형이라 같은 처방을 썼다(어긋나면 기동 거절). provider 이름도 자유 문자열이 아니게 막았다 — 계약 enum 은 `R2`·`MINIO_LOCAL` 둘뿐이고, 세 번째 이름은 여기서 멀쩡히 저장된 뒤 FastAPI 에서 파싱에 실패한다(원인에서 한 홉 떨어진 자리다).

### 007 문서 업로드 TTL·정리 정책 확정 제안 — #84 (`S15P21A604-106`) 🚧

앞서 *"TTL은 값은 구현 시 정함"* 으로 미뤘던 것을 AI 파트가 물어와 값과 근거를 확정 제안했다. GitLab #84 노트.

- 🤖 **TTL 3개** — presigned PUT URL `expiresAt` **15분**(20MB 단일 PUT, 1Mbps ≈ 3분) / 미완료 행 → `EXPIRED` **1시간** / `EXPIRED` → R2 객체 삭제 **24시간**. 전부 설정값이고 위는 기본값(research §62가 heartbeat·lease·sweeper를 그렇게 둔 결).
- 🤖 **1시간을 짧게 잡은 근거가 실측이다** — `docs/08` §7에 **문서 삭제 endpoint가 없다**(`upload-url`·`complete`·`GET 목록`·`PATCH` 4개뿐). FR-018이 AI 직원당 10개로 제한하니 유령 행 하나가 슬롯 10%를 잠그는데 사용자가 되찾을 방법이 없다. 같은 파일은 멱등 재발급으로 애초에 안 막히므로, TTL이 실제로 푸는 건 *다른* 파일의 슬롯 회수뿐이다.
- 🤖 **`EXPIRED` 신설** — `FAILED`(파일 있고 처리 실패 + 사유 동반)·`DISABLED`(READY를 검색에서 뺀 것 + 재처리 복귀 경로)는 의미가 다르다. **AI yaml 변경 0** — 콜백 목표 상태가 아니다. 부분 UNIQUE 인덱스 조건(`QUEUED/PROCESSING/READY`)도 그대로라 정의를 안 바꾼다.
- 🔍 **논리 만료가 불가능하다** — Postgres 부분 인덱스 술어는 IMMUTABLE이어야 하고 `now()`는 STABLE이다. "만료됐지만 아직 `QUEUED`인 행"을 인덱스에서 뺄 방법이 없어서, DB를 최후 방어선으로 두는 설계가 성립하지 않는다. 그래서 실제 상태 전이를 택했다. `@EnableScheduling`은 이미 `SsafestaApplication`에 켜져 있고 `@Scheduled`가 0개라 이 sweeper가 첫 번째가 된다(주기 5분 제안).
- 🤖 **R2 lifecycle rule로는 안 된다** — 객체 키에 미완료와 정상 문서를 가르는 prefix가 없다. `pending/` 분리는 최대 20MB 복사 + 계약 §Upload flow 2·6·7 변경이고, `AbortIncompleteMultipartUpload`는 단일 PUT에 해당 없다. **Spring이 DELETE**하고, 이는 새 권한 요구가 아니다 — 계약 §Verification outcomes가 이미 *"reject and quarantine/delete per document policy"* 로 서버 삭제를 전제한다. 단 credential 4종에 삭제 주체가 없어 인프라 확인 1건을 남겼다.
- 🔍 **제안 흐름에 없던 것 1건** — PUT은 성공했는데 complete만 늦은 경우. `EXPIRED` 행의 complete를 **받는다**(HEAD로 객체 실재 시 `QUEUED` 되살림, 없으면 410). **이것이 상태 만료 1시간과 객체 삭제 24시간을 가른 이유다** — 같은 시각이면 되살림 창이 0이 되고 느린 회선 사용자의 20MB가 버려진다.
- 📎 **`objectKey` 정정 접수** — `origin/ai`는 `objectKey`인데 `origin/develop`은 여전히 `s3Key`다(#51 미해결분). 내가 `s3Key`로 인용한 건 develop을 봤기 때문. `docs/08` §7 예시도 BE 몫으로 남았고, DB 컬럼 `ai_documents.s3_key`는 **V13에서 바꾸지 않고** JPA `@Column`으로 흡수한다(013a `avatar_code` ↔ `avatarCode` 선례). `SOURCE_HASH_MISMATCH`는 양쪽 `failureCode` enum에 아직 없다.

#### T047 통보 내용 (사람이 Jira·노션에 옮길 것)

**Unity**

1. **`version`과 `schemaVersion`은 다른 값이다.** `version`=공개 회차, `schemaVersion`=구조 버전(현재 1). `BoothLayoutDto`에는 `version`만 있어 `schemaVersion`은 `JsonUtility`가 무시하므로 **지금은 안전**하다. 문제는 `specs/005/spec.md` §Layout JSON 예시가 `"version": 2`로 적혀 있고 문맥상 구조 버전으로 읽힌다는 것 — 그 예시대로 필드를 맞추면 **공개 회차를 구조 버전으로 파싱한다.** 예시를 `"schemaVersion": 1`로 정정하는 것이 통보의 실질이며, 3파트 계약이라 BE가 임의로 못 고친다.
2. **published 경로가 실물로 존재한다.** `HttpBoothApiClient`가 지금 404를 맞는 그 URL이다. `useMockApi`를 끄고 Base URL만 바꾸면 **Unity 코드 수정 없이** 붙는다. `404 LAYOUT_NOT_PUBLISHED`(공개 없음/재임대로 연결 끊김)는 현재 graceful skip 그대로 두면 되고, **`409 BOOTH_LEASE_EXPIRED`는 404와 다르게 다룰지 판단 필요**(사라진 게 아니라 닫힌 것).
3. **부스 6m × 6m × 6m 상호 확인.** 원점이 바닥 중앙이라는 전제로 `|x|,|z| ≤ 3`, `0 ≤ y ≤ 6`으로 구현했다. 이 해석이 맞는지 한 번 짚어야 한다 — 틀리면 정상 배치가 거부되거나 벽 밖 배치가 통과한다.

**FE**

1. **모르는 필드는 거부된다.** 계약에 없는 필드가 하나라도 있으면 `409 LAYOUT_VALIDATION_FAILED` + `rule: MALFORMED_LAYOUT`으로 **저장 자체가 실패**한다. C-03(scale)이 확정되면 순서는 **3파트 합의 → BE가 `schemaVersion` 2로 올리고 필드 추가 → 배포 → 그다음 FE 전송**이다. FE가 먼저 보내면 전부 실패한다.
2. **`expectedRevision` 필수.** 읽은 `revision`을 되돌려 보낸다(최초 0). 불일치 시 `409 LAYOUT_REVISION_CONFLICT`이고 `errors[0]`에 서버의 현재 revision이 온다. **계약서 초안의 "409 본문에 최신 Draft 동봉"은 구현하지 않았다** — 봉투에 자리가 없어 revision만 알린다. 충돌 시 `GET draft`를 한 번 더 해야 하며, FE가 반대하면 재논의 지점이다.
3. **오류 응답이 `{code, message, requestId}`가 됐다** (003·004 포함 전 endpoint). **`code`로 분기하고 문자열 매칭은 하지 마라.** 검증 실패에는 `errors`(차단)·`warnings`(허용)가 붙는다. `X-Request-Id` 헤더 = 본문 `requestId` = 서버 로그.
4. **모든 `message`는 한글이다.** 그대로 노출해도 된다.
5. **좌표는 FE가 환산해 보내고 BE는 고치지 않는다.** 자릿수도 유지된다(`2.10` → `2.10`). 단 `-0.0` → `0.0`, `1e2` → `100`으로 표기가 바뀔 수 있다 — PostgreSQL `numeric`이 하는 일이고 **값은 같다.** 버그로 오해하지 말 것.
6. **`PUT /booths/{id}/facade` 신설.** 외관 4필드, `logoUrl`은 **https만**.

**AI**

- 오류 봉투가 005부터 실제 동작한다. `임대만료_AI대화_종료계약_검토.md` §3에서 "이미 그 형태"라고 쓴 건 사실과 달랐고 정정해 뒀다 — 문서에만 있었다. FastAPI도 같은 봉투를 쓰면 FE가 파서를 한 벌만 관리한다.
