### 프론트엔드 없이 OAuth 로컬 검증 경로 추가

- 🤖 로컬 `FRONTEND_BASE_URL` 기본값을 `http://localhost:8080`으로 변경했다. OAuth 성공 후 `/auth/callback`은 임시로 Swagger UI로 redirect하므로 5173 프론트 서버 없이 완료 API를 테스트할 수 있다.
- 🤖 실제 프론트 연동 시에는 환경변수 `FRONTEND_BASE_URL`을 프론트 origin으로 바꾸며, `/auth/callback`은 프론트가 소유한다.
- 🤖 로컬 Swagger 회귀 테스트용 `/auth/callback` redirect는 유지하되 OpenAPI 목록에서는 숨겼다. 실제 프론트 배포 시에는 사용하지 않는다.
- 🤖 Swagger가 브라우저 자동 전송용 `oauth_handoff` HttpOnly cookie를 수동 필수 입력값으로 노출하지 않도록 OpenAPI 파라미터에서 숨겼다.
- 🤖 `/api/v1/auth/refresh`의 `refresh_token` cookie와 브라우저 Origin 헤더도 Swagger 수동 입력에서 숨겼다. 동일 origin 브라우저 요청은 Path 제한 Refresh cookie를 자동 전송한다.
- 🤖 HTTP `localhost:8080` 테스트에서 handoff cookie가 누락되어 OAuth 완료 API가 401이 되는 문제를 해결했다. local profile은 `AUTH_COOKIE_SECURE=false`, 실제 HTTPS 배포는 반드시 `true`로 설정한다.
- 🔗 트러블슈팅: [T-101](트러블슈팅.md#t-101-http-localhost에서-oauth-handoff-cookie-미전송-2026-08-19-해결)
- 🤖 실행 서버를 curl로 검증해 OAuth 완료 endpoint가 handoff 처리 전에 Spring Security에서 401되는 것을 확인했다. 정확 endpoint 공개 규칙을 추가했다.
- 🔗 트러블슈팅: [T-102](트러블슈팅.md#t-102-oauth-완료-endpoint가-인증-필요로-매칭됨-2026-08-19-해결)
- 🤖 OAuth 완료 endpoint를 JWT Resource Server와 별도 SecurityFilterChain으로 분리해 Swagger의 Bearer 상태와 무관하게 handoff cookie만 처리하도록 강화했다.
- 🤖 handoff cookie 누락은 400, Redis handoff 만료·재사용은 410으로 구분해 기존의 모호한 401 응답을 제거했다.
- 🤖 새 OAuth handoff 410을 추적해 `|` 구분자 역직렬화 정규식 오류를 수정했다. handoff가 정상 소비된 뒤에도 410이 반환되던 문제다.
- 🔗 트러블슈팅: [T-103](트러블슈팅.md#t-103-새-oauth-handoff가-즉시-410으로-보이는-원인-추적-2026-08-19-해결)
