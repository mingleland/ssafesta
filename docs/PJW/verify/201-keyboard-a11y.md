# S15P21A604-201 — Game Studio 접근성 키보드 전용 조작 검증 결과

> 검증일: 2026-08-27 | 검증자: 박준우 | 대상: `test/S15P21A604-201-keyboard-a11y` 브랜치

## 배경

작업 내용 "키보드 전용 배치·이동·저장 시나리오 점검·수정" — 마우스를 쓰지 않고
핵심 편집 플로우(배치→이동→저장)를 완주할 수 있는지 점검하고, 막혀 있으면 고친다.

## 발견한 버그 및 수정

`TopDownCanvas.tsx`의 오브젝트 배치는 캔버스 클릭/드롭 좌표로만 위치를 정하는 마우스 전용
동작이었다. `GameStudioShell.tsx`의 `onKeyDown`에는 배치를 "확정"하는 키 입력이 전혀 없어서,
팔레트에서 배치 도구를 고른 뒤(배치 모드 진입 자체는 팔레트가 일반 `<button>`이라 Tab+Enter로
가능) 실제 오브젝트를 놓을 방법이 마우스밖에 없었다 — 키보드 전용 사용자는 배치 자체를 완주할
수 없는 상태였다.

**수정**: 배치 모드(`placementPreset !== null`)에서 Enter 또는 Space를 누르면 현재 Scene
중앙 좌표(`Math.floor(width/2), Math.floor(height/2)`)에 배치하도록 `GameStudioShell.tsx`에
핸들러를 추가했다.

1차 구현은 기존 `keyboardCanvasContext`(포커스가 `document.body`나 `.gss-map-canvas`/
`.gss-map-object`여야 함) 게이트 안에 넣었으나, 팔레트 버튼을 키보드로 활성화한 직후에는
포커스가 그 버튼에 남고 캔버스에 tabIndex가 없어 body/canvas로 옮겨갈 방법이 없다는 걸
재현 중에 발견했다 — 게이트 조건 자체가 이 핸들러를 영구히 못 타게 막고 있었다. `!editingText`
조건만 남기고 게이트 밖으로 옮겨 실제로 팔레트 버튼에 포커스가 있는 상태에서 Enter/Space가
동작하도록 고쳤다.

## 한계

배치 확정 시 좌표는 항상 Scene 중앙 고정이다. 정밀한 좌표 지정(마우스 클릭 지점)은 여전히
마우스 전용이지만, 완료 조건("핵심 플로우 키보드 완주")은 배치·이동·저장 각 1회 완주로
충족되며 이번 수정으로 "배치 자체가 키보드로 불가능"했던 완전 차단 상태는 해소됐다.
