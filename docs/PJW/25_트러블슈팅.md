## T-1 (2026-08-27)
- 증상: 201 검증 중 Alt+L(레이어 패널 토글)을 시도하는 과정에서 한 번, 포커스가 캔버스/팔레트가
  아니라 Scene 이름 입력창에 가 있는 상태로 걸려 "l" 문자가 그대로 입력창에 타이핑됨
  (`도서관 입구` → `도서관 입구l`). 재시도 시 포커스를 캔버스 오브젝트로 명시적으로 옮긴 뒤에는
  정상적으로 레이어 패널이 열려 재현되지 않음.
- 원인: 미상. 직전에 시도했던 다른 탭으로의 브라우저 네비게이션이 `beforeunload` "변경사항이
  있습니다" 대화상자에 막혀 취소된 직후였다는 정황은 있으나, 이게 실제 원인인지 자동화 도구
  (Claude in Chrome)의 이벤트 주입 아티팩트인지 구분하지 못했다.
- 조치/상태: 입력창 값은 즉시 Backspace로 원복. 재현 조건을 특정하지 못해 코드 수정은 하지 않음
  — 실사용자가 겪을 시나리오인지(포커스 관리 버그) 자동화 환경 특유의 현상인지 불확실한 채로
  보류. 재발 시 재현 절차(직전 대화상자 취소 여부 포함)를 함께 기록할 것.
- 관련: S15P21A604-201, festa-frontend/src/game-studio/studio/ui/GameStudioShell.tsx

## T-2 (2026-08-27)
- 증상: 263 작업 중 `festa-frontend/src/game-studio/runtime/reference/ReferenceGamePlayer.tsx`를
  `git add`하려 하면 "The following paths are ignored by one of your .gitignore files" 경고와
  함께 exit 1이 남 (다만 이미 tracked 파일이라 실제로는 정상 staging됨 — 새 untracked 파일이면
  완전히 막힐 것으로 보임).
- 원인: 루트 `.gitignore`의 `reference/`·`references/` 패턴(3~4번째 줄, 앞에 `/`가 없어 모든
  깊이에 매치)이 원래 의도한 Unity 벤더 자산 폴더(`reference/`, CLAUDE.md의 READ ONLY 참조 자산)
  뿐 아니라 `festa-frontend/src/game-studio/runtime/reference/`처럼 이름이 우연히 같은 소스
  디렉터리까지 전부 무시 대상으로 잡음.
- 조치/상태: 이번엔 파일이 이미 tracked라 우회 없이 정상 커밋됨. 패턴 자체는 고치지 않음 —
  루트 `.gitignore`는 게임 스튜디오 파트 소유가 아니고, 수정하려면 Unity 자산 무시 규칙과
  충돌하지 않는지 확인이 필요해 범위 밖이라 판단. 앞으로 `game-studio/.../reference/` 하위에
  **새(untracked) 파일**을 추가하는 사람은 `git add -f`가 필요할 수 있다는 점만 기록해 둔다.
- 관련: S15P21A604-263, `.gitignore`(루트), festa-frontend/src/game-studio/runtime/reference/
