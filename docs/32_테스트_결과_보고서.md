## 2. 자동 테스트

2026-09-23 에 `caa1c60d` 를 새 작업 트리로 받아 GitLab CI 와 같은 도구로 실행했다.

| 파트 | 도구 | 실행 범위 | 결과 | 소요 |
|---|---|---|---|---:|
| Backend | Maven Surefire, JUnit 5, Testcontainers(PostgreSQL) | 전체 (`./mvnw test`), 통합 테스트 클래스 109개 포함 | 1,748 통과 · 0 실패 | 3분 35초 |
| Frontend | Vitest | 전체 (`npx vitest run`), Game Studio 포함 | 파일 253 · 테스트 1,680 통과 | 46초 |
| AI | pytest (Python 3.13) | CI 범위 `tests/unit` + `tests/contract` | 377 통과 | 9초 |

CI 에서는 develop 으로 가는 MR 마다 바뀐 파트의 테스트가 돌고, 최신 파이프라인이 성공해야 병합할 수 있다. Backend 는 DB·마이그레이션·Repository 변경이 있을 때만 Testcontainers 통합 테스트까지 돌리는데, 위 수치는 강제로 전체를 돌린 결과다.

Unity 는 `festa-unity/**` 를 바꾼 MR 에서만 Jenkins Unity agent 가 스크립트 컴파일과 EditMode 검사를 돌리고, 그 결과가 MR 필수 성공 상태가 된다 ([Unity MR gate](../infra/evidence/gitlab-unity-mr-gate.md)). 라이선스가 있는 에디터가 필요해 이번 로컬 실행에는 넣지 않았다. Unity 동작은 3장의 실측과 4장의 릴리스 빌드로 확인했다.

## 5. 남은 항목

- Unity CI 게이트는 컴파일과 EditMode 검사까지다. 월드 동작·멀티플레이는 자동 테스트가 없어 실측 문서와 릴리스 빌드 확인에 기대고 있다.
- 사용자 테스트 관통 체크리스트([user-test-qa-checklist](./KHS/inbox/user-test-qa-checklist.md))는 사전 검증 열만 채워져 있고 1·2회차 기록 칸은 비어 있다.
- 월드 동시 접속 부하 테스트(계획서의 10/20/30/40~50명 단계)는 결과를 한데 모은 문서가 없다. 봇 부하 실행 기록은 게임 파트 작업일지에 나뉘어 있다. 임대·코인 동시 요청 부하 테스트는 Backend 자동 테스트에 들어 있어 위 1,748건에 포함된다.
