- 🔍 **리뷰 지적 2건(P2) 반영** ⑴ `java.net.URI`는 포트를 `*DIGIT`로만 봐서 `https://x.com:99999`가 host까지 멀쩡히 파싱된다 — **연결 불가능한 주소가 저장**되고 방문자는 죽은 링크를 만난다(SC-002). 포트가 있으면 `1~65535`만 허용하도록 규칙을 추가했다. `:abc`·`:-1`·오버플로는 authority가 registry-based가 돼 기존 host 규칙이 이미 잡고 있었다 ⑵ `catch (DataIntegrityViolationException)`이 **모든** 무결성 위반을 중복으로 번역하고 있었다 — `booth_id` FK가 깨져도 "이미 프로젝트가 있습니다"가 된다. `BoothLeaseService.translateRace`처럼 **제약 이름을 보고** 판별하고, 모르는 위반은 삼키지 않고 그대로 올린다(500 + 큰 로그가 조용히 틀린 409보다 정직하다)
- 🔍 **2차 리뷰 14건 반영.** 실제 결함 5건 — ⑴ `validatedName` 이 `null` 을 돌려주는 경로가 있어 미가드 호출 시 `changeName(null)` 로 NOT NULL 을 깰 수 있었다 ⑵ `touch()` javadoc 이 "값이 바뀐 요청에서만"인데 호출부는 무조건이라 **같은 값 PATCH 도 `updated_at` 을 흔들었다** → `Objects.equals` 비교 후 갱신 ⑶ `saveAndFlush` 근거 주석이 틀렸다 — `IDENTITY` 는 `save()` 가 이미 INSERT 를 낸다. 주석을 "SEQUENCE 로 바꾸면 catch 가 무력해진다"로 정정(코드는 유지) ⑷ cause 루프 가드가 자기참조만 막아 **2-사이클에서 무한루프** → `MAX_DEPTH` 경계 ⑸ 동시성 테스트의 인자 없는 `future.get()` 이 스위트를 세울 수 있었다 → 시한 부여
- 🔍 **한글 도메인이 거부되고 있었다.** `java.net.URI` 는 authority 를 RFC 2396 으로 읽어 `한글도메인.com` 의 host 를 `null` 로 준다 — 한국 서비스가 한국 도메인을 "형식 오류"로 막고 있었다. `IDN.toASCII` 로 판정하되 **저장은 원문 그대로**(불변식 I-3). 언더스코어 호스트는 RFC 1123 위반이라 거부 유지. 고치면서 **포트 검사가 원본 URI 를 보는 버그를 스스로 만들었다** — IDN 경로는 `getPort()` 가 항상 -1 이라 규칙을 빠져나간다. 해석된 URI 로 둘 다 보게 하고 회귀 테스트를 박았다
- 🤖 중복 3종을 `common` 으로 승격 — `ConstraintViolations`(제약 이름 판별, `BoothLeaseService` 사본 제거) · `PresenceField`(016·009 가 같은 패턴을 각자 갖고 있었다) · `ApiException.fieldInvalid()`(같은 봉투 조립이 저장소에 8곳). **팩토리는 내가 만진 3곳에만 적용**했고 game·user·world 5곳은 별건으로 남겼다 — 남의 파일을 이 티켓에서 쓸어담지 않는다

- 🔍 **`IDN.toASCII` 에 authority 를 통째로 넘긴 것도 결함이었다** — 인자를 도메인 이름 하나로 보므로 `user@한글.com` 을 `xn--user@-lt1tk15s.com` 이라는 다른 이름으로 만든다. host 만 변환하고, 재조립 결과가 host(+port) 뿐인지 확인한다. 아니면 **검증한 URI 와 저장하는 문자열이 다른 곳을 가리킨다**
- 🔍 **4라운드 — 내 앞 커밋이 연 구멍을 잡았다.** "raw 에서 `@` 를 이미 거르니 중복"이라며 `isPlainAuthority` 의 `getUserInfo` 검사를 지웠는데, 그건 **ASCII `@` 에만** 참이었다. 전각 `＠`(U+FF20)는 `IDN.toASCII` 를 거치며 `@` 가 되므로 raw 검사가 끝난 뒤에 userinfo 가 생긴다 — `https://한글.com＠evil.com` 이 `evil.com` 으로 해석돼 통과했다. **해석된 URI 에서 한 번 더 본다** (두 검사가 각각 다른 것을 잡는다)

- 🔍 **5라운드 — 전각 `：` 가 원본에 없던 포트를 만들었다.** `https://한글.com：8080/x` 는 변환 후 포트 8080 으로 해석되는데 값이 정상 범위라 포트 규칙에도 안 걸린다. **내 앞 probe 출력에 `：99999` 가 이미 찍혀 있었는데 "포트 규칙이 잡네"로 넘겼다** — 99999 라 걸린 것이지 8080 이면 통과다
- 🤖 **문자 하나씩 쫓는 것을 그만뒀다.** `＠` 막으니 `：` 가 나왔고 다음도 있었을 것이다. `IDN.toASCII` 는 이름표를 정규화하는 함수이므로 **구조 문자를 만들어 냈다면 그건 이미 이름이 아니다** — 변환된 host 가 `[A-Za-z0-9.-]` 만 담는지 묻는 `isHostLabels` 한 줄로 `＠`·`：`·`／`·`？`·`＃` 를 한꺼번에 막는다. `。` 는 그대로 통과(정당한 라벨 구분자)

### 018 층 구조 설계 확정 — 판정 정정 ⚠️
- 🤖 초안 권장: "단일 씬 + 공간 분리 + 네트워크 가시성 제어" (NGO 씬 동기화 복잡도 회피 목적)
- 👤 **리드 반려**: 씬은 나눈다. 엘리베이터가 로딩이다. 한 씬에 두 층을 두면 트래픽을 감당할 수 없다
- **정정 사유 — 초안이 틀렸다**:
  - 단일 씬이면 두 층 에셋이 **초기 다운로드에 전부 포함**된다. 현재 86.9MB + 1층 → 웹 접속 자체가 부담
  - Unity Web 힙 한도상 두 층 + 다수 캐릭터 동시 상주는 위험
  - 서버 부하가 층으로 분산되지 않는다
  - 초안은 **씬 동기화 복잡도만 저울에 올리고 WebGL의 지배적 제약(용량·메모리)을 빠뜨렸다**
- ✅ **확정: 층 = 별도 씬 + 별도 월드 세션.** 엘리베이터가 세션 전환을 가리는 로딩 연출
  - 기존 `WorldSessionDto`의 `worldId`/`channelId`를 그대로 확장 — 새 계약 불필요
  - 대신 **재접속 실패 처리가 1급 요구사항**이 됨 (FR-011, SC-003): "어느 층에도 없는 상태" 금지
  - 상태 머신 설계: **세션을 먼저 확보하고 나서 현재 층을 떠난다** → 실패 케이스 절반 제거
- 파급: spec 002에 목적 층 파라미터 필요(C-06, BE 합의), Infra는 층 수만큼 컨테이너 필요(C-08),
  017 음성 층 격리는 **자동 해결**(세션이 다르면 음성 방도 다름)
- 교훈: 아키텍처 권고 시 **그 프로젝트의 지배적 제약**을 먼저 확인할 것. 이 프로젝트는 Unity Web이고
  용량·메모리가 항상 1순위 제약이었다 (T-19/T-20 이력이 이미 그것을 말하고 있었다)
