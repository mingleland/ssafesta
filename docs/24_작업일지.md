### 018 층 구조 설계 확정 — 판정 정정 ⚠️
- 🤖 초안 권장: "단일 씬 + 공간 분리 + 네트워크 가시성 제어" (NGO 씬 동기화 복잡도 회피 목적)
- 👤 **리드 반려**: 씬은 나눈다. 엘리베이터가 로딩이다. 한 씬에 두 층을 두면 트래픽을 감당할 수 없다
- **정정 사유 — 초안이 틀렸다**:
  - 단일 씬이면 두 층 에셋이 **초기 다운로드에 전부 포함**된다. 현재 86.9MB + 1층 → 웹 접속 자체가 부담
  - Unity Web 힙 한도상 두 층 + 다수 캐릭터 동시 상주는 위험
  - 서버 부하가 층으로 분산되지 않는다
  - 초안은 **씬 동기화 복잡도만 저울에 올리고 WebGL의 지배적 제약(용량·메모리)을 빠뜨렸다**
- ✅ **확정: 층 = 별도 씬 + 별도 월드 세션.** 엘리베이터가 세션 전환을 가리는 로딩 연출
  - 기존 `WorldSessionDto`의 `worldId`/`channelId`를 그대로 확장 — 새 계약 불필요
  - 대신 **재접속 실패 처리가 1급 요구사항**이 됨 (FR-011, SC-003): "어느 층에도 없는 상태" 금지
  - 상태 머신 설계: **세션을 먼저 확보하고 나서 현재 층을 떠난다** → 실패 케이스 절반 제거
- 파급: spec 002에 목적 층 파라미터 필요(C-06, BE 합의), Infra는 층 수만큼 컨테이너 필요(C-08),
  017 음성 층 격리는 **자동 해결**(세션이 다르면 음성 방도 다름)
- 교훈: 아키텍처 권고 시 **그 프로젝트의 지배적 제약**을 먼저 확인할 것. 이 프로젝트는 Unity Web이고
  용량·메모리가 항상 1순위 제약이었다 (T-19/T-20 이력이 이미 그것을 말하고 있었다)
