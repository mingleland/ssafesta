# SSAFY FESTA 문서 인덱스

이 폴더는 기존 통합 기획서·서비스 기능 명세·UI/UX 가이드·AI API·Jira 가이드의 중복 내용을 분리하고, 부족했던 기술/검증 문서를 새로 작성한 **20종 프로젝트 문서 세트**다.

## 문서 분리 원칙

- **기획서**: 왜 만들고 무엇을 만들지
- **기능 명세**: 사용자가 어떤 기능을 어떻게 사용할지
- **정책/NFR**: 모든 기능에 공통 적용되는 규칙과 품질 기준
- **User Flow/IA**: 사용자가 어떤 경로로 기능에 도달하는지
- **UI/UX**: 화면 표현 원칙
- **Wireframe**: 실제 화면 골격
- **전체 아키텍처**: 시스템 경계와 책임
- **파트별 설계서**: 해당 파트 내부 구현 구조
- **API/Realtime**: 시스템 사이의 계약
- **Test/QA**: 무엇을 어떻게 검증할지
- **Demo**: 완성 결과를 어떤 흐름으로 보여줄지

같은 설명을 여러 문서에 장문으로 반복하지 않고, 필요한 경우 다른 문서를 참조하도록 구성했다.

## 기존 문서에서 이동된 주요 내용

### 통합 기획서에 섞여 있던 내용

- 문제 정의 / 핵심 가치 / Persona → **01 프로젝트 기획서**
- 기능 체크리스트 → **02 서비스 기능 명세서**
- Coin/임대/AI 격리 정책 → **03 정책/NFR**
- 사용자 시나리오 → **04 User Flow + IA**
- 시스템 구성도 → **07 전체 시스템 아키텍처**
- Backend 도메인 → **08 API**, **09 DB**
- React Booth Studio 구조 → **10 Frontend**
- Unity Runtime → **11 Unity Client**
- NGO/Dedicated Server/Channel → **12 Unity Network**
- RAG/AI 구조 → **13 AI 시스템**
- AWS/ECS 배포 → **15 Infra**
- 실시간 상담/Presence → **16 Realtime**
- MVP 검증 조건 → **19 Test/QA**
- 발표 화면 → **20 Demo**

### 기존 독립 문서

- 서비스 기능 명세 초안 → 02로 재구성
- UI/UX 디자인 가이드 → 05로 재구성, Wireframe은 06으로 분리
- AI 서버 API 설계서 → 13(시스템) + 14(API)로 분리
- Jira 가이드 → 18로 정리

## 확정안과 제안안 구분

업로드 자료에 직접 근거가 있는 내용은 그대로 유지했다. 자료에 없지만 문서를 완성하기 위해 필요한 구현 세부는 다음 문서에서 **Draft/제안**으로 표시했다.

- Backend Endpoint 상세
- DB Table/Column 상세
- Redis Key
- Spring/FastAPI ECS 배치 방식
- WebSocket Event Envelope
- Frontend 상태 관리 도구
- Unity Transport 세부 값

이 항목들은 구현 시작 전에 팀에서 최종 확정해야 한다.

## 현재 기준으로 의도적으로 확정하지 않은 항목

> **확정된 항목은 이 목록에서 뺀다.** 결정값과 근거는 `docs/26_팀_결정_필요사항.md`의 결정 기록 로그가 정본이다 — 상태를 두 곳에 적으면 한쪽만 갱신돼 문서가 자기 자신과 모순된다 ([#59](https://github.com/kanghyunsoon/ssafesta/issues/59), `docs/17` §21-2).

- 플랫폼 수수료율 *(spec 012로 이관)*
- Chunk size / Top-K *(결정이 아니라 구현 후 튜닝값)*
- 재접속 상세 정책
- 이벤트/경쟁관 상세 주기
- Unity Web ↔ Dedicated Server **Transport 세부 설정** — 방식은 WebSocket으로 확정됐고(`docs/26` ①-1) `wss` 종단 실측만 남았다 ([#52](https://github.com/kanghyunsoon/ssafesta/issues/52))
- AI 실패 시 Coin 환불 · Conversation 저장 위치·보존 기간 · Rate Limit 수치 *(`docs/26` ②표)*

미정 사항을 구현자가 임의로 결정하지 않도록 각 관련 문서에 다시 표시했다.
