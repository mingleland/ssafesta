# 기준선(Baseline) 동결 워크플로

> **목적**: 동작이 검증된 상태를 "기준선"으로 동결해 Git 태그로 남기고, 이후 작업이 그 위에 안전하게 쌓이게 한다.
> AI 에이전트에게 작업을 시킬 때 완성된 코드를 재구현/리팩터링하는 사고를 막는 것이 핵심이다.
> 첫 적용: POC 기준선 (`v0.0.1-poc`, 2026-08-08)

---

## 언제 동결하는가

- 마일스톤 단위 검증이 끝났을 때 (POC 완료, MVP1 동결, MVP2 동결, 시연 직전)
- 큰 구조 변경(패키지 업그레이드, 아키텍처 변경) **직전** — 되돌아올 지점 확보
- doc 01 §11의 "Week 6 이후 핵심 아키텍처 변경 금지"도 이 워크플로로 집행한다

## 동결 절차 (5단계)

### 1. 검증 — 기준선에 포함될 기능의 동작 확인

- 완료 조건을 체크리스트로 명시하고 전부 통과시킨다
- 새 기능 추가 금지. 검증 중 발견된 버그 수정만 허용

### 2. 문서 교정 — 코드와 문서의 불일치 제거

- `festa-unity/Docs/poc-status.md` (또는 해당 마일스톤 상태 문서) 최신화
- 검증 중 배운 함정은 트러블슈팅 문서에 추가 (재발 방지)

### 3. 커밋 — doc 17 규칙대로

- 논리 단위로 분리 (예: `docs:` 커밋과 `feat(unity):` 커밋 분리)
- 커밋 전 `git status`로 제외 대상(Library/, Builds/, reference/)이 안 딸려오는지 확인

### 4. 태그 — doc 17 §22 규칙

```text
v0.0.1-poc      ← POC 기준선
v0.1.0-mvp1     ← 1차 MVP 동결
v0.2.0-mvp2     ← 2차 MVP 동결
v1.0.0-demo     ← 시연 버전
```

### 5. 선언 — 팀/AI 에이전트에 동결 공지

- 이후 모든 작업 지시(사람/AI 모두)에 **"기준선 vX.X.X 위에서 작업, 기준선 코드 재설계 금지"**를 명시한다

---

## AI 에이전트 작업 지시 템플릿

에이전트에게 다음 작업을 시킬 때 프롬프트 앞에 붙인다:

```text
현재 기준선: <태그명> (동결됨)
기준선에 포함된 것: <완료 기능 목록 — poc-status.md에서 복사>

규칙:
1. 기준선 코드를 재구현하거나 리팩터링하지 마라. 필요한 경우에만 최소 수정한다.
2. 이번 작업 범위는 아래 항목뿐이다: <구체적 작업>
3. 이번에 하지 않을 것: <제외 목록>
4. 완료 조건: <체크 가능한 조건 목록>
5. 작업 후 보고: 수정 파일 / 테스트 결과 / 남은 문제 / 다음 추천
```

### 프롬프트 작성 시 주의 (실제 겪은 것)

- **에이전트는 진행 상황을 모른다** — 이미 끝난 작업을 지시하면 그대로 다시 만든다. 지시 전에 상태 문서(poc-status.md)와 대조할 것
- 클래스명/구조를 프롬프트에 나열할 때 **현재 코드와 이름이 다르면** 이름 맞추기용 무의미한 리팩터링을 유발한다. 책임 단위로 서술하고 구조는 기존 코드를 따르게 할 것
- "하지 않을 것" 목록이 "할 것" 목록만큼 중요하다
