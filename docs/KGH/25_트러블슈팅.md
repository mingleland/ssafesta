# 트러블슈팅

### T-04. Windows Proactor 이벤트 루프에서 psycopg 비동기 연결 실패 (2026-08-28, 해결)

- **증상**: 실제 PostgreSQL 17을 사용하는 migration 테스트 5건은 통과했지만 async repository 테스트 3건이 `Psycopg cannot use the 'ProactorEventLoop'` 오류로 실행되지 않았다.
- **원인**: Windows의 asyncio 기본 `ProactorEventLoop`는 psycopg 비동기 연결이 지원하지 않는 이벤트 루프 구현이다. Job 로직이나 DB schema의 실패는 아니었다.
- **해결**: 실제 DB 통합 테스트의 session 범위 `event_loop_policy` fixture가 Windows에서 `WindowsSelectorEventLoopPolicy`를 사용하도록 설정했다. 이후 repository 통합 테스트 3건과 전체 테스트 83건이 통과했다.
- **예방**: Windows에서 psycopg async 통합 테스트를 추가할 때 Selector 정책 fixture를 공통 conftest에서 재사용하고, Linux 운영 환경과 분리된 테스트 런타임 차이로 기록한다.

### T-03. Windows 기본 Python·pytest 임시 경로로 테스트 실행 불가 (2026-08-28, 해결)

- **증상**: `python -m pytest`가 WindowsApps 실행 별칭을 시작하지 못했고, 번들 Python으로 만든 `.venv`에서도 기존 `tmp_path` 테스트가 사용자 Temp 아래 `pytest-of-SSAFY` 접근 거부로 중단됐다.
- **원인**: 기본 `python.exe`가 실제 설치가 아닌 Windows 앱 실행 별칭이었고, 현재 제한 환경에서 pytest 기본 임시 루트에 접근할 수 없었다.
- **해결**: Codex 번들 Python으로 worktree 내부 `.venv`를 만들고 테스트 의존성을 격리 설치한 뒤 `--basetemp .venv/pytest-tmp`를 지정해 단위 테스트 62건을 통과시켰다.
- **예방**: Windows 제한 환경에서는 실제 Python 경로를 먼저 확인하고, 프로젝트에서 무시되는 worktree 내부 경로를 pytest 임시 루트로 명시한다.

### T-02. 경로별 로그만 보고 파트 커밋을 단일 파일 커밋으로 오판함 (2026-08-26, 해결)

- **증상**: `git log -- <spec 경로>`에서 spec 008 커밋 하나만 확인하고 `cherry-pick --no-commit`을 시도했으나, 해당 커밋에 API 문서와 spec 004 변경도 포함돼 공유 문서 충돌이 발생했다.
- **원인**: 경로 제한 로그는 “그 경로를 변경한 커밋”만 보여줄 뿐 커밋의 전체 변경 파일 목록을 보여주지 않는다. 적용 전에 `git show --stat <commit>` 또는 `git diff-tree`로 전체 범위를 확인하지 않았다.
- **해결**: 충돌 적용분 세 파일을 작업 브랜치 HEAD로 복원한 뒤, `docs/jira-gitlab-workflow.md` §4-1의 얽힌 커밋 이식 절차에 따라 `specs/008-ai-conversation-rag/spec.md` 한 파일만 선택해 이식했다.
- **예방**: 파트 브랜치 커밋을 이식하기 전 `git show --stat --oneline <commit>`으로 전체 파일 범위를 확인한다. 이슈 외 파일이 섞여 있으면 cherry-pick하지 않고 `git checkout <파트-커밋> -- <허용 경로>`로 파일 단위 이식한다.

## T-001 — spec 007 산출물 간 확정 계약과 작업 목록 불일치

- **날짜**: 2026-08-26
- **증상**: 확정된 callback 404 정책과 저장소 운영 범위가 일부 산출물에만 반영됐고, 세 번째 OpenAPI 계약 테스트·callback 종료 컬럼 migration 작업이 누락됐다. `tasks.md`에는 표준 형식이 아닌 `T008a`, `T075a`, `T075b`도 남아 있었다.
- **원인**: GitLab 후속 합의를 기존 작업 목록에 증분 반영하면서 계약 수, 데이터 모델, migration, 작업 식별자와 의존성 참조를 함께 점검하지 않았다.
- **해결**: P0 수동 장애 정책과 미확정 항목 등록 위치를 통일하고, 세 OpenAPI 스키마 검증·storage reconciliation Backend 동작 테스트 및 callback 종료 필드를 작업에 추가했다. 작업 식별자와 모든 참조를 `T001~T079`로 재정렬한 뒤 중복·누락을 검사했다.
- **예방**: 파트 간 계약 변경 시 spec·plan·research·data-model·contracts·quickstart·tasks를 한 묶음으로 검색하고, 작업 ID 연속성·계약 파일 수와 테스트 수·DB 필드와 migration 작업 대응을 구현 착수 전 검사한다.
