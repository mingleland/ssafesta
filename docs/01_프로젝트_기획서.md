# SSAFY FESTA 프로젝트 기획서

> **문서 목적**: 프로젝트가 해결하려는 문제, 목표 사용자, 핵심 가치, 범위와 우선순위를 정의한다.  
> **문서 상태**: Draft / 팀 합의 후 확정  
> **이 문서에서 다루지 않는 것**: 세부 API, DB 컬럼, 네트워크 패킷, AWS 리소스 설정, UI 수치

---

## 1. 프로젝트 정의

### 1.1 한 줄 소개

**SSAFY 구성원이 가상 SSAFY 공간에서 서로 만나고, 한정된 부스를 임대해 AI 서비스·프로젝트 전시·설문·상담·이벤트 공간을 직접 제작하고 운영하는 사용자 제작형 소셜 메타버스 플랫폼**

### 1.2 핵심 구조

```text
사용자 접속
→ Unity 기반 SSAFY 월드 탐색
→ 부스 발견 또는 임대
→ Booth Studio로 콘텐츠 제작
→ Publish
→ Unity 월드에 데이터 기반 반영
→ 다른 사용자가 방문
→ AI / 프로젝트 / 설문 / 직원 상담 이용
→ 운영자는 반응·수익·설문 결과 확인
```

핵심은 개발팀이 콘텐츠를 계속 추가하는 방식이 아니라 **사용자가 준비된 기능 오브젝트를 조합해 새로운 부스를 만드는 제한형 UGC 구조**다.

## 2. 개발 배경과 문제 정의

### 2.1 프로젝트 결과물이 분산된다

SSAFY에서 생성되는 프로젝트, 포트폴리오, 스터디, 아이디어 검증 결과물은 GitLab, Notion, 배포 링크, 설문 링크 등 여러 채널에 분산된다. 프로젝트 종료 후 다른 교육생이 결과물을 발견하거나 직접 체험하기 어렵다.

### 2.2 프로젝트 홍보와 사용자 검증의 접점이 부족하다

개발 중 실제 사용자 반응을 얻기 위해 설문 링크를 따로 배포하거나 주변 사람에게 직접 참여를 요청해야 한다. 팀원·스터디원 모집 또한 게시글 중심이라 실제 프로젝트 체험과 모집 과정이 분리된다.

### 2.3 AI 서비스를 만들어도 실제 사용자에게 제공하기 어렵다

AI 기능 자체보다 별도 UI, 서버, 배포 환경을 만드는 비용이 커 실제 사용자에게 공개하기 어렵다. SSAFY FESTA는 운영자가 프롬프트와 문서를 등록해 AI 직원을 구성하고 부스에 배치하도록 한다.

### 2.4 일반 메타버스는 콘텐츠 확장이 개발팀에 의존한다

월드를 만든 뒤 새 콘텐츠를 추가할 때마다 개발팀이 게임 로직과 씬을 수정하는 구조는 단기 프로젝트에 부담이 크다. SSAFY FESTA는 데이터 기반 Booth Runtime으로 이 의존도를 줄인다.

## 3. 프로젝트 목표

1. SSAFY 구성원이 프로젝트·AI 서비스·포트폴리오·모집 정보를 한 공간에서 발견할 수 있게 한다.
2. 사용자가 별도의 Unity 개발 없이 자신의 부스를 제작하고 운영할 수 있게 한다.
3. AI 직원과 실제 사람 직원 상담을 하나의 흐름으로 연결한다.
4. 부스 임대·코인·장식·미니게임·경쟁 요소로 가벼운 게임성을 제공한다.
5. 영구 서비스 데이터와 실시간 월드 상태를 분리해 확장 가능한 구조를 만든다.
6. 향후 World Channel, Booth Instance, AR, 다른 캠퍼스로 확장 가능한 구조를 확보한다.

## 4. 핵심 사용자

### 4.1 프로젝트 홍보형

- 완성한 프로젝트를 다른 교육생에게 보여주고 싶다.
- 영상, 링크, AI 도슨트, 설문을 한 공간에서 제공하고 싶다.
- 방문자 반응을 확인하고 싶다.

### 4.2 AI 서비스 운영형

- 자소서 첨삭, 기술 상담, 프로젝트 설명 등 목적형 AI 서비스를 빠르게 운영하고 싶다.
- 별도 서비스를 처음부터 개발하기보다 프롬프트와 문서를 설정해 배포하고 싶다.

### 4.3 모집형

- 프로젝트·스터디 팀원을 모집하고 싶다.
- 소개 영상, 모집 공고, 지원 설문, 실시간 상담을 하나의 부스에서 연결하고 싶다.

### 4.4 방문·탐색형

- 다른 팀의 프로젝트와 포트폴리오를 구경하고 싶다.
- AI 서비스, 이벤트, 미니게임을 가볍게 체험하고 싶다.
- 다른 접속자와 같은 공간에 있다는 느낌을 받고 싶다.

## 9. 동시 접속 방향

전체 서비스 동접과 한 월드가 처리하는 인원을 분리한다.

| 구분 | 목표 |
|---|---:|
| 전체 서비스 | 100명+ 확장 가능한 구조 |
| 11F World 1채널 | 30~40명 운영 목표 |
| 월드 부하 테스트 | 최대 50명 수준 |
| Booth Instance | 8~12명 확장 목표 |
| 팀 기본 단위 | 최대 6명 |

`30~40명`은 NGO의 절대 제한이 아니라 Unity Web 환경의 렌더링·애니메이션·네트워크 비용을 고려한 운영 목표다. 실제 값은 부하 테스트 후 결정한다.

## 10. MVP 대표 성공 시나리오

### 10.1 1차 MVP

```text
A 로그인
→ 빈 부스 임대
→ Booth Studio에서 AI NPC + Video Screen 배치
→ 프로젝트 PDF 업로드
→ AI Prompt 설정
→ Publish
→ A/B가 Unity Dedicated Server 접속
→ 서로의 이동 확인
→ B가 A 부스 외부에서 입장 확인
→ Server가 활성 임대 검증 후 해당 내부 슬롯으로 이동
→ Published Layout 확인
→ B가 AI에게 프로젝트 질문
```

일반 부스 방문은 여러 사용자가 함께 이용하는 공유 공간이다. 부스 전체 독점 예약은 1차 MVP에서 제외하고, 사람 상담이나 비공개 행사처럼 독점이 필요한 기능에만 별도 세션/예약을 둔다.

### 10.2 2차 MVP

```text
B가 AI 상담
→ 사람 상담 요청
→ 등록 Staff에게 알림
→ Staff 수락
→ AI Conversation Summary 전달
→ 실시간 텍스트 상담
→ B가 Survey 제출
→ 운영자가 Dashboard에서 방문·설문·수익 확인
```

## 15. 최종 정의

> SSAFY FESTA는 사용자가 웹 기반 Booth Studio에서 자신의 AI·프로젝트·설문·상담 부스를 직접 제작하면 Unity 멀티플레이 세계에 데이터 기반으로 반영되고, 다른 사용자가 이를 실시간으로 방문·체험하며 운영자는 AI·사람 상담·경제·운영 데이터를 통해 부스를 지속적으로 운영하는 사용자 제작형 소셜 메타버스 플랫폼이다.
