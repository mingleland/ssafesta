# SSAFY FESTA AI 시스템 설계서

> **대상**: 부스별 AI Agent, 문서 RAG, Conversation, Human Handoff Summary  
> **서버**: FastAPI  
> **MVP 전략**: Base LLM + Prompt + RAG  
> API Endpoint 상세는 `14_AI_Server_API_명세서.md`에서 관리한다.

---

## 1. AI 시스템 목표

1. 사용자가 직접 AI 직원의 역할과 Prompt를 설정할 수 있다.
2. 운영자가 등록한 문서를 기반으로 답변한다.
3. Booth/Agent 간 문서가 섞이지 않는다.
4. 답변을 Streaming으로 제공할 수 있다.
5. 필요하면 AI 상담 내용을 요약해 사람 직원에게 넘긴다.
6. AI 장애가 Unity World 전체 장애로 전파되지 않는다.

## 4. Agent Config

실행 시 필요한 설정:

```text

boothId
name
role
tone
specialty
systemPrompt
responseLength
forbiddenTopics
handoffEnabled
servicePrice
```

### Source of Truth

Spring DB를 기본으로 한다.

FastAPI가 Agent를 실행할 때:

- Request에 검증된 Config Snapshot을 전달받거나
- 내부 인증을 통해 Spring에서 조회

중 하나를 선택한다.

## 5. Document Pipeline

```text
Upload to R2 (S3-compatible API)
→ Processing Job 생성
→ File Download
→ Text Parsing
→ Normalization
→ Chunking
→ Metadata 부여
→ Embedding
→ pgvector 저장
→ READY
```

## 6. Document 상태


`READY`가 아니면 RAG 검색에 포함하지 않는다.

## 7. 지원 문서 형식

기존 초안의 초기 후보:

- PDF

최종 허용 형식·최대 크기는 구현 전 확정한다.

## 8. Chunking

Chunk 크기와 overlap은 문서 특성·Embedding 모델에 따라 결정한다.

MVP에서 고정 수치를 문서 기획으로 임의 확정하지 않는다.

Chunk Metadata 최소 후보:

```text
documentId
boothId
agentId
chunkIndex
sourceTitle
page/section (가능한 경우)
```

---

## 9. Vector Data Isolation

검색 전에 반드시 Scope를 결정한다.

```text
scope.boothId
scope.agentId
allowedDocumentIds(optional)
```

Query:

```text
WHERE booth_id = :boothId
  AND agent_id = :agentId
  AND document_status = 'READY'
ORDER BY embedding distance
LIMIT :topK
```

Top-K는 TBD다.

### Critical Test

Booth A의 Agent가 Booth B의 문서 Chunk를 단 한 건도 반환하지 않아야 한다.

## 10. RAG Flow

```text
User Message
   ↓
Conversation Context
   ↓
Agent Config
   ↓
Query Normalize(optional)
   ↓
Vector Search
   ↓
Relevant Chunks
   ↓
Prompt Builder
   ↓
LLM
   ↓
Answer + Source Metadata
```

---

## 11. Prompt 구성 원칙

```text
System Instruction
+ Agent Role/Tone
+ Safety / Forbidden Topic Rule
+ Retrieved Context
+ Conversation Context
+ Current User Message
```

운영자 System Prompt가 플랫폼 필수 보안·격리 규칙을 덮어쓸 수 없게 계층을 분리한다.

---

## 12. Conversation

Conversation 식별자:

```text
conversationId
userId
boothId
agentId
status
createdAt
```

### Context 전략

초기에는 최근 Message + 필요 시 Summary 방식이 단순하다.

장기 대화의 모든 원문을 무제한 Prompt에 넣지 않는다.

보존 정책은 미정이다.

---

## 13. Streaming

MVP에서는 SSE를 우선 검토한다.

Event 개념:

```text
start
 token/delta
 source
 done
 error
```

실제 POST + SSE 구현 호환성은 Client 환경에서 검증한다. 문제가 있으면 WebSocket을 대안으로 둔다.

---

## 14. Source 반환

RAG 답변은 가능한 경우 다음 Metadata를 반환한다.

```json
{
  "documentId": 152,
  "title": "프로젝트_기획서.pdf",
  "chunkId": "chunk_152_03"
}
```

사용자에게 원문 전체를 노출한다는 의미가 아니라 답변이 어떤 등록 문서를 사용했는지 추적하기 위한 정보다.

---

## 15. Handoff Summary

사람 상담 요청 시:

```text
Conversation
→ Summary Prompt
→ 핵심 질문/주제/마지막 의도 추출
→ Spring Consultation에 전달
```

Response 후보:

```text
summary
topics[]
lastUserIntent
```

FastAPI가 직원 선택이나 상담방 생성까지 담당하지 않는다.

---

## 16. AI 자동 Handoff — P2

향후:

```text
handoffRecommended: true
handoffReason: PROJECT_OWNER_REQUIRED
```

초기에는 사용자 직접 버튼 요청을 우선한다.

---

## 17. LLM Provider Adapter

Provider가 확정되지 않았으므로 호출부를 추상화한다.

```text
LLMClient
├─ generate()
├─ stream()
└─ healthCheck()
```

Provider 교체가 API/Business Layer 전체 변경으로 이어지지 않게 한다.

---

## 18. Embedding Provider Adapter

```text
EmbeddingClient
└─ embed(texts)
```

Embedding 모델 변경 시 dimension migration이 필요하므로 Model ID와 Vector schema를 함께 관리한다.

---

## 19. Fine-tuning 전략

MVP 필수 아님.

향후 후보:

- Query Routing Model
- Reranker
- Human Handoff 판단
- 충분한 검수 데이터 확보 후 LoRA / QLoRA

기능 차별화를 위해 무리하게 자체 LLM 학습을 우선하지 않는다.

## 20. Agent Test Studio — P2

운영자에게 제공할 수 있는 디버깅 정보:

- 질문

- Retrieved Chunks

실제 방문자 화면에는 내부 Prompt나 민감 설정을 노출하지 않는다.

---

## 21. 오류 / Fallback

### 문서 없음

- Agent 설정에 맞는 일반 답변 허용 여부를 정책으로 결정
- 또는 등록 자료 없음 안내

### RAG 실패

- 오류를 LLM에게 빈 Context로 조용히 넘기지 않고 관측 가능하게 기록

### LLM Timeout

- 사용자에게 재시도 안내
- World 연결 유지

### Streaming 중단

- 부분 응답 상태 표시
- 재질문 가능

---

## 22. 보안

- boothId / agentId 권한 검증
- Prompt Injection으로 다른 Booth 데이터 접근 불가
- 다른 Booth 데이터는 애초에 Retrieval Scope에서 제외
- Object Key를 클라이언트가 임의 지정하지 않음
- API Key 로그 금지
- 원문 대화 로그는 정책 확정 전 최소화

## 24. 품질 평가

### 기능 정확성

- 문서 처리 성공률
- Agent Scope Isolation
- Source 반환
- Streaming 완료

### RAG 품질

테스트 질문 세트를 만들고:

- 관련 Chunk 검색 여부
- 근거 없는 답변 비율
- 문서 없음 Fallback

을 평가한다.

### Handoff Summary

- 핵심 사용자 의도 포함
- 불필요한 장문 방지
- 원 대화 왜곡 여부
