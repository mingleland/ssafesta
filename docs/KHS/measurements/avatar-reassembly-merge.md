# 옷을 갈아입으면 검은 얼룩 — 병합이 옛 병합체를 다시 삼킨다 (S15P21A604-334)

작업일 2026-08-31 · 발견: 배포(릴리즈) WebGL 빌드, 실사용자 경로

## 증상

캐릭터 로비에서 상의를 **"없음" 으로 바꿨다가 다시 입으면** 셔츠 가슴에 **검은 얼룩 두 개**가
생긴다. 어깨·넥라인에도 검은 자국이 남는다. 처음 조립할 때는 멀쩡하다.

## 원인 — 지연 파괴가 병합 후보에 남는다

`AvatarAssembler.Apply()` 안의 순서:

```
Equip(각 카테고리)        → 옛 파츠에 Destroy
UpdateBodyVisibility()   → 옷에 가려지는 신체를 끈다
CombineSameMaterialParts() → 같은 재질끼리 병합
```

**플레이 모드의 `Destroy` 는 프레임 끝까지 미뤄진다.** 그래서 마지막 단계에서 후보를 고를 때
**직전에 파괴를 건 옛 병합체가 아직 살아 있고 `enabled` 다.** 게다가 `_merged` 목록은 그 직전에
비워졌으므로 걸러지지도 않는다 → **새 병합이 옛 병합체를 통째로 다시 삼킨다.**

옛 병합체에는 그때 보이던 형상(상의를 벗었을 때의 **속옷**)이 구워져 있다. 그것이 새 병합
메시에 영구히 남아 셔츠를 뚫고 나온 것이 검은 얼룩이다.

### 실측 근거

| | |
|---|---|
| 병합 메시 정점 | 기준 **2,573** → 옷 갈아입은 뒤 **8,508** (전체 바디 파츠 합은 3,962) |
| 병합체만 끄고 렌더 | **얼룩이 사라진다** — 얼룩은 병합 메시 안에 있다 |
| 깨끗한 병합 OFF 세션 | **얼룩 없음** |

## 처음 내린 두 판정이 틀렸다 — 둘 다 계측 결함이었다

**① "렌더러가 누적된다" — 아니다.** 20 → 26 으로 늘어 보인 것은 **에디터가 포커스를 잃어
프레임이 멈춘 상태**에서 잰 값이었다(`Time.frameCount` 가 Apply 전후 모두 38). 파괴 대기 중인
오브젝트를 센 것이다. `Application.runInBackground = true` 로 프레임을 돌리자 중복은 사라졌다.

**② "병합과 무관하다" — 아니다.** 병합 OFF 로 A/B 했다고 믿었지만, `CombineSameMaterialParts`
가 **꺼져 있을 때 정리보다 먼저 `return`** 해서 **옛 병합체가 그대로 살아 있었다.** 즉 OFF 가
아니었다. 성별을 왕복시켜 `BuildBody()` 로 전체를 재구축한 **진짜 OFF** 에서는 얼룩이 없다.

> **교훈 — 에디터가 포커스를 잃으면 플레이 모드 프레임이 멈춘다.** 지연 파괴가 얽힌 것을 잴 때
> `runInBackground` 를 켜지 않으면 "죽는 중인 오브젝트" 를 실재로 착각한다. T-228 과 같은 뿌리다.

## 수정 셋

1. **파괴 대기 집합(`_dying`) 도입** — `Equip` 이 파괴를 건 파츠를 기록하고 병합 후보에서 제외
2. **옛 병합체도 `_dying` 에 등록** — `DestroySafe(_merged)` 역시 지연되므로 같은 처리가 필요하다.
   **이것이 실제 원인이었다**(1번만으로는 안 고쳐졌다)
3. **병합이 꺼져 있어도 정리는 한다** — 원본 되살리기·옛 병합체 파괴를 마친 뒤에 `return`.
   전에는 토글을 끄는 순간 화면이 옛 상태로 굳었다

`_dying` 은 `Apply` 마다 **비우지 않고** 실제로 파괴가 끝난 것만 걷어낸다(`RemoveWhere(go => !go)`).
비웠더니 한 프레임에 Apply 가 연속으로 불릴 때 앞선 호출의 파괴 대상을 잊어 **정점이
2,573 → 247,164 로 터졌다.**
