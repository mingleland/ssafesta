# 원격 아바타 최적화 3종 A/B — 30기 동시 표시 (S15P21A604-236)

측정일 2026-08-30 · 도구 `Festa.Diagnostics.AvatarCostAb` (F9) · main 씬 · 에디터 Host

> ⚠ **에디터 측정이다.** WebGL 실측이 아니다. 2026-08-25 비용 분해도 에디터에서 했으므로
> 같은 기준끼리는 비교되지만, **절대값을 배포 성능으로 인용하면 안 된다.**

## 방법

조건을 **교대로** 3회차 돌린다(A,B,A,B,…). 한 조건을 몰아서 재면 그 사이의 드리프트가
차이에 통째로 섞인다. 회차마다 아바타를 비우고 **프레임을 한 번 넘긴 뒤** 다시 세운다 —
플레이 모드의 `Destroy` 는 프레임 끝까지 미뤄지므로 같은 프레임에 세우면 이전 회차가
살아 있다(T-228 과 같은 함정). 회차당 정착 120프레임을 버리고 300프레임을 표본으로
**중앙값**을 쓴다.

## 1차 — 전/후 (완료 조건이 요구한 수치)

| 조건 | 회차별 중앙값 (ms) | 대표 | 활성 스킨메시 |
|---|---|---:|---:|
| 전 (최적화 없음) | 7.40 / 7.18 / 7.37 | **7.37** | 338 |
| 후 (병합+LOD+컬링) | 6.91 / 6.89 / 6.91 | **6.91** | 218 |

**7.37 → 6.91 ms (−0.46 ms, 6.2%)**. 회차 간 흔들림이 각각 ±0.11 / ±0.01 로 작아 이 값은 신뢰할 만하다.

렌더러는 338 → 218. 기준선 8을 빼면 330 → 210, 즉 **아바타당 11 → 7** 로
S15P21A604-258 에서 잰 값이 그대로 재현됐다.

## 2차 — 손잡이별 기여

어느 손잡이가 실제로 값을 내는지 추론하지 않고 재려고 조건을 5개로 늘렸다.

| 조건 | 1회차 | 2회차 | 3회차 | 회차 내 `전` 대비 |
|---|---:|---:|---:|---|
| 전 (최적화 없음) | 9.24 | 7.84 | 7.86 | — |
| 병합만 | 8.51 | 7.46 | 6.63 | −0.73 / −0.38 / −1.23 → **3/3 음수** |
| LOD만 | 9.50 | 7.13 | 10.66 | +0.26 / −0.71 / +2.80 |
| 컬링만 | 12.47 | 7.02 | 10.48 | +3.23 / −0.82 / +2.62 |
| 후 (3종 전부) | 7.31 | 6.63 | 8.93 | −1.93 / −1.21 / +1.07 |

**2차는 1차보다 훨씬 시끄럽다** — 조건이 늘어 회차가 길어지고 소환·파괴 churn 이 늘면서
±3 ms 스파이크가 섞였다. 그래서 **이 표에서 1 ms 미만의 차이는 읽지 않는다.**
그럼에도 분명한 것이 하나 있다: **`병합만` 은 3회차 모두 `전` 보다 낮다.** 나머지 둘은 부호가 뒤집힌다.

## 왜 LOD·컬링은 값이 안 나오나 — 이 조건에서는 **할 일이 없기 때문이다**

측정 중 실측: 30기 전부 카메라로부터 **58~103 unit**, 절두체 안 **210/210**, `isVisible` **210/210**.

- `AvatarAnimationLod._nearDistance` 는 **220 unit** 이다. 전원이 근거리 밴드(band 0)에 들어간다.
  코드상 band 0 은 애니메이터를 그대로 켜 두고 본 가중치도 원복한다 — **정의상 아무 일도 하지 않는다.**
- `CullUpdateTransforms` 는 **화면 밖** 아바타의 본 갱신을 막는 장치다. 전원이 보이면 막을 것이 없다.

즉 **완료 조건이 지정한 "30기 동시 표시" 는 3종 중 2종이 작동하지 않는 시나리오다.**
두 장치의 값은 멀거나 화면 밖인 경우에 나오며, 그 시나리오는 이 조건이 재지 않는다.
**따라서 −0.46 ms 는 3종의 합이 아니라 사실상 병합 단독의 몫으로 읽어야 한다.**

## 외형 조합별 시각 회귀 — 158개 조합 통과

도구 `Festa.Diagnostics.AvatarMergeIntegrity` (F12).

스크린샷으로는 판정할 수 없다. `AvatarStressSpawner` 는 **색만** 흔들고 아이템 조합은
기본값 하나뿐이라 조합을 검사하지 못하고, 사람 눈은 폴리곤 한 덩이가 빠진 것을 못 잡는다
(T-223·T-214 둘 다 유니티가 에러를 내지 않아 눈으로만 발견됐다).

대신 **불변식**을 봤다 — 조립 결과를 `재질 이름 → 그려지는 정점 수 합` 으로 요약하면
병합 ON/OFF 가 정확히 같아야 한다. 카탈로그의 **모든 아이템을 한 번씩** 입혀 비교했다.

```
[MergeIntegrity] 통과 — 조합 158개에서 병합 ON/OFF 의 재질별 정점 수가
완전히 일치한다. 병합으로 잃은 기하가 없다.
```

전 조합(곱집합)이 아니라 **아이템당 최소 1회** 커버리지다 — 특정 아이템이 병합에서
탈락하는 사고는 아이템 단위로 일어나므로 이 커버리지로 잡힌다.

## 근거리 애니메이션 품질 저하 없음

코드 근거 — `AvatarAnimationLod` 의 band 0(≤220 unit)은 `Animator.enabled` 를 건드리지 않고
`ApplySkinQuality(e, 0)` 로 본 가중치를 원복한다. **근거리는 Unity 기본 경로 그대로다.**

실측 근거 — 위 측정에서 30기 전원이 band 0 이었고 `LOD만` 조건이 `전` 과 구분되지 않았다.
LOD 가 근거리에서 아무것도 바꾸지 않는다는 것이 숫자로도 확인된다.

## 남는 것

- **WebGL 실측이 없다.** 에디터 값이므로 배포 성능의 근거로 쓸 수 없다.
- **먼 거리·화면 밖 시나리오를 재지 않았다.** LOD·컬링의 값은 거기서 나오는데 이번 조건은
  그 상황을 만들지 않는다. 40인 부하 테스트(별도 머신 필요) 때 함께 재는 것이 맞다.
