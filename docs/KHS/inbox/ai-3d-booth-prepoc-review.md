# AI 3D Booth Pre-PoC 개념 아키텍처 v2 — 게임 파트 검토

> 검토일 2026-09-12 · 대상 문서 `SSAFESTA_AI_3D_Booth_PrePoC_Concept_Architecture_v2.md` (FE 전달)
> 판단 기준: 지금 develop 에 있는 코드와 오늘까지의 실측값. 추정은 추정이라고 적는다.

## 1. 문서 자체에 대한 판단

**방향은 우리 실측과 어긋나지 않는다.** 특히 세 가지가 맞다.

- **완전 자유 Scene Generation 배제**(§4·§49) — 동선·Spawn·Collision 을 AI 에게 맡기지 않겠다는 것. 우리 내부 부스는 방 규격·입출구·스폰이 이미 고정돼 있어서 그 전제가 그대로 성립한다.
- **방문자 런타임에 생성하지 않음**(§25·§49) — 생성 시간과 방문자 로딩을 분리한다. WebGL 진입이 이미 무거운 우리 상황에서 이건 타협 불가 조건이다.
- **WebGL 을 최적화 대상이 아니라 Hard Constraint 로**(§28) — "좋으면 적용" 이 아니라 통과 게이트. 우리가 T-245·T-246 에서 배운 것과 같은 결론이다.

Non-goals(§49)와 "확정하지 않는 것"(§47)을 분리해 둔 것이 이 문서의 가장 큰 미덕이다. 헌법 30조(미정 항목을 임의로 확정하지 않는다)와 같은 태도라, 이 상태 그대로 기준선으로 삼아도 된다.

## 2. 적합도 — 문서가 요구하는 구조의 절반은 이미 있다

| 문서가 요구하는 것 | 지금 상태 | 근거 |
|---|---|---|
| Fixed Runtime Shell (방·입출구·스폰·콜라이더) | **있음** | `FestaInteriorBuilder`. 방 내부 실측 x −4.88~+5.00 m · z −3.81~+6.97 m, `Interior_NN/SpawnPoint`·`ReturnPoint_NN`·`Portal_Ext_NN` |
| Runtime Scene Manifest (§23) | **있음 — 이름만 다르다** | `BoothLayoutDto`: `objects[type, assetCode, position, rotationY, configId]` + `schemaVersion`. 게시·조회·렌더 경로가 전부 돈다 |
| Booth Studio 편집 (§24) | **있음** | 09-11 실측: 스튜디오 배치 → 게시 → 유니티 생성이 위치·회전 8/8 일치 |
| Asset Library | **부분** | `BoothObjectRegistry` 매핑 49행(타입 기본 + assetCode 지정). `Prefabs/Booth/` 11종, 프로젝트 전체 프리팹 37종. Semantic Card·썸네일·임베딩은 없음 |
| Vector 인프라 재사용 (§14) | **있음** | BE 에 pgvector — `CREATE EXTENSION vector`, `embedding VECTOR(1536)`. 다만 문서 지적대로 **RAG 텍스트 임베딩이라 값 재사용은 안 된다** |
| Semantic Zone (§21) | **없음** | 방 좌표계가 확정돼 있어 정의만 하면 된다 |
| Constraint Solver (§22) | **씨앗만** | FE `overlap.ts`(회전 반영 AABB 겹침)·`clampToBooth`, 게임 쪽 실물 bounds 방 경계 검사(`S15P21A604-657`). 동선·카메라 가림·Zone 은 없음 |
| 런타임 GLB 로딩 (§26·§27) | **패키지만 있고 검증 0** | `com.unity.cloud.gltfast 6.19.0` 이 `Packages/manifest.json` 에 있는데 **우리 코드에서 한 번도 쓰지 않았다** |

즉 "Fixed Shell + Generated Theme" 라는 구조 자체는 우리가 이미 그 모양으로 만들어 뒀다. 바뀌는 것은 **Theme Kit 을 어디서 가져오느냐** 하나다 — 지금은 빌드에 포함된 프리팹을 `assetCode` 로 참조하고, 문서는 런타임에 내려받는 GLB 를 가리킨다.

## 3. 미검증 위험 셋 — 여기가 PoC 의 진짜 과녁이다

### ① 런타임 GLB 경로가 우리 WebGL 빌드에서 성립하는지 모른다

glTFast 는 들어 있지만 **한 번도 쓴 적이 없다.** 확인해야 하는 것:

- WebGL(IL2CPP) 빌드에서 실제로 로드되는가
- 생성 에셋의 임의 머티리얼을 **URP Lit 으로 정규화**해야 한다(프로젝트 규칙). 안 하면 런타임 머티리얼이 마젠타로 깨진다 — 부스 placeholder 에서 이미 겪었다
- 셰이더 변형이 늘면 진입이 다시 굳는다(T-245·T-246: 프리로드·분산 모두 1~4분 굳음, 변형 수 감축만 답이었다)
- Draco/KTX2 압축을 쓰면 디코더가 추가로 붙는다

**이게 실패하면 §11~§27 설계가 전부 의미를 잃는다.** 그래서 PoC 의 첫 실험이어야 한다.

### ② WebGL 용량이 이미 한계다

지금 릴리스 산출물 실측:

```
data.unityweb   131 MB
wasm.unityweb     9 MB
합계            약 140 MB (릴리스 zip 147~152 MB)
```

여기에 진입 50~84초(#129)가 겹쳐 있다. 부스별 Theme Kit 을 얹으려면 문서 §26(선택 로드 · 진입 시 전체 프리로드 금지)이 **유일한 답**인데, 그건 지금 없는 런타임 시스템이다. 순서가 뒤집히면 안 된다 — 스트리밍/언로드가 먼저 서고 그다음이 생성이다.

### ③ 계약 확장이 3파트 동시 변경이다

지금 레이아웃 JSON 은 `assetCode` **문자열 → 빌드 포함 프리팹** 매핑이다. 생성 에셋을 넣으려면 최소한 URL·무결성 해시·런타임 예산(삼각형/텍스처/바운즈)이 함께 와야 하고, 그러면 `schemaVersion` 2 + BE 저장 + FE 스튜디오 표시까지 같이 움직인다. 파서는 forward-compat 이라 모르는 필드로 깨지지는 않지만, **표시·검증은 세 파트가 같이 붙어야 한다.**

## 4. 남은 기간 대비 판정

§48 의 "Pre-PoC / MVP 핵심" 12개 항목을 남은 기간에 전부 세우는 것은 **현실적이지 않다.** 다만 문서도 그렇게 주장하지 않는다 — Pre-PoC 기준선이라고 스스로 못 박아 뒀다.

권하는 좁히기:

```
부스 1칸 · 프로젝트 1개 · Hero Asset 1개
성공 판정 = 그 GLB 가 WebGL 에서 뜨고, 진입 시간과 FPS 가 지금보다 나빠지지 않는다
```

이 하나가 되면 §11(Theme Kit)·§12(재사용+선택 생성)·§26(선택 로드)이 한꺼번에 검증된다. 안 되면 나머지를 설계할 이유가 없다.

## 5. 게임 파트가 지금 낼 수 있는 것

PoC 실험 설계 전에 이쪽에서 먼저 내놓을 수 있는 Fixture(문서 §46 과 대응):

1. **방 규격·Semantic Zone 좌표 정본** — 방은 이미 실측돼 있다. HERO/INFO/DEMO/SUPPORT/ENTRY 를 그 좌표 위에 얹기만 하면 된다.
2. **런타임 예산 실측치** — 지금 빌드 기준 삼각형·텍스처 메모리·draw call·진입 시간. 문서가 "PoC 에서 측정" 이라고 남겨 둔 숫자의 기준선이 된다.
3. **Seed Asset Semantic Card 자동 추출** — 부스 프리팹의 폴리 수·실물 바운즈·썸네일은 에디터에서 뽑을 수 있다(바운즈는 `BakeMesh` 로 실측해야 한다 — `SkinnedMeshRenderer.bounds` 는 bind-pose 라 거짓말을 한다). 손으로 적지 않는다.
4. **glTFast 스파이크** — 위 ①. 반나절 규모로 먼저 친다.

## 6. 문서에 보탰으면 하는 것

- **누가·언제가 없다.** 범위·인력·기간이 비어 있어 "PoC 실험 설계" 로 넘어가는 순간 바로 막힌다. 남은 기간 안에서 무엇을 포기할지부터 정하는 편이 낫다.
- **실패 폴백이 없다.** 생성 실패·예산 초과일 때 방문자에게 무엇을 보여줄지가 빠져 있다. 우리 규칙은 "조용히 기본값으로 되돌리지 않는다" 이고, 부스는 미게시면 **기본 프레임 유지**다 — 그 규칙과 이어 붙여야 한다.
- **기존 게시 레이아웃과의 관계.** 이미 게시된 부스(오브젝트 8개짜리)가 있는 상태에서 AI Theme Kit 이 그 방에 **공존하는지 대체하는지** 가 정해져 있지 않다. 스튜디오 편집 결과와 충돌한다.
- **언로드 시점과 멀티플레이.** §26 의 Exit → Unload 는 혼자일 때의 그림이다. 같은 월드에 여러 명이 있고 서로 다른 부스를 드나든다 — 누가 나갈 때 무엇을 내리는지가 NGO 동기화와 맞물린다.
- **Seed Asset 라이선스.** 지금 부스 프리팹 상당수가 벤더 팩(Synty 등)이다. 그 썸네일·임베딩을 공용 Asset Pool 로 돌리는 것은 §18 의 IP 체크 대상이다 — 처음부터 표시해 두는 편이 낫다.

## 7. 한 줄 결론

**구조는 맞다. 순서만 지키면 된다** — 런타임 GLB 경로 스파이크 → 선택 로드/언로드 → 그다음에 생성. 이 순서를 뒤집으면 생성 품질이 아무리 좋아도 WebGL 에서 뜨지 않는다.
