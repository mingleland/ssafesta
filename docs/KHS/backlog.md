   - 파츠별 bounds 보정만으로 재발해 부스 직원의 모든 활성 스킨 파츠가 동일한 전신 bounds를 공유하고 `updateWhenOffscreen`을 사용하도록 재수정했다.

   - 남은 확인: 벽 앞에 2명 이상 붙어 연속 이동할 때 양쪽 클라이언트 모두 벽 밖으로 빠지지 않는지 검증한다.

11. **벽과 비빌 때 캐릭터가 떠오르는 문제** — `S15P21A604-643`

    - 소유자 `CharacterController`와 원격 `CapsuleCollider`를 같은 반경으로 맞춰 화면별 접촉 거리 차이를 막는다.
    - 남은 확인: 벽 평행 이동 시 시각 간격과 수직 상승 여부, 원격 플레이어 간 접촉 거리.

    - 상태: **최신 game 스택에 재구현·컴파일 완료/멀티 시각 검증 대기**.
    - 멀티플레이에서 렌더 오브젝트의 배치 Transform과 상호작용 기준 Transform이 같은 레이아웃 좌표를 사용해야 한다.
    - 회전·이동한 노트북 여러 개와 호스트·클라이언트 양쪽에서 프롬프트 범위를 확인한다.

13. **부스 제목 간판 콜라이더를 실제 형상에 맞춤**
    - 상태: **수정·컴파일 완료/플레이 검증 대기** — `S15P21A604-611` 후속.

    - 수정 전에는 지면 위 14.6 높이에 평평한 뚜껑이 깔려 간판 주변 어디에 올라서도 공중에 떠 보였다.
    - 남은 확인: 간판 주변 보행·점프 시 뜬 발판이 사라졌는지, 판을 몸으로 통과하지 않는지 확인한다.

## 작업 운영 기준

- 최신 develop의 `festa-unity/`만 game 동기화 브랜치로 가져와 game을 게임 파트 최신본으로 유지한다.
- Unity 작업은 최신 game에서 작업 브랜치를 만들고 원본 프로젝트 폴더에서 진행한다.
- 작업 브랜치는 먼저 game 대상 MR로 병합하고, game 파이프라인과 무관하게 최신 game에서 다음 작업을 계속한다.
- 배포 시 develop에서 별도 이식 브랜치를 만든 뒤 game의 완료된 작업 파일만 이슈 단위로 가져와 develop에 반영한다. game 브랜치 전체를 develop에 병합하지 않는다.
- 씬·프리팹·asset 변경은 Unity에서 수행하며 YAML을 직접 편집하지 않는다.
- 게임 파트 작업일지와 트러블슈팅은 각각 `docs/KHS/24_작업일지.md`, `docs/KHS/25_트러블슈팅.md`에만 기록한다.
- 사용자 소유의 `ProjectSettings/QualitySettings.asset` 변경과 미추적 QA 산출물은 작업 커밋에 포함하지 않는다.
