   - 상태: **최신 Unity 위 재적용 완료/MR !927 자동병합 대기**.
   - 직원 시각물과 상호작용 콜라이더 중심은 씬에서 일치시켰다.
   - 남은 확인: 최신 develop에서 다른 씬 왕복 후에도 위치 유지, 상호작용 시 플레이어 바라보기, 발·다리 파묻힘 없음, 5분 뒤 수면 위치 복귀.
   - 최신 develop의 Unity 트리 위에서 Unity로 위치를 다시 저장했으며, game 병합 뒤 런타임으로 재검증한다.

2. **헤어·의상 색상 최종 반영 확인** — `S15P21A604-776`, 기존 `S15P21A604-746`
   - 상태: **최신 Unity 위 재적용 완료/MR !927 자동병합 대기**. 사용자가 초록 헤어 정상 표시를 확인했다.

   - 남은 확인: 최신 develop에서 로컬·원격 아바타와 재접속 후 색상 유지.

3. **속옷 단독 상태 제거와 기본 의상 강제** — `S15P21A604-777`
   - 상태: **병합 완료·로비 Play 실측 완료** (2026-09-16). 상의 없음 → 기본 상의, 하의 없음 → 기본 하의, 한벌옷 상태에서 상의 선택 → 한벌옷 해제·하의 복원까지 확인했다.
   - 여성 기본 상의는 링거 티셔츠, 기본 하의는 일자 팬츠로 고정한다.
   - 상의·하의의 `없음` 선택으로 속옷만 남는 경로를 제거하고, 저장값이 0이거나 유효하지 않아도 기본 의상으로 정규화한다.
   - 남성도 카탈로그의 기본 상·하의를 같은 규칙으로 보장한다.

4. **한벌 의상 ↔ 상의·하의 전환 시 기존 의상 유지**
   - 상태: **병합 완료·로비 Play 실측 완료** (3번과 같은 검증).
   - 한벌 의상에서 상의를 선택하면 기존/기본 하의를 유지하고, 하의를 선택하면 기존/기본 상의를 유지한다.
   - 어느 전환 순서에서도 속옷 단독 상태가 발생하지 않아야 한다.

5. **NPC 옷이 화면 가장자리에서 사라지는 컬링 회귀** — `S15P21A604-749`
   - 상태: **원인 실측·수정 완료/플레이 검증 대기** (2026-09-16 3차).
   - 라이브 실측으로 원인을 확정했다: 벤더 NPC 프리팹(ithappy Casino_Free)의 옷·얼굴·머리 렌더러 `localBounds`가 **(0.15, 0.12, 0.03)** — 15cm 상자다. 몸만 (1.46, 1.85, 0.43)로 정상이라 몸은 남고 옷만 먼저 컬링됐다.
   - 앞선 두 차례 수정은 `BoothStaff` 런타임 조립 경로만 고쳤는데, 축제장 직원 12명·안내데스크·운영데스크는 **씬에 놓인 벤더 프리팹 인스턴스**라 그 코드를 타지 않았다.
   - `NpcSkinnedBoundsUnifier`가 씬 로드 시 플레이어를 제외한 모든 NPC의 같은 rootBone 렌더러 bounds를 합쳐(15% 여유) 전부에 씌운다. 라이브에서 NPC 28기·렌더러 184개 적용, 안내데스크 6/6 렌더러 동시 표시 확인.
   - 남은 확인: 화면 가장자리 왕복 시 옷과 몸이 함께 나타나고 함께 사라지는지.

### P1 — 멀티플레이 충돌·상호작용

6. **하이스트라이커 상호작용 중 이동·걷기 애니메이션 잔류** — `S15P21A604-585`
   - 상태: **병합 완료/플레이 검증 대기**. 대형 동기화 커밋 `1e539763` 에 이미 포함돼 `game` 에 들어가 있다.
   - 상호작용 즉시 이동 입력과 걷기 블렌드를 0으로 만들고, 실제 Strike 애니메이션이 끝난 뒤 이동을 복구한다.
   - 서버 거절·응답 유실 시 영구 잠금되지 않도록 요청 단계 제한시간을 둔다.

7. **원격 아바타 평지 박힘·무릎 굽힘 실환경 재검증** — `S15P21A604-737`

   - 2클라이언트에서 평지 이동과 단차 이동을 각각 확인한다.

8. **원격 이동 1~2초 지연·급가속 실환경 재검증** — `S15P21A604-738`
   - 상태: **병합 완료/실환경 검증 대기**.
   - 일반 이동 델타를 Unreliable, 위치·회전 보간을 새 Lerp로 변경했다.
   - 붙어서 플레이하는 2클라이언트에서 시작·정지 지연, 방향 전환, 패킷 손실 뒤 따라잡기를 실측한다.

9. **Shift 빠른 반복 시 스케이트처럼 미끄러지는 달리기 전환**
   - 상태: **병합 완료/플레이 체감 검증 대기** — `S15P21A604-747`.
   - Shift를 일정 시간 이상 유지해야 달리기 모션으로 전환하고, 짧은 탭은 걷기 상태를 유지하도록 히스테리시스/디바운스를 넣는다.

10. **벽에서 서로 밀 때 벽 밖으로 이탈하는 문제**
   - 상태: **구조 재설계·라이브 검증 완료** — `S15P21A604-761` (2026-09-16).
   - 원인: 원격 캡슐이 내 CharacterController 에 단단한 벽으로 작용해, 상대가 밀고 들어오면 엔진 디페네트레이션이 나를 임의 거리로 튕겨 얇은 벽을 통과시켰다. 사후 스윕 보정은 시작점이 이미 벽 안이면 놓친다.
   - Player↔Player 물리 충돌을 끄고(`PlayerCollisionPolicy`), 겹친 만큼을 속도(상한 90u/s)로 풀어 Move() 를 거치게 했다. 밀림이 벽 판정을 거치므로 구조적으로 뚫을 수 없다.
   - 라이브 실측: 더미 캡슐이 밀고 들어오자 플레이어가 벽까지 밀려 **3.07u(반지름+스킨)에서 정지**, 더미가 관통해 지나가자 반대로 밀려나옴. 벽 반대편으로는 한 번도 가지 않았다.
   - 남은 확인: 실제 2클라이언트에서 같은 동작.

11. **벽과 비빌 때 캐릭터가 떠오르는 문제** — `S15P21A604-643`
    - 상태: **라이브 실측 완료 — 재현 안 됨** (2026-09-16).
    - 벽 정면 밀착(걷기)과 45° 비스듬히 벽을 따라 달리기(65u/s) 두 시나리오에서 루트 높이 0.304, 지면 위 0.220(=skinWidth)으로 **변화 없음**. 벽 접촉 시 루트가 0.12 오르는 것은 접지 보정이 시각물을 같은 양 내려 상쇄한다.
    - 캡슐 반지름은 실측 몸통(2.83)에 맞춘 2.85 다. 남는 것은 팔이 벽에 파고드는 시각 클리핑뿐이며 부유가 아니다.

12. **사용자 배치 노트북의 상호작용 범위가 중앙에 남는 문제** — 기존 작업 브랜치 `S15P21A604-751`
    - 상태: **최신 game 스택에 재구현·컴파일 완료/멀티 시각 검증 대기**.

    - 회전·이동한 노트북 여러 개와 호스트·클라이언트 양쪽에서 프롬프트 범위를 확인한다.

13. **부스 제목 간판 콜라이더를 실제 형상에 맞춤**
    - 상태: **수정·컴파일 완료/플레이 검증 대기** — `S15P21A604-611` 후속.
    - 입간판 12개의 루트 박스 콜라이더(9.1×14.6×15.0)를 제거하고 A자 판 두 장의 메시 콜라이더로 교체했다.

### P2 — 커스터마이징 UX와 월드 UI

14. **구매 전 실착 미리보기·취소 복원**
    - 상태: **로비 Play 실측 완료** (2026-09-16). 잠긴 상의를 누르면 `topId` 가 그 옷으로 바뀌고 창을 닫으면 원래 값으로 정확히 돌아왔다. 구매 성공 경로는 Mock 이 구매를 항상 거절해 실서버에서 확인한다.
    - 잠긴 항목을 누르면 구매 창이 열리는 동안 그 항목을 실제로 입혀 보여 주고, 사지 않고 닫으면 이전 외형으로 되돌린다.
    - 구매 창을 화면 오른쪽으로 옮기고 배경 어둡기를 낮춰 아바타가 보이게 했다.
    - 남은 확인: 상의·하의·한벌옷·모자 각각의 미리보기와 취소 복원, 구매 성공 시 착용 유지, 잠긴 항목 연속 클릭.

15. **다른 파츠 선택 시 기존 색상 창 자동 닫기**
    - 상태: **로비 Play 실측 완료** — `S15P21A604-780`. 색상 창을 연 채 다른 상의를 고르자 창이 닫혔다.
    - 헤어·의상 등 선택 대상이 바뀌면 이전 색상 설정 창과 임시 상태를 닫아 잘못된 파츠 편집을 막는다.

16. **NPC·플레이어 이름표의 벽 관통 표시 방지** — `S15P21A604-703`
    - 상태: **차폐 5점 판정으로 보강·실측 완료/사용자 시각 확인 대기**.
    - 기존 차폐 레이의 1.5u 끝점 제외를 0.1u로 줄이고 hit 용량을 8→32로 늘려 벽 바로 앞과 복잡한 부스의 누락을 막았다.
    - (09-16) 한 점 판정 → 글자 사각형 5점 과반 판정(`WorldTextOcclusion`) + Overlay 셰이더로 반 토막 제거. 말풍선에도 적용. 표시 거리는 이름표·데스크 라벨 무제한(사용자 결정), 말풍선 220u. [T-235](25_트러블슈팅.md)

17. **채팅 메시지를 해당 캐릭터 위 말풍선으로 표시**
    - 상태: **Unity 수신부 구현·컴파일 완료/FE 한 줄 연결 대기**.
    - `WorldChatBridge.ReceiveChat(json)` 이 `/topic/world/chat` 방송 payload를 그대로 받아 `senderUserId`로 `NetworkPlayer.UserId`를 찾고 머리 위에 말풍선을 띄운다.
    - 표시 시간은 글자 수에 비례해 3~7초, 표시 거리 150u, 카메라 뒤쪽은 그리지 않는다.
    - FE는 `SendMessage('WorldChatBridge','ReceiveChat', JSON.stringify(msg))` 한 줄만 추가하면 된다 — 새 필드를 만들지 않았다. 계약 확인 항목은 `docs/26`에 등록했다.

18. **좌클릭 주먹질 애니메이션**
    - 상태: **구현·컴파일 완료/플레이 검증 대기**.
    - 사용자가 준 Mixamo Boxing 3종에서 **잽 구간만 잘라** `Punch01~03`(0.33·0.33·0.40초)으로 다시 임포트하고 상태 speed 1.25 로 재생한다 — 한 대당 0.27~0.32초다.
    - 연속 클릭은 **콤보**로 이어진다(현재 2종 교대). 치는 중에 누른 입력은 예약해 끝나는 순간 이어 친다. 마지막 주먹 뒤 0.8초 안에 누르지 않으면 처음부터 다시 시작한다.
    - Punch2 는 실측상 **발차기 계열**(발 들림 0.155·발 전방 0.495, 손 0.347)이라 상체 마스크와 맞지 않아 콤보에서 제외했다. 열거형 값과 애니메이터 상태는 남겨 뒀다.
    - 임팩트 순간 정면 11u·55° 안에 사람이 있으면 0.12초 동안 18u/s 로 **아주 살짝(약 2.2u≈17cm)** 밀린다. 피해·경직은 없다.
    - 밀림은 맞은 사람의 소유 클라이언트가 자기 컨트롤러로 수행한다(`PlayerPunchImpact` → 서버 거리 재확인 → 대상 소유자). 남의 transform 을 직접 옮기면 화면이 갈라진다.
    - 주먹은 `UpperBodyPunch` 마스크를 쓰는 `Punch` 레이어에서만 재생한다. 다리는 Base Layer 의 서기·걷기를 유지하므로 발이 들썩이지 않고 **걸으면서도 칠 수 있다**.
    - 남은 확인: 연타 시 세 동작이 끊김 없이 이어지는지, 걸으며 칠 때 하체가 자연스러운지, 2클라이언트에서 같은 순서로 보이는지, 밀림 세기가 적당한지.

19. **미니맵은 Tab을 누르는 동안만 표시**
   - 상태: **구현·컴파일 완료/MR 준비** (`S15P21A604-611` 후속).
   - `KeyDown` 토글을 제거하고 Tab 또는 WebGL 대체키 M을 누르는 동안만 열며, 키를 떼거나 표시 불가 상태가 되면 즉시 닫는다.

20. **기본 추적 카메라 시점 상향**
    - 상태: **수정·컴파일 완료/플레이 검증 대기**.
    - 시선 높이를 최대 줌아웃 14.4 → 17.4(어깨), 최대 줌인 17.5 → 19.5 로 올렸다. 시선이 오르면 카메라 위치도 함께 올라 앞쪽 시야가 열린다.
    - 프리팹 직렬화 값이 스크립트 기본값을 덮으므로 둘 다 맞췄다.
    - 남은 확인: 줌 최대/최소와 실내 좁은 통로에서 화면 구도가 답답하지 않은지 육안 확인.
    - 캐릭터 정중앙을 보던 추적 기준점을 위로 올려 전방 시야를 확보하되 좁은 실내·벽 클리핑을 함께 확인한다.

24. **아바타가 목표 키의 76%로 렌더링되던 문제**
    - 상태: **완료 — 스폰 첫 프레임부터 22.4u** (2026-09-16).
    - 정착 타이머에 얹었던 보정이 스폰 직후 `ApplyEmote(None)` 의 `_regroundAt=0` 에 지워져 두 세션 연속 돌지 않았다. 타이머를 분리하고, 조립 직후 `Animator.Update(0)` 로 첫 포즈를 만들어 **같은 프레임에** 재도록 바꿔 작았다 커지는 구간을 없앴다. 부스 직원도 같은 방식.
    - 라이브 실측: 스폰 직후 첫 샘플부터 배율 13.84·키 22.7u. 외형 재조립을 강제해도 같은 프레임에 유지. 멀티는 각 클라이언트가 본인·원격 아바타마다 같은 경로로 맞춘다.

25. **옷을 바꾸면 그 옷의 고유 색으로 돌아가기** (사용자 지시 2026-09-16)
    - 상태: **구현·로비 Play 실측 완료**.
    - 색 설정이 카테고리 단위로 남아 새 옷에 이전 옷 색이 그대로 씌워지고 있었다. 옷 아이템이 바뀐 카테고리의 색 설정만 비워 재질 고유색으로 돌아가게 했다. 함께 입은 다른 옷의 색은 그대로다.
    - v0 외형(전체색 하나)은 조립기가 어떤 옷이든 그 색으로 덮으므로 먼저 v1 로 올려 카테고리 단위 비우기가 실제로 먹게 했다.
    - 실측: 상의 A1 빨강 → 다른 상의 선택 → 고유색, 하의 색 유지.
    - 라이브 실측: 플레이어 16.94u(1.28m) 대 안내데스크 NPC 20.75u(1.56m). 보정 호출 후 배율 10.55→13.96, 키 **22.38u(1.69m)** 확인.
    - 굽기 실패 시 다음 정착 시점에 재시도하도록 보강했다 — 한 번 실패로 76%에 영영 머무는 경로를 막았다.
    - 키 정규화가 스킨 메시의 **바인드포즈 bounds** 를 기준으로 삼아, 실제 선 자세는 목표 22.375u 의 76%인 17.06u(1.29m)로 나왔다.
    - 포즈가 잡힌 뒤 `BakeMesh` 로 다시 재서 배율을 고치는 보정을 플레이어와 부스 직원 양쪽에 넣었다. 실측 17.06 → 22.38u(1.69m).
    - 커진 몸에 맞춰 캡슐을 17.5/2.5 → 22.4/2.85(중심 11.2)로 다시 맞췄다.
    - 남은 확인: 실제 플레이에서 안내데스크·아케이드기·문 높이 대비 비율, 좁은 통로 통행, 직원 NPC 와 키가 맞는지.

## 작업 운영 기준

- 최신 develop의 `festa-unity/`만 game 동기화 브랜치로 가져와 game을 게임 파트 최신본으로 유지한다.
- Unity 작업은 최신 game에서 작업 브랜치를 만들고 원본 프로젝트 폴더에서 진행한다.
- 작업 브랜치는 먼저 game 대상 MR로 병합하고, game 파이프라인과 무관하게 최신 game에서 다음 작업을 계속한다.
- 배포 시 develop에서 별도 이식 브랜치를 만든 뒤 game의 완료된 작업 파일만 이슈 단위로 가져와 develop에 반영한다. game 브랜치 전체를 develop에 병합하지 않는다.
- 씬·프리팹·asset 변경은 Unity에서 수행하며 YAML을 직접 편집하지 않는다.
- 게임 파트 작업일지와 트러블슈팅은 각각 `docs/KHS/24_작업일지.md`, `docs/KHS/25_트러블슈팅.md`에만 기록한다.
- 사용자 소유의 `ProjectSettings/QualitySettings.asset` 변경과 미추적 QA 산출물은 작업 커밋에 포함하지 않는다.
