## 1. 지금 확정된 상태

- 정식 캐릭터 커스터마이징 화면은 **Unity `CharacterLobby`**다. React 오버레이로 교체하지 않는다.
- AI 채팅·상담·설문처럼 장문 한글 입력이 필요한 기능은 기존대로 React 오버레이를 사용한다. 이 결정은 아바타 화면에만 해당한다.
- Rukha93 모듈형 `fa` 외형의 파츠 선택, 아이템별 유효 색상, 자연스러운 무작위, 최초 추천/저장 외형 복원, 썸네일·팝업·레이아웃 개선은 Unity에서 완료됐다.
- 크롭 자켓의 몸통 누락과 하의 피부 관통을 포함한 대표 조합을 수정했고, 로비와 월드는 같은 `AvatarConfig`를 사용한다.
- 과거 `sk`/`rt` 외형은 읽기 호환만 유지한다. 신규 생성·저장 기준은 `fa|g=...|i=...|p=...|q=...|w=...`, 최대 **3800자**다.
- Unity UI/런타임 완료 커밋: `16c26d6`; 계약·QA 문서 동기화 커밋: `148f6e7`. 이 문서가 포함된 최신 `origin/game`을 최종 기준으로 사용한다.

### 2026-08-20 추가 확정

- **11층 월드 모델이 `11th-0820-size(0.8).skp`다** (씬 인스턴스 `11th-0820`). `localPosition (-5.125, 1.45, 94.0375)` / `localRotation (0,180,0)` / `localScale (12.5, 12.5, 12.5)`. 쉘 콜라이더는 자식 `ssafy-11th-room`에 비볼록 MeshCollider.
- ⚠️ **이 인스턴스에는 씬 레벨 보정이 들어 있다.** 엘리베이터 쪽을 다시 만들며 방이 짧아졌는데 사물함 패널은 제자리에 남아, 패널 두 줄을 방 끝벽으로 스냅했다(먼 줄 −25.77, 가까운 줄 +23.86). **모델 재임포트나 인스턴스 재생성 시 사라진다** — 복구 절차는 T-151, 근본 수정은 SketchUp 재익스포트.
- **모델 교체 시 정렬 기준은 방 쉘이다.** 랜드마크 정렬은 크기만 다를 때만 유효하다. 방 치수를 축별로 비교해 0.8배가 아닌 축이 있으면 형상이 바뀐 것이다 (T-149, T-151).
- 스폰은 `ConnectionManager.GetSpawnPosition`의 코드 상수 `(-75, 0, -235)`다. **모델 배치가 곧 스폰 위치**이므로 월드를 교체할 때마다 바닥 높이 `y=0.082`를 레이캐스트로 재확인한다 (T-149).
- 콜라이더는 **루트 `11th` 자체**에 비볼록 MeshCollider로 붙어 있다 (구 모델은 자식 `Mesh1318`이었다).
- **에셋 정리 완료.** `Assets/` 469MB → 278.8MB, 최상위는 `_Project/`와 `Plugins/` 둘뿐이다. `Art/Avatar/Rukha93` → `Art/Avatar/ModularCharacter`로 벤더명을 걷고, URP·Input·NetworkPrefabs는 `_Project/Settings/` 아래로 모았다.
- **미사용 판정은 GUID 검색으로 하지 않는다.** `Resources/` 경로 로드, `Shader.Find` 이름 로드, ProjectSettings 참조, 모델 파일에 임베드된 머티리얼→텍스처는 GUID로 보이지 않는다. `AssetDatabase.GetDependencies`로 판정한다 (T-150).
- `Assets/Plugins/WebGL/FestaUnityBridge.jslib`는 Unity 규약 폴더라 옮기지 않는다.
- **spec 위치는 루트 `specs/`다** (develop 규약). `docs/specs/`는 제거됐다.
- **spec 005 좌표 왕복 검증 통과.** 실측 world 좌표가 기대표와 소수점까지 일치했고 FE 이정헌 + BE 황덕 서명이 완료됐다. `assetCode` 종단 검증도 통과했다.
- 기준 커밋: `1403a44` (develop 문서·규약 병합). 이 병합은 **문서만** 담았고 `festa-unity`는 한 파일도 바뀌지 않았다.

### P0-0. 지금 바로 착수 가능 (2026-08-20 기준)

## 3. 다른 PC에서 시작하는 절차

```powershell
git clone <원격 저장소 URL> ssafesta
Set-Location ssafesta
git switch game
git pull --ff-only origin game
git status --short
```

1. Unity Hub에서 `festa-unity`를 **Unity 6000.0.78f1**로 연다.
2. `Assets/_Project/Scenes/CharacterLobby.unity`를 열고 컴파일 완료를 기다린다.
3. Unity MCP를 해당 Editor 인스턴스에 연결한다.
4. Play Mode에서 최초 추천 무작위, 저장된 `fa` 복원, 기본 의상 탭 `상의`, 색상 팝업 드래그를 확인한다.
5. Console error/warning 0건과 16:9 Game View 레이아웃을 확인한 뒤 다음 구현을 시작한다.

새 PC에서는 깨끗한 clone을 권장한다. 현재 작업 PC에만 남아 있는 vendor `.unitypackage.meta` 삭제와 `ProjectSettings` 변경은 아바타 작업 커밋에 포함되지 않았으므로 그대로 따라 커밋하지 않는다.

## 11층 모델 재export 요청 — SSAFY 글자 분리 (2026-08-20)

### 요청 내용

11층 SketchUp 모델을 다시 내보낼 때 **바닥에 서 있는 SSAFY 3D 글자를 별도 그룹**으로
분리해 달라고 요청한다. `walls, floor, ceiling` 을 그룹으로 나눠준 것과 같은 방식이다.

### 왜 필요한가

현재 글자는 독립 오브젝트가 아니라 `ssafy-11th-room` 노드의 **자체 병합 메시**
(8,052 verts, 서브메시 3개) 안에 있다. 두 단계로 확인했다.

1. 그 렌더러만 끄면 글자만 사라지고 벽·바닥·부스·현판은 그대로다.
2. 서브메시 2(`ssafy_blue`)만 다른 색으로 칠하면 글자가 칠해진다.

그런데 **서브메시 2 에는 글자만 있는 게 아니다.** 파란 안내 데스크
("함께가요 미래로!", x≈-140 / z≈-190)도 같은 슬롯이다. 같은 브랜드 색이라
하나로 병합됐다. 그래서 오브젝트 단위도, 재질 단위도 글자만 분리할 수 없다.

Unity 에서 메시를 잘라내는 것도 가능하지만 `Read/Write Enabled` 활성화 =
재임포트가 필요하고, T-157 의 한글 이름 메시 중복(`Mesh 함께가요 미래로!`) 때문에
참조 재연결이 보장되지 않는다. 게다가 모델을 다시 받을 때마다 반복해야 한다.

### 같이 요청하면 좋은 것

- **메시 이름을 영문으로** — 현재 `함께가요 미래로!` 등 한글 이름이 중복돼
  임포트마다 `Identifier uniqueness violation` 경고가 난다 (T-157).
- 천장 높이 — 원본에서 천장이 벽 상단보다 66단위 위에 떠 있다. Unity 에서
  정렬해 쓰고 있지만 원본이 맞으면 그 단계가 없어진다.

### 새 모델을 받은 뒤 할 일

**`Festa/World/천장 조명 셋업 다시 적용`** 메뉴 한 번 실행하면 끝난다
(`Assets/_Project/Scripts/Editor/WorldCeilingSetup.cs`).

재적용되는 것 — 모델 인스턴스에 걸린 오버라이드라 교체하면 날아간다:

| 항목 | 수량 |
|---|---|
| 머티리얼 슬롯 (라인조명·다운라이트·천장배경) | 109 |
| `MeshCollider` (`floor`, 벽 2장, 방 자체) | 4 |
| 천장 광원 재배치 (기구 bounds 기준) | Spot 90 + Point 9 |

재임포트와 무관해서 **다시 만들지 않는 것**:

- `WorldCeilingLights` 아래 광원 — 모델과 별개인 일반 씬 오브젝트
- `WorldCeiling{LightStrip,Downlight,Black}.mat` — 프로젝트 소유 애셋
- `RenderSettings`(환경광·sun 제거), `Mobile_RPAsset` 광원 한도
- `BoothSlot_*` 아래 부스 오브젝트

주의 — **천장 정렬은 재적용에서 분리해 뒀다** (`Festa/World/천장을 벽 상단에 맞춤`).
층고를 의도적으로 조정해 둔 경우 재적용이 덮어쓰면 안 되기 때문이다.

교체 후에는 `Festa/World/셋업 검증 (읽기 전용)` 으로 스폰 40/40 과 콜라이더 수를 확인한다.
모델 구조(노드 이름)가 바뀌면 이 도구의 이름 상수를 먼저 맞춰야 한다.

### 조명 색·세기를 바꿀 때

값은 **`WorldCeilingSetup.cs` 상단 상수**에 모여 있다. 씬에서 직접 고치면
도구를 다음에 실행할 때 되돌아가므로, **상수와 씬을 같이 바꾼다** (또는 상수만
고치고 도구를 실행한다 — 이쪽이 안전하다).

| 상수 | 현재 값 | 의미 |
|---|---|---|
| `SpotColor` | `(1, 0.945, 0.855)` | 다운라이트 색. 살짝 웜 |
| `FillColor` | `(1, 0.955, 0.885)` | 타일 채움광 색 |
| `AmbientColor` | `(0.215, 0.208, 0.198)` | 환경광. **광원과 같은 색 방향이어야 한다** |
| `SpotIntensity` / `FillIntensity` | 420 / 260 | 1 m = 10 unit 스케일 보정값 (T-160) |
| `SpotRange` / `FillRange` | 120 / 160 | 천장~바닥 49.5 unit 을 덮는 값 |

주의 두 가지:

1. **환경광 색 방향을 광원과 맞춰라.** 쿨한 환경광(B > R)은 웜톤 광원을 상쇄한다.
   실제로 처음 웜톤 작업 때 환경광이 `(0.20, 0.21, 0.24)` 로 쿨이라 효과가 반감됐다.
2. **조명면 머티리얼도 같이 바꿔라** — `WorldCeiling{LightStrip,Downlight}.mat` 의
   base color. 기구 자체가 웜 화이트로 보여야 바닥에 떨어지는 빛과 일관된다.
   이 둘은 애셋이라 도구가 건드리지 않는다.
