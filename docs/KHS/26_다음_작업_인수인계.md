### ASC — 로컬 작업 통제 체계 도입 (2026-08-21)

**`.asc/` 는 Git 에 올리지 않는다** (`.gitignore`). 세션 상태는 팀 산출물이 아니다.
기존 `Spec → 구현 → 검증 → Issue/PR` 흐름을 **바꾸지 않고**, 그 위에서 **세션 간 인수인계**와
**GitHub 요청 감지**만 따로 관리한다.

| 경로 | 용도 |
|---|---|
| `.asc/README.md` | 체계 설명·원칙. 여기부터 읽는다 |
| `.asc/controller/queue.md` | 다음 작업 큐. **우선순위는 사람이 정한다** |
| `.asc/execution/sessions/<id>/` | 세션별 `goal.md`·`scope.md`·`handoff.md` |
| `.asc/monitoring/inbox/` | 승인 대기 초안 + `.seen.json` |
| `.asc/verify/` | 검증 세션 결과 (구현 세션과 분리) |

**원칙 — AI 에는 조사·구현·검증·초안을 맡기고, 무엇을 할지 정하는 권한과 팀에 발언·반영하는 권한은 사람이 갖는다.**

## 11층 모델 재export 요청 — SSAFY 글자 분리 (2026-08-20)

### 요청 내용

11층 SketchUp 모델을 다시 내보낼 때 **바닥에 서 있는 SSAFY 3D 글자를 별도 그룹**으로
분리해 달라고 요청한다. `walls, floor, ceiling` 을 그룹으로 나눠준 것과 같은 방식이다.

### 왜 필요한가

현재 글자는 독립 오브젝트가 아니라 `ssafy-11th-room` 노드의 **자체 병합 메시**
(8,052 verts, 서브메시 3개) 안에 있다. 두 단계로 확인했다.

1. 그 렌더러만 끄면 글자만 사라지고 벽·바닥·부스·현판은 그대로다.
2. 서브메시 2(`ssafy_blue`)만 다른 색으로 칠하면 글자가 칠해진다.

그런데 **서브메시 2 에는 글자만 있는 게 아니다.** 파란 안내 데스크
("함께가요 미래로!", x≈-140 / z≈-190)도 같은 슬롯이다. 같은 브랜드 색이라
하나로 병합됐다. 그래서 오브젝트 단위도, 재질 단위도 글자만 분리할 수 없다.

Unity 에서 메시를 잘라내는 것도 가능하지만 `Read/Write Enabled` 활성화 =
재임포트가 필요하고, T-157 의 한글 이름 메시 중복(`Mesh 함께가요 미래로!`) 때문에
참조 재연결이 보장되지 않는다. 게다가 모델을 다시 받을 때마다 반복해야 한다.

### 같이 요청하면 좋은 것

- **메시 이름을 영문으로** — 현재 `함께가요 미래로!` 등 한글 이름이 중복돼
  임포트마다 `Identifier uniqueness violation` 경고가 난다 (T-157).
- 천장 높이 — 원본에서 천장이 벽 상단보다 66단위 위에 떠 있다. Unity 에서
  정렬해 쓰고 있지만 원본이 맞으면 그 단계가 없어진다.

### 새 모델을 받은 뒤 할 일

**`Festa/World/천장 조명 셋업 다시 적용`** 메뉴 한 번 실행하면 끝난다
(`Assets/_Project/Scripts/Editor/WorldCeilingSetup.cs`).

재적용되는 것 — 모델 인스턴스에 걸린 오버라이드라 교체하면 날아간다:

| 항목 | 수량 |
|---|---|
| 머티리얼 슬롯 (라인조명·다운라이트·천장배경) | 109 |
| ~~콜라이더~~ → **임포트 시 애셋 내장으로 이관 (2026-08-21)** — Mesh 20 / Capsule 3, `WorldModelNaming.AddColliders`. 재적용 불필요 | 23 |
| 벽 개구부 봉쇄 — 엘리베이터 문 (좌표를 박지 않고 훑어서 탐지) | 3 |
| 천장 광원 재배치 (기구 bounds 기준) | Spot 90 + Point 9 |

재임포트와 무관해서 **다시 만들지 않는 것**:

- `WorldCeilingLights` 아래 광원 — 모델과 별개인 일반 씬 오브젝트
- `WorldCeiling{LightStrip,Downlight,Black}.mat` — 프로젝트 소유 애셋
- `RenderSettings`(환경광·sun 제거), `Mobile_RPAsset` 광원 한도
- `BoothSlot_*` 아래 부스 오브젝트
- `@WorldCollisionSeals` 아래 봉쇄 박스 — 모델 밖 독립 오브젝트 (다만 도구가 매번 재생성한다)

주의 — **천장 정렬은 재적용에서 분리해 뒀다** (`Festa/World/천장을 벽 상단에 맞춤`).
층고를 의도적으로 조정해 둔 경우 재적용이 덮어쓰면 안 되기 때문이다.

교체 후에는 `Festa/World/셋업 검증 (읽기 전용)` 으로 스폰 40/40 과 콜라이더 수를 확인한다.
모델 구조(노드 이름)가 바뀌면 이 도구의 이름 상수를 먼저 맞춰야 한다.

### 조명 색·세기를 바꿀 때

값은 **`WorldCeilingSetup.cs` 상단 상수**에 모여 있다. 씬에서 직접 고치면
도구를 다음에 실행할 때 되돌아가므로, **상수와 씬을 같이 바꾼다** (또는 상수만
고치고 도구를 실행한다 — 이쪽이 안전하다).

| 상수 | 현재 값 | 의미 |
|---|---|---|
| `SpotColor` | `(1, 0.945, 0.855)` | 다운라이트 색. 살짝 웜 |
| `FillColor` | `(1, 0.955, 0.885)` | 타일 채움광 색 |
| `AmbientColor` | `(0.215, 0.208, 0.198)` | 환경광. **광원과 같은 색 방향이어야 한다** |
| `SpotIntensity` / `FillIntensity` | 420 / 260 | 1 m = 10 unit 스케일 보정값 (T-160) |
| `SpotRange` / `FillRange` | 120 / 160 | 천장~바닥 49.5 unit 을 덮는 값 |

주의 두 가지:

1. **환경광 색 방향을 광원과 맞춰라.** 쿨한 환경광(B > R)은 웜톤 광원을 상쇄한다.
   실제로 처음 웜톤 작업 때 환경광이 `(0.20, 0.21, 0.24)` 로 쿨이라 효과가 반감됐다.
2. **조명면 머티리얼도 같이 바꿔라** — `WorldCeiling{LightStrip,Downlight}.mat` 의
   base color. 기구 자체가 웜 화이트로 보여야 바닥에 떨어지는 빛과 일관된다.
   이 둘은 애셋이라 도구가 건드리지 않는다.
