## 2. 명세에는 있는데 코드에 없거나 어긋나는 것

### 2.1 T029A가 최신 결정과 정면 충돌

`tasks.md`의 T029A는 여전히 `[ ]`이고 내용은 "demo vhost에 `${ROOT_DOMAIN}` alias를 붙여라"다.
그런데 C-15와 T055가 그 alias를 **제거**하기로 확정했고 코드도 제거했다.
→ **삭제하거나 superseded 표시 필요.**

### 2.2 상태 전이 순서가 README와 pipeline에서 다르다

`infra/deploy/state/README.md`:

```
RUNNING_UNVERIFIED -> VERIFIED -> MAINTENANCE_ACTIVE -> PUBLIC_ACTIVE/CURRENT
```

실제 `production-promotion.groovy`:

```
MAINTENANCE_ACTIVE -> RUNNING_UNVERIFIED -> VERIFIED -> CURRENT
```

`prepare-production-cutover.sh` 주석도 "검증된 candidate의 cutover 준비"라고 쓰였지만
실제로는 candidate 생성·검증 **전에** 실행된다.

### 2.3 maintenance fence가 World를 막지 않는다

명세는 "public 전환 전 maintenance fence"라고 한다.
그러나 `prepare-production-cutover.sh`는 `prod.conf`만 503으로 바꾸고
`world-prod.conf`는 건드리지 않는다. 이어 candidate World가 같은 `27777`에 기동된다.

→ 기존 `world-prod.conf`가 활성 상태면 **candidate World가 검증·activation 전에
공개 WSS로 노출될 수 있다.** `publicCutoverPerformed=false` 계약과 어긋난다.

### 2.4 Production env 파일의 DB 대상이 검증되지 않는다

compose는 `BACK_ENV_FILE`, `AI_ENV_FILE`을 그대로 읽고, 배포는 파일 존재만 확인한다.
env 파일 안 `POSTGRES_DB`, `POSTGRES_USER`, `REDIS_USERNAME` 값은 **검사하지 않는다.**

→ bootstrap evidence가 정상이어도 Jenkins credential이 Demo DB를 가리키면
**Production 컨테이너가 Demo 데이터에 붙는다.** 저장소만으로는 실제 대상 확인 불가.

### 2.5 핵심 사용자 여정 검증을 실제로 안 한다

명세: 웹 접속 → 로그인 → 월드 입장 → AI 응답 전체가 성공 조건.

실제 `verify-production-public.sh`:

- `/`, `/api/`, OAuth 경로가 **`2xx/3xx/4xx`면 통과**
- AI health endpoint
- WebGL manifest sourceCommit
- World WSS Upgrade 101

로그인 완료, 인증 callback 성공, World entry token 발급, 실제 AI 응답은 **실행하지 않는다.**
`4xx`도 성공이라 `/api/`가 없어도 통과한다.

### 2.6 squash 금지가 자동 pre-merge gate가 아니다

`check-promotion-mr-gate.sh`가 `mr.squash`를 검사하지만 **자동 호출자가 없다.**
`.gitlab-ci.yml`의 main MR `mr-status`는 secret scan만 한다.

현재 자동 보장은 **merge 후 ancestry 거부** 하나뿐이다.
merge 전 squash를 실제로 막는 건 사람이 스크립트를 직접 돌리는 것에 의존한다.

### 2.7 Production receipt를 만드는 코드가 없다

pipeline은 `receipts/<id>.json`이 **이미 있어야** 시작한다.
`APPROVED_FOR_PRODUCTION` receipt를 생성해 그 위치에 쓰는 운영 스크립트는
저장소에서 발견되지 않았다. schema·validator·test fixture만 있다.
→ receipt 생성·승인·배치 절차는 **확인 불가**.

### 2.8 bootstrap이 pipeline에 연결돼 있지 않다

pipeline은 `bootstrap.json`이 READY인지 검사만 하고 `bootstrap-production-data.sh`를
호출하지 않는다. 그 스크립트가 요구하는 비밀번호 4종도 Jenkins credential binding에 없다.
→ 1회 수동 선행 작업이라면 **runbook과 실행 주체가 문서에 없다.**

### 2.9 승인 권한 분리 미구현

두 `input` gate는 승인자 **이름만 기록**하고 허용 submitter를 제한하지 않는다.
T031G도 `[ ]`다. "사람 승인"은 구현됐지만 "권한 있는 사람만 승인"은 아니다.

### 2.10 AI 전용 pgvector 계약 위반

infra-002는 "AI database에만 vector extension"을 반복 명시한다.
그러나 `bootstrap-production-data.sh`는 `festa_prod_business`와 `festa_prod_ai` **양쪽에서**
`CREATE EXTENSION IF NOT EXISTS vector;`를 실행한다.
→ 예외라면 명세가 없고, 예외가 아니라면 코드 오류다.

### 2.11 plan 내부 자기모순

- `plan.md:9`: develop merge 후 demo 자동 배포
- `plan.md:24`: "일반 develop push는 demo 자동 배포 금지"
- 코드: `FESTA_DEPLOY_ENVIRONMENT=demo` (자동 배포함)

`plan.md:24`가 잔존 문구다.

### 2.12 "무중단 승격" 표현이 실제와 다르다

`spec.md:35`는 "무중단"이라고 하지만 실제는 root 도메인 전체에 의도적으로 503을 걸고
같은 포트에서 컨테이너를 교체한다. 최신 correction이 코드와 맞으므로 앞부분이 낡았다.

### 2.13 MR 단위가 아니라 push range 단위다

`spec.md`는 한 MR 단위 atomic batch처럼 설명하지만, 실제 판정 단위는
