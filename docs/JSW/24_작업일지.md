### PostgreSQL R2 백업 서명 실패 원인 확정·수정 (S15P21A604-226)

- 🤖 원인은 자격증명이 아니라 AWS CLI 의 기본 trailer checksum 이었다. 2.23 부터 업로드에 CRC32 체크섬을 기본으로 붙이면서 요청이 `aws-chunked` + `STREAMING-UNSIGNED-PAYLOAD-TRAILER` 로 나가고, R2 가 그 서명을 `SignatureDoesNotMatch` 로 거절했다.
- 🤖 `backup_init` 의 AWS config 에 `request_checksum_calculation = when_required` 와 `response_checksum_validation = when_required` 를 추가했다. backup·restore 가 같은 초기화를 쓰므로 한 곳 수정으로 양쪽에 적용된다.
- 🧪 판별 근거 — 같은 endpoint·bucket·path-style 설정에서 reader·writer 두 credential 로 `head-bucket` 을 실행해 둘 다 성공(`"BucketRegion": "APAC"`)했다. credential 형식도 Access Key ID 32자 hex·Secret 64자 hex·비-hex 0개로 정상이었다. 본문이 있는 `put-object` 만 실패한다는 것이 확인되면서 요청 형태로 범위가 좁혀졌다.
- 🧪 Cloudflare 대시보드 실측으로 버킷 `festa-postgres-backups` 존재와 `festa-postgres-backup-writer` 토큰의 scope·Object Read & Write·Active 를 재확인했다. 이름·scope 가설은 여기서 완전히 배제됐다.
- ✅ merge 후 `festa-postgres-backup` `#11`(`dev`/`manual-test`)이 `Finished: SUCCESS` 로 끝나 실제 R2 업로드 해소를 확인했다. `dump.sh` 는 `set -euo pipefail` 아래에서 데이터베이스별 dump 와 manifest 를 각각 `put-object` 하므로 종료 코드 0 은 모든 업로드 성공을 뜻한다. 09-13 이후 처음으로 백업본이 생성됐다. T057 document inventory 대조와 T058 retention 은 후속으로 남는다.
- ⚠️ 진단용 Replay 빌드 `#9` 콘솔에 writer Access Key ID 가 평문으로 남았다. Jenkins 는 credential username 을 마스킹하지 않는다. 해당 빌드 로그를 삭제하고, 이후 진단은 값을 인자로 넘기지 않고 환경변수로만 쓴다.

### 긴급 규약 — 파트 브랜치 대상 MR 은 `mr-status` 만으로 통과시킨다 (S15P21A604-185)

- **배경**: develop 머지 슬롯이 동시 2개뿐이라 파트마다 한 건씩 줄 서는 것이 병목이 됐다. 각 파트가 자기 브랜치(`ai`·`back`·`front`·`game`)에 작업을 모아 둔 뒤 한 번에 develop 으로 올리는 방식으로 전환하기로 했고, 그 중간 병합을 MR 로 하려니 `Pipelines must succeed` 머지 체크에서 막혔다.
- **왜 설정으로 못 푸는가**: GitLab 의 `Pipelines must succeed` 는 프로젝트 전체 스위치다. target 브랜치별로 나눌 수 없어 끄면 `develop`·`main` 보호까지 같이 풀린다. 보호 브랜치는 이 둘뿐이고 파트 브랜치는 애초에 무보호라, push 는 되지만 MR 을 열면 머지 체크가 걸린다.
- **조치**: `.gitlab-ci.yml` 의 `workflow.rules` 에 파트 브랜치 target MR 규칙을 추가해 파이프라인이 생성되게 했다. 동시에 `.{ai,back,front,game}-changes` 네 anchor 에 `TARGET != develop → when: never` 가드를 넣어 컴포넌트 CI 와 Unity dispatch 는 develop 대상에서만 돌게 했다. 결과적으로 파트 브랜치 MR 은 `mr-status` 하나(=`secret-scan`)만 돌고 30초 내 성공한다.
- **적용 조건 (놓치기 쉬움)**: MR 파이프라인은 **소스 브랜치의** `.gitlab-ci.yml` 을 읽는다. 이 변경이 develop 에 병합된 뒤에도, 이미 열려 있는 브랜치는 develop 을 한 번 받아와야(`git merge origin/develop` 또는 rebase) 파이프라인이 생긴다. 이걸 모르면 "고쳤다는데 왜 그대로냐"가 된다.
- **대가**: 파트 브랜치 구간의 코드 검증이 0회다. 해당 파트의 develop MR 이 그 덩어리의 첫 검증이 되고, 실패 시 어느 작업이 원인인지 좁히기 어렵다. 브랜치를 오래 끌수록 비용이 커지므로 파트 브랜치를 자주 develop 에서 rebase 하는 편이 낫다.
- **해제 조건**: ① 러너 동시 실행 한도가 늘어 develop 직행이 감당되거나 ② 파트 브랜치 배칭을 끝내면, `workflow.rules` 의 파트 브랜치 규칙과 네 anchor 의 target 가드를 **함께** 지운다. 한쪽만 지우면 파트 브랜치 MR 에서 전체 CI 가 돌거나(①만 지움) 파이프라인이 다시 안 생긴다(②만 지움).
- **부수 정리**: `workflow.rules` 말미의 `$CI_COMMIT_BRANCH` 규칙 두 개는 앞선 무조건 `when: never` 뒤에 있어 도달 불가한 죽은 코드였다. "브랜치에 push 하면 CI 가 돈다"는 오해를 만들던 원인이라 함께 제거했다.
- 📎 관련 경로: `.gitlab-ci.yml`

### S15P21A604-185 Jenkins JCasC projectMatrix 전환으로 Job-level 권한 유효화

- **증상**: Game MR(!858)의 `unity-mr-validation-dispatch` 잡이 Jenkins HTTP 403으로 실패하며 merge가 차단됐다.
- **원인**: `infra/jenkins/casc/authorization.yaml`의 `authorizationStrategy`가 `globalMatrix`로 선언되어 있어, Job DSL에서 선언한 `unity-mr-validator`의 Job 단위 Item.Read/Item.Build 권한이 무시되고 전역(Discover만 존재)으로 판정됐다.
- **해결**: `globalMatrix`를 `projectMatrix`(`ProjectMatrixAuthorizationStrategy`)로 전환했다. 전역 권한을 확대하지 않고 최소권한 원칙을 유지한 채 Job 단위 권한이 정상 평가된다. `test-foundation.sh` 정적 검사도 함께 갱신했다.

### S15P21A604-185 GitLab Jenkins queue polling 취소 오탐 수정

- **증상**: `unity-mr-validation-dispatch`에서 Jenkins build 요청(201)은 성공했으나, 큐 폴링 도중 `In the quiet period. Expires in 4.8 sec` 에러 메시지와 함께 exit code 1로 실패했다.
- **원인**: Jenkins Queue 대기 아이템(WaitingItem) API는 미취소 상태일 때 `cancelled` 필드를 생략한다. `.gitlab-ci.yml`의 `jq -r '.cancelled'`가 `null`을 반환해 `test "null" = false` 조건이 거짓으로 판정되어 큐가 취소된 것으로 오탐했다.
- **해결**: `.gitlab-ci.yml`에서 `.cancelled // false`로 null을 기본 false 처리하도록 수정했다. 또한 `festa-unity-mr-validation`에 `quietPeriod(0)`을 추가해 불필요한 5초 대기 없이 즉시 빌드가 큐에서 실행 단계로 전이되도록 했다.

### S15P21A604-185 Unity MR 검증 Groovy pipeline syntax 탈출 수정

- **증상**: Jenkins에서 `festa-unity-mr-validation` 빌드가 `WorkflowScript: 24: illegal string body character after dollar sign; sh "test "$(git rev-parse HEAD)" = ..."` 컴파일 에러로 즉시 실패했다.
- **원인**: Groovy의 큰따옴표 문자열(GString) 내에서 `$(...)`가 변수 보간 문법으로 해석되려다 컴파일 에러가 발생했다.
- **해결**: `\$(git rev-parse HEAD)`로 달러 기호를 이스케이프하여 정상적인 셸 명령 치환이 수행되도록 수정했다.

### S15P21A604-185 Unity MR 검증 repositoryUrl fallback 보완

- **증상**: Jenkins `festa-unity-mr-validation` 빌드 #6에서 `ERROR: Error fetching remote repo 'origin'`으로 실패했다.
