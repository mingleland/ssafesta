- 🤖 새 인프라 다이어그램과 `docs/15`, `docs/21`, `docs/22`, `docs/26`, `specs/infra-002-environments/spec.md`, Unity 배포 인수인계를 대조해 기존 ALB·ACM·Route53 전제와 단일 EC2·Cloudflare 전제의 충돌 범위를 확인
- 🤖 현재 보유 자원(AWS IAM 없음, 단일 EC2)에는 `Cloudflare Proxy → EC2 Nginx → 내부 컨테이너` 구조를 채택하고 ALB는 후속 관리형 이관 대상으로 두는 권고안을 도출
- 🤖 외부 TLS는 Cloudflare Edge에서, 원본 구간 TLS는 Nginx에서 각각 종료하며 Cloudflare `Full (strict)`와 Nginx의 Let’s Encrypt 인증서를 사용하는 이중 TLS 경계를 정리
- 🤖 demo 도메인은 동일 등록 도메인 아래 `demo`·`api`·`ai`·`world` 호스트로 분리하고, 현재 `world.<domain>`은 단일 Unity 서버에 연결하는 방향을 확정
- 🤖 외부 `wss://world.<domain>:443` 요청을 Nginx가 내부 `ws://Unity:7777`로 전달하므로 Cloudflare의 7777 포트 제한을 회피함을 확인
- 🤖 WSS·Refresh Cookie·SSE는 설계상 차단이 해소됐지만 실제 배포 후 실측 검증은 별도로 필요함을 확인
