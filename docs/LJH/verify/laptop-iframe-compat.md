# 부스 노트북 iframe 호환성 — 수동 검증 체크리스트 (S15P21A604-946)

자동화로 가릴 수 없는 것만 여기서 본다. 단위 테스트는 `sandbox`·`allow` 토큰이 DOM 에 실리는지
까지만 단언하고, **그 토큰이 실제 브라우저에서 무엇을 풀어 주는지**는 손으로 확인한다.

## 이번 변경이 약속하는 것 / 약속하지 않는 것

약속 — 프레임이 연 팝업이 부모 sandbox 를 상속해서 깨지던 OAuth/SSO 흐름을 개선한다.

약속하지 않음 — 외부 서비스 자체 정책, third-party cookie·파티션 스토리지 제한, IdP 정책으로
실패하는 경우. 그리고 상대가 `X-Frame-Options`·CSP `frame-ancestors` 로 embedding 을 명시
차단한 경우. **차단되는 것이 정상 결과**이고 우회하지 않는다.

## 준비

부스 관리 → 외부 링크에서 홈페이지 주소를 바꿔 가며 노트북(F)으로 진입한다.
관찰 대상은 오버레이 본문과 브라우저 콘솔 두 곳이다.

## 표본 5건

| # | 주소 성격 | 기대 |
|---|---|---|
| 1 | 팝업 OAuth 로 로그인되는 https 사이트 | 프레임 안에서 로그인 버튼 → 팝업이 **정상 창**으로 뜨고 IdP 이동·콜백이 끝난다. 로그인 상태가 프레임에 반영되면 통과 |
| 2 | `X-Frame-Options: DENY` 인 https 사이트 | 프레임이 비고 콘솔에 차단 로그. **이것이 정상** — 하단 안내대로 새 탭에서 열리면 통과 |
| 3 | http 사이트 | iframe 을 아예 걸지 않고 "이 주소는 창 안에서 열 수 없습니다 / http 로 시작하는 주소라…" 안내. 새 탭 버튼으로 열리면 통과 |
| 4 | SSAFESTA 자신의 오리진 | 같은 안내 + "축제장 자신을 가리키는 주소입니다". 프레임이 **없어야** 통과 |
| 5 | 일반 정적 https 사이트 | 프레임 안에 정상 표시. 전체화면 버튼이 있으면 동작하면 통과 |

## 함께 봐 둘 것 — 나중에 좁아질 수 있는 자리

`infra/environments/nginx/snippets/security.conf` 에 `Permissions-Policy: camera=(), microphone=(),
geolocation=()` 가 들어 있다. **지금은 어느 site 설정에서도 include 되지 않아 배포에 나가지 않지만**,
나중에 배선되면 그 헤더가 최상위 문서의 allowlist 를 먼저 닫으므로 iframe 에 위임할 수 있는 범위도
함께 줄어든다. 이번 변경이 위임하는 다섯 가지(`autoplay`·`clipboard-write`·`fullscreen`·
`encrypted-media`·`picture-in-picture`)는 그 목록과 겹치지 않아 당장은 영향이 없다.
