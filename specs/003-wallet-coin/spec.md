# Feature Specification: Coin 지갑 / 원장

**Spec**: `003-wallet-coin`
**Created**: 2026-08-12
**Status**: Draft — **BE 검토 대기**
**주 담당**: Backend (Spring)
**선행 spec**: 001
**근거 문서**: docs/02 §2.10(ECON-01~04), `.specify/memory/constitution.md` Article IV-20

> 이 spec은 **경제의 무결성**이 전부다. 잔액이 원장과 어긋나거나 중복 지급이 생기면
> 임대·보상·미니게임이 전부 신뢰를 잃는다. 기능 자체는 단순하지만 **정확성 요구가 가장 높은 spec**이다.

## User Scenarios & Testing

### User Story 1 — 코인을 받고 쓴다 (Priority: P0)

사용자가 가입 시 초기 코인을 받고, 매일 지급을 받고, 부스 임대에 사용한다.

**Why this priority**: 004(임대)·007~008(AI 이용)·014(미니게임 보상)가 전부 여기에 의존한다.

**Independent Test**: 가입 → 초기 코인 확인 → 임대로 차감 → 잔액과 거래 내역이 일치.

**Acceptance Scenarios**:

1. **Given** 신규 사용자, **When** 계정이 생성되면, **Then** 정책상 초기 코인이 지급되고 원장에 기록된다.
2. **Given** 로그인한 사용자, **When** 잔액을 조회하면, **Then** 현재 잔액을 확인할 수 있다.
3. **Given** 오늘 아직 일일 지급을 받지 않은 사용자, **When** 조건을 충족하면, **Then** 일일 코인이 **하루 한 번만** 지급된다.
4. **Given** 잔액이 충분한 사용자, **When** 코인을 사용하는 기능을 실행하면, **Then** 잔액이 줄고 원장에 차감이 기록된다.
5. **Given** 잔액이 부족한 사용자, **When** 코인을 사용하려 하면, **Then** 실행이 거부되고 사유가 안내된다.

### User Story 2 — 같은 요청이 두 번 와도 한 번만 처리된다 (Priority: P0)

**Why this priority**: 네트워크 재시도·더블클릭은 반드시 일어난다. 이걸 막지 못하면 코인이 새거나 이중 차감된다.

**Independent Test**: 동일한 차감 요청을 연속 2회 전송 → 잔액이 한 번만 변한다.

**Acceptance Scenarios**:

1. **Given** 차감 요청이 처리된 상태, **When** 동일 요청이 다시 도착하면, **Then** 잔액이 추가로 변하지 않는다.
2. **Given** 동시에 도착한 두 차감 요청, **When** 잔액이 한 건에만 충분하면, **Then** 하나만 성공하고 다른 하나는 거부된다.

### User Story 3 — 거래 내역을 본다 (Priority: P1)

**Acceptance Scenarios**:

1. **Given** 거래가 있는 사용자, **When** 내역을 조회하면, **Then** 지급·차감이 시각과 사유와 함께 보인다.
2. **Given** 내역이 많은 사용자, **When** 조회하면, **Then** 페이지 단위로 나뉘어 제공된다.

### Edge Cases

- **잔액과 원장 합계가 어긋나는 경우** → 즉시 감지할 수 있어야 한다 (정합성 점검 수단 필요)
- 지급 도중 서버가 죽은 경우 → 절반만 반영된 상태가 남으면 안 된다
- 게스트 사용자의 코인 [NEEDS CLARIFICATION: 게스트에게 코인을 주는가 — **권장: 주지 않는다** (헌법 12조)]
- 관리자 수동 조정이 필요한 경우 → 원장에 남아야 한다
- 일일 지급의 "하루" 기준 시각 [NEEDS CLARIFICATION: 자정 기준인가 24시간 기준인가]

## Requirements

### Functional Requirements

- **FR-001**: 사용자는 자신의 현재 코인 잔액을 조회할 수 있어야 한다.
- **FR-002**: 신규 계정 생성 시 정책상 초기 코인이 지급되어야 한다.
- **FR-003**: 일일 지급은 **하루 한 번만** 이루어져야 한다.
- **FR-004**: 모든 지급·차감은 **원장(Ledger)에 기록**되어야 한다 (헌법 20조).
- **FR-005**: 원장 항목은 유형(충전/사용/보상/환불)과 사유를 가져야 한다.
- **FR-006**: 잔액은 원장과 **항상 일치**해야 한다.
- **FR-007**: 동일한 요청이 여러 번 도착해도 **한 번만 반영**되어야 한다 (멱등성).
- **FR-008**: 동시에 도착한 차감 요청이 잔액을 음수로 만들어서는 안 된다.
- **FR-009**: 잔액 부족 시 명확한 사유와 함께 거부되어야 한다.
- **FR-010**: 코인 변경은 **REST/DB 트랜잭션으로만** 이루어져야 한다 — 실시간 이벤트로 잔액을 바꾸지 않는다 (헌법 20조).
- **FR-011**: 게임 서버(Unity)가 코인을 직접 변경할 수 없어야 한다 (헌법 2조).
- **FR-012**: 사용자는 자신의 거래 내역을 조회할 수 있어야 한다.
- **FR-013**: 관리자 조정도 원장에 기록되어야 한다.

### Key Entities

- **Wallet**: 사용자의 지갑. 소유자, 현재 잔액, 갱신 시각
- **Ledger Entry**: 원장 항목. 소유자, 유형(CHARGE/SPEND/REWARD/REFUND), 금액, 사유, 참조(임대·게임 등), 멱등성 키, 발생 시각

## Success Criteria

- **SC-001**: 임의 시점에 모든 사용자의 잔액이 원장 합계와 일치한다 (불일치 0건).
- **SC-002**: 동일 요청 2회 전송 시 잔액이 한 번만 변한다 (중복 반영 0건).
- **SC-003**: 동시 차감 요청에서 잔액이 음수가 된 사례가 0건이다.
- **SC-004**: 일일 지급이 하루에 두 번 이루어진 사례가 0건이다.
- **SC-005**: 사용자가 자신의 코인이 왜 늘고 줄었는지 내역만 보고 이해할 수 있다.
