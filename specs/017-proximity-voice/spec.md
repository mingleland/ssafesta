## User Scenarios & Testing

### User Story 1 — 가까이 가면 목소리가 들린다 (Priority: P1)

같은 층에 있는 사용자끼리, 가까울수록 크게 멀수록 작게 서로의 목소리가 들린다.

**Why this priority**: 부스 상담·팀 모집처럼 "말로 하는 게 빠른" 상황에서 텍스트보다 훨씬 자연스럽다.
다만 1차 MVP의 핵심 흐름(제작→공개→AI 상담)에는 없어도 되므로 P1.

**Independent Test**: 두 사용자가 멀리 떨어진 상태에서 말하면 안 들리고, 걸어서 가까워지면 점점 크게 들린다.

**Acceptance Scenarios**:

1. **Given** 두 사용자가 같은 월드에 접속, **When** 서로 가까이 있으면, **Then** 상대의 목소리가 들린다.
2. **Given** 두 사용자가 대화 중, **When** 한 사용자가 멀어지면, **Then** 목소리가 점점 작아지다가 일정 거리 밖에서는 들리지 않는다.
3. **Given** 마이크 권한을 허용하지 않은 사용자, **When** 월드를 이용하면, **Then** **듣기는 정상 동작**하고 말하기만 비활성화된다.
4. **Given** 음성 기능에 문제가 생긴 경우, **When** 사용자가 계속 플레이하면, **Then** 월드 접속·이동·AI 상담은 영향받지 않는다.

### User Story 2 — 내 마이크를 통제할 수 있다 (Priority: P1)

**Acceptance Scenarios**:

1. **Given** 음성 사용 중, **When** 음소거하면, **Then** 다른 사용자에게 내 소리가 전달되지 않는다.
2. **Given** 음성 사용 중, **When** 누가 말하고 있으면, **Then** 누가 말하는지 시각적으로 알 수 있다.
3. **Given** 처음 접속한 사용자, **When** 음성 기능을 켜면, **Then** 마이크 권한 요청이 발생하고 거부해도 월드는 정상 이용된다.

### Edge Cases

- 30~40명이 같은 공간에 있고 다수가 동시에 말하는 경우 → 서버 대역폭·클라이언트 믹싱 부하
- 부스 안과 밖의 소리가 벽을 통과하는 문제 [NEEDS CLARIFICATION: 벽 차폐를 구현하는가 — 거리만으로 충분한가]
- 층이 다른 사용자 (spec 018 이후) → 다른 층 소리는 들리지 않아야 함
- 브라우저 자동재생 정책으로 사용자 조작 전에는 소리가 재생되지 않음
- 이어폰 없이 스피커 사용 시 에코·하울링
- 악의적 사용(욕설·소음) → 신고·차단 수단 [NEEDS CLARIFICATION: MVP 범위 포함 여부]

## ⚠️ 기술 제약 — 설계 전 필독

**Unity Web(WebGL) 빌드는 마이크를 사용할 수 없다.** Unity의 `Microphone` 클래스는 WebGL 플랫폼에서 지원되지 않는다.
따라서 "Unity가 음성을 녹음해서 게임 서버로 보낸다"는 구조는 **애초에 성립하지 않는다.**

또한 게임 서버(NGO)로 음성을 실어 나르는 것도 피해야 한다:

- NGO는 상태 동기화용이지 실시간 미디어 전송용이 아니다
- 음성은 지속적 고대역폭 스트림이라 위치 동기화 대역폭을 잠식한다
- 헌법 2조(게임 서버는 실시간 월드 상태만) 취지에도 어긋난다

**따라서 권장 구조는 이렇다:**

```text
[브라우저 / React]                        [Unity]
마이크 캡처 (getUserMedia)      ←   음성을 다루지 않음
WebRTC로 음성 송수신 (SFU)          위치 정보만 브릿지로 전달
거리별 볼륨 계산·적용                     ↓
   ↑ ─────────── 각 플레이어 위치 ────────┘
```

- **음성 경로**: 브라우저 ↔ SFU 서버 (LiveKit / mediasoup 등). 게임 서버를 거치지 않는다
- **거리 계산**: Unity가 각 플레이어의 위치를 주기적으로 웹에 넘기고, 웹이 상대별 볼륨을 조절한다
- **Unity의 역할**: 위치 제공 + 말하는 사람 표시(선택). 그것뿐이다

이 구조는 헌법 17조(입력·미디어는 웹 레이어)와도 일치한다.

[NEEDS CLARIFICATION: SFU를 직접 호스팅할 것인가, 관리형 서비스를 쓸 것인가 — 비용·시간 트레이드오프]

## Requirements

### Functional Requirements

- **FR-001**: 사용자는 같은 층의 다른 사용자 목소리를 들을 수 있어야 한다.
- **FR-002**: 목소리의 크기는 **두 사용자 사이의 거리에 따라** 달라져야 한다.
- **FR-003**: 일정 거리 밖의 사용자 목소리는 들리지 않아야 한다.
- **FR-004**: 음성은 **게임 서버(NGO)를 경유해서는 안 된다** — 별도 실시간 미디어 경로를 사용한다.
- **FR-005**: 마이크 권한을 거부해도 **듣기와 월드 이용은 정상 동작**해야 한다.
- **FR-006**: 사용자는 자신의 마이크를 음소거할 수 있어야 한다.
- **FR-007**: 누가 말하고 있는지 시각적으로 표시되어야 한다.
- **FR-008**: 음성 기능 장애가 월드 접속·이동·부스·AI 기능을 중단시켜서는 안 된다.
- **FR-009**: 다른 층의 사용자 목소리는 거리와 무관하게 들리지 않아야 한다 (spec 018 이후).
  *spec 018이 **층별 세션**으로 확정되어, 음성 방을 층 단위로 두면 이 요구사항은 자동 충족된다.
  거리 계산에서 층을 걸러낼 필요가 없다.*
- **FR-010**: 사용자는 음성 기능 전체를 끌 수 있어야 한다.

### Key Entities

- **Voice Participant**: 음성 세션 참가자. 사용자 식별자, 말하기 상태, 음소거 여부
- **Spatial Context**: 볼륨 계산의 입력. 각 참가자의 위치, 층 식별자

## Success Criteria

- **SC-001**: 가까운 사용자의 목소리가 명확히 들리고, 먼 사용자의 목소리는 들리지 않는다.
- **SC-002**: 말하기 시작부터 상대가 듣기까지의 지연이 대화가 가능한 수준이다. [NEEDS CLARIFICATION: 목표 수치 — 통상 300ms 이하]
- **SC-003**: 음성 기능을 끄거나 실패한 상태에서 월드의 다른 기능이 100% 정상 동작한다.
- **SC-004**: 마이크 권한을 거부한 사용자도 월드를 온전히 이용할 수 있다.
- **SC-005**: 목표 인원 동시 접속 시 음성으로 인해 위치 동기화가 저하되지 않는다.
