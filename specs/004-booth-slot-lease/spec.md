## User Scenarios & Testing

### User Story 1 — 빈 부스를 임대한다 (Priority: P0)

사용자가 비어 있는 부스 슬롯을 코인으로 임대해 자기 부스를 갖는다.

**Why this priority**: UGC의 출발점. 임대가 안 되면 Studio도 Runtime도 의미가 없다.

**Independent Test**: 빈 슬롯 확인 → 임대 → 코인 차감 → 내 부스로 표시됨 → 다른 사용자에게는 사용 중으로 보임.

**Acceptance Scenarios**:

1. **Given** 로그인한 사용자, **When** 슬롯 목록을 보면, **Then** 빈 슬롯과 사용 중 슬롯이 구분되어 보인다.
2. **Given** 잔액이 충분한 사용자, **When** 빈 슬롯을 임대하면, **Then** 코인이 차감되고 임대가 생성된다 — **둘은 하나의 트랜잭션**이다.
3. **Given** 잔액이 부족한 사용자, **When** 임대를 시도하면, **Then** 거부되고 코인이 차감되지 않는다.
4. **Given** 이미 활성 임대가 있는 사용자, **When** 또 임대를 시도하면, **Then** 거부되고 사유가 안내된다 (D01).
5. **Given** 임대한 사용자, **When** 내 부스를 조회하면, **Then** 시작·만료 시각과 남은 시간이 보인다 (D07).

### User Story 2 — 한 슬롯은 한 사람만 (Priority: P0)

**Why this priority**: 슬롯이 7개뿐이라 동시 요청이 실제로 발생한다. 여기서 깨지면 코인만 사라지고 부스는 못 얻는다.

**Independent Test**: 같은 슬롯에 두 사용자가 동시에 임대 요청 → **한 명만 성공**, 실패한 쪽은 코인이 차감되지 않음.

**Acceptance Scenarios**:

1. **Given** 두 사용자가 같은 빈 슬롯에 동시 요청, **When** 처리되면, **Then** 정확히 한 명만 성공한다.
2. **Given** 실패한 사용자, **When** 잔액을 확인하면, **Then** 코인이 차감되어 있지 않다.

### User Story 3 — 만료되면 정리된다 (Priority: P0)

**Independent Test**: 임대 만료 → 신규 방문자가 그 부스에 들어갈 수 없음 → 콘텐츠는 보존됨 → 재임대 시 Draft로 시작.

**Acceptance Scenarios**:

1. **Given** 만료 시각이 지난 임대, **When** 신규 방문자가 접근하면, **Then** 입장과 신규 AI/상담 요청이 차단된다 (D03).
2. **Given** 만료 순간 진행 중이던 대화, **When** 짧은 유예가 지나면, **Then** 정상 종료된다 (D03).
3. **Given** 만료된 부스, **When** 소유자가 확인하면, **Then** Layout·AI·문서·설문·프로젝트가 **보존**되어 있다.
4. **Given** 보존된 콘텐츠가 있는 슬롯, **When** 누군가 재임대하면, **Then** **Draft 상태로 시작**하며 과거 게시본이 자동 공개되지 않는다 (D08).

### Edge Cases

- 결제 성공 후 임대 생성 실패 → **코인만 사라지는 상태가 절대 없어야 한다** (D06 REFUND 경로)
- 만료 직전에 임대한 경우 → 24시간이 온전히 보장되는가 (D02)
- 재임대한 사람이 이전 소유자와 다른 경우 → **이전 소유자의 콘텐츠가 새 소유자에게 보이면 안 된다** [NEEDS CLARIFICATION: 보존 콘텐츠의 소유권]
- 서버 시간대 처리 (UTC 저장 / Asia/Seoul 표시)
- 만료 처리 스케줄러가 멈춘 경우 → 만료된 부스가 계속 노출됨

## Requirements

### Functional Requirements

- **FR-001**: 사용자는 부스 슬롯 목록과 각 슬롯의 사용 여부를 조회할 수 있어야 한다.
- **FR-002**: 사용자는 빈 슬롯을 코인으로 임대할 수 있어야 한다.
- **FR-003**: **코인 차감과 임대 생성은 하나의 원자적 처리**여야 한다 — 한쪽만 반영된 상태가 남으면 안 된다.
- **FR-004**: 한 슬롯에는 **동시에 하나의 활성 임대만** 존재해야 한다.
- **FR-005**: 한 사용자는 **활성 임대를 1개만** 가질 수 있다 (D01).
- **FR-006**: 임대 기간은 **결제 시각부터 24시간**이다 (D02).
- **FR-007**: 사용자는 임대의 시작·만료 시각과 남은 시간을 확인할 수 있어야 한다 (D07).
- **FR-008**: 만료 시 신규 입장과 신규 AI/상담 요청이 차단되어야 한다 (D03).
- **FR-009**: 만료 시 이미 진행 중인 대화는 짧은 유예 후 종료되어야 한다 (D03).
- **FR-010**: 임대 종료 후에도 Layout·AI·문서·설문·프로젝트·인벤토리가 **보존**되어야 한다.
- **FR-011**: 재임대 시 **Draft 상태로 시작**해야 한다 (D08).
- **FR-012**: **P0에서 연장·자동 갱신을 제공하지 않는다** (D05).
- **FR-013**: **사용자 변심에 의한 환불을 제공하지 않는다.** 서버 오류·중복 차감은 `REFUND` 원장으로 복구한다 (D06).
- **FR-014**: **Lease 결제·취소·양도는 Owner만** 할 수 있다 (D10).
- **FR-015**: 운영자가 월드에 없어도 게시된 부스는 유지되어야 한다.
- **FR-016**: 게스트는 임대할 수 없어야 한다 (헌법 12조).

### Key Entities

- **Booth Slot**: 월드의 임대 가능 자리. 식별자, 유형(USER_RENTAL/관리자), 위치, 층
- **Lease**: 한 번의 임대. 슬롯, 소유자, 시작 시각, 만료 시각, 상태(활성/만료), 결제 참조
- **Booth**: 부스의 영속 콘텐츠. 슬롯과 분리되어 보존된다

## Success Criteria

- **SC-001**: 동시 임대 요청에서 한 슬롯이 두 명에게 임대된 사례가 0건이다.
- **SC-002**: 코인만 차감되고 임대가 생성되지 않은 사례가 0건이다.
- **SC-003**: 만료된 부스에 신규 방문자가 입장한 사례가 0건이다.
- **SC-004**: 재임대 시 이전 게시본이 의도치 않게 공개된 사례가 0건이다.
- **SC-005**: 사용자가 자기 부스의 남은 시간을 언제든 확인할 수 있다.
