## Summary

**타이머 정지 게임**: 서버가 5~10초 사이 목표 시간을 발급하고, 사용자가 그 시각에 맞춰 정지시킨다. 오차가 보상을 결정한다.

이 게임을 고른 이유는 구현 비용이 가장 낮으면서 **서버 검증이 자연스럽기 때문**이다.
목표 시간을 서버가 발급하고 시작·정지 시각을 서버가 기준으로 삼으면, 클라이언트 조작 여지가 거의 없다.

## 구현 원칙

### 1. 경제 처리는 전부 서버

보상 지급은 Spring이 판단하고 원장에 기록한다 (헌법 16조).
Unity는 **결과를 보고할 뿐 지급을 결정하지 않는다.** 이 경계는 게임 종류와 무관하게 고정이다.

```text
Unity: 게임 진행 → 결과 보고
Spring: 검증 → 한도 확인 → 지급 판단 → Ledger 기록
```

### 2. 멱등성이 필수

같은 게임 결과가 두 번 도착해도 한 번만 지급되어야 한다 (FR-004).
게임 세션 식별자를 Unity가 발급하고 서버가 중복을 판별하는 방식을 권장한다.

### 3. 단독 플레이 (확정)

멀티플레이는 동기화·판정·이탈 처리가 전부 추가되어 비용이 몇 배가 된다. 단독 플레이로 고정한다.

### 3-1. 목표 시간은 서버가 발급한다

클라이언트가 목표 시간을 정하면 "가장 쉬운 목표"를 고를 수 있다.
서버가 발급하고 서버 시각 기준으로 오차를 계산하면 검증 로직이 따로 필요 없다.

### 4. 게임은 월드와 분리

게임 실패·중단이 월드 접속에 영향을 주면 안 된다 (FR-007).
게임 로직을 월드 상태와 얽지 않는다.
